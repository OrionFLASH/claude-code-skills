# Правила создания скилов

## Имя и расположение
- Имя скила — kebab-case (`^[a-z0-9]+(-[a-z0-9]+)*$`), совпадает с именем папки `skills/<имя>/`, с полем `name` во frontmatter `SKILL.md` и с `name` в `plugin.json`.
- Новый скил создаётся только через `tools/new-skill.sh` (`.ps1`): он делает каркас и регистрирует скил в README и marketplace.json.

## Обязательные файлы скила
| Файл | Назначение |
|------|------------|
| `.claude-plugin/plugin.json` | имя, версия, описание; `"skills": ["./"]` — скил лежит в корне плагина |
| `SKILL.md` | frontmatter (`name`, `description` с триггерами) и компактная инструкция |
| `README.md` | описание, входные параметры, примеры вызова, зависимости, ограничения |
| `CHANGELOG.md` | журнал версий |
| `tests/` | сценарии самопроверки |

По необходимости: `references/` (детали), `templates/`, `scripts/`, `hooks/hooks.json` (хуки плагина; команды через `${CLAUDE_PLUGIN_ROOT}`, при ошибке хук молчит и не блокирует запрос), `INSTALL.md` (установка и обновление), `.shared` (список общих модулей), `.status` (статус для таблицы README: «в разработке», «стабильный», «устарел»).

## Универсальность
- Внутри скила нет конкретных сайтов, репозиториев, логинов, токенов, e-mail и других личных данных. Всё это — входные параметры.
- В примерах используются заглушки: `example.com`, `owner/repo`, `$ENV_VAR`. Исключение — публичные демо-стенды для самопроверки в `tests/` (например, `demo.playwright.dev`).
- Секреты передаются только через переменные окружения и не попадают в логи, отчёты, коммиты.

## SKILL.md
- Компактный: назначение, порядок работы, ссылки на `references/`. Цель — до ~300 строк.
- `description` содержит триггеры на русском и английском.
- Детали, чек-листы, длинные таблицы — в `references/`.

## Версии
- SemVer в `plugin.json` и `CHANGELOG.md` (должны совпадать — проверяет validate).
- Git-тег на релиз: `<имя-скила>/vX.Y.Z`.
- MAJOR — несовместимые изменения входных параметров или формата результатов; MINOR — новые возможности; PATCH — исправления.

## Скрипты
- Кроссплатформенно: bash (`.sh`) + PowerShell (`.ps1`).
- Python — только стандартная библиотека. Общую логику лучше писать на Python, а `.sh`/`.ps1` делать тонкими обёртками.
- Node-зависимости ставятся локально в папку скрипта (`package.json`), не глобально.
- Код, нужный нескольким скилам, — в `shared/scripts/` (единственный источник правды). При установке из маркетплейса копируется только папка плагина, поэтому ссылаться на `../../shared` нельзя: скил перечисляет нужные файлы в `skills/<имя>/.shared` (по одному пути на строку), `tools/validate.sh --fix` копирует их в `skills/<имя>/scripts/shared/`, а `tools/validate.sh` проверяет побайтовое совпадение. Вендоренные копии вручную не править.
- Тестовые помощники, нужные нескольким скилам (например, проверка примеров команд документации `doc_commands.py`), — в `shared/tests/`: строка `tests/<файл>` в `.shared` копирует его в `skills/<имя>/tests/helpers/shared/` тем же `tools/validate.sh --fix` и с той же побайтовой проверкой.

## Перед коммитом
- `tools/validate.sh <имя>` без ошибок.
- Скил есть в таблице README и в `marketplace.json` (new-skill делает это сам; validate проверяет).
- Запись в `CHANGELOG.md` скила и, при заметных изменениях, в корневом `CHANGELOG.md`.

## Git
- Любая доработка — в отдельной ветке (`feature/…`, `fix/…`, `docs/…`), затем слияние в `main`.
- Коммиты — на английском.

## Язык
- Документация и пояснения — на русском. Идентификаторы, имена файлов, коммиты — на английском.
