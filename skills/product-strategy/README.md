# product-strategy

Скилл Claude Code: по репозиторию, из которого запущен, готовит подробную стратегию развития и роста продукта. Сначала он опрашивает владельца, проверяет и доустанавливает инструменты, разбирает код и запущенное приложение, затем исследует рынок, конкурентов, сообщества, спрос и правовые ограничения. В реестр попадает от 50 до 200 предложений (по умолчанию 100), у каждого есть доказательства, шаги и оценки. Результат — план на ближайшие месяцы и видение на несколько лет, макеты и референсы дизайна, интерактивная веб-страница, XLSX, PPTX и PDF.

## Что получится
| Файл (`<OUT>/deliverables/`) | Что внутри |
|---|---|
| `index.html` | главный результат: офлайн-страница с резюме и тремя главными ставками, всеми разделами стратегии, реестром (фильтры, сортировка по любой метрике, карточки, экспорт CSV/JSON), оценками и чувствительностью, графиками, Гантом на весь горизонт, Kanban, кликабельными блок-схемами, кнопкой «🔍 Увеличить» у каждого графика и схемы (крупный просмотр с живым графиком: масштаб жестами и колесом, подсказки и подробности по каждому элементу), сквозным поиском по странице и исследованиям, кликабельными ссылками «раздел N», задачами плана и терминами глоссария, макетами и референсами (зоны с описаниями), конкурентами (поиск, «где лучше они / мы», скриншоты), источниками и вопросами владельцу |
| `strategy.xlsx` | реестр, оценки с формулами и редактируемыми весами, модель, источники, KPI, Kanban, конкуренты, Гант |
| `strategy.pptx`, `strategy.pdf` | презентация 40–60 слайдов основной части, топ-30 предложений карточками, приложение |
| `REPORT.md`, `README.md` | отчёт о прогоне (что сделано, чего не хватило, решения за владельца, токены) и порядок чтения |

Исходные данные лежат в `<OUT>/research`, `data`, `charts`, `mockups`, `design-refs` и `competitors`. Из них всё пересобирается одной командой `build_all.py`.

## Отслеживание выполнения стратегии (с 1.2)
Стратегия не разовая. Запущенный в репозитории с прошлой стратегией, скилл сам находит её (`strategy/*/`, `../<repo>-strategy/*/`; несколько — спросит, какую контролировать), сверяет план с кодом, коммитами, issues и PR репозитория (GitHub — только чтение) и отмечает статусы: сделано, частично, в работе, запланировано, не начато, отстаёт, заблокировано, не делаем, неактуально. Предложения привязываются к уже заведённым issues (по P-id или по сходству текста, неочевидное — вопросом), на таймлайне и доске видно «сделано / не сделано / доделать», считаются следующие шаги с учётом зависимостей, готовятся предложения по корректировке стратегии и черновики недостающих issues (создаются только по вашему «да»). Результат — раздел «Прогресс выполнения» на странице и лист в XLSX, `research/progress.md`, динамика по срезам. Режимы: «Отследить выполнение» и «Отследить и пересмотреть» (с обновлением текста стратегии). Подробно — `references/tracking.md`.

## Что нового в 1.5
- **Режим идеи без ручной работы**: опрос 1.5 — карточка «Начало» (для кого приложение, режим опроса), предзаполнение из текста запроса, условные блоки (ИИ, админка, данные, платформа, право, интерфейс, прототип), проверки противоречий и ёмкости до старта, нарезка на очереди после светофора; чтение материалов владельца по ссылкам из запроса.
- **Личный режим**: концепция инструмента для себя — без аудитории и денег, со стоимостью владения, build vs buy, личными KPI и экспериментами N = 1.
- **Новые шаги**: пересмотр идеи после исследования рынка (C4.5), второй раунд зависимостей от авторов (C7.5), выбор направления дизайна владельцем по галерее вариантов (C8a → C8-ask → C8b).
- **Рабочий прототип (C8.5)**: статический HTML+JS по `file://` с ядром расчётов и тестами, режимами интерфейса и смоуком — по желанию владельца.
- **План и числа сходятся**: одна ёмкость во всех расчётах, базовая линия плана и проверка текста по ней, профили модели `web-direct` и `personal`, черновики решений и резюме.
- **Страница**: «🔍 Увеличить» у каждого графика и схемы, сквозной поиск, кликабельные сущности и глоссарий, просмотр макетов с подсказками элементов, Гант на весь горизонт.
- **Контроль прогона**: статус с ETA, черновик страницы, журнал ручных вмешательств, ворота полноты в `build_all --strict`, каркас отчёта, обязательный диспетчер агентов, «быстрая концепция» ≈ 10 агентов.
Подробности — `CHANGELOG.md`, `references/concept-mode.md`, `references/prototype.md`, `references/interactive-site.md`.

## Как следить за прогоном (с 1.5)
- `init_run.py <OUT> --status` — таблица «фаза → статус → что открыть сейчас → ETA → кто работает».
- `build_all.py <OUT> --preview` — черновая страница `build/preview/index.html` без ворот.
- `report.py <OUT>` — каркас `REPORT.md` из данных прогона (`--check` — всё ли заполнено).

## Что нового в 1.4
- **Страница — многофайловый сайт**, а не один тяжёлый HTML: `index.html` (≈ 150–200 КБ) + `assets/` (CSS, JS, данные, графики, картинки) + `data/` (CSV/JSON). Открывается офлайн двойным кликом; `--single` возвращает один файл, `--lite` — один файл + картинки рядом, `--zip` — архив для отправки. Свои доработки без пересборки сборщика — `build/extra.css|js` и `build/extra/*.css|js` (во всех режимах, API `window.PS`).
- **Интерактивные графики**: у каждой диаграммы кликабельны все элементы (точки, столбцы, ступени воронки, узлы, ячейки, события). Панель объясняет, что это, что значит и что на этом этапе делать, и даёт ссылки на разделы стратегии, предложения, фильтры реестра, Гант и Kanban; есть управление с клавиатуры и глубокие ссылки `#chart/<график>/<элемент>`.
- **Файл задач для Claude Code** — опция опроса: один MD-файл с эпиками и задачами (по разделам: интерфейс, продукт, платформа, привлечение…), с ссылками на макеты, спеки, эксперименты и стратегию. Отдаёте его Claude Code в репозитории продукта — он сам создаёт эпики и issues. Состав выбирается в опросе или в конце прогона; можно «только интерфейс и дизайн».
- **Внешний продукт без кода** (раунд 0 опроса): сбор статистики магазинов, разбор APK, свой слой опроса «чей продукт и кто заказчик».
- **Надёжнее реестр и тексты**: накопительная карта id, безопасный `--append`, `overrides.json`, единые решения (`decisions.json`) и плейсхолдеры чисел модели и экспериментов, калькулятор выборок, проверка повторов; `render_brief.py`, `dispatch.py` и `check_paths.py` для оркестрации.
- **Мобильные макеты** и иконки, исправления набора, проверка схем.
Подробности — `CHANGELOG.md`, `references/interactive-site.md`, `references/handoff.md`, `references/external-product.md`, `references/decisions.md`.

## Режим «Идея → концепция продукта» (с 1.3)
Когда продукта ещё нет, а есть только идея. Отдельный скилл `product-concept` в этом же плагине: вы даёте идею в 1–2 фразах, скилл **задаёт не меньше 15 вопросов о ней** (по умолчанию 25, можно 40 или своё число ≥ 15; банк из 40 вопросов в 9 темах — проблема, аудитория, ценность, MVP, рынок и аналоги, деньги, команда, дизайн, риски), после чего сам: делает **предпроверку жизнеспособности** (Jev/TypeSafe, светофор go / оговорки / стоп), находит **конкурентов и аналоги** (прямые, косвенные, заменители, аналоги из соседних сфер, вдохновение, анти-примеры — с уроками), придумывает и обосновывает **сильные и слабые стороны (SWOT)**, JTBD, персоны, ценностное предложение и канвасы, собирает реестр предложений с оценками и зависимостями, модель дохода или устойчивости, MVP и дорожную карту, технологическое решение, метрики и **эксперименты проверки** (интервью, фейковая дверь, лендинг), риски, план от идеи до запуска и **концепт дизайна**: три направления языка дизайна, `tokens.css` выбранного, макеты ключевых экранов (≥ 8) и карточки референсов. Результат — та же интерактивная страница `index.html` (плюс XLSX, PPTX, PDF по выбору) и `REPORT.md` со светофором и тем, что проверить в первую очередь.

С 1.5: опрос начинается с карточки «Начало» (для кого приложение, режим опроса), ответы из текста запроса подставляются сами, условные блоки задают вопросы про ИИ, админку, данные, платформу, право, интерфейс и прототип, а противоречия и нехватка времени на MVP выясняются до старта. После рынка идея пересматривается (продолжить / сузить / остановиться), направление дизайна выбираете вы по галерее, по желанию собирается рабочий прототип. **Личный режим** — концепция инструмента для себя: без аудитории и денег, со стоимостью владения и build vs buy.

```text
/product-strategy:concept приложение для обмена книгами между соседями
/product-strategy:product-concept идея: сервис, который ...
!concept ...        concept: ...        !идея ...        # метки в начале запроса, без подтверждения
!concept автопилот ...                                    # минимум вопросов, значения по умолчанию
```
Или фразой: «у меня идея продукта …», «оцени идею», «придумай стратегию для продукта, которого ещё нет» — скилл сначала спросит, запускать ли режим. Папку результата вы выбираете карточкой каждый раз (текущая папка `concept/<имя>/<дата>/`, рядом, `~/concepts/…` или свой путь); сводка перед стартом всегда показывает строку «Папка: … ВНУТРИ / ВНЕ репозитория». Подробно — `references/concept-mode.md`.

## Как запустить
```text
/product-strategy
/product-strategy стратегия роста на год, 150 предложений, конкуренты и макеты
!strategy автопилот                 # без вопросов, параметры по умолчанию
!strategy track                     # отследить выполнение прошлой стратегии
/product-strategy:concept <идея>    # продукта ещё нет — концепция по идее (см. выше)
```
Или обычной фразой: «напиши стратегию развития этого приложения». Скилл сначала спросит, запускать ли его.

## Опрос (4 раунда + открытые вопросы)
0. **Проект.** Цель (личный, open-source, коммерческий), видимость репозитория, команда, валюта; от них зависит профиль «нулевой бюджет, один разработчик».
1. **Цель и объём.** Тип стратегии, глубина, число предложений, горизонт.
2. **Что анализируем.** Репозиторий, запуск приложения, сайт, Issues; конкуренты, сообщества, спрос и события, право; дизайн; финансовая модель.
3. **Рынки и деньги.** Языки и рынки, бюджет (три варианта), платный уровень, форматы.
4. **Место и инструменты.** Папка результата, TypeSafe, субагенты, политика установки.
5. **Открытые вопросы** — тоже карточками с вариантом по умолчанию: продукт, адрес, цифры, конкуренты, ограничения, материалы, автор, готовность открыть код.

Подробно — в `references/intake.md`.

## Параметры по умолчанию
| Параметр | По умолчанию |
|---|---|

| Предложений в реестре | 100 (минимум 50, на выбор 150 и 200) |

## Зависимости
Обязательны Python 3.10+ (скрипты используют только стандартную библиотеку) и git. Рекомендуются Node.js 18+ (Playwright и pptxgenjs ставятся в папку прогона), gh и плагины-помощники. Установка и промпты для установки, обновления и дополнительных модулей описаны в [INSTALL.md](INSTALL.md).

## Ограничения
- Внешний мир — только чтение: никаких публикаций, писем, регистраций, оплат, входа в аккаунты и записи в чужие репозитории.
- Цифры без источника помечаются как оценка или допущение. Доступ к закрытой аналитике должен дать владелец.
- Скриншоты конкурентов и макеты на основе чужих материалов годятся только для внутреннего обсуждения, это отмечается в отчёте.
- Очень большой прогон (глубина «максимально», 200 предложений) расходует много токенов. Глубину и число субагентов выбирайте в опросе.
