## Шаги
1. **Токены**: перенести значения выбранного направления из `mockups/tokens.css` в `css/base.css` (обе темы; контраст текста ≥ 4,5:1); для каждого режима — `css/tokens-<id>.css` с селектором `:root[data-mode="<id>"]` (оболочка ставит `data-mode` на `<html>`).
2. **Оболочка** (`index.html`, `js/app.js`): название {PRODUCT}, переключатель режимов из реестра, тема, бейджи (текст бейджа концепта — ровно «Концепт продукта, не существующая функция»), ссылка «К содержимому», подвал с оговоркой «данные вымышлены». Режим и ввод сохраняются в localStorage и `#hash` (в try/catch).
3. **Режимы**: для каждого режима из {PROTO_MODES} — строка `<script src="js/mode-<id>.js"></script>` перед `js/app.js` и файл-заглушка `js/mode-<id>.js` (регистрирует режим с карточкой «Режим в разработке, смотрите макет …» и ссылкой на макеты), чтобы оболочка работала до прихода агентов режимов. Пример `mode-example.js` удалить из `index.html`, когда есть хотя бы один свой режим.
4. **ИИ** (если роль ИИ не «без ИИ»): `js/llm.js` — шаблонный объяснитель по фактам ядра, фикстуры `fixtures/llm-replies.js` (числа — из канона), сверка «N из N сверены» и запретные формулировки (из `legal.md`/`ai.md`), оговорка у ответа; живая локальная модель — только кнопкой и только `127.0.0.1`/`localhost`, с понятными причинами отказа (не запущена, CORS, запрет браузера).
5. **Контракт** в `prototype/README.md`: как открыть, структура, контракт режима (`registerMode`, `ctx`, события состояния, токены режима), владелец общих файлов, ограничения прототипа (демо-данные, `file://`, локальная модель через локальный сервер), чего нет.
