## Шаги
1. Поля, которые реально отдаёт выбранная среда ИИ (время, токены, причины окончания, ошибки) — по документации (ссылки из `sources-ai.json` или `sources.json`); каких полей нет — честно.
2. Каталог метрик по группам: время (p50/p95 от запроса до ответа, до первого токена, загрузка модели, доля холодных стартов), скорость (токенов в секунду), токены (вход, кэш, выход, заполнение контекста, обрезка), ресурсы (память, доля на GPU), надёжность (ошибки по классам, ответы не по схеме, отмены, повторы, откаты на шаблон), качество (валидный вывод с первой попытки, сверка чисел «N из N», запрещённые формулировки, оценка пользователя, эталонный прогон, регрессия), использование (разборы в день, «день × час», доля расчётов с разбором). Для каждой: формула, единицы, источник поля, где хранится, вид визуализации, порог (с меткой), **минимальная выборка** (например, p95 — не меньше 20 замеров), крайние случаи.
3. Журнал событий: какие события (старт, этап, прогресс, итог, ошибка), какие поля — **только числа и коды, без текста запроса и ответа** по умолчанию; срок хранения, лимит записей, удаление; что уходит на сервер (если сервер есть) — только по согласию.
4. Экраны и индикаторы: пилюля здоровья в шапке (состояния, текст), лента последних разборов с итогом «N из N сверены · t с», страница журнала (период, графики с минимальной выборкой, пустое состояние), экран эталонов (результат последнего прогона, n, порог). Ключи будущих макетов (`M2x-ai-…`) — для C8, с 12–25 элементами для подсветки `data-hs-*`.
5. Правило слов: «качество» — только про эталонный набор с числом n; скорость и сверка — «исправность».
6. Предложения в реестр (группа G9, 5–15): что внедрить в MVP (обычно — сохранение статистики ответа и итог «N из N»), что в v1, что позже; у каждого — KPI, который предложения реестра иначе не посчитать.
