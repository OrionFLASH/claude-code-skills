## Шаги
1. Посмотреть эталон и скриншоты; понять компоненты набора. **Набор не писать заново** и не копировать к себе: всё нужное уже в `_kit.css`; не хватает компонента — собрать его в своём макете с префиксом ключа и сообщить в отчёте.
2. Для каждого ключа: продумать сценарий (что видит пользователь, главное действие, состояния), затем собрать `mockups/concepts/<key>.html` на наборе.
3. Подключение в `<head>`: `<link rel="stylesheet" href="../tokens.css"><link rel="stylesheet" href="_kit.css">` (+ `<script src="_kit.js" defer></script>`); viewport — атрибутом `<html data-viewport="mobile">` для мобильных ключей из {VIEWPORTS} (десктоп — без атрибута или `data-viewport="desktop"`). По атрибуту скрипт снимков сам находит макет и размер — индекс макетов не нужен.
4. Тема: по умолчанию светлая; если набор поддерживает тёмную (`data-theme="dark"`) и экран важен в обеих — можно второй вариант в том же файле или отдельным ключом `<key>-dark` (согласовано в {KEYS}).
5. Бейдж: `<div class="ps-concept-badge">Концепт, не существующая функция · {PRODUCT} · {DATE}</div>` — виден и не закрывает главное (на мобильных — над нижней панелью).
6. Рендер и проверка только своих ключей: `PS_NODE_DIR=<кэш Node-модулей из факт-листа или ~/.cache/product-strategy/node> node {SKILL_DIR}/scripts/node/shoot_mockups.mjs {OUT} --only <ключ>[,<ключ>…]` → PNG рядом с HTML и `{OUT}/data/mockups-check.<ключ>.json` (свой файл на ключ — параллельные агенты не затирают друг друга). Открыть свой PNG через Read, исправить дефекты, повторить. Флаги — `--help`.

## Правила
- Язык интерфейса — {LANG} (как в продукте). Тексты правдоподобные, без lorem ipsum, без персональных данных реальных людей.
- Детально, на компонентах набора; новых классов — с префиксом ключа (`m05-…`), чтобы не конфликтовать.
- Без внешних запросов (шрифты, CDN, картинки по сети); только локальные файлы.
- Не копировать чужие логотипы, иллюстрации, тексты; паттерны конкурентов — своими компонентами.
- Контраст текста ≥ 4,5:1 (крупный ≥ 3:1), в том числе для бейджей, кнопок-предупреждений и текста на штриховке; кликабельные зоны ≥ 24 px.
- `_kit.css`/`_kit.js`/`tokens.css`/`_base.html` не менять; нашёл баг набора — описать в отчёте (оркестратор исправит один раз для всех).
- Не запускать git; писать только в пути из «Выдачи».
