## Шаги
1. Выбрать {COUNT} предложений: минимум по одному на каждую из трёх ставок, остальные — быстрые победы воронки. Если эксперимент A/B невозможен (мало трафика) — предложить другой дизайн проверки (фейковая дверь, опрос, ручной сервис, поэтапный запуск с до/после) и честно это указать.
2. Для A/B рассчитать размер выборки на группу для бинарной метрики:
   `n = (z_{1−α/2} + z_{1−β})² × (p1(1−p1) + p2(1−p2)) / (p2 − p1)²`, где p1 — базовая конверсия, p2 = p1 + MDE; по умолчанию α = 0,05 (z = 1,96), мощность 80 % (z = 0,84). Показать подстановку чисел. Пример: p1 = 0,10, MDE = +0,02 → n ≈ (2,8)² × (0,09 + 0,1056) / 0,0004 ≈ 3 834 на группу.
3. Длительность = 2 × n / (трафик в день на входе эксперимента), не меньше 7 дней (полный недельный цикл), не больше 6 недель; если дольше — увеличить MDE или сменить метрику, указать это.
4. Критерий остановки: заранее заданная длительность/выборка; без «подглядывания» с остановкой при первом p < 0,05; защитные метрики с порогом досрочной остановки.
5. Решение: что делаем при победе / проигрыше / ничьей.
5а. **Записать расчёт в `data/experiments.json`** — для каждого эксперимента с числовой метрикой (A/B, фейковая дверь, до/после, критерий отказа): `python3 {SKILL_DIR}/scripts/sample_size.py {OUT} --add E01 --baseline <p1> --mde <MDE> [--relative] --title "<название>" --metric "<метрика>" --proposal <P-id> [--traffic <N> --per week|day|month] [--kind rate]` (`--kind rate` — события в неделю, сравнение двух периодов «до/после»; без `--traffic` поток берётся из `data/model.json`). Скрипт сам считает `n` и срок и пишет файл; руками JSON не править. В тексте плана и стратегии выборка и срок — плейсхолдерами `{exp:E01.n}`, `{exp:E01.weeks}` (значения — `python3 {SKILL_DIR}/scripts/sample_size.py {OUT}`). Качественные проверки (интервью) — без `--add`, с числом интервью и правилом насыщения в тексте.
6. Без повторов: план эксперимента не пересказывает обоснование предложения и стратегию — одна строка со ссылкой на P-id и раздел; объём — на дизайн, расчёт и критерии. Чисел рангов не писать.

## Режим идеи (mode: concept)
Продукта и трафика ещё нет: эксперименты проверяют гипотезы **до разработки** (фейковая дверь, посадочная с листом ожидания, интервью, концепт-макеты и кликабельный прототип, ручной сервис, предзаказ); базовые доли — `[допущение]` из `data/model.json` или аналогов; трафик — плановый поток предзапуска из модели (`--traffic` с меткой допущения). Макет в «Что нужно для запуска» — ключ из `data/mockups-index.json` (индекс строится из плана макетов до их съёмки), иначе «макета нет».

## Личный режим (`project.audience` = `personal`, `circle` или `personal_then_public` в `{OUT}/build/run-config.json`)
Аудитории нет — выборок на пользователях и A/B на трафике тоже. Эксперименты — **на себе, N = 1**: «неделя с инструментом вместо прежнего способа» (до/после), чередование дней A/B/A/B, повторные замеры одной метрики (время задачи, число ошибок, пропущенные события, решения, которые пришлось переделать). Для каждого: метрика и как её записывать (журнал, таймер, выгрузка), длительность в днях (не меньше двух циклов использования), порог «стоит того / не стоит» (`[допущение]`), что мешает честности (эффект новизны, сезонность) и как это гасится. Расчёт — `sample_size.py … --kind rate` (события в неделю до/после) или честное «N = 1: статистика не применяется, решение по порогу». Кругу (`circle`) — 2–5 человек, интервью и дневник вместо выборки. Порог «стоит того» — от модели личного профиля (`model.py --profile personal`: `data/model.json → scenarios.base.value`, `net_value`, `breakeven_month`, `hours_saved_per_week_to_break_even` — значение с пометкой источника; в тексте стратегии, раздел 8, — плейсхолдерами `{model:base.value|money}`, `{model:base.net_value}`, `{model:base.breakeven_month}`, `{model:base.hours_saved_per_week_to_break_even|1}`).
