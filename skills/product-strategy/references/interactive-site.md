# Страница стратегии как многофайловый сайт и интерактивные графики (1.4)

Спецификация двух доработок `build_html.py` / `charts.py` по обратной связи пользователей. Источник правды для разработки и тестов; пользовательское описание — в README.

## 1. Многофайловая страница (режим `site`, по умолчанию)
Проблема: `deliverables/index.html` — один файл на 5–42 МБ (CSS, JS, данные, картинки внутри). Его неудобно открывать, пересылать, коммитить, публиковать; правки CSS/JS невозможны без пересчёта хешей CSP.

Решение — **сайт из нескольких файлов, работающий офлайн по двойному клику (`file://`)**:
```text
deliverables/
  index.html            оболочка: разметка и текст разделов (≤ 1 МБ без данных), ссылки на файлы ниже
  assets/app.css        стили (раньше <style>)
  assets/app.js         логика страницы (раньше встроенный <script>)
  assets/data.js        window.PS_DATA = {…}: реестр, оценки, конкуренты, модель, Гант, Kanban, источники (JS, а не JSON: fetch() по file:// запрещён)
  assets/charts-<группа>.js   window.PS_CHARTS[ключ] = {svg, meta}: SVG интерактивных графиков и пояснения к их элементам,
                        по файлу на группу — раздел графика из charts-index.json (`section`: scores, registry, plan, model,
                        market…; нет раздела — `other`); файл подключается динамически при первом показе графика группы или по
                        глубокой ссылке #chart/<ключ>/<id>; в single/lite SVG и meta встроены в index.html, файлов charts-*.js нет
  assets/img/…          скриншоты, макеты, референсы: WebP/PNG, одна копия на изображение, миниатюры thumbs/
  assets/extra.css, extra.js   необязательные пользовательские правки из <OUT>/build/extra.{css,js} (подключаются, если есть)
  data/                 открытые данные рядом: proposals.json, proposals.csv, scores.csv, competitors.csv, gantt.csv, kanban.csv, sources.csv (для людей и импорта; страница от них не зависит)
```
- Ссылки на файлы **относительные**, внешних запросов нет. Версионирование от кэша: `?v=<короткий хеш содержимого>`.
- Режим `--single` — прежний автономный файл (для Artifact ≤ 16 МБ и пересылки одним файлом); `--lite` остаётся и означает «single с картинками в assets/». `build_all.py` пробрасывает `--single`/`--lite`; без флагов собирается **site**. Если сайт > 25 МБ суммарно — совет (WebP, миниатюры), а не ошибка.
- Папка `deliverables/` после сборки самодостаточна: можно zip-нуть целиком (`build_all.py … --zip` → `deliverables/strategy-site.zip`).
- CSP: в режиме `site` — `default-src 'none'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'` (проверить `'self'` при `file://` в Chromium, WebKit, Firefox; если движок не принимает — запасной вариант без CSP-мета, но с проверкой «внешних запросов 0» и `referrer: no-referrer`; решение записать в `CHANGELOG`). Хеши sha256 нужны только в режиме `single`.
- Режим идеи (`mode: concept`) использует тот же сборщик и получает те же режимы.
- Старый вывод (`single`) должен оставаться побайтово совместимым по содержимому разделов: тесты `test_build_html.py` проходят в обоих режимах.

## 2. Интерактивные графики
Правило: **ни одного «голого» рисунка**. Каждая диаграмма — встроенный SVG, у которого каждый значимый элемент (точка, столбец, ступень воронки, узел, ячейка, событие, стрелка) кликается, фокусируется с клавиатуры и открывает **панель пояснений**: что это, что означает, что в этом этапе делать, ссылки на другие места страницы.

### 2.1 Разметка SVG (делает `charts.py`)
- Каждый интерактивный элемент: `data-ps-el="<id>"`, `tabindex="0"`, `role="button"`, `aria-label="<название элемента>"`, класс `ps-el`; id уникален внутри графика (`P018`, `stage-activation`, `cat-acquisition`, `kpi-north-star`…).
- Корневой `<svg>`: `data-ps-chart="<ключ>"`, `<title>`/`<desc>` (краткое описание для скринридеров).
- Подписи и легенда — тоже элементы (клик по легенде подсвечивает соответствующие элементы).

### 2.2 Метаданные пояснений (делает `charts.py`, пишет `charts/<ключ>.meta.json`)
```json
{"key": "funnel", "title": "…", "howto": "Как читать график: …", "legend": [{"label": "…", "text": "…"}],
 "elements": {"stage-activation": {
   "title": "Активация", "kind": "stage|point|bar|node|cell|event|link",
   "summary": "Что это (1–2 предложения)", "meaning": "Что значит значение именно здесь", 
   "actions": ["Что делать на этом этапе (1–4 пункта, из шагов предложений и глоссария)"],
   "metrics": [{"label": "Значение", "value": "40 %", "tag": "допущение"}],
   "links": [{"label": "Раздел 7. Конверсия и онбординг", "href": "#s7"}, {"label": "P032 — Quickstart", "href": "#p/P032"},
             {"label": "Показать в реестре", "href": "#registry?category=conversion"}]}}}
```
- Источники текста, по приоритету: (1) `data/chart-notes.json` — заметки авторов/оркестратора по `{ключ: {id: {…}}}` (опционально, перекрывают остальное); (2) данные прогона (предложение: название, `rationale`, `steps[]`, `effect_kpi`, оценки, зависимости, горизонт; модель: стадия воронки, допущения; Гант: задача, критерий готовности, зависимости; конкурент: вердикт, где лучше они/мы); (3) **глоссарий** `references/chart-glossary.ru.json` (статические определения: стадии AARRR, оси матрицы «усилия–эффект», что такое «торнадо», «критический путь», WSJF/RICE, классы доказательств и т. п.). Никакого выдумывания: нет данных — пометка «пояснение не задано» и предупреждение сборщику.
- Ссылки: `#s<N>` — раздел стратегии N; `#p/P018` — карточка предложения в реестре (раскрывает строку); `#registry?category=…&horizon=…&class=…` — реестр с фильтром; `#chart/<ключ>/<id>` — глубокая ссылка на элемент графика; `#flow/<ключ>`, `#mockup/<ключ>`, `#competitor/<slug>`, `#gantt/<G01>`, `#kanban/<P018>`. Все цели должны существовать (проверка сборщика).
- Покрытие: каждый `data-ps-el` имеет запись в `elements`, и наоборот; для каждого графика заполнены `howto` и `legend`.

### 2.3 Поведение на странице (делает `build_html.py`)
- Клик, `Enter`/`Space` по элементу открывает панель справа (на экранах < 700 px — нижний лист); в панели заголовок, «Что это», «Что значит», «Что делать», метрики с метками достоверности, ссылки; `Esc` закрывает; `←`/`→` — предыдущий/следующий элемент того же графика; фокус возвращается на элемент.
- Выбранный элемент подсвечивается в SVG (контур, не только цвет — контраст ≥ 3:1 в обеих темах); под графиком — кнопка «Как читать график» (раскрывает `howto` и легенду).
- Глубокие ссылки `#chart/<ключ>/<id>` открывают раздел, прокручивают к графику и выбирают элемент; ссылки в панели ведут к разделам/предложениям/фильтрам реестра на этой же странице.
- Подсказка при наведении (tooltip) — короткое `title` элемента; без JS график остаётся читаемым (SVG статичен, `<desc>` описывает).
- Печать: панель скрыта, графики статичны.
- Гант, Kanban, блок-схемы (`flows`), карточки референсов и матрица конкурентов уже интерактивны; привести их к одной панели и схеме ссылок, где это дёшево; карточки скриншотов конкурентов и макетов открываются в просмотрщике с подписью и ссылкой на предложения.

### 2.4 Проверки (smoke и тесты)
- Для демо-прогонов (обычного и режима идеи): во всех графиках клик по КАЖДОМУ `data-ps-el` открывает непустую панель; клавиатура; Esc; все `links[].href` разрешаются; ни одного графика без `howto`; внешних запросов 0; ошибок консоли 0.
- Движки: Chromium и WebKit обязательно (как в smoke), Firefox — если установлен; в `REPORT.md` перечислять проверенные движки.
- Страница `site` открывается по `file://` без ошибок и ведёт себя как `single`.

## 3. Слой интерактивности, поиск и сущности (1.5)
Источник: два боевых прогона product-concept (AR — FB-035…FB-039, SM — раздел 8). Раньше это делали внешние слои после сборки
(`postprocess_interactive.py`, `postbuild_enhance.py`) и `build_html.py` стирал их при пересборке; теперь всё — в генераторе.

### 3.1 Где живёт слой
- Исходники — `templates/site/ps-interact.js` (просмотр графиков и схем), `ps-search.js` (поиск), `ps-ents.js` (сущности, глоссарий),
  `ps-layer.css` (стили всех слоёв). `build_html.py` встраивает JS в общий скрипт сразу после app.js (site — `assets/app.js`,
  single/lite — тот же встроенный скрипт, хеш CSP считается по всему тексту), CSS — в app.css / `<style>` блоком `/* ps-1.5:start … end */`.
  Нет папки `templates/site/` — страница собирается без слоёв с предупреждением.
- Разметку пишет сборщик (а не скрипт после загрузки): у каждого графика и схемы — `<div class="psi-wrap psi-chart|psi-flow">` +
  `<button class="psi-zoom">🔍 Увеличить</button>` + плашка `.psi-cue`; строка `.psi-hint` «Графики и схемы кликабельны: наведите — подсказка,
  нажмите — подробности, 🔍 — увеличить.» — под H1 и под заголовком каждого раздела с графиками или схемами. Старые «⤢ увеличить» и
  «открыть схему как картинку» убраны (ссылки `#lb=c-<ключ>` / `#lb=flow-<ключ>` по-прежнему работают).

### 3.2 Поведение (критерии FB-035)
- Курсор: `zoom-in` на фоне, `pointer` на элементах; клик по фону, «🔍» или Enter/Space на кнопке — просмотр.
- Подсказка при наведении и фокусе с клавиатуры — мгновенная: «название + первое предложение „что это“» (графики — `#cp-tip`, схемы — `#psi-tip`),
  контур элемента; системный `<title>` снимается.
- Панель элемента на странице: графики — «Что это / Что значит / Что делать / Метрики / Связанные предложения / Где на странице»; схемы —
  окно «Что это / Как сейчас / Что сделать / Как измерять / Связанные предложения».
- Просмотр `#psi-lb`: живая копия SVG (не `<img>`), «−», «+», «Сброс», «Панель», «✕ Закрыть»; колесо, щипок трекпада (Safari `gesture*`,
  Chrome/Firefox Ctrl+колесо), щипок и двойное касание, перетаскивание, `+`/`-`/`0`, стрелки; каждый элемент наводится и нажимается,
  «Пред./След.» и ←/→; без выбора — «Вывод», «Как читать» и список всех элементов; P-id открывают карточку поверх просмотра; Esc закрывает
  верхний слой (карточку, затем просмотр) и возвращает фокус на кнопку; Tab не выходит из окна.
- Телефон (≤ 699 px): кнопка над картинкой (≥ 44×36 px, не закрывает заголовок), просмотр на весь экран, панель — нижний лист.
- Печать: без кнопок, плашек, подсказок и просмотра. Тема — токены `--ps-*`.
- API `window.PSI`: `open(ключ[, id])`, `close()`, `select(id)`, `state()`, `isOpen()`.

### 3.3 Размеры до загрузки (FB-037) и доступность схем (FB-038)
- Заглушка ленивого графика (site): `style="--ps-ar:W / H;--ps-mh:Npx"` из viewBox SVG; на ≤ 699 px — `min-height` = 560·H/W + рамка (SVG там не
  уже 560 px). Картинки `<img>` — `width`/`height` и `style="width:…px;aspect-ratio:W / H"` (телефонный макет — ширина по высоте 540).
- Схема: корень `role="group"` (не `img`), `aria-labelledby` — только на существующие (переименованные областью) id, иначе `aria-label` =
  название схемы; у каждого блока `data-node` — `<title class="ps-nt">` из `flows.json → nodes[].label: what` (свой `<title>` не дублируется)
  и `aria-label «… — открыть расшифровку»`. `check_flow.mjs` падает (`node_no_title`) на блоке без `<title>`, если блок описан в flows.json
  (label или what); `--strict-titles` — для всех блоков.

### 3.4 Хуки расширения (подключаемые слои)
- `build/extra.css`, `build/extra.js` и папка `build/extra/*.css|*.js` (по имени файла) подключаются **во всех режимах**: site — файлы
  `assets/extra.*`, `assets/extra/<имя>`; single/lite — встроенные `<style>`/`<script>` после основного (у скрипта — свой хеш CSP; скрипт с
  `</script` в single не встраивается).
- `window.PS` (app.js): `data(id)`, `router` (= `PS_ROUTER`), `openProposal`, `openInfo`, `openNode`, `openGantt`, `openKanban`, `openLayer`,
  `closeLayer`, `closeAll`, `linkify(el)`, `on(событие, fn)` / `emit`, `replace(имя)`, `isReplaced`, `replaced()`. События: `ready` (уже было —
  fn вызывается сразу), `chart:select`, `layer:open|close`, `viewer:open|close|select`, `search:open`.
- `PS.replace('lightbox'|'viewer'|'search'|'entities')` — расширение берёт компонент на себя: встроенный не срабатывает, `<html data-ps-replaced>`,
  smoke пропускает его проверки с пояснением «заменён расширением» (условие окружения, `--require all` их не требует).

### 3.5 Сквозной поиск
- Кнопка «🔎 Поиск по странице» в меню и в мобильной шапке, клавиши `/` и Ctrl/Cmd+K, ссылка `#q=<текст>`; окно — слой `.layer` (Esc).
- Индекс — при первом открытии: блоки разделов (абзац, пункт, строка таблицы, подпись, план, Kanban…), реестр (название, описание, обоснование,
  шаги, KPI, доказательства, теги), конкуренты, блоки схем, задачи Ганта, карточки Kanban, пояснения графиков, глоссарий, прочие
  `research/**/*.md` (кроме выведенных на страницу; ≤ 200 000 знаков на файл, ≤ 3 МБ всего; single — блок `d-docs`, site —
  `assets/search-docs.js` по `<meta name="ps-docs">`, подгружается при первом поиске).
- Совпадение: начало слова («калькул» → «калькулятор»); формы слова — общая основа без типичного окончания («цена» → «цены», «ценой», но не
  «ценность»); «фраза в кавычках»; все слова в блоке или флажок «любое из слов»; флажок «внутри слова» — подстрока; регистр и е/ё не важны.
- Фильтры по виду (Стратегия, Реестр, Конкуренты, Графики, Схемы, План и Kanban, Макеты и дизайн, Рынок/модель/источники, Глоссарий,
  Исследования), `<mark>` в выдаче, после перехода — `mark.pss-hit` в целевом блоке (строке реестра, карточке, панели графика, окне).
  ↑/↓ — по выдаче, Enter — перейти. Поиск в реестре, конкурентах и фильтрах таблиц тоже понимает несколько слов и фразы.

### 3.6 Сущности текста и глоссарий
- `ps-ents.js` делает ссылками: «раздел N»/«разделы 5 и 7»/«разд. 3» → `#sN` (если раздел есть); G-id задач Ганта → окно задачи; M-ключи
  макетов (M01, если однозначно) → `#mockup/<ключ>`; названия конкурентов (+ `aliases`) → карточка; ID из первой ячейки строк таблиц текста
  (H1, E03, R12, PS2…) → строка (id `ent-<ID>`); термины глоссария → подсказка с определением и окно «что это, где ещё упоминается».
  ID — каждое упоминание, имена и термины — первое в блоке. Аудит — `PS_ENTS.audit()` (P-/G-id, «раздел N», ID строк вне ссылок).
- Глоссарий — `research/glossary.md` (`build_appendix.py --only glossary`): строки `| Термин | Значение |` и `- **Термин** — …`; синонимы — из
  словаря `templates/glossary.md`; «(источник: …)» в конце — поле src. На странице — раздел «Глоссарий» (`#glossary`, строки `gl-<ключ>`),
  данные `d-gloss`, ссылки `#gl/<ключ>`. Нет файла — раздела и терминов нет (страница прежняя).

### 3.7 Макеты в просмотре
- У фигуры макета всегда `data-mock`, `data-pids`, `data-html` (живой HTML → «Открыть интерактивный макет ↗», для макетов с подсказками — `#hs`),
  вторая тема снимка — `data-alt` / `data-alt-theme` (кнопка «Тема» в просмотре).
- Вторая тема (`shoot_mockups.mjs`): в записи `data/mockups-index.json` — `themes: {"light": "…png", "dark": "…png"}` или `png_dark` / `png_light` / `png_alt`.
- Подсказки элементов (стандарт `data-hs-*`, mockup-kit/_hotspots.js): координаты — `mockups/hotspots.json`
  `{"version": 1, "mockups": {"<ключ>": {"items": [{"n", "id", "title", "what", "why", "p": ["P001"], "sec": [5], "r": [x, y, w, h]}]}}}`
  (r — доли ширины/высоты снимка) или поле `hotspots` записи mockups-index.json (r — доли, либо x/y/w/h в пикселях снимка); нет координат —
  описания из атрибутов `data-hs`, `data-hs-title`, `-what`, `-why`, `-p`, `-sec` самого HTML (список без зон). В данных — псевдореференс
  `d-refs["m:<ключ>"]` (`mock: true`, `html`): зоны с номерами поверх снимка, в боковой панели — что это, для чего, P-id, разделы.
- Рядом с макетами — ссылки на `mockups/gallery.html` и `prototype/index.html`, если они есть.

### 3.8 Гант на весь горизонт, таблицы, карточки
- Шкала: план — месяцы 1…H (`strategy.horizon_months`), видение — до конца года последней задачи (горизонт 6 и задачи до 24-го → «7–12», «год 2»).
  Месяцы без единой задачи — пробел плана: штриховка `.ggap`, «нет задач» на шкале, строка в легенде, предупреждение сборщика. На графике
  `charts.py` — граница видения по H и элементы `gap-<с>-<по>` с пояснением (глоссарий `area-gap`).
- Таблицы текста: колонка, пустая (или «—») во всех строках, не выводится; колонке с короткими значениями и одним-двумя длинными (медиана < 20,
  максимум > 40 знаков и в 2,5 раза больше) — ширины `<colgroup>` (иначе «пустая область»).
- Карточка реестра на ≤ 900 px: открыта только «Суть» (и «Выполнение»), остальное — строки `<details>` с числом пунктов.
