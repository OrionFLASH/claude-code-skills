# Страница стратегии как многофайловый сайт и интерактивные графики (1.4)

Спецификация двух доработок `build_html.py` / `charts.py` по обратной связи пользователей. Источник правды для разработки и тестов; пользовательское описание — в README.

## 1. Многофайловая страница (режим `site`, по умолчанию)
Проблема: `deliverables/index.html` — один файл на 5–42 МБ (CSS, JS, данные, картинки внутри). Его неудобно открывать, пересылать, коммитить, публиковать; правки CSS/JS невозможны без пересчёта хешей CSP.

Решение — **сайт из нескольких файлов, работающий офлайн по двойному клику (`file://`)**:
```text
deliverables/
  index.html            оболочка: разметка и текст разделов (≤ 1 МБ без данных), ссылки на файлы ниже
  assets/app.css        стили (раньше <style>)
  assets/app.js         логика страницы (раньше встроенный <script>)
  assets/data.js        window.PS_DATA = {…}: реестр, оценки, конкуренты, модель, Гант, Kanban, источники (JS, а не JSON: fetch() по file:// запрещён)
  assets/charts.js      window.PS_CHARTS = {ключ: {svg, meta}}: SVG графиков и пояснения к их элементам; подгружаются при показе раздела
  assets/img/…          скриншоты, макеты, референсы: WebP/PNG, одна копия на изображение, миниатюры thumbs/
  assets/extra.css, extra.js   необязательные пользовательские правки из <OUT>/build/extra.{css,js} (подключаются, если есть)
  data/                 открытые данные рядом: proposals.json, proposals.csv, scores.csv, competitors.csv, gantt.csv, kanban.csv, sources.csv (для людей и импорта; страница от них не зависит)
```
- Ссылки на файлы **относительные**, внешних запросов нет. Версионирование от кэша: `?v=<короткий хеш содержимого>`.
- Режим `--single` — прежний автономный файл (для Artifact ≤ 16 МБ и пересылки одним файлом); `--lite` остаётся и означает «single с картинками в assets/». `build_all.py` пробрасывает `--single`/`--lite`; без флагов собирается **site**. Если сайт > 25 МБ суммарно — совет (WebP, миниатюры), а не ошибка.
- Папка `deliverables/` после сборки самодостаточна: можно zip-нуть целиком (`build_all.py … --zip` → `deliverables/strategy-site.zip`).
- CSP: в режиме `site` — `default-src 'none'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'` (проверить `'self'` при `file://` в Chromium, WebKit, Firefox; если движок не принимает — запасной вариант без CSP-мета, но с проверкой «внешних запросов 0» и `referrer: no-referrer`; решение записать в `CHANGELOG`). Хеши sha256 нужны только в режиме `single`.
- Режим идеи (`mode: concept`) использует тот же сборщик и получает те же режимы.
- Старый вывод (`single`) должен оставаться побайтово совместимым по содержимому разделов: тесты `test_build_html.py` проходят в обоих режимах.

## 2. Интерактивные графики
Правило: **ни одного «голого» рисунка**. Каждая диаграмма — встроенный SVG, у которого каждый значимый элемент (точка, столбец, ступень воронки, узел, ячейка, событие, стрелка) кликается, фокусируется с клавиатуры и открывает **панель пояснений**: что это, что означает, что в этом этапе делать, ссылки на другие места страницы.

### 2.1 Разметка SVG (делает `charts.py`)
- Каждый интерактивный элемент: `data-ps-el="<id>"`, `tabindex="0"`, `role="button"`, `aria-label="<название элемента>"`, класс `ps-el`; id уникален внутри графика (`P018`, `stage-activation`, `cat-acquisition`, `kpi-north-star`…).
- Корневой `<svg>`: `data-ps-chart="<ключ>"`, `<title>`/`<desc>` (краткое описание для скринридеров).
- Подписи и легенда — тоже элементы (клик по легенде подсвечивает соответствующие элементы).

### 2.2 Метаданные пояснений (делает `charts.py`, пишет `charts/<ключ>.meta.json`)
```json
{"key": "funnel", "title": "…", "howto": "Как читать график: …", "legend": [{"label": "…", "text": "…"}],
 "elements": {"stage-activation": {
   "title": "Активация", "kind": "stage|point|bar|node|cell|event|link",
   "summary": "Что это (1–2 предложения)", "meaning": "Что значит значение именно здесь", 
   "actions": ["Что делать на этом этапе (1–4 пункта, из шагов предложений и глоссария)"],
   "metrics": [{"label": "Значение", "value": "40 %", "tag": "допущение"}],
   "links": [{"label": "Раздел 7. Конверсия и онбординг", "href": "#s7"}, {"label": "P032 — Quickstart", "href": "#p/P032"},
             {"label": "Показать в реестре", "href": "#registry?category=conversion"}]}}}
```
- Источники текста, по приоритету: (1) `data/chart-notes.json` — заметки авторов/оркестратора по `{ключ: {id: {…}}}` (опционально, перекрывают остальное); (2) данные прогона (предложение: название, `rationale`, `steps[]`, `effect_kpi`, оценки, зависимости, горизонт; модель: стадия воронки, допущения; Гант: задача, критерий готовности, зависимости; конкурент: вердикт, где лучше они/мы); (3) **глоссарий** `references/chart-glossary.ru.json` (статические определения: стадии AARRR, оси матрицы «усилия–эффект», что такое «торнадо», «критический путь», WSJF/RICE, классы доказательств и т. п.). Никакого выдумывания: нет данных — пометка «пояснение не задано» и предупреждение сборщику.
- Ссылки: `#s<N>` — раздел стратегии N; `#p/P018` — карточка предложения в реестре (раскрывает строку); `#registry?category=…&horizon=…&class=…` — реестр с фильтром; `#chart/<ключ>/<id>` — глубокая ссылка на элемент графика; `#flow/<ключ>`, `#mockup/<ключ>`, `#competitor/<slug>`, `#gantt/<G01>`, `#kanban/<P018>`. Все цели должны существовать (проверка сборщика).
- Покрытие: каждый `data-ps-el` имеет запись в `elements`, и наоборот; для каждого графика заполнены `howto` и `legend`.

### 2.3 Поведение на странице (делает `build_html.py`)
- Клик, `Enter`/`Space` по элементу открывает панель справа (на экранах < 700 px — нижний лист); в панели заголовок, «Что это», «Что значит», «Что делать», метрики с метками достоверности, ссылки; `Esc` закрывает; `←`/`→` — предыдущий/следующий элемент того же графика; фокус возвращается на элемент.
- Выбранный элемент подсвечивается в SVG (контур, не только цвет — контраст ≥ 3:1 в обеих темах); под графиком — кнопка «Как читать график» (раскрывает `howto` и легенду).
- Глубокие ссылки `#chart/<ключ>/<id>` открывают раздел, прокручивают к графику и выбирают элемент; ссылки в панели ведут к разделам/предложениям/фильтрам реестра на этой же странице.
- Подсказка при наведении (tooltip) — короткое `title` элемента; без JS график остаётся читаемым (SVG статичен, `<desc>` описывает).
- Печать: панель скрыта, графики статичны.
- Гант, Kanban, блок-схемы (`flows`), карточки референсов и матрица конкурентов уже интерактивны; привести их к одной панели и схеме ссылок, где это дёшево; карточки скриншотов конкурентов и макетов открываются в просмотрщике с подписью и ссылкой на предложения.

### 2.4 Проверки (smoke и тесты)
- Для демо-прогонов (обычного и режима идеи): во всех графиках клик по КАЖДОМУ `data-ps-el` открывает непустую панель; клавиатура; Esc; все `links[].href` разрешаются; ни одного графика без `howto`; внешних запросов 0; ошибок консоли 0.
- Движки: Chromium и WebKit обязательно (как в smoke), Firefox — если установлен; в `REPORT.md` перечислять проверенные движки.
- Страница `site` открывается по `file://` без ошибок и ведёт себя как `single`.
