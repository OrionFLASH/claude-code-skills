# Передача в разработку: файл задач для Claude Code (`handoff.py`)

Один Markdown-файл `<OUT>/deliverables/CLAUDE_CODE_TASKS.md`, который владелец отдаёт Claude Code в репозитории продукта. Claude Code по нему сам находит материалы стратегии, показывает план эпиков и задач, после подтверждения создаёт GitHub issues (эпики → задачи) и заполняет таблицу соответствия. Скрипт работает без сети и ничего в GitHub не создаёт.

## Запуск
```
python3 <SKILL_DIR>/scripts/handoff.py <OUT> [--scope ui,product|all] [--detail links|brief|full] [--horizon now|next|all]
                                             [--out FILE] [--repo-prefix PATH] [--force] [--dry-run]
python3 <SKILL_DIR>/scripts/handoff.py <OUT> --list-sections --json      # разделы для карточек выбора
```
Значения по умолчанию — из `build/run-config.json → handoff` (см. `data-contract.md`), флаги главнее; без блока — `scope: all`, `detail: brief`, `horizon: next`. Код выхода: 0 — готово, 2 — нет `data/proposals.json` или неверный раздел/значение.

## Разделы (эпики)
| id | Эпик | Разделы strategy.md | Что попадает |
|---|---|---|---|
| `ui` | Интерфейс и дизайн | 7, 10 | предложения с макетом (`mockup`/`mockups`/`mockups-index`), с тегами `ui`/`ux`/`design`, категории `conversion`/`product` со словами интерфейса (`UI_STEMS`/`UI_WORDS` в `handoff.py`: экран, интерфейс, onboarding, онбординг, README-витрина, страниц…, макет, UI, UX) в названии, описании или шагах; общие работы `U01` язык дизайна (`mockups/tokens.css`), `U02` карточки референсов (`design-refs/*.md`), `U03` блок-схемы (`data/flows.json`), `U04` макеты без привязки |
| `product` | Продукт и функции | 10 | категории `product`, `new_lines` |
| `platform` | Технологии, платформа, качество | 11 | `platform` |
| `acquisition` | Привлечение, контент, каталоги | 6, 4 | `acquisition`, `partnerships` |
| `conversion` | Конверсия и онбординг | 7 | `conversion` без признаков ui |
| `retention` | Удержание и поддержка | 9 | `retention` |
| `analytics` | Аналитика и измерения | 12 | `analytics` |
| `monetization` | Модель дохода и устойчивость | 8 | `monetization` |
| `localization` | Локализация и документация | 6, 11 | `localization` |
| `compliance` | Право, безопасность, риски | 13 | теги `legal`/`security`/`compliance` или `risks.legal`/`risks.privacy` ≥ 4 |
| `experiments` | Эксперименты и проверки гипотез | 12, 7 | `research/experiments/E*.md` (всегда горизонт now) и дешёвые проверки `CT-P…` — `cheap_test` предложений горизонта now без своего эксперимента |

Правила:
- Предложение попадает **ровно в один** раздел: `ui` → `compliance` → по категории (неизвестная категория → `product` с пометкой). `experiments` предложения не забирает: эксперимент и дешёвая проверка — отдельные задачи со ссылкой «проверяет: P…».
- Горизонт: `now` — только now; `next` — now и next; `all` — все (vision в лейблах → `horizon:later`).
- Предпосылки (`scores.json → blocked_by`, иначе `dependencies`) не дублируются: внутри набора — «после: P007 (эпик «…»)», вне набора — «(вне набора)» и строка в «Предпосылки вне выбранного».

## Структура файла
1. **Шапка** — продукт, дата стратегии (`run-config.created`), режим (по репозиторию / концепция по идее), разделы, горизонт, подробность, где лежит папка стратегии; итог (эпики, задачи, P0/P1, не вошли).
2. **Инструкция для Claude Code** — из `templates/handoff-tasks.md`: прочитать файл и стратегию → проверить репозиторий и дубли (`gh issue list --search`) → показать план и **дождаться подтверждения** → лейблы `epic`, `P0–P3`, `area:<id>`, `horizon:now|next|later` (только отсутствующие) → эпики, затем задачи в порядке зависимостей (sub-issues, если доступны) → тело: контекст, чек-лист, критерии приёмки, зависимости, материалы → по-русски, без секретов → ничего не менять в существующих issues → заполнить таблицу соответствия.
3. **Карта материалов** — «что — где — для чего», только существующие файлы; отсутствующие перечислены одной строкой.
4. **Эпики и задачи** — у эпика цель (по умолчанию для раздела + первый абзац раздела strategy.md, если он есть), номер раздела стратегии, KPI (частые KPI задач) и задачи-чекбоксы: `ID · название — P0…P3 · horizon · усилие · после: …`. Подробность:
   - `links` — строка задачи и материалы (спецификация, эксперимент, макет и PNG, карточка референса, блок-схема, разделы strategy.md с упоминанием P-id);
   - `brief` — + суть (description + rationale ≤ 400 знаков), шаги чек-листом, KPI;
   - `full` — + критерии приёмки (раздел «Критерии приёмки»/«Требования» спецификации, иначе KPI и `done_criteria` Ганта), риски ≥ 3, дешёвый тест, доказательства (класс и 1–2 источника), экран макета с зонами из `design-refs/*.json → hotspots`, срок из Ганта.
5. **Макеты и референсы** — ключ, название, P-id, `.html`, `.png`, карточка (макеты выбранных задач; при выбранном `ui` — все).
6. **Эксперименты** — ID, P-id, гипотеза и метрика (первая строка разделов «Гипотеза», «Метрики»), путь.
7. **Приложение** — таблица эпиков (Issue № эпика) и таблица `ID → раздел → эпик → Issue №` (номер подставляется из `data/issue-links.json`, если связь уже есть), предпосылки вне выбранного, не вошедшие предложения с причиной (раздел не выбран / горизонт), пропущенные материалы (нет спецификации, интерфейсная задача без макета, макет без файла или PNG, нет scores, нет разделов strategy.md, нет экспериментов/макетов).

Блоки без данных не ломают сборку: пишется пометка «… нет — блок пропущен».

## Пути
- `<OUT>` внутри git-репозитория → пути от корня репозитория (`strategy/<дата>/research/strategy.md`); иначе — относительно `<OUT>` и в шапке «Папка стратегии: `<имя>` (вне git-репозитория)». `--repo-prefix` задаёт префикс вручную (`.` — без префикса).
- Абсолютных путей нет: перед записью путь папки прогона, корень репозитория и домашняя папка вычищаются; похожие на токены строки заменяются на «[скрыто]»; угловые скобки в текстах заменяются (`‹ ›`), чтобы в файле не было HTML.
- В ссылки попадают только существующие файлы.

## Идемпотентность и ручные правки
Последняя строка файла — `generated-by: handoff.py · sha256:<16 знаков>` (сумма содержимого выше). Повторный запуск с теми же данными даёт тот же файл. Если сумма не сходится или строки нет (файл правили, например Claude Code вписал номера issues), файл не затирается: свежая версия — рядом в `CLAUDE_CODE_TASKS.generated.md`; `--force` перезаписывает.

## Выбор разделов (для оркестратора)
`--list-sections --json` печатает массив `{id, title, tasks, tasks_all_horizons, p0, p1, has_mockups, mockups, strategy_sections, approx_chars, approx_lines, about, summary}` — число задач для выбранного горизонта; `summary` годится в описание варианта AskUserQuestion (multiSelect, ≤ 4 варианта в вопросе — разделы нарезаются по нескольким вопросам; разделы с `tasks: 0` не предлагать). Выбор пишется в `run-config.json → handoff.scope`.
