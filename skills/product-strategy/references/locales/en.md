# Пакет локали `en`: англоязычная глобальная аудитория

Подключается, когда в `strategy.markets` есть `en` (и как общий подход для рынков без своего пакета). Отправной список для фазы 4 и авторов разделов 4, 6, 8, 13 — не готовые факты: правила площадок, условия сервисов и нормы проверяются по первоисточнику с датой. Здесь нет цифр, ссылок и пересказа правил конкретных площадок. Доступность сервисов зависит от страны владельца и покупателя — это проверяется для каждого прогона отдельно.

## 1. Каналы и площадки

| Площадка / тип | Для чего подходит | Что проверить до предложения |
|---|---|---|
| Hacker News (формат Show HN) | devtool, open source, необычная инженерия | правила Show HN: что считается подходящим проектом, нужен ли работающий продукт без регистрации |
| Reddit (тематические сабреддиты) | нишевые сообщества по интересам и технологиям | правила каждого сабреддита отдельно (самопродвижение, дни для проектов, требования к аккаунту) |
| Product Hunt | запуск потребительских и SaaS-продуктов, devtool | правила запуска и требования к странице продукта |
| Indie Hackers и подобные сообщества основателей | истории запуска, обратная связь | правила публикаций о своих продуктах |
| Блог-платформы для разработчиков (например, dev.to, Hashnode) | технические статьи «как сделано» | правила рекламного контента и раскрытия аффилированности |
| Lobsters и другие сообщества по приглашению | технические обсуждения | порядок получения доступа; правила о самопродвижении |
| Соцсети (X, Mastodon, Bluesky, LinkedIn) | анонсы, «строю в открытую», B2B (LinkedIn) | правила платформы; для Mastodon — правила конкретного инстанса |
| YouTube и короткие видео | демо, уроки | правила платформы, раскрытие спонсорства |
| Discord и Slack сообщества | поддержка пользователей, нишевые сообщества | правила сервера, каналы для самопродвижения |
| Stack Overflow и Q&A-площадки | ответы на вопросы в теме продукта | правила раскрытия аффилированности в ответах |
| Хостинги кода: темы репозитория, awesome-списки, каталоги пакетов | devtool и open source | правила списка или каталога; заявку подаёт владелец |
| Рассылки и подкасты ниши | упоминания в подборках | правила подачи, маркировка спонсорства |

## 2. Самопродвижение: общие правила
- Польза сообществу сначала; ссылка — только если правила это разрешают; раскрывать, что продукт свой.
- Правило не найдено — `ban_risk` не ниже 3, формат без ссылки.
- Без накруток голосов, фальшивых отзывов, сетей аккаунтов, массовых рассылок.
- Скилл и агенты ничего не публикуют — только план для владельца.

## 3. Поиск и спрос
- **Google Search Console**, **Bing Webmaster Tools** — реальные запросы сайта; только экспорт владельца.
- **Google Trends** — относительная динамика без входа (не объём).
- **Google Keyword Planner** и коммерческие SEO-инструменты — объёмы требуют аккаунта или подписки: без экспорта владельца `volume: null`, график `keywords-clusters`.
- GEO: видимость в ответах AI-ассистентов — только наблюдаемые факты.

## 4. Магазины и каталоги
- App Store, Google Play, Microsoft Store, Mac App Store — требования к публикации, комиссии и правила внутренних платежей — по актуальным правилам.
- Каталоги расширений браузеров — правила каждого каталога.
- Менеджеры пакетов: языковые реестры пакетов, Homebrew, winget, Scoop, Snap, Flathub — правила публикации.

## 5. Платёжные пути
| Путь | Когда | Что проверить |
|---|---|---|
| Платёжные процессоры (например, Stripe, PayPal) | прямые продажи и подписки | доступность для страны владельца, требования к юрлицу, налоги |
| Merchant of record (например, Paddle, Lemon Squeezy) | продажи цифровых продуктов по миру без собственной налоговой регистрации в каждой стране | доступность для страны владельца, комиссия — со страницы тарифов, условия выплат |
| Спонсорство open source (например, GitHub Sponsors, Open Collective) | поддержка открытых проектов | доступность для страны получателя, условия выплат |
| Платформы для авторов (например, Patreon, Ko-fi) | донаты и подписки | условия, комиссии, выплаты |
| Внутренние платежи магазинов | цифровые товары в приложениях | обязательность и комиссии по правилам магазина |

## 6. Право: чек-лист рисков (не юридическая консультация)
- **GDPR** (ЕС) и **UK GDPR**: правовое основание обработки, политика, права субъектов, договоры с обработчиками, передача данных за пределы ЕС/Великобритании.
- **ePrivacy / cookies**: согласие на необязательные cookies и трекинг для пользователей из ЕС.
- **CCPA/CPRA** (Калифорния) и законы других штатов США — проверить пороги применимости.
- **Налог на цифровые услуги** (НДС/VAT в ЕС и Великобритании, налоги с продаж в США) — merchant of record снимает часть нагрузки; проверить.
- **Раскрытие рекламы и отзывов** (например, правила FTC в США): спонсорство и аффилированность раскрываются.
- **CAN-SPAM** и аналоги: правила коммерческих рассылок.
- **Доступность**: требования к доступности цифровых продуктов на рынке ЕС — проверить применимость к продукту и дату вступления в силу.
- **Авторское право и DMCA**: скриншоты конкурентов — цитата-иллюстрация, не реклама; уведомления о нарушении на хостингах кода.
- **Лицензии open source**: совместимость лицензий зависимостей; список одобренных лицензий — у организации, которая их утверждает (проверить по первоисточнику).
- **Товарные знаки**: чужие названия — только номинативно.
- **Санкционные и экспортные ограничения**: могут влиять на доступность сервисов и платежей для владельца и аудитории — проверить для своей страны.

## 7. Особенности аудитории
- Высокая конкуренция за внимание в техсообществах: «покажи свой проект» работает, если есть демо без регистрации и ясная первая минута.
- Открытый код, приватность и локальная обработка — сильные аргументы для технической аудитории.
- Ожидается самообслуживание: документация, понятные цены, отмена подписки в один клик.

## 8. Профиль `zero-budget-solo` на рынке `en`
- Бесплатные каналы: Show HN и запуски, тематические сабреддиты по правилам, статьи на блог-платформах, awesome-списки, каталоги пакетов.
- Деньги: спонсорство open source; merchant of record — когда появятся продажи, если доступен для страны владельца.

## 9. Обязательные проверки
- [ ] Правила каждой площадки из `data/communities.json` — URL правил.
- [ ] Доступность платёжного пути для страны владельца.
- [ ] Применимость GDPR/CCPA к тому, что продукт делает с данными.
- [ ] Требования магазинов и каталогов, если продукт там публикуется.
