# Фаза C8.5 «Рабочий прототип» (режим идеи, с 1.5.0)

Статичные макеты C8 — гипотезы дизайна. Для продуктов с вычислительным ядром (калькуляторы, аналитика, ИИ-разбор, планировщики) владелец часто хочет **работающий** прототип: настоящие расчёты на демо-данных, переключение режимов интерфейса, тесты — чтобы проверить ага-момент и логику до разработки. Фаза C8.5 строит его из набора `templates/prototype-kit/` по четырём брифам. Прототип — концепт: бейдж «Концепт, не существующая функция», данные вымышлены и помечены.

## Когда запускать
- `idea.facets.prototype_needed` (опрос, блок «Прототип и передача в разработку») — да, или владелец попросил прототип в запросе;
- по умолчанию предложить владельцу, если в MVP есть расчёты, правила или ИИ-разбор (одна карточка «Нужен ли рабочий прототип?»: ядро расчётов / ядро + один экран / ядро + все режимы / не нужен);
- автопилот — «ядро + один экран»; `quick` — только ядро с тестами;
- не запускать: продукт без вычислений (каталог, контент), владелец ответил «не нужен».

Порядок: после C8 (выбрано направление дизайна, есть `mockups/tokens.css` и макеты ключевых экранов) и **после канона демо-данных** (`data/demo-canon.json` — шаг до макетов; нет — канон собирает агент ядра из чисел макетов). До C9: сборка страницы ссылается на прототип, файл задач для Claude Code — на его ядро и тесты.

## Брифы и порядок волн
| Волна | Бриф | Что делает | Пишет только в |
|---|---|---|---|
| 1 | `prototype-core.md` | копирует набор, пишет ядро расчётов (чистые функции) и тесты, воспроизводящие канон; демо-данные | `prototype/js/core*.js`, `prototype/js/data.js`, `prototype/fixtures/`, `prototype/tools/` |
| 2 | `prototype-shell.md` | оболочка: состояние, реестр режимов, тема, бейджи, токены режимов, ИИ-клиент на фикстурах, README с контрактом | общие файлы прототипа (список в README набора) |
| 3 (параллельно) | `prototype-mode.md` × N | один режим интерфейса на агента (`--set MODE_ID=<id>`) | `prototype/js/mode-<id>.js`, `prototype/css/mode-<id>.css`, `prototype/tests/smoke-<id>.mjs`, `prototype/shots/*-<id>-*.png` |
| 4 | `prototype-regression.md` | подключает режимы, прогоняет все тесты и смоук (Chromium + WebKit), сверку канона, пишет `HANDOFF.md` и `data/prototype.json` | общие файлы, `prototype/HANDOFF.md`, `prototype/shots/`, `data/prototype.json` |

Число агентов: `quick` — 1 (ядро), `standard` — 2–3 (ядро; оболочка + один режим; регрессия), `deep` — 2 + режимов + 1. Модель — opus для ядра и оболочки, sonnet для режимов по готовому контракту (по триажу, `references/orchestration.md`).

## Правила (проверяются тестами и регрессией)
1. **Числа макетов = числа ядра.** Один канон демо-данных (`data/demo-canon.json`, иначе `prototype/fixtures/canon.json`): ядро воспроизводит его в `node prototype/js/core.test.js <канон>`; значения на макетах помечены `data-canon="<кейс>.<поле>"`, повторяющиеся элементы графиков — `data-canon-item="<кейс>.<поле>"` (их число = значению канона: «4 значка — в подписи 4»); `python3 prototype/tools/check_canon.py prototype --core` сверяет всё сразу. Расхождение исправляется в макете или ядре, а не в каноне «под результат».
2. **Демо-данные помечены**: `demo: true` в записях, бейдж «демо-данные» на экране, детерминированный генератор (seed) — снимки и тесты стабильны.
3. **Контракт режимов**: `PK.registerMode({id, title, order, mount(root, ctx), unmount(root)})`, `ctx = {core, data, store, llm, demoLabel}`; общее состояние — только `ctx.store.get/set/subscribe`; токены режима — `css/tokens-<id>.css` с `:root[data-mode="<id>"]`. Режимы не правят общие файлы.
4. **Офлайн по `file://`**: обычные `<script src>`, без ES-модулей, сборки, npm, CDN и внешних шрифтов. Ограничения прототипа (например, локальная модель требует локального сервера) — в README прототипа.
5. **Без внешних запросов**: смоук блокирует и считает ошибкой любой запрос, кроме `file:`/`data:`/`blob:`/`about:`; единственное исключение — локальная модель ИИ (`127.0.0.1`/`localhost`) по действию пользователя.
6. **ИИ без зависимости от модели**: ответы для тестов и снимков — фикстуры (`fixtures/llm-replies.js`); модель чисел не считает — `core.verifyNumbers` сверяет числа ответа с фактами («N из N сверены»), `core.checkForbidden` ловит запретные формулировки; не прошёл — откат на шаблон с причиной. Тест с живой моделью — отдельный и необязательный.
7. **Доступность и взаимодействие**: цели нажатия ≥ 32 px (мышь) и ≥ 44 px (тач), видимый фокус, клавиатура, `prefers-reduced-motion`, обе темы; смоук проверяет размеры целей в обычном и тач-окне (390 × 844).
8. **Общие файлы — один владелец**: `index.html`, `js/app.js`, `js/state.js`, `js/modes.js`, `css/base.css`, `tests/smoke.mjs`, `README.md` правит агент оболочки (волна 2) или регрессии (волна 4); агенты режимов пишут только свои файлы и снимки со своим `<id>` в имени и не перезаписывают чужие снимки и ожидания.
9. Временные файлы агентов — только `build/tmp/<имя брифа>/`; git не запускать.

## Связка с передачей в разработку
`prototype/HANDOFF.md` (агент регрессии): задачи «перенести ядро в боевой стек» (функции ядра → модули продукта, тесты канона → тесты продукта), «перенести режимы» (по экрану), **список расхождений прототип ↔ боевая версия** (что упрощено: хранение, вход, данные, модель ИИ, офлайн), команды проверки. `data/prototype.json` — сводка для сборки и отчёта: `{"status": "ok|partial|failed", "path": "prototype/index.html", "modes": ["…"], "core_tests": {"passed": N, "failed": 0}, "kit_tests": {…}, "smoke": {"chromium": "ok", "webkit": "ok|skipped"}, "canon": {"cases": N, "checked": N, "errors": 0}, "handoff": "prototype/HANDOFF.md"}`. Файл задач для Claude Code (`handoff.py`) и раздел 14 концепции ссылаются на прототип, его тесты и `HANDOFF.md`; в разделе 11 — одна строка «рабочий прототип: что проверено ядром».

## Проверки фазы
```bash
node <OUT>/prototype/js/core.test.js <OUT>/data/demo-canon.json      # ядро = канон (или без аргумента — fixtures/canon.json)
node <OUT>/prototype/js/kit.test.js                                  # контракт оболочки
python3 <OUT>/prototype/tools/check_canon.py <OUT>/prototype --core  # макеты = канон = ядро
node <OUT>/prototype/tests/smoke.mjs --webkit                        # браузер: режимы, темы, цели, без внешних запросов
```
Непройденное — в `data/prototype.json` (`status: partial`) и в отчёт; прототип не публикуется и не выкладывается на хостинг без явного запроса владельца.
