# Что уходит в TypeSafe, размер и журнал

## Что отправляется

- С версии 2.0 триаж **универсальный**: в TypeSafe уходит **каждый запрос пользователя от 40 символов** любой тематики (код, письма, личные вопросы, документы), кроме пропускаемых локально: подтверждения и благодарности без поручения, команды `/…`, служебные сообщения среды. Раньше (1.x) тоже уходило всё от 40 символов, но заметка показывалась только для разработки.
- Отправляется только **дайджест текста запроса** — не файлы проекта, не данные, не история диалога. Строки, похожие на ключи, токены и пароли (`Bearer …`, `sk-…`, `ghp_…`, `password=…`, длинные hex/base64), заменяются на «[скрыто]» до отправки и до записи в журнал.
- Посмотреть, что уйдёт: `typesafe_triage.py --digest "текст"` (или текст через stdin).
- С 2.2 для **короткого продолжения** («продолжай тесты», «и ещё добавь…», "continue …", до 300 знаков) к дайджесту добавляется **одна строка «активная задача»**: первый открытый пункт `- [ ] …` из `TASKS.md` проекта (или первая строка раздела «Где остановился»), до 200 знаков, с той же маскировкой секретов; помечена как контекст, а не часть просьбы. Остальное содержимое `TASKS.md` не отправляется. Выключить — `TYPESAFE_TRIAGE_CONTEXT=off`; `--digest` в каталоге проекта показывает эту строку. Сообщения ассистента и история диалога по-прежнему не отправляются.
- С 2.1 в **том же** запросе уходят и вопросы второй оси (effort: план из зависимых шагов, цена поверхностного ответа, проверка результата, поиск неизвестного, ограничения, согласование частей). Текст — тот же дайджест, правило приватности не меняется; запросов не стало больше, входных токенов на запрос — примерно на 40 % больше: вопросы считаются во входе (проверено: короткий запрос 1867 → 2627 токенов).
- С 2.3 хук читает **стенограмму сессии** (`transcript_path` из ввода хука) — **только хвост файла (до 1 МБ) и только служебные поля**: модель последнего ответа основной сессии (`message.model`, ответы субагентов пропускаются), effort, версия Claude Code, имена инструментов, есть ли ключ `effort` во входе `Agent` и флаг ошибки его результата. Текст сообщений не читается, не сохраняется и не отправляется. Зачем: честно сравнить «нужный уровень» с реальной моделью сессии и знать, есть ли у `Agent` параметр `effort`. Не определять модель — `TYPESAFE_TRIAGE_SESSION_MODEL=unknown` (или задать её самому: `=sonnet`).
- **Не уходят никуда** (считаются локально): окружение проекта (есть ли git, тесты, CI, lock-файлы, порядок числа файлов — без чтения содержимого файлов, кроме первого слова маркера `.typesafe-triage-effort`), признаки общего интерактивного состояния (каталог `.profile/` и файл `DevToolsActivePort` в нём, открытые пункты `TASKS.md` про прогон/браузер/вход), история сессии из журнала (и наследование оценки для продолжений), текущий effort сессии из `settings.json` (только чтение). `--where` читает в `settings.json` только блоки `hooks` и `enabledPlugins` и выводит лишь команды хуков.

## Выключатели

| Что | Эффект |
|-----|--------|
| пустой файл `.typesafe-triage-off` в каталоге проекта или выше | хук в этом проекте полностью молчит, ничего не отправляет и не пишет |
| `TYPESAFE_TRIAGE_CONTEXT=off` | без строки «активная задача» из `TASKS.md` в дайджесте |
| `TYPESAFE_TRIAGE_SESSION_MODEL=unknown` | модель сессии не определяется (заметка так и скажет); effort сессии и параметр `effort` у Agent по-прежнему берутся из стенограммы |
| `TYPESAFE_TRIAGE_PROJECT_LOG` не задана | журнал проекта не ведётся (по умолчанию) |
| `TYPESAFE_TRIAGE=off` (также `0`, `false`, `no`) | то же глобально / для сессии |
| `--pause "причина"` | TypeSafe не используется до `--resume`; уровень — только локальная эвристика (в сеть ничего не уходит) |
| нет `TYPESAFE_API_KEY` | в сеть ничего не уходит; уровень по эвристике |

## Размер

Предел API — 64k токенов на запрос (иначе HTTP 400 `max_tokens_exceeded`; ~20 тыс. знаков лога ≈ 14 тыс. токенов), а точность падает раньше от лишнего шума. Поэтому уходит **дайджест до 4500 знаков**: короче 3000 — как есть; иначе большие вставки сжимаются (код в ```` ``` ````, серии из 20+ строк подряд, сплошные длинные строки без пробелов → начало и конец + пометка «пропущено N строк»), а сама просьба остаётся целиком; если всё ещё длинно — начало (55 %) и конец (45 %), середина заменяется пометкой. Сверхдлинный ввод (> 100 тыс. знаков) сначала режется. Если сервис всё же ответил `max_tokens_exceeded` — один повтор с дайджестом до 1500 знаков; отказ по размеру не авария (паузы нет, уровень по эвристике). Локальная эвристика работает с полным текстом на машине. Агенту при `--run` задача передаётся целиком (потолок 400 тыс. знаков).

## Журнал

`~/.claude/typesafe-triage/log.jsonl`, права 0600, только локально: время, короткий хэш, первые 200 символов запроса (секреты замаскированы), уровень, источник (`typesafe`/`heuristic`), причины, метрики, сигналы, тип задачи, размер, токены; с 2.1 — effort, его источник и глубина, источник модели, **хеш** `session_id` (не сам идентификатор) и признак повтора — по ним хук поднимает effort при «опять не работает» в той же сессии.

С 2.2 — ещё `inherited` (унаследованные модель и effort), `shared_state` (найденные признаки общего состояния), `active_task: true` (сама строка не пишется), `takeover`/`late` (заметку дал второй вызов хука / TypeSafe не уложился в бюджет). **Пропуски и отказы** хука тоже пишутся, но без текста запроса: время, хеш, длина, хеш сессии и поле `skipped` с причиной («короткая реплика», «команда /…», «дубль: заметку дал другой вызов хука», «ошибка RuntimeError»…); в историю сессии и сводку моделей они не входят.

С 2.3 — `action` (сам / agent / ask), `action_why`, `action_hints`, `session_tier` (уровень модели сессии). **Молчание «реже»** (короткое продолжение с прежним решением) пишется без текста запроса: время, хеш, длина, хеш сессии, поле `quiet`, модель, effort, действие.

**Журнал проекта** `triage-log.jsonl` (2.3, опция, по умолчанию выключен: `TYPESAFE_TRIAGE_PROJECT_LOG=on|путь` или `--project-log`) лежит в корне проекта и **не содержит текста запроса**: время, id решения (хеш запроса или id задачи `--batch`), хеш сессии, тип задачи, модель, effort, уверенность, действие, источник оценки, ожидаемый расход; в фактах (`--fact`) — модель, effort, токены, минуты, исход, число замечаний. Файл в репозитории — решите, коммитить ли его (обычно — в `.gitignore`).

Идемпотентность хука: `~/.claude/typesafe-triage/dedup/` (каталог 0700) — файлы 0600, имя = sha256(session_id + промпт), внутри только `{"state": "pending"|"done", "pid", "ts"}` (без текста); старше 8 минут удаляются при следующем запросе. Журнал нужен для подстройки порогов и разбора «почему не было заметки»; удалить можно в любой момент.
