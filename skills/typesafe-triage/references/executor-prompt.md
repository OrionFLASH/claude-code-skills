# Шаблон самодостаточного промпта исполнителя

Исполнитель (`Agent` или `--run`) не видит истории диалога: всё, что ему нужно, должно быть в промпте. Этот шаблон повторялся в каждом брифе (в отзыве — 7 раз), поэтому он вынесен сюда. `--batch` подставляет в него поля задачи (`id`, `goal`, `task`, `context`, `paths`, `constraints`, `criteria`, `report`) и модель/effort из триажа; пустые поля получают значения по умолчанию. Вручную — скопируйте блок ниже и заполните.

Правила:

- **Цель и критерии готовности** — проверяемые: «тесты зелёные», «команда X выводит Y», а не «сделай хорошо».
- **Файлы** — только те, что задача меняет. Пересекающиеся пути у двух исполнителей — запускать по очереди (`--batch` с `paths` скажет, какие).
- **Запреты** — ветка, без merge и push, без глобальных установок, секреты не печатать, скилл typesafe-triage не применять.
- **Атрибуция.** Строку `Co-Authored-By` исполнитель ставит **из своей системной инструкции атрибуции** — это его фактическая модель (исполнитель на opus пишет opus, на sonnet — sonnet). Модель оркестратора в бриф не вписывать. Если пользователь в `CLAUDE.md` задал свою строку — главнее она. Так история коммитов честная и единообразная: по строке видно, кто писал код.
- **Отчёт** — короткий и одинаковый у всех исполнителей: оркестратору его сводить.

## Поля задачи для `--batch`

| Поле | Обязательно | По умолчанию |
|---|---|---|
| `id` | нет | `T1`, `T2`, … |
| `task` | да | — |
| `goal` | нет | первая строка `task` |
| `paths` | нет (без него параллельность не проверяется) | «пути не заданы: сначала найди нужные файлы, правь минимально необходимое» |
| `context` | нет | «—» |
| `constraints` | нет (строка или список) | «—» |
| `criteria` | нет (строка или список) | «тесты зелёные (новые — на каждый пункт), поведение вне задачи не изменилось» |
| `report` | нет | «ветка и список коммитов; что сделано; чем проверено (команды и итог); что не сделано и почему; найденное по дороге» |

Пример файла:

```json
{"tasks": [
  {"id": "P1", "task": "Выгрузка CSV теряет строки с BOM: найди причину, исправь, добавь тест", "paths": ["src/export/", "tests/test_export.py"],
   "criteria": ["тест на BOM падает до правки и проходит после", "все тесты зелёные"]},
  {"id": "P2", "task": "Поправь опечатки в REPORT.md", "paths": ["docs/REPORT.md"]},
  {"id": "P3", "task": "Добавь в REPORT.md раздел «Не проверено»", "paths": ["docs/REPORT.md"]}
]}
```

P2 и P3 трогают один файл — `--batch` выстроит их в очередь «P2 → P3», P1 пойдёт параллельно.
