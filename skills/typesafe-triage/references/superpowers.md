# Совместная работа с SuperPowers и субагентами (проверено опытом)

| Что | Факт |
|---|---|
| Хуки SuperPowers | только `SessionStart` (подставляет вводный скилл `using-superpowers`). Хука на запросы пользователя у него нет, общего состояния с нашим тоже: оба хука независимо добавляют контекст, прямого конфликта нет. |
| Хук триажа в субагентах (`Agent`, в т. ч. из SuperPowers) | **не срабатывает**: промпт субагента — не запрос пользователя (в журнале нет ни одного промпта субагентов; субагент заметки не видит). Второго обращения в TypeSafe там нет. |
| Хук в дочернем `claude -p` (`--run`) | срабатывал бы (проверено), поэтому `--run` ставит в окружение агента `TYPESAFE_TRIAGE_CHILD=1`: хук там молчит, вложенный `--run` запрещён. Рекурсии и двойной оценки нет. |
| Скиллы в списке субагента | `typesafe-triage` и SuperPowers видны и субагентам — поэтому правило «субагентам скилл не применять». |

**Чья модель главнее, когда работа идёт по SuperPowers.** У SuperPowers свой выбор модели по ролям (`subagent-driven-development` → *Model Selection*, `executing-plans`): «наименее мощная модель, которая справляется»; механические задачи — дешёвая, интеграция — стандартная, архитектура и итоговое ревью — самая сильная; **model указывать всегда явно** (пустое значение наследует модель сессии); ревьюерам и исполнителям по прозе — не ниже средней; в раундах исправлений 4–5 — на ступень выше застрявшего. Порядок приоритета:

1. Нельзя никогда: запускать **haiku** или **fable** без подтверждения пользователя. «Самая сильная доступная модель» у SuperPowers = **opus**; «дешёвая модель» для механических ролей = **sonnet**, пока пользователь явно не согласился на haiku.
2. Есть план SuperPowers → модели ролей берутся из его раздела Model Selection (он точнее: решает по каждой задаче). Совет триажа тут — вход для решения «делегировать ли всё» и страховка: если весь запрос тяжёлый (opus/fable), роли «архитектура/итоговое ревью» не снижать.
3. Плана нет → правила триажа: уровень не ниже рекомендованного, для содержательных подзадач — не ниже текущей модели.
4. Общий набор защит качества: тесты, чтение результата субагента, проверка на данных; при сомнении — ступень выше.

**Effort (с 2.1).** SuperPowers effort не выбирает — его даёт заметка триажа. При делегировании по плану SuperPowers ставь `Agent(model=<из Model Selection>, effort=<из заметки>)`; для ролей «архитектура/итоговое ревью» — не ниже рекомендованного effort, для механических ролей — `medium` (механика не требует глубины даже на opus), `low`/`max` — только с согласия пользователя. В раундах исправлений, где SuperPowers поднимает модель «на ступень выше застрявшего», effort поднимает и сам триаж — по истории сессии («опять не работает»).
