# Как определяется effort (глубина размышления)

Источник правды — константы вверху `scripts/triage_effort.py` (политика), `scripts/triage_heuristics.py` (сигналы текста и явные указания) и `scripts/typesafe_triage.py` (вопросы `EFFORT_SCORES`, `EFFORT_FLAGS`). Здесь — смысл, порядок и таблицы.

## Шкала и полоса без вопросов

С 2.7 подтверждений нет: **low** и **max** ставятся без вопроса, но по строгим условиям (low — глубина TypeSafe ≤ 0,15, уверенность ≥ 0,7, нет диагностики/слов риска; на haiku — только чистое чтение, иначе medium; max — только opus/fable, глубина ≥ 0,85, критичность, уверенность ≥ 0,8, согласие текста). Колонка «Без подтверждения» ниже описывает режим `TYPESAFE_TRIAGE_CONFIRM=on`. Базовые уровни по моделям и роли уровней — `sources.md` (R5–R8).

| Effort | Когда | Без подтверждения |
|---|---|---|
| `low` | уверенно лёгкое: факт, определение, сортировка, перечень, механика без решений | **нет** → `medium` |
| `medium` | рутина по образцу: письмо, правка «как у соседнего поля», резюме, формула | да |
| `high` | диагностика, неясность, сравнение, юридическое/финансовое объяснение; **по умолчанию при сомнении** | да |
| `xhigh` | многошаговая работа с высокой ценой ошибки: миграции, безопасность, финмодели для решений, доказательства | да (в заметке — предупреждение о расходе) |
| `max` | критичное и необратимое: боевые деньги/данные без отката, предельная сложность | **нет** → `xhigh` |

Константы: `EFFORTS`, `CONFIRM_EFFORTS = {"low": "medium", "max": "xhigh"}`, `OPTIONAL_CONFIRM_EFFORTS = {"xhigh": "high"}` (добавьте в `CONFIRM_EFFORTS`, чтобы спрашивать и про xhigh — `safe_effort` пройдёт цепочку max → xhigh → high), `COSTLY_EFFORTS = (xhigh, max)`, `DEFAULT_EFFORT = high`.

Модель и effort — **независимые** оси: модель = способность исполнителя, effort = сколько ему думать. Effort не выводится из модели и наоборот; связь — только правила согласованности (слой e).

## Слои оценки

Каждый слой пишет свой вклад в `effort_reasons` с буквой слоя — по ним видно, почему выбран уровень.

### a) TypeSafe (тот же единственный запрос)

К вопросам модели (шкалы `complexity`, `reasoning`, `ambiguity`, `risk`, флаги `needs_investigation`, `novel_design` — см. [levels.md](levels.md)) добавлены узкие вопросы effort. Формулировки доменно-нейтральные, уровни шкал — конкретные ситуации с примерами из разных областей (по документации TypeSafe: одна мысль на вопрос, ситуации, а не степени).

| Id | Тип | Вопрос | Вес |
|---|---|---|---|
| `reasoning` | Score 4 | сколько аккуратного мышления нужно (механика → рутина → аккуратно → глубоко) | 0.26 |
| `shallow_cost` | Score 4 | что будет при быстром ответе «с первого взгляда» (то, что нужно → нормально с обычной аккуратностью → упустит важное → правдоподобно неверно и вредно) | 0.16 |
| `planning` | Score 4 | сколько зависимых шагов (один → несколько очевидных → много, зависят от находок → длинная цепочка с контрольными точками/откатом) | 0.10 |
| `ambiguity` | Score 3 | насколько неясно, что сделать | 0.08 |
| `risk` | Score 4 | цена незаметной ошибки | 0.08 |
| `complexity` | Score 4 | объём работы | 0.04 |
| `verification` | Noul | нужно ли проверять результат (тесты, пересчёт, сверка с источниками, крайние случаи) | 0.08 |
| `exploration` | Noul | нужен ли поиск неизвестного (где, почему, какие варианты) | 0.05 |
| `constraints` | Noul | есть ли жёсткие ограничения/критерии приёмки, которые надо удержать разом | 0.04 |
| `coordination` | Noul | нужно ли согласовать несколько частей (файлы, документы, источники, системы, люди) | 0.04 |
| `needs_investigation` | Noul | причина проблемы неизвестна | 0.03 |
| `novel_design` | Noul | нужно придумать новое (творчество/новизна) | 0.04 |

Глубина TypeSafe = Σ вес × значение (шкалы нормированы на верхний уровень, у Noul — вероятность «да»). Нет ответа на часть вопросов (старый сервер) — веса оставшихся перенормируются. Уверенность оси — минимум `confidence` у `reasoning`, `shallow_cost`, `planning`.

### b) Текст (`triage_heuristics.py`, без сети)

| Сигнал | Примеры слов/признаков | Вес в глубине текста |
|---|---|---|
| намерение (максимум найденных) | найти/показать 0.10, переименовать/отсортировать 0.15, объяснить 0.30, написать 0.35, исправить/рассчитать 0.50, проверить/сравнить/исследовать 0.60, оптимизировать/мигрировать 0.65, разобраться/почему 0.70, спроектировать 0.75, доказать 0.85; не распознано 0.35 | 0.34 |
| диагностика | ошибка, лог, трассировка, «иногда», «периодически», «плавающий», «не воспроизводится», timeout, 5xx, «не сходится» | 0.12 |
| критичность | прод, необратимость, безопасность, деньги, право/медицина, потеря данных (группы) | 0.12 |
| структура | пункты списка, шаги («затем», «после этого»), перечисления | 0.08 |
| ограничения | «нельзя», «обязательно», «строго», «без простоя», must not, exactly, обратная совместимость | 0.06 |
| математика | доказательство, формула, вероятность, ∑ ∫ ≤ | 0.06 |
| требования / критерии приёмки | «должен», must; «критерии приёмки», «все тесты должны проходить» | 0.05 / 0.05 |
| неопределённость | «не знаю», «непонятно», «может быть», «или», not sure | 0.05 |
| объём | «все файлы», «весь проект», «50 страниц» | 0.05 |
| код/логи, длина | вставки, длина прозы | 0.04 / 0.04 |
| «лёгкие» слова без «глубоких» | − 0.12; короткий вопрос без диагностики − 0.06 | |

Текст **только поднимает** оценку TypeSafe: прибавляется `EFF_HEUR_RAISE = 0.5` превышения. Также считаются язык (ru/en/mixed), вопрос или поручение, повтор после неудачи. Посмотреть: `--signals "текст"`.

### c) Окружение (локально, без чтения содержимого файлов, в TypeSafe не уходит)

`env_context(cwd)`: git-репозиторий (ищется вверх, домашний каталог не сканируется), тесты (`tests/`, `pytest.ini`, `conftest.py` …), CI (`.github/workflows`, `.gitlab-ci.yml` …), lock-файлы, порядок числа файлов (не больше 3000 и 0.15 с), маркер `.typesafe-triage-effort`. Влияет **только на работу над проектом** (намерения исправить/спроектировать/мигрировать…, пути, код) и не больше `ENV_MAX_BUMP = 0.06`: большой проект (≥ 1000 файлов) +0.04, нет тестов и CI +0.03 (проверить нечем). Есть тесты — в причинах «проверь ими».

Маркер `.typesafe-triage-effort` в каталоге проекта (или выше) — первое слово `low|medium|high|xhigh|max` — **пол effort** для проекта; это настройка пользователя, поэтому повторного вопроса нет.

### d) История сессии (журнал, только эскалация)

Журнал `log.jsonl` хранит хеш `session_id`, хеш запроса и признак `retry`. Повтор = признаки неудачи в тексте («опять не работает», «всё ещё не», «не помогло», «та же ошибка», "still broken", "didn't help") **или** тот же запрос (тот же хеш) в этой сессии за 2 часа. Подряд идущие повторы, заканчивающиеся текущим запросом:

| Повтор подряд | effort | модель |
|---|---|---|
| 1 | +1 ступень | — |
| 2 | +2 ступени | +1 (haiku → sonnet, sonnet → opus; не выше opus) |
| 3 и больше | +2 (потолок `HISTORY_MAX_STEPS`) | +1 |

История сама не поднимает до `max` (`HISTORY_AUTO_CEIL = xhigh`). Простое «снова»/«ещё раз» без признака неудачи повтором не считается («чтобы файл снова читался»).

### e) Согласованность модель × effort

| Правило | Константа |
|---|---|
| haiku — не выше `high` | `HAIKU_EFFORT_MAX` |
| fable — не ниже `high` | `FABLE_EFFORT_MIN` |
| риск ≥ 0.67 или необратимость ≥ 0.6 (без TypeSafe — ≥ 2 групп слов риска) → не ниже `high` при любой модели | `RISK_EFFORT_MIN`, `RISK_EFFORT_AT` |
| чисто механическая работа (`mechanical` ≥ 0.8, без диагностики) и невысокий риск → не выше `medium` даже на opus | `MECHANICAL_EFFORT_MAX` |
| opus/fable + `low` — только для объёмной механики (`breadth` ≥ 0.67), иначе `medium` | `HEAVY_LOW_BREADTH` |
| `low` — только если глубина TypeSafe ≤ 0.18, текста ≤ 0.30, уверенность ≥ 0.6, нет диагностики/риска/«глубоких» слов | `LOW_TS_MAX`, `LOW_TEXT_MAX`, `CONF_LOW` |
| `max` — глубина ≥ 0.84, критичность (риск ≥ 0.9 или необратимость ≥ 0.8), уверенность ≥ 0.7, текст согласен | `MAX_CONF`, `MAX_TEXT_MIN` |
| низкая уверенность (< 0.5) у границы (≤ 0.06) → +1 ступень, но не в `max` | `EFF_CONF_ESCALATE`, `EFF_ESC_MARGIN` |

**Допустимые сочетания (проверено живьём, claude 2.1.292).** `claude -p --model <m> --effort <e>` с промптом «ответь ok» принят для всех 15 сочетаний haiku/sonnet/opus × low/medium/high/xhigh/max (ни одного отказа). На sonnet и opus число thinking-токенов заметно растёт на xhigh/max; на haiku различия не выражены — возможно, effort на haiku действует слабо (поэтому haiku ≤ high). fable живьём не проверялся. Неизвестное значение (`--effort bogus`) CLI **не отклоняет**, а печатает предупреждение и берёт effort по умолчанию — поэтому `build_agent_cmd` проверяет значение сам. Матрица — `MODEL_EFFORTS`.

### f) Без TypeSafe

Нет ключа, сеть, пауза защиты, слишком большой вход → только слои b → c → d, `effort_source = heuristic`, уверенность «низкая», полоса `medium..xhigh` (ни `low`, ни `max`, кроме явного указания пользователя):

1. рутина (намерения только найти/преобразовать/объяснить/написать, без диагностики, слов риска и открытой неопределённости) и глубина текста < 0.35 → `medium`;
2. глубина ≥ 0.45 и (≥ 2 групп риска или риск + тяжёлое намерение ≥ 0.65) → `xhigh`;
3. иначе → `high` (при сомнении).

### g) Калибровка

`--calibrate` гоняет `triage_cases.json` (80+ кейсов, 15 областей, ru/en): для каждого — модель и effort против ожидаемого диапазона (`tier_ok`, `effort_ok`), глубина и причины, затем распределение effort, матрица «ожидаемый → выданный» и сводка журнала. Отложенная часть (~20 %, `sha1(task) % 5 == 0`) показывается отдельно: подстраивать пороги — только по `--split train`, затем проверить `--split holdout`. `--cache файл` сохраняет ответы TypeSafe (ключ — набор вопросов + дайджест), чтобы повторные прогоны не тратили запросы. `--selftest` — то же без матрицы; код возврата 1, если есть «ниже ожидаемого».

## Явные указания пользователя (согласие, приоритет над автооценкой)

| В тексте | Эффект |
|---|---|
| «на opus», «модель haiku», "use fable", "run on sonnet" | модель задана, подтверждение не нужно (`model_source = user`) |
| «не на opus», "don't use opus" | уровень исключён → ближайший ниже (затем выше) |
| «effort max», «max effort», «усилия: высокие», «уровень усилий низкий» | effort задан точно (`effort_source = user`) |
| «ultrathink» | `max` |
| «без размышлений», «минимум усилий», "no thinking", "minimal effort" | `low` |
| «очень тщательно», «максимально глубоко», "think really hard", "think harder" | не ниже `xhigh` |
| «подумай как следует», «тщательно», «глубоко», «не торопись», "think hard", "thoroughly" | не ниже `high` |
| «кратко», «навскидку», «одной фразой», "quick answer", "briefly" | `low` (но при высокой цене ошибки — не ниже `high`) |
| «не нужно глубоко» / «не надо кратко» / «не нужен effort max» | потолок `medium` / пол `high` / потолок `xhigh` |
| «быстро, но очень тщательно» | противоречие — мягкие указания не применяются |

Слово уровня без маркера («opus magnum», «сервис быстро падает») указанием не считается. Каждая найденная фраза попадает в причины один раз.

### Упоминание (mention) и использование (use)

Указание — это когда пользователь **просит**, а не когда **рассказывает** о словах. Функция `mentions()` в `triage_heuristics.py` маскирует упоминания до поиска указаний:

| Где маркер | Считается | Пример |
|---|---|---|
| в обратных кавычках или блоке кода | упоминание | `` `effort max` `` |
| в пересказе — от слова-сигнала до конца предложения: «ассистент/Claude/модель/он/пользователь/заметка/отчёт + ответил/сказал/написал/пишет/советует/предлагает…», «ответ ассистента», «в отчёте», «в цитате», «написано:», «цитирую», "the note says", "he said", "in the report" | упоминание | «Ассистент ответил: effort max передать не могу» |
| сразу после подписи «слово / фраза / выражение» | упоминание (только эта кавычка или маркер) | «Слово «ultrathink» ставит максимум» |
| в кавычках «…», "…", “…”, „…“, '…', и в предложении **несколько** маркеров в кавычках (перечень примеров) | упоминание | «тщательно» поднимает, «кратко» снижает |
| в кавычках, одиночный, но в предложении **нет** повелительного глагола (часто после двоеточия-пояснения) | упоминание | «Модель можно назвать прямо: «на opus»» |
| в кавычках, одиночный, вне кавычек есть повелительный глагол («сделай», «запусти», «разбери», «пожалуйста», "please", "run"…) | **указание** | «Сделай это «на opus»» |
| без кавычек и пересказа | **указание** (как раньше) | «ultrathink: разбери…», «на opus сделай…», «effort max, пожалуйста» |

**Вставленный отчёт/цитата** (`report` в `--signals`): текст от 200 знаков, где повторяется предложение от 40 знаков с маркером (абзац вставили дважды) или есть ≥ 3 маркеров в кавычках. Тогда повторяющиеся предложения маскируются целиком, все кавычки — упоминания, а мягкие слова («тщательно», «кратко», «глубоко») не учитываются вовсе: в отчёте это описание, а не просьба. Явные маркеры вне кавычек и пересказа («сделай на opus») работают и в отчёте. Повтор строк лога без маркеров отчётом не считается. Отрицания работают как раньше; сколько маркеров скрыто — поле `mentions`.

## Уточняющий вопрос

`clarify = true`, если одновременно: высокая ставка (риск ≥ 0.67, необратимость или слова критичности), неуверенная оценка (уверенность < 0.5 или нет TypeSafe) и открытая задача (неясность ≥ 0.6 или слова неопределённости), и пользователь сам ничего не задал. Заметка просит **один** короткий вопрос, а не угадывать.

## Строка «/effort» для основной сессии

Хук читает (только чтение) текущий effort сессии: с 2.3 — из стенограммы (effort последнего ответа) или `CLAUDE_EFFORT`, иначе `CLAUDE_CODE_EFFORT_LEVEL`, `effortLevel` в `.claude/settings.local.json`, `.claude/settings.json` проекта и `~/.claude/settings.json`. Если он известен и отличается от рекомендуемого на ≥ 2 ступени, а действие — «сам», в заметке строка «Делаешь сам (effort сессии …): предложи «/effort X»». `effortLevel` автоматически не меняется.

## Когда у Agent нет параметра effort

Параметр `effort` у инструмента `Agent` есть не во всех версиях и окружениях Claude Code, а хук схему инструментов не видит. С 2.3 пункт про effort появляется **только когда заметка велит делегировать** (`Agent` или «спросить» перед агентом) и зависит от того, известно ли про параметр (`TYPESAFE_TRIAGE_AGENT_EFFORT`, `--set-agent-effort yes|no`, успешный вызов `Agent` с `effort` в стенограмме):

| Параметр | Пункт заметки |
|---|---|
| есть | «effort=X — параметром Agent: он есть, а правило CLAUDE.md/скилла — явное требование его передать» (без `--run`) |
| нет | «У Agent нет параметра effort (не ошибка): в промпт агента «…»» (+ `--run` для критичного) |
| неизвестно | «effort — параметром Agent, если он есть в схеме (…явное требование); нет — не ссылайся на него (не ошибка), в промпт агента «…». Есть ли параметр — запиши один раз: --set-agent-effort yes|no» |

Чем заменить параметр, зависит от `effort_delivery`:

| `effort_delivery` | Когда | Что в заметке сверх `Agent(model=…, effort=…)` |
|---|---|---|
| `agent_param` | `medium`/`high` без высокой цены ошибки | фраза глубины уровня (короткая) |
| `prompt` | `low`, `xhigh`, `max` или effort задан пользователем/маркером проекта | готовая фраза глубины для промпта агента |
| `run` | `high` и выше при высокой цене ошибки (риск ≥ 0.67, необратимость, без TypeSafe — ≥ 2 групп слов риска), `max` или effort задан явно | фраза + команда `--run` (отдельный процесс `claude -p --model … --effort …`) для изолируемой работы; не показывается, если параметр у `Agent` точно есть |

Все запасные способы — **один** пункт заметки. Заметка 2.3 не длиннее заметки 2.1.1 на тех же входах больше чем на ~25 % (проверяется тестом), а для действия «сам» — обычно одна строка.

Фразы глубины (`EFFORT_PROMPT` в `typesafe_triage.py`; английская — если запрос на английском):

| Effort | Русский | English |
|---|---|---|
| `low` | Ответь кратко, без лишних шагов и рассуждений. | Answer briefly, without extra steps or deliberation. |
| `medium` | Обычная аккуратность, без лишней глубины. | Ordinary care, no extra depth. |
| `high` | Думай тщательно: проверь крайние случаи и результат. | Think carefully: check edge cases and the result. |
| `xhigh` | Думай очень тщательно: сравни альтернативы, проверь крайние случаи, перепроверь результат. | Think very carefully: compare alternatives, check edge cases, re-verify the result. |
| `max` | Думай максимально глубоко: разбери альтернативы и риски, проверь каждый шаг, в конце — самопроверка. | Think as deeply as possible: weigh alternatives and risks, verify every step, self-check before answering. |

Команда `--run` в заметке: `python3 <полный путь к typesafe_triage.py> --run --tier <модель> --effort <effort> [--edit|--readonly] "<задача>"` (Windows — `python`; домашний каталог записан как `$HOME` — так работает и в bash, и в PowerShell). Для haiku/fable добавлен `--confirmed`, для low/max — `--confirmed-effort`; если подтверждение ещё нужно, в заметке приписка «(--confirmed* — после «да»)». Явное указание пользователя в запросе — уже согласие. Агент `--run` не видит истории диалога: задача должна быть самодостаточной.

Это не замена параметра в обычной работе: фраза в промпте — мягкое требование (модель агента может думать меньше), `--run` — точный effort, но без контекста сессии и с правами `--edit`/`--readonly`.

## Поля результата (добавлены к формату 2.0, старые сохранены)

| Поле | Смысл |
|---|---|
| `effort` | рекомендуемый уровень |
| `effort_confidence` | высокая / средняя / низкая / задано |
| `effort_confirm` | нужен ли вопрос пользователю (low/max не от пользователя) |
| `effort_fallback` | безопасная замена без подтверждения |
| `effort_source` | `typesafe` / `heuristic` / `user` / `project` |
| `effort_reasons` | вклад слоёв a–e, история, явные указания |
| `effort_depth`, `effort_layers` | итоговая глубина и численный вклад слоёв |
| `model_source` | `auto` / `user` |
| `explicit` | найденные явные указания (каждое один раз, не больше 4) |
| `mentions` | сколько маркеров-упоминаний скрыто (кавычки, код, пересказ, отчёт); поле есть, только если > 0 |
| `effort_delivery` | `agent_param` / `prompt` / `run` — чем заменить параметр effort, если его нет у Agent (2.1.2) |
| `clarify` | предложить уточняющий вопрос |
| `retry`, `session`, `env` | повтор, хеш сессии, сводка окружения |
| `action` | 2.3: действие `{kind: self/agent/ask, why, reason, agent, fallback, hints, session_tier, …}` — [action.md](action.md) |
| `session_model`, `session_effort`, `agent_effort` | 2.3: модель и effort основной сессии и есть ли у Agent параметр effort (что удалось узнать локально) |
| `continuation`, `prev`, `history_n` | 2.3: короткое продолжение?, прошлое решение сессии, сколько оценённых запросов в сессии |
| `decision_id`, `expected` | 2.3: id решения и ожидаемый расход (только при включённом журнале проекта) |

Коды `--run`: 0 — успех / dry-run; 2 — нет задачи, haiku/fable без `--confirmed`, low/max без `--confirmed-effort`, неизвестный effort, `--readonly` вместе с `--edit`, вложенный запуск; 124 — тайм-аут агента; 127 — нет `claude`.
