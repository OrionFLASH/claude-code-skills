## 1. Две ручки: модель и effort

| № | Правило | Источник |
|---|---|---|
| R1 | Модель — набор фиксированных весов («насколько способен»), effort — сколько работы Claude выполняет: сколько файлов читает, как много проверяет, как далеко идёт по шагам до отчёта. Не «время мышления» | S1, S2, S12 |
| R2 | Эффорт влияет на все токены ответа: текст, вызовы инструментов, мышление. На низком — меньше и короче вызовов инструментов, без вступлений; на высоком — больше вызовов, объяснение плана, подробные итоги | S2 |
| R3 | Effort — поведенческий сигнал, а не жёсткий бюджет; единственный жёсткий потолок — `max_tokens` | S1, S2 |
| R4 | Шкала effort откалибрована отдельно для каждой модели: одно имя уровня — разный объём работы; при смене модели начинать с её дефолта | S2, S3, S12 |
| R5 | Эффорт «подбирается как общее предпочтение по типу работы, а не по каждой задаче»; менять посреди сессии нежелательно (кэш) | S1, S13 |
| R6 | Модель «слишком слабая → ошибка при полном контексте» лечится мощнее моделью; «слишком быстро остановилась» лечится effort | S1, S12 |

## 2. Диагностика неудач и порядок эскалации

| № | Правило | Источник |
|---|---|---|
| R7 | Сначала проверьте контекст: расплывчатый запрос, не те инструменты, не те навыки. Часто повышение effort не нужно — надо исправить постановку | S1 |
| R8 | «Пропустила файл, не запустила тесты, бросила рефакторинг на полпути» → **выше effort** (особенно если он был ниже дефолта модели) | S1 |
| R9 | «Имела весь контекст, явно старалась и всё равно ошиблась; уверенно неправа независимо от контекста» → **мощнее модель** | S1 |
| R10 | **Модель меняют, только если повышение effort не помогло** | S12 |
| R11 | Меняя модель, начинайте с дефолтного effort новой модели: на самом сильном уровне ничего не оставляйте «по инерции»; сильная модель может справиться меньшим effort | S12 |
| R12 | Двигаться по одной ступени: поднять на уровень, перезапустить, остановиться, когда начало получаться; вниз — так же | S12 |
| R13 | Политика «сначала дёшево, при провале дороже»: прогон на `low`, перезапуск только провалившихся на `high` — дешевле, чем всё на `high` (Opus 5.5: ≈ 97 % за ≈ $0,17 против 95,3 % за $0,29). Нужен проверяемый сигнал неудачи | S5 |
| R14 | Если качества не хватает: если effort снижали — вернуть; иначе попробовать **следующий класс модели на low** | S5 |
| R15 | Слишком низкий effort: модель останавливается рано и возвращает недоделанное — итого дороже; слишком высокий: переосмысление и «нашла больше задач, чем поручено» | S12 |

## 3. Когда какая модель

| № | Правило | Источник |
|---|---|---|
| R16 | Большинство задач агентной работы начинаются с **Opus 5.5 на дефолте (`medium`)**; Fable — для требовательных рассуждений и долгих агентных задач либо когда Opus на более высоком effort не справился | S4, S5, S6 |
| R17 | Малая модель — для рутины: точно описанные правки, механические изменения, вопросы по коду в контексте; платить за невостребованную способность незачем | S1 |
| R18 | Большая модель лучше справляется с неоднозначностью; точные инструкции — рецепт успеха для малой | S1 |
| R19 | Если на большой модели рутина идёт давно — спуск вниз ускорит и обычно удешевит без потери качества | S1 |
| R20 | Sonnet — для большей части кодинга (фичи, тесты, известные баги, рефакторинг); Opus — когда застряли или изменение широкое (трудная отладка, сквозной рефакторинг, архитектура); Haiku — быстрая механика (переименования, строки логов, объяснение регулярок, шаблонный код) | S11 |
| R21 | Opus расходует заметно больше квоты, чем Sonnet; Opus на рутине — самый быстрый способ исчерпать дневной лимит | S11 |
| R22 | Планировать на Opus, исполнять на Sonnet (`opusplan`); смена модели не стирает разговор | S3, S11 |
| R23 | Позиционирование: Opus 5.5 — «основная рабочая лошадка» (длинные автономные агенты, рефакторинг, сложные системы, документы, компьютерное управление); Sonnet 5.5 — повседневные, чётко очерченные задачи, «быстрый и дешёвый компаньон Opus»; Haiku 5.5 — высокий поток, задержка, классификация, маршрутизация, извлечение, субагенты с чёткими подзадачами, массовые мелкие правки | S4, S16, S9 |
| R24 | Если ваша оценка не показывает, что Opus не справляется, Fable не нужна: «если Opus уже проходит планку, его скорость и цена могут быть лучше» | S13 |
| R25 | Рекомендация «начинать с самой умной общедоступной модели и настраивать effort» — для случаев, где неизвестна планка; цена за задачу у более умной модели часто ниже, особенно на низком effort | S13 |
| R26 | Сравнивать модели нужно по цене за **решённую** задачу и на хвосте нагрузки (самые трудные 10 %), а не по цене за токен и по медиане | S5 |
| R27 | Начинать с малой модели трудно отличить сбой модели от сбоя постановки | S13 |
| R28 | Стратегия «исполнитель + советник»: слабая модель-исполнитель консультируется у сильной на трудных местах (Sonnet 5 с советником Fable 5: в пределах 10 % балла Fable за 63 % цены) | S13, S5 |

## 4. Fable: когда да, когда нет

| № | Правило | Источник |
|---|---|---|
| F1 | Позиционирование: самая мощная общедоступная модель; многочасовые асинхронные задачи, автономные агенты (часы), кодовая база целиком, ревью, глубокое исследование, документы; «исправляет первопричины, а не симптомы», сама пишет тесты | S16, S4 |
| F2 | В Claude Code: подходит для задач «больше одного подхода»; держит долгие автономные сессии, исследует перед действием, проверяет работу чаще | S3 |
| F3 | Получить максимум: описывайте **результат, а не шаги**; отдавайте неоднозначные задачи (поиск первопричин, отладка сбоев, архитектурные решения); **не добавляйте напоминаний о проверке** — сама проверяет; давайте работу крупнее обычной; задавайте цель (`/goal`) | S3 |
| F4 | Цена: $10/$50 за млн токенов (Opus 5.5 — $4/$20, Sonnet 5.5 — $2/$10, Haiku 5.5 — от $0,10/$0,50); задержка «медленнее»; чтение кэша $0,25 | S6 |
| F5 | Fable не является моделью по умолчанию ни на одном тарифе; выбирается явно. Использование Fable может списываться с **usage credits**, а не с лимитов тарифа; в интерактивной сессии есть запрос согласия, а в неинтерактивном режиме `-p` и в SDK без запроса Claude Code списывает кредиты **без вопроса** | S3 |
| F6 | Эффорт Fable 5.1: старт `high` (дефолт); вверх `xhigh`/`max` — только для самой чувствительной к способности работы; вниз `medium`/`low` — для рутинной или чувствительной к задержке при подтверждённом качестве | S2, S6 |
| F7 | На `low` Fable 5.1 «часто конкурентна с Opus и Sonnet по цене за задачу при более высоком балле» — включайте её в сравнение там, где вы запускали бы малую модель на высоком effort. На SWE-bench Pro Fable 5.1 на `low` решила 88,6 % за $0,54 на решённую задачу против 77,4 % за $0,84 у Sonnet 5 на дефолте | S6, S5 |
| F8 | Но на насыщенных задачах Opus 5.5 на дефолте равен Fable 5.1 на дефолте (92,8 % против 92,3 %, в пределах шума) за **пятую часть цены** ($0,22 против $1,19); Opus 5.5 на `low` — 87,4 % за $0,12. Анонс Anthropic: «Opus 5.5 работает на уровне Fable 5.1 на большинстве задач и стоит на 40 % меньше Opus 5» | S5, S16 |
| F9 | На долгих исследовательских циклах Fable делает **больше** работы, а не меньше; Fable 5.1 «оправдывает цену только на `low`»: DeepResearch Bench II — 66 % за $4,66 на `low` и тот же балл на `high` за $7,12 | S5 |
| F10 | Кривая «качество—цена» на исследовании и знаниях почти плоская: `low` теряет 1–3 пункта за треть–половину цены, `medium` равен дефолту за 70–87 % цены, дефолт не даёт измеримого выигрыша над `medium` | S5 |
| F11 | `xhigh`/`max` на Fable: может «написать черновик в мышлении, а затем переписать» — дольше и дороже; для длинных текстов запускать на `high` | S6 |
| F12 | Независимые замеры: Fable 5.1 на `max` = `xhigh` (индекс 53, $5,98 против $7,63) — прирост нулевой, цена выше; Opus 5.5 на `high` (54, $1,82) выше Fable 5.1 на `high` (51, $3,91); Fable на `low` (47, $2,37) ниже Opus на `medium` (51, $1,34) | B1 |
| F13 | В реальных сессиях агентов (Agent Arena, 8.10.2026) лучший по общему счёту — Opus 5.5 `high` ($1,79 за задачу); Fable 5.1 `max` — третья ($6,34, в 3,5 раза дороже) | B4 |
| F14 | Terminal-Bench 4.0 в Claude Code: Opus 5.5 `max` 64,8 % (±3,1; $4,7 тыс.), Fable 5.1 `max` 57,9 % (±3,8; $6,2 тыс.) | B3 |
| F15 | Классификаторы безопасности: запросы по кибербезопасности (**высокорисковая двойная выгода**, наступательная работа, пентест, CTF) и биологии перенаправляются на другие модели; биология — на Opus 5, кибер — на Opus 4.8; **поиск уязвимостей в исходном коде разрешён**. После перенаправления сессия продолжается на запасной модели. Классификатор может сработать и от содержимого репозитория (CLAUDE.md, git status), если там материалы по безопасности/биологии | S3, S6, S7 |
| F16 | Ложные срабатывания Fable чаще при формулировках «компилируется ли без ошибок» (лучше «есть ли ошибки»), редких языках программирования, base64 в выводе инструментов | S6 |
| F17 | Fable 5.1 — меньше обновлений о ходе работы, при низком effort реже ищет (отвечает по памяти), чаще переписывает файл целиком, иногда делает больше, чем просили, и «описывает следующий шаг вместо выполнения» — нужна инструкция «заканчивай задачу целиком» и «только то, что просили» | S6 |
| F18 | Явный подъём к Fable после неудачи на Opus: «если ваши проверки на Opus 5.5 на `xhigh` или `max` всё ещё не проходят на трудных рассуждениях или долгих агентных задачах — переходите на Fable 5.1» | S4 |
| F19 | Встроенный агент Explore при сессии на Fable (подписка/Console) идёт на Opus, а не на Fable: разведка кодовой базы не требует самой дорогой модели | S10 |

## 5. Уровни effort: что они значат и во что обходятся

| № | Правило | Источник |
|---|---|---|
| E1 | `low` — «самое эффективное; значительная экономия токенов при некотором снижении способностей»; для простых задач, где важны скорость и цена, **например субагенты**; быстрые реплики с просмотром каждого результата (идеи, набросок, переименование) | S2, S3 |
| E2 | `medium` — баланс скорости, цены и качества; дефолт Opus 5.5 и Haiku 5.5; на Opus 5.5 и Sonnet 5.5 — повседневная инженерная работа с ясным объёмом (новая функция) | S2, S3 |
| E3 | `high` — сложные рассуждения, трудный кодинг, агентные задачи; важна проверка, вероятны крайние случаи (баг в существующей кодовой базе); дефолт Fable 5.1, Sonnet 5.5 (API), Opus 5 | S2, S3 |
| E4 | `xhigh` — расширенная способность для долгой работы: агентные и кодинговые задачи **дольше 30 минут** с бюджетами в миллионы токенов; глубже `high` без полной цены `max` | S2, S3 |
| E5 | `max` — «абсолютный максимум без ограничений на токены»; трудные задачи без присмотра (поиск уязвимостей); **склонен к переосмыслению, отдача убывает; тестировать перед широким применением; Claude Code сам делает `max` только на сессию** | S2, S3, S12 |
| E6 | Резервируйте `xhigh` и `max` для работы, где вы **измерили** выигрыш в качестве (Opus 5.5, Sonnet 5.5) | S7, S8 |
| E7 | Opus 5.5 на `medium` равен или превосходит Opus 5 на `high`; на нескольких кодинговых оценках `low` близок к нему при много меньшей цене. При одном уровне Opus 5.5 думает больше за ход, чем Opus 5, особенно на `xhigh`/`max` | S3, S7 |
| E8 | Opus 5.5: `high` → `medium` теряет ≈ 2,5 пункта SWE-bench Pro при ≈ 70 % цены; на `low` теряет ≈ 8 пунктов при ≈ трети цены; `xhigh` выигрывает ≈ 1,4 пункта при 2,5-кратной цене `high` | S5 |
| E9 | Независимо: Opus 5.5 — `low` 42 / $0,55; `medium` 51 / $1,34; `high` 54 / $1,82; `xhigh` 56 / $3,46; `max` 58 / $5,98 (индекс Artificial Analysis); время ответа 16 → 28 → 43 → 134 → 667 с | B1 |
| E10 | Независимо: Sonnet 5.5 `max` (56, $5,46) дороже и хуже Opus 5.5 `xhigh` (56, $3,46); Sonnet 5.5 `xhigh` (52, $2,01) не лучше Opus 5.5 `medium` (51, $1,34) — **высокий effort на малой модели часто хуже, чем следующий класс на низком** | B1 |
| E11 | В Claude Code на `max` Sonnet 5.5 расходует 19,4 млрд токенов на Terminal-Bench 4.0 против 8,0 млрд у Opus 5.5 | B3 |
| E12 | Haiku 5.5: старт `medium` (в том числе агентный кодинг); `low` — чат, короткие задачи с инструментами, большой поток, но в длинных агентных промптах **чаще пропускает поиск, останавливается рано и пропускает проверки**; `high` — знания, длинные агентные задачи, строгое следование инструкциям; `xhigh`/`max` — только при подтверждённом выигрыше, и сравнивайте с Sonnet 5.5. Переход `low` → `medium` вдвое сократил раннюю остановку, но удвоил выходные токены | S2, S9 |
| E13 | Sonnet 5.5: старт `high`, но для агентного кодинга — `medium` для хорошо описанных задач, `high` для трудных или длинных; для чата — `medium` или `low`.
