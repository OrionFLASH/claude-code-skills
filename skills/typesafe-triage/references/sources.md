# Источники правил выбора модели и effort (2.7)

Свод для политики скилла: какая задача — на какую модель Claude и с каким effort. Составлен по списку `sources-claude-model-effort.md` (пользователь, 9 октября 2026), версии моделей — Fable 5.1, Opus 5.5, Sonnet 5.5, Haiku 5.5.

| **S2** Документация платформы «Effort» | то же: поисковые выдержки (уровни, дефолты, рекомендации по моделям) | первоисточник, выдержки |
| **S3** Документация Claude Code «Model configuration» / справка «Change the model, effort, and thinking settings» | поисковые выдержки (что значит каждый уровень в Claude Code) | первоисточник, выдержки |

## Правила и их место в коде

| № | Правило | Источник | Где в скилле |
|---|---|---|---|
| R1 | Модель и effort — разные ручки: модель — насколько способен исполнитель, effort — насколько тщательно он работает (сколько файлов читает, сколько проверяет, сколько шагов проходит до отчёта) | S1, S2 | две оси: `typesafe_triage.decide` и `triage_effort.decide_effort` |
| R2 | Диагностика неудачи: модель имела весь контекст и всё равно ошиблась (выдумала, не поняла архитектуру, не тот подход) → **мощнее модель**; пропустила файл, не запустила тесты, бросила рефакторинг → **выше effort** | S1 | `triage_heuristics.retry_kind`, `triage_effort.history_escalation` (#53) |
| R3 | Рутина (точно описанные правки, механические изменения, вопросы по коду в контексте) — меньшая модель без потери качества и дешевле; на сложной работе крупная модель может снизить итоговую цену за задачу | S1, S5 | признак «точная правка», защита от лишнего шага вверх (#54), делегирование вниз (2.6) |
| R4 | Для большинства задач — дефолт модели; effort — общее предпочтение по типу работы | S1, S2 | `eff.MODEL_EFFORT_DEFAULT`, пол effort по моделям (#52) |
| R5 | Дефолты: **medium** у Opus 5.5 и Haiku 5.5, **high** у Fable 5.1 (и у Opus 5 и более ранних); Sonnet 5.5: medium для хорошо описанных, high для сложных/долгих | S2, S4 | пол haiku/опора sonnet/пол fable (#52) |
| R6 | Уровни в Claude Code: **low** — быстрые реплики с просмотром каждого результата (идеи, набросок, переименование); **medium** — повседневная работа с ясным объёмом (новая функция); **high** — важна проверка, вероятны крайние случаи (баг в существующей кодовой базе); **xhigh** — сложный кодинг и агентные задачи (> 30 минут), глубже high без полной цены max; **max** — трудные задачи без присмотра (поиск уязвимостей), **склонен к переосмыслению, отдача убывает** | S2, S3 | пороги effort и ограничения low/max (#51, #52) |
| R7 | Haiku: начинать с medium; low — чат, короткие задачи с инструментами, большой поток; в длинных агентных промптах на **low пропускает поиск, останавливается рано, пропускает проверки**; high — знания и длинные агентные задачи. Позиционирование: субагенты с чётко очерченными подзадачами, массовые мелкие правки, классификация, браузерная автоматизация, простой кодинг | S2, S5 | `HAIKU_EFFORT_MIN=medium`, строгие критерии haiku, подсказка проверять результат (#51) |
| R8 | Sonnet 5.5: повседневная работа с чётким объёмом (код, баги, ревью, анализ, документы); xhigh/max — только если замеры показывают выигрыш | S2, S5 | потолок sonnet — xhigh (#52) |
| R9 | Opus 5.5: «основная рабочая лошадка» — длинные автономные агенты в больших кодовых базах, рефакторинг, сложные системы, документы, компьютерное управление; для сложного кодинга начинать с xhigh | S4, S5, S3 | пороги opus, effort xhigh для тяжёлого кодинга |
| R10 | Fable 5.1: максимальная способность — многочасовые агентные сессии, глубокое исследование, изменения по всей кодовой базе, поиск первопричин; начинать с high; xhigh/max — самая чувствительная к способности работа; **запросы по кибербезопасности и биологии автоматически перенаправляются на менее мощные модели** | S2, S4, S5 | жёсткие критерии fable, запрет при кибер/био-темах (#51) |
| R11 | Слабости Opus 5: «непродуктивная самопроверка», переусложнение мелких правок, больше неверных фактов, чем у Opus 4.8 → явно ограничивать объём и не уходить в лишние проверки | S6 | строка-ограничитель в промпте исполнителя (#56) |
| R12 | Контекст — главный ресурс; плохой результат часто следствие контекста или отсутствия проверки, а не модели: дать способ проверить работу, сначала план, свежий контекст для ревью | S7 | диагностика (R2), цена контекста при делегировании (2.4) |
| R13 | Менять модель и effort до начала работы: смена посреди диалога может сбросить кэш промпта и удорожить его | S1 (смежная статья), S2 | заметка советует `/effort` один раз, а не на каждый запрос |
| R14 | Шкала effort откалибрована отдельно для каждой модели: одно и то же имя — не одно и то же значение; при смене модели перепроверять | S2, S3 | эталонный корпус и `--calibrate` (#57) |

## Расхождения и ограничения

- **Дефолт Opus 4.7 в Claude Code — xhigh, в API — high** (S3 против S2): скилл не привязывается к версиям Opus, а ставит effort по глубине задачи.
- **Дефолт Sonnet 5.5:** страница effort отдельной строки не даёт, руководство по миграции называет high — скилл держит medium для описанных задач и high для сложных.
- Источники называют **уровни, а не пороги**: границы «хорошо описанная», «сложная», «важна проверка» переведены в числовые оси TypeSafe и калибруются на корпусе (`triage_cases.json`, `--calibrate`), а не берутся из документов.
- Заявления производителя о моделях (S5) — позиционирование, а не независимые измерения; независимые бенчмарки (S8) обновляются быстрее, чем выходят версии скилла, поэтому в код не зашиваются.
- Цена и скорость в источниках приведены по моделям (Haiku 5.5 $0,10/$0,50, Sonnet 5.5 $2/$10, Opus 5.5 $4/$20, Fable 5.1 $10/$50 за млн токенов): fable оправдана только там, где задача действительно упирается в способность.
