## [2.2.0] — 2026-10-09
По обратной связи 2026-10-09 (T-1…T-6).

### Исправлено
- **T-4: «заметка пропала».** Расследование по журналу `~/.claude/typesafe-triage/log.jsonl` и файлам настроек:
  - **Что случилось в отзыве.** Сессия прогона (хеш `93fe6d066c68`) последний раз записана в журнал в 00:21:17, хотя продолжалась до ~01:26; два последних запроса не дали ни заметки, ни записи в журнал, то есть скрипт вообще не запускался. В 00:06:26 был установлен плагин `typesafe-triage` 2.1.3, а в 00:28:44 из `~/.claude/settings.json` убран ручной хук на `$HOME/.claude/skills/typesafe-triage/scripts/typesafe_triage.py`, и папку `~/.claude/skills/typesafe-triage` удалили (каталог `~/.claude/skills` изменён в ту же секунду; прежний хук виден в `settings.json.bak-20261009`). Правки хуков в `settings.json` открытая сессия подхватывает на лету, а хук плагина, установленного после её старта, — только после `/reload-plugins` или перезапуска. В итоге после 00:28:44 в этой сессии хука не было ни одного. Причина — переход «ручной хук → плагин» в открытой сессии. Метка-дубль здесь ни при чём: в этой сессии был один хук. Скрипт эту ситуацию поправить не может, поэтому добавлены `--where` и правила в INSTALL.md (ниже).
  - **Гипотеза о метке-дубле подтвердилась как отдельный скрытый дефект.** Метка ставилась до триажа. Если первый вызов падал или его обрывал тайм-аут Claude Code, второй (ручной хук + хук плагина) молчал. Это воспроизведено тестом на настоящих процессах: первый вызов «убит» SIGKILL, второй молчал. Кроме того, любое исключение в хуке глушилось без следа.
  - Исправление: у метки два состояния, «в работе» (ставится до триажа, внутри только `state`, `pid` и `ts`) и «готово» (ставится после вывода заметки). Второй вызов ждёт первого. Если первый умер, его метка устарела или он не ответил за бюджет, работу подхватывает второй (поле `takeover` в журнале).
  - Весь хук укладывается в `HOOK_BUDGET_S` = 8 с, бюджет Claude Code — 10 с. За этим следит сторожевой поток: зависание (например, DNS) больше не обрывается тайм-аутом Claude Code, который выбрасывает вывод. Вместо этого выдаётся заметка по эвристике и сообщение «TypeSafe-триаж пропущен: TypeSafe-оценка не уложилась в 8 с…».
  - Хук не молчит без причины. При пропуске он выдаёт одну строку «TypeSafe-триаж пропущен: <причина>»: реплика, команда, служебное сообщение, «реплика по оценке TypeSafe». При сбое (ошибка, некорректный ввод, не уложились) строка попадает ещё и в `systemMessage`. Каждый пропуск пишется в журнал без текста запроса (поле `skipped`). Такие записи не участвуют в истории сессии и в сводке моделей. Хук молчит только при выключателе, внутри `--run` и когда заметку уже дал другой вызов.
- **T-5:** подсказки `typesafe_guard` («выполните … --resume») и документация больше не ссылаются на жёсткий `~/.claude/skills/typesafe-triage/…`, которого нет при установке плагином.

### Добавлено
- **T-5: `--where`.** Первая строка вывода — фактический путь скрипта. Дальше идут способ установки, состояние, команда запуска и хуки `UserPromptSubmit` на `typesafe_triage.py` в `settings.json` (глобальном и проектном), с предупреждениями: «хук ведёт в несуществующий файл» (`python3` без файла вернёт код 2, а он блокирует запрос), «два хука», «хука нет». Также выводится, включён ли плагин и какие версии лежат в кэше. Из настроек читаются только блоки `hooks`/`enabledPlugins`.
- SKILL.md использует `${CLAUDE_SKILL_DIR}/scripts`: Claude Code подставляет каталог скилла и для плагина, и для `~/.claude/skills`. В INSTALL/README каталог `S` определяется по способу установки, а проверка идёт через `--where`.
- Ручной хук в INSTALL/README записан в защищённой форме `if [ -f … ]`: если папки скилла нет, выводится «триаж пропущен: скрипт хука не найден», а не код 2. Ещё описано, когда хук плагина начинает работать (новая сессия или `/reload-plugins`).
- **T-1: активная задача и наследование.** Короткое продолжение («продолжай тесты», «и ещё добавь…», "continue …", до 300 знаков) наследует оценку последнего оценённого запроса сессии. Модель и effort берутся не ниже прежних, но не выше opus/xhigh, явные указания пользователя главнее. Пометка — «уверенность унаследована», уточняющий вопрос не задаётся. В дайджест для TypeSafe добавляется одна строка «активная задача»: первый открытый пункт `TASKS.md` проекта, до 200 знаков, секреты маскируются. Выключается через `TYPESAFE_TRIAGE_CONTEXT=off`. Строку показывает и `--digest`.
- **T-2:** тип задачи `qa` (тестирование продукта: сценарии, поиск дефектов, замеры, issues со скриншотами). Описание `software` уточнено: «включая автотесты».
- **T-3: общее интерактивное состояние.** Признаки проверяются локально: профиль браузера `.profile/` в проекте, `DevToolsActivePort` (CDP), открытые пункты `TASKS.md` про прогон, браузер или вход, фразы «в моём браузере», «я уже вошёл», CDP, 9222. При таких признаках заметка пишет: «Общее интерактивное состояние (…): делегируй только независимые части — исполнитель получит свой браузер и сессию». Поле `shared_state` добавлено в результат и в журнал.
- **T-6:** в SKILL.md явно сказано, что правило пользователя в `CLAUDE.md` «ставь effort из заметки» и сама заметка — это то явное требование, которого ждёт описание `Agent(effort=…)`.
- Тесты: `test_typesafe_hook_skip.py` (сбой, зависание, ожидание и подхват, «убитый» первый вызов на настоящих процессах, строки пропуска, журнал), `test_typesafe_context.py` (`--where`, активная задача, наследование, `qa`, общее состояние), `test_typesafe_docs.py` (пути в документации, правило effort). Прежние тесты «хук молчит» переписаны под строку пропуска. Всего 244 теста.

## [2.1.2] — 2026-10-08
Две проблемы из реального использования: у инструмента `Agent` бывает нет параметра `effort`, и слова из цитат принимались за явные указания.
### Исправлено
- Заметка хука больше не требует безусловно «effort указывай явно»: effort передаётся, только если у `Agent` есть такой параметр; если нет — не пытаться и не ссылаться на него (это не ошибка).
- Явные указания: упоминание не считается использованием. Маркеры в кавычках («…», "…", “…”, '…'), в коде, в пересказе («ассистент ответил…», «заметка советует…», «в отчёте…», «пользователь пишет…», «написано:») и после подписи «слово/фраза» игнорируются; одиночный маркер в кавычках в повелительной фразе («сделай это «на opus»») остаётся указанием. Вставленный отчёт (повтор предложений с маркерами, ≥ 3 маркеров в кавычках) не даёт указаний из цитат и мягких слов.
- Найденные указания в причинах и в заметке («Задано пользователем») больше не дублируются.
### Добавлено
- Запасные способы задать глубину без параметра: готовые фразы для промпта агента для каждого уровня (`EFFORT_PROMPT`, ru/en) и, когда effort критичен (high и выше при высокой цене ошибки, max или задан явно), команда `--run` с полным путём к скрипту и флагами подтверждения. Всё — одним пунктом заметки; для обычного effort (medium/high без высокой цены ошибки) ничего не навязывается. Рост заметки — не больше ~25 %.
- Поля результата `effort_delivery` (`agent_param` / `prompt` / `run`) и `mentions` (сколько маркеров-упоминаний скрыто); в `--signals` — `mentions` и `report`.
- Документация: раздел «Когда у Agent нет параметра effort» и правило mention/use в `references/effort.md`; условная строка про effort для `CLAUDE.md` в INSTALL.md и UPDATE.md.
- Тесты: условная заметка и запасные способы, размер заметки, команда `--run` из заметки принимается `--run --dry-run`, реальный вставленный отчёт (в т. ч. повторённый дважды) не даёт указаний, прямые указания и отрицания работают, дедупликация (200 тестов).

## [2.1.0] — вторая ось: reasoning effort
### Добавлено
- Вторая независимая ось `effort` (`low < medium < high < xhigh < max`) рядом с моделью; модуль `scripts/triage_effort.py`. Полоса без вопросов — `medium..xhigh` (при сомнении `high`); `low` и `max` — только с подтверждения (`CONFIRM_EFFORTS`), без него `low → medium`, `max → xhigh`; `xhigh` вынесен в `OPTIONAL_CONFIRM_EFFORTS`.
- Слоистая оценка с прозрачными причинами (`effort_reasons`): a) TypeSafe — новые вопросы в том же запросе (`planning`, `shallow_cost`, `verification`, `exploration`, `constraints`, `coordination`) плюс прежние шкалы; b) текст — намерение, требования, критерии приёмки, ограничения, неопределённость, диагностика, критичность, объём, математика; c) окружение — git, тесты, CI, lock-файлы, порядок числа файлов, маркер `.typesafe-triage-effort` (локально); d) история сессии — повторы после неудачи поднимают effort (потолок +2, не до max) и при втором повторе модель (не выше opus); e) правила согласованности модель × effort; f) запасной вариант без TypeSafe.
- Явные указания пользователя в тексте («на opus», «effort max», «ultrathink», «тщательно», «кратко», "use haiku", "think hard"…) — согласие и приоритет над автооценкой, с учётом отрицаний.
- Заметка хука: пара «модель + effort», один `AskUserQuestion` на обе оси, `Agent(model=…, effort=…)`, строка `/effort …` для основной сессии (если её effort известен и отличается на ≥ 2 ступени), один уточняющий вопрос при неуверенной оценке и высокой цене ошибки.
- `--run`: `--effort`, `--confirmed-effort`, передача `claude -p --effort`; `--dry-run` показывает effort. Неизвестный effort отклоняется (CLI сам его молча игнорирует — проверено).
- Идемпотентность хука: второй вызов на тот же запрос (`session_id` + хеш промпта) в течение 8 с молчит — ручной хук и хук плагина не дают двух заметок.
- Хук плагина `hooks/hooks.json` (`${CLAUDE_PLUGIN_ROOT}`, запуск `python3`, при отсутствии — `python`); проверено `claude plugin validate` и живым запуском `--plugin-dir`.
- `--calibrate` (распределение effort, матрица «ожидаемый → выданный», сводка журнала, `--split train|holdout`, `--cache`); `triage_cases.json` расширен до 82 кейсов (15 областей, ru/en, явные указания, отрицания, история) с ожидаемыми диапазонами `effort_ok`/`tier_ok`.
- Документация `references/effort.md`; живая проверка сочетаний `claude -p --model haiku|sonnet|opus --effort <все 5>` (все приняты).

### Изменено
- Результат триажа дополнен полями `effort`, `effort_confidence`, `effort_confirm`, `effort_fallback`, `effort_source`, `effort_reasons`, `effort_depth`, `effort_layers`, `model_source`, `explicit`, `clarify`, `retry`, `env`, `session` (формат аддитивный, старые поля сохранены); журнал — effort, источник, хеш сессии, признак повтора.
- Запасной вариант модели без TypeSafe: opus также при ≥ 2 группах слов риска (без условия объёма), при намерении «доказать» и при риске + намерении не легче «проверить/сравнить». Словари сигналов расширены (кредит/ипотека/оценка/инвесторы, учётные данные, лекарства/закон, «периодически», 5xx); «переезд» считается риском только для баз/серверов/систем.
- Заметка начинается с «TypeSafe-триаж: уровень X, effort Y (…)».

## [2.0.0] — универсальный триаж и четыре уровня
### Изменено (несовместимо)
- Триаж универсальный: оцениваются любые задачи (код, документы, письма, анализ, данные, исследование, планирование, ревью, ops). Вопрос `software_dev` и правило «молчать вне разработки» удалены; пропускаются только короткие реплики/подтверждения, команды `/…` и служебные сообщения среды.
- Уровни `haiku < sonnet < opus < fable` (`TIERS`). haiku и fable никогда не запускаются автоматически (`CONFIRM_TIERS`): заметка требует `AskUserQuestion`, без «да» — sonnet/opus. В `--run` и `--tier` они допускаются только с новым флагом `--confirmed`; `build_agent_cmd` без `confirmed=True` их отклоняет.
- Вопросы к TypeSafe переписаны доменно-нейтрально по документации (уровни-ситуации с примерами): шкалы `complexity`, `reasoning`, `ambiguity`, `risk` (4 уровня, верхний — критично/необратимо), новая `breadth`; флаги `read_only`, `mechanical`, `needs_investigation`, `silent_errors` (вместо `touches_data_rules`), новые `irreversible`, `novel_design`, `conversational`; Choice `domain` (для заметки и журнала).
- Формат результата: `model` есть всегда; новые поля `source` (`typesafe`/`heuristic`), `confidence`, `confirm`, `fallback`, `skip`, `signals`, `domain`; поле `dev` удалено.
- Заметка хука — короткая и императивная: когда делегировать (`Agent(model=…)`), когда делать самому, вопрос пользователю для haiku/fable.
- Журнал пишет все оценённые запросы (не только разработку), реплики не пишутся.

### Добавлено
- Локальные эвристики `scripts/triage_heuristics.py`: длина, пункты, перечисления, шаги, файлы, код/логи, слова критичности (прод, необратимость, безопасность, деньги, юридическое/медицинское, потеря данных), «глубокие» и «лёгкие» слова. Только поднимают нагрузку, могут запретить haiku, должны подтвердить fable.
- Запасной вариант: без ответа TypeSafe (нет ключа, сеть, пауза защиты, слишком большой вход) уровень по эвристике — только sonnet/opus с пометкой «уверенность низкая».
- Ворота haiku по вероятности верхней половины шкал (из `probabilities`), шаг вверх за низкую уверенность — только у границы уровня.
- Команды `--signals`, `--selftest --heuristic`; `triage_cases.json` с универсальными кейсами (письма, планы, анализ, стратегия, договор, финмодель, fable, реплики).
- `references/`: `levels.md`, `guard.md`, `privacy.md`, `superpowers.md`.

### Сохранено
- Путь `~/.claude/skills/typesafe-triage/scripts/`, публичное API `typesafe_guard`, CLI-команды, хук-протокол (JSON на stdout, никогда не блокирует, ошибка = молчание), файлы состояния, выключатели, `TYPESAFE_TRIAGE_CHILD`, маскировка секретов, дайджест.
