# typesafe-triage

Универсальный триаж **любых** задач (код, документы, письма, анализ, данные, исследование, планирование, ревью, ops, право, финансы, учёба): TypeSafe (модель Jev) отвечает на узкие вопросы, локальные сигналы считают текст, окружение и историю сессии, а код детерминированно выбирает **две независимые оси**:

- **модель** Claude — `haiku` < `sonnet` < `opus` < `fable` (способность исполнителя);
- **reasoning effort** — `low` < `medium` < `high` < `xhigh` < `max` (сколько думать).

Работает глобально через хук `UserPromptSubmit`: добавляет к запросу короткую заметку, которая с 2.3 начинается одной строкой **`ДЕЙСТВИЕ: сам | Agent(model=…, effort=…) | спросить — причина. Уверенность: …`**, а по команде `--run` сам запускает отдельного агента `claude -p --model … --effort …`.

- **Действие** (2.3) выбирается кодом: явная просьба пользователя («используй субагента», «сделай сам») главнее индексов; общее устройство или сессия (браузер пользователя, CDP, эмулятор) — «сам»; долгое ожидание — «сам» с подсказкой «фоновый скрипт, а не субагент»; небольшая задача или диалог — «сам»; нужный уровень выше **реальной модели сессии** (из стенограммы, локально) или большая изолируемая задача — `Agent(…)`; накопленный контекст дорого передавать — «сам». Модель сессии неизвестна — заметка так и пишет. Одна причина до 15 слов, одна уверенность, без чисел осей. Подробно — [references/action.md](references/action.md).
- **Принудительный запуск** (2.4.2): `/typesafe-triage:typesafe-triage <задача>`, метка `triage:` / `триаж:` / `!triage` (с уровнем: `triage:opus/high`, `!triage haiku`) или фраза «сделай триаж» в запросе снимают пропуски хука (короткая реплика, «болтовня», команда `/…` этого скилла, режим «реже»); модель, effort и действие выбираются как обычно. Подробно — `SKILL.md`.
- **Секреты и персональные данные** (2.5): пароли на русском и английском («пароль: …», «пароль от сервера …», `password=…`), seed-фразы, приватные ключи, токены и ключи API, JWT, URL с паролем, номера карт, e-mail, телефоны и номера документов маскируются до отправки, в журнал и в строку «активная задача». Запрос с приватным ключом, seed-фразой или номером карты в TypeSafe **не отправляется вовсе** (уровень по локальной эвристике, пользователь видит сообщение). Политика — `TYPESAFE_TRIAGE_SECRETS=block` (по умолчанию) / `strict` (любая находка) / `mask`; проверка — `--scan "текст"` и `--digest`. Подробно — `references/privacy.md`.
- **Реже** (2.3): короткое продолжение («продолжай», «и ещё…») с тем же решением — без заметки (журнал: `quiet`, без текста запроса).
- **`--check`** (2.3) проверяет, что хук реально зарегистрирован (`settings.json` пользователя и проекта, включённые и установленные плагины, `disableAllHooks`), печатает команды починки и имя скилла для `Skill` (`typesafe-triage:typesafe-triage` у плагина), находит «призраков» (битые ссылки, резервные копии в `~/.claude/skills`).
- **`--batch tasks.json`** (2.3) — пакет подзадач: таблица `{id, model, effort, confidence, reasons}`, порядок по `paths` (пересечения — «выполнять последовательно»), текст одного `AskUserQuestion`, готовые `Agent(...)` и промпты исполнителей по [шаблону](references/executor-prompt.md).
- **Журнал проекта и факты** (2.3, опция): `triage-log.jsonl` в корне проекта без текста запроса, `--fact` после подзадачи (токены, минуты, исход), `--calibrate` сводит факты.
- **Автозапись факта** (2.4, опция, выкл.): `TYPESAFE_TRIAGE_AUTO_FACT=on` + журнал проекта — хук плагина `PostToolUse` (Agent) и `SubagentStop` сам пишет модель, effort, токены, минуты и число вызовов инструментов агента из документированных полей хуков; привязка к решению — меткой `triage:<id>` в `description` (надёжно и при параллельных агентах), исход — по-прежнему `--fact`, он дополняет автоматический факт.
- **Чем занята сессия** (2.4): из служебных полей стенограммы, без текста — вызовы инструментов по видам, накопленные факты, реплики, токены контекста; доля записи и доля работы против диалога. От 30 фактов или в сессии-диалоге продолжение «как обсуждали» — «сам» (передавать контекст дорого); `--check` показывает эти числа.

- Без вопросов: `sonnet`/`opus` и `medium`/`high`/`xhigh`. **`haiku`, `fable`, `low`, `max` — только после подтверждения пользователя** (один `AskUserQuestion` на обе оси), иначе ближайшее безопасное: haiku → sonnet, fable → opus, low → medium, max → xhigh.
- Явные указания в тексте запроса («на opus», «effort max», «ultrathink», «тщательно», «кратко», "use haiku", "think hard") — согласие и приоритет; отрицания («не нужно глубоко») учитываются. Упоминания не считаются: слова в кавычках, коде, пересказе («ассистент ответил…») и во вставленных отчётах.
- Если у инструмента `Agent` нет параметра `effort` (бывает в части версий Claude Code), заметка не требует его: глубина задаётся готовой фразой в промпте агента, а для критичной изолируемой работы заметка даёт команду `--run` (`claude -p --effort …`).
- Повторы в сессии («опять не работает») поднимают effort (до +2 ступеней, не до max) и при втором повторе — модель на ступень (не выше opus).
- Без ответа TypeSafe (нет ключа, сеть, пауза защиты) обе оси выбирают локальные сигналы (sonnet/opus, medium..xhigh, «уверенность низкая»).
- Пропускаются короткие реплики и подтверждения, команды `/…` (кроме слэш-вызова самого скилла), служебные блоки среды (`<system-reminder>`, `<ide_selection>` вырезаются, остальной текст оценивается) — но не молча: вместо заметки строка «TypeSafe-триаж пропущен: <причина>» (сбои — ещё и сообщением пользователю) и запись в журнал. Повторный вызов хука на тот же запрос (ручной хук + хук плагина) молчит, только если первый выдал заметку; оборвался первый — заметку даёт второй. Весь хук укладывается в 8 с.
- Короткие продолжения («продолжай тесты», «и ещё добавь…») наследуют оценку предыдущего запроса сессии (не выше opus/xhigh) и получают в дайджесте строку «активная задача» из `TASKS.md`.
- Тип задачи `qa` (тестирование продукта); при признаках общего интерактивного состояния (профиль браузера/CDP в проекте, активный прогон в `TASKS.md`, «в моём браузере») заметка советует делегировать только независимые части.

## Входные параметры
| Параметр | Обязательный | По умолчанию | Описание |
|----------|--------------|--------------|----------|
| `TYPESAFE_API_KEY` | нет (без него — только локальные сигналы) | — | ключ TypeSafe, переменная окружения (например, в `settings.json` → `env`) |
| `TYPESAFE_TRIAGE=off` | нет | — | выключить триаж полностью (или пустой файл `.typesafe-triage-off` в каталоге проекта или выше) |
| `TYPESAFE_TRIAGE_CONTEXT=off` | нет | — | не добавлять к дайджесту строку «активная задача» из `TASKS.md` |
| `.typesafe-triage-effort` | нет | — | файл в каталоге проекта: первое слово (`high`, `xhigh`…) — минимальный effort для проекта |
| `TYPESAFE_TRIAGE_SESSION_MODEL` | нет | определяется локально | модель основной сессии (`sonnet`, `opus`…) или `unknown` — не определять |
| `TYPESAFE_TRIAGE_AGENT_EFFORT` / `--set-agent-effort` | нет | по стенограмме | `yes`/`no` — есть ли у инструмента `Agent` параметр `effort` |
| `TYPESAFE_TRIAGE_PROJECT_LOG` / `--project-log` | нет | выкл. | `on` или путь — журнал решений `triage-log.jsonl` в корне проекта |
| `TYPESAFE_TRIAGE_AUTO_FACT` | нет | выкл. | `on` — автозапись факта после субагента хуком плагина (нужен и журнал проекта) |
| `--set-budget USD` | нет | 2 | месячный потолок расходов на TypeSafe |
| `--confirmed` / `--confirmed-effort` (для `--run`) | нет | — | пользователь явно подтвердил haiku/fable / effort low/max |
| `--tier …` / `--effort …` (для `--run`) | нет | рекомендация | модель / effort вручную |

## Установка
Установка и обновление — одна инструкция [INSTALL.md](INSTALL.md): macOS, Linux, Windows, маркетплейс, ключ, хук, правило для CLAUDE.md, промпты для Claude Code (установка и обновление), проверка и откат. Кратко:

1. Поставить скил: `/plugin install typesafe-triage@claude-code-skills` (хук приходит с плагином: `hooks/hooks.json`) **или** `tools/install.sh typesafe-triage` (симлинк в `~/.claude/skills/typesafe-triage`, хук — вручную).
2. Задать `TYPESAFE_API_KEY`.
3. Для установки симлинком/копией — добавить хук в `~/.claude/settings.json`:

```json
"hooks": {
  "UserPromptSubmit": [
    { "hooks": [ { "type": "command", "timeout": 10,
      "command": "f=\"$HOME/.claude/skills/typesafe-triage/scripts/typesafe_triage.py\"; if [ -f \"$f\" ]; then python3 \"$f\" --hook; else echo '{\"systemMessage\":\"TypeSafe-триаж пропущен: скрипт хука не найден, проверьте установку (--where)\"}'; fi" } ] }
  ]
}
```

Автозапись факта (2.4, опция) при ручной установке — ещё два хука (`PostToolUse` с `"matcher": "Agent|Task"` и `SubagentStop`) на `scripts/triage_autofact.py`: [INSTALL.md](INSTALL.md) → «Автозапись факта». Проверка `if [ -f … ]` нужна, чтобы после удаления папки скилла запрос не блокировался (`python3` без файла возвращает код 2). Если хук есть и в `settings.json`, и в плагине — заметка всё равно одна, но лучше оставить один. Хук только что установленного плагина работает в новых сессиях или после `/reload-plugins`.

## Примеры вызова
`S` — каталог `scripts` установленного скилла: в Claude Code — `${CLAUDE_SKILL_DIR}/scripts`; плагин — `S=$(ls -d ~/.claude/plugins/cache/*/typesafe-triage/*/scripts | sort -V | tail -1)`; клон — `skills/typesafe-triage/scripts`. Точный путь печатает `--where` (первая строка).

```bash
python3 "$S/typesafe_triage.py" --where     # путь скрипта, способ установки, хуки в settings.json и их проблемы, имя для Skill
python3 $S/typesafe_triage.py --check       # ключ, сеть, хук зарегистрирован? команды починки (код 0 / 1 — TypeSafe / 3 — хук)
python3 $S/typesafe_triage.py --batch tasks.json --prompts      # пакет подзадач: таблица, порядок, одно подтверждение, Agent(...)
python3 $S/typesafe_triage.py --fact P1 --model opus --effort xhigh --tokens 550000 --minutes 25 --outcome ok
python3 $S/typesafe_triage.py "Сравни три предложения поставщиков и дай рекомендацию"   # JSON: model, effort, причины
python3 $S/typesafe_triage.py --signals "текст"                 # локальные сигналы и явные указания, без сети
python3 $S/typesafe_triage.py --run --edit --dry-run "текст задачи"   # claude -p --model … --effort … (haiku/fable, low/max понижаются)
python3 $S/typesafe_triage.py --run --tier fable --confirmed --effort max --confirmed-effort "…"  # только после явного согласия
python3 $S/typesafe_triage.py --calibrate --split holdout        # распределение effort и расхождения на отложенной части
```
Полный список команд и правила применения заметки — в [SKILL.md](SKILL.md); как считается модель — [references/levels.md](references/levels.md), effort — [references/effort.md](references/effort.md).

## Зависимости
Python 3, только стандартная библиотека; для тестов — `pytest`. Для точной оценки нужен аккаунт TypeSafe (без него работают локальные сигналы). Для `--run` — Claude Code CLI с опцией `--effort` (проверено на 2.1.292).

## Приватность и ограничения
- **В TypeSafe уходит каждый запрос от 40 символов любой тематики** (кроме реплик, команд и служебных сообщений) — дайджест до 4500 знаков, секреты маскируются; вопросы effort идут в том же запросе. Для короткого продолжения — ещё одна строка «активная задача» (первый открытый пункт `TASKS.md`, до 200 знаков; `TYPESAFE_TRIAGE_CONTEXT=off` — выключить). Окружение проекта, история сессии и служебные поля стенограммы (модель, effort, версия, был ли `Agent` с `effort`, с 2.4 — счётчики инструментов, фактов, реплик и токенов; без текста сообщений) считаются локально и никуда не отправляются. Где отправка недопустима — `.typesafe-triage-off` или `TYPESAFE_TRIAGE=off`. Подробнее — [references/privacy.md](references/privacy.md).
- Основную сессию Claude Code переключить нельзя (ни модель, ни effort) — совет применяется делегированием через `Agent(model=…, effort=…)`; для работы в самой сессии заметка может предложить `/effort …`. `effortLevel` в настройках не меняется.
- Защита от ухода баланса в минус и сбоев — [references/guard.md](references/guard.md). Модуль `typesafe_guard.py` используют и другие скилы.
- Состояние, журнал и метки идемпотентности: `~/.claude/typesafe-triage/`.
