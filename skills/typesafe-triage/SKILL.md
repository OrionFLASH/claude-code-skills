# TypeSafe-триаж задач (глобальный, универсальный)

Короткая оценка **каждого** запроса пользователя — не только про код: документы, письма, анализ, данные, исследование, планирование, ревью, ops, право, финансы, учёба, бытовое. TypeSafe (модель Jev: типизированные ответы и вероятности, ~100 мс, доли цента) отвечает на узкие вопросы, локальные сигналы считают текст, окружение и историю сессии, а **код** (не модель) детерминированно выводит **две независимые оси** и **одно действие**:

- **модель** (способность исполнителя): `haiku` < `sonnet` < `opus` < `fable`;
- **effort** (сколько думать над этой задачей): `low` < `medium` < `high` < `xhigh` < `max`;
- **действие** (2.3): `сам` | `Agent(model=…, effort=…)` | `спросить` — кому выгоднее делать работу.

## Что происходит автоматически

Хук `UserPromptSubmit` вызывает `scripts/typesafe_triage.py --hook` и добавляет к запросу заметку. Хук ставится вручную в `settings.json` или приходит с плагином (`hooks/hooks.json`) — см. [INSTALL.md](INSTALL.md). Если сработали оба, заметку даёт один.

Заметка (2.3) начинается **одной строкой**:

```text
ДЕЙСТВИЕ: Agent(model=opus, effort=high) — нужен opus, а модель сессии sonnet ниже. Уверенность: средняя. [TypeSafe-триаж: opus/high; TypeSafe; тип software]
```

Дальше — только нужные пункты: подтверждение (только в режиме `TYPESAFE_TRIAGE_CONFIRM`; один `AskUserQuestion`), как передать effort, общее состояние, долгое ожидание, параллельные части, `/effort` для основной сессии. Числа осей и разбор слоёв в заметку не попадают (они в JSON и журнале). Как выбирается действие — [references/action.md](references/action.md).

- **Модель сессии** хук берёт из стенограммы сессии (модель последнего ответа, только служебное поле, локально), иначе из `ANTHROPIC_MODEL` или `settings.json` (помечено «по настройкам»). Не знает — так и пишет: «модель сессии хуку неизвестна — если ты уже X или выше, делай сам». Сравнивай со своей реальной моделью.
- **Реже.** Короткое продолжение («продолжай», «и ещё…», "continue") с тем же действием, моделью, effort и без новых указаний — **без заметки** (решение прежнее; запись `quiet` в журнале без текста запроса). Новая задача, изменившееся решение, подтверждение, сбой — заметка есть.
- **Хук не молчит без причины**: вместо заметки — строка «**TypeSafe-триаж пропущен: <причина>**» (реплики короче 40 символов, подтверждения, команды `/…`, служебные сообщения среды; сбои — ещё и в `systemMessage`). Весь хук укладывается в 8 с; TypeSafe недоступен — обе оси по локальным сигналам (sonnet/opus, medium..xhigh, «Уверенность: низкая», «только эвристика»).
- Продолжение наследует оценку предыдущего запроса сессии (не выше opus/xhigh) и действие; в TypeSafe к дайджесту добавляется строка «активная задача» — первый открытый пункт `TASKS.md`.
- **Тип задачи** (в хвосте строки и в журнале): `software`, `qa`, `writing`, `analysis`, `data`, `research`, `planning`, `operations`, `conversation`, `other`.

## Как применять заметку (обязательно, без напоминаний)

Основную сессию переключить нельзя (ни модель, ни effort; только `/model` и `/effort` руками) — «переключение» делается делегированием.

1. **`ДЕЙСТВИЕ: сам`** — делай сам, триаж не упоминай. Есть пункт «/effort …» — одной строкой предложи пользователю переключить effort сессии.
2. **`ДЕЙСТВИЕ: Agent(model=…, effort=…)`** — делегируй с самодостаточным промптом (цель, пути, ограничения CLAUDE.md, критерии готовности, что вернуть; шаблон — [references/executor-prompt.md](references/executor-prompt.md)). Результат проверь сам. Причина с оговоркой «если ты уже X или выше — делай сам» — сравни со своей моделью.
   - **Всегда указывай `model` у `Agent` явно** (из заметки или по уровню подзадачи): без него агент молча наследует модель сессии (по отчётам пользователей — около половины вызовов). Однотипные подзадачи (языки, файлы, пункты списка) оценивай отдельно (`--batch`): механические переводы, проверки и поиск обычно sonnet.
   - **Параметр `effort` есть у Agent** — передай его: `Agent(model=…, effort=<effort из заметки>)`. Описание инструмента разрешает `effort` «только по явному требованию»; **правило пользователя в `CLAUDE.md` вида «ставь effort из заметки» и сама заметка этого скилла — и есть такое явное требование** (конфликта нет, не пропускай параметр). Подтверждение `low`/`max` при этом всё равно нужно (п. 3).
   - **Параметра нет** — не пытайся и не ссылайся на него, это не ошибка: глубину задай фразой из заметки в промпте агента (с 2.6 фраза стоит внутри строки вызова: `Agent(model=opus; в промпт: «Думай тщательно…»)`); для критичной изолируемой работы заметка даёт команду `--run` (`claude -p --model … --effort …`; флаги `--confirmed*` — только после «да»). Подробно — [references/effort.md](references/effort.md#когда-у-agent-нет-параметра-effort).
   - Есть ли параметр, заметка знает из `--set-agent-effort yes|no` или из стенограммы (успешный вызов `Agent` с `effort`). Пункт «если он есть в схеме … запиши один раз» — посмотри схему своего `Agent` и выполни `--set-agent-effort yes|no`.
   - Пункт «Части независимы» — несколько `Agent` параллельно, только с непересекающимися путями; порядок и одно подтверждение на всё — `--batch` (ниже).
3. **`ДЕЙСТВИЕ: спросить`** — с 2.7 это **только** «неуверенная оценка при высокой цене ошибки»: сначала **один** короткий уточняющий вопрос пользователю (цель, границы, критерий готовности), потом работа. Вопросов о haiku, fable, effort low и max больше нет — они выбираются без подтверждения по строгим критериям (см. «Гарантии качества»). Если включено `TYPESAFE_TRIAGE_CONFIRM` (старое поведение) и заметка просит согласие — **один** `AskUserQuestion` на обе оси (тексты «Да, X» / «Нет, Y» — в заметке); нет «да» → ближайшее безопасное: haiku → sonnet, fable → opus, low → medium, max → xhigh.
4. **Явные указания пользователя в запросе** («на opus», «effort max», «ultrathink», «тщательно», «кратко», «используй субагента», «сделай сам», "use haiku", "think hard"…) — уже согласие и главнее индексов: повторно не спрашивай (в заметке — «Задано пользователем»). Отрицания учитываются. **Упоминание — не указание**: маркеры в кавычках, в `коде`, в пересказе и во вставленном отчёте не считаются.
5. Пункт «**Общее интерактивное состояние** (…)» (браузер пользователя, CDP, эмулятор/устройство, активный прогон в `TASKS.md`) — делегируй **только независимые части**: исполнитель не увидит твоих вкладок, входа и устройства. Пункт «**Долгое ожидание**» — запусти фоновый скрипт (Bash в фоне, Monitor) и проверяй его, а не держи субагента.
6. Субагентам ставь уровень и effort **не ниже рекомендованных** (оценка относится к запросу целиком).
7. Заметка «**ВАЖНО (TypeSafe)**» → в начале ответа одной-двумя строками передай пользователю её текст, дальше работай по заметке. Если там «в запросе найдены секреты … не отправлен», а также при строке «Безопасность: в запросе пользователя есть секреты» — не повторяй секреты в ответе и не записывай их в файлы, журналы, коммиты и issues; если это настоящие данные, посоветуй пользователю их сменить.
8. Строка «**TypeSafe-триаж пропущен: …**» → заметки нет: для реплик работай как обычно; при сбое уровень и effort выбирай сам (пользователь видит сообщение). **Нет ни заметки, ни строки:** на короткое продолжение — решение прежнее, действуй по последней заметке; на новую содержательную задачу — хук не работает: один раз выполни `--check` и одной строкой скажи пользователю «хук не активен — триаж вручную» и команду починки из вывода.

9. **Скилл вызван слэш-командой с текстом задачи** (`/typesafe-triage:typesafe-triage проверь …`) и заметки «ДЕЙСТВИЕ:» в контексте нет (старая версия хука): выполни `python3 $S/typesafe_triage.py "<текст задачи>"` и действуй по `action` из ответа, как по заметке. С 2.4.2 хук сам триажит такой вызов.

## Опции по результатам использования (2.6, выключены по умолчанию)

| Опция | Что делает |
|---|---|
| `TYPESAFE_TRIAGE_DELEGATE_DOWN=on` (или `"delegate_down": true` в `config.json`) | если нужен уровень **ниже** модели сессии, а работа рутинная и изолируемая (переводы, проверки по списку, правки в нескольких файлах), действие — `Agent(model=<рекомендация>)` вместо «сам» («sonnet достаточно — субагент дешевле»); не при дорогом контексте, общем состоянии, риске, ожидании, мелочи; haiku — только с согласия |
| `TYPESAFE_TRIAGE_ECONOMY=on` (`"economy": true`) | при сессии на opus/fable запрос без признаков риска, объёма и явных указаний не отправляется в TypeSafe («экономный режим»): экономит ≈ 1 с и доли цента на запрос; рисковые и крупные оцениваются как обычно; не работает вместе с делегированием вниз |

Понять, нужны ли они: `--report` (при ≥ 90 % решений «сам: не выше модели сессии» отчёт прямо рекомендует одно из двух либо `TYPESAFE_TRIAGE=off`). Недоступность TypeSafe из региона (HTTP 451) даёт отдельную часовую паузу без повторов (`references/guard.md`). Запрос, начатый с пути (`/Users/…/файл.md …`), больше не считается командой.

## Принудительный запуск из запроса (2.4.2)

Пользователь может сам потребовать триаж — хук тогда **не пропускает** запрос (короткая реплика, «болтовня», команда `/…` этого скилла, режим «реже») и всегда даёт заметку. Модель, effort и действие выбираются как обычно.

| Способ | Пример | Замечание |
|---|---|---|
| Слэш-вызов скилла | `/typesafe-triage:typesafe-triage проверь орфографию в docs` (у копии в `~/.claude/skills` — `/typesafe-triage …`) | аргументы — задача; без аргументов — «после метки нет текста задачи» |
| Метка в начале | `triage: …`, `триаж: …`, `!triage …`, `!триаж …` | только начало запроса; метка в оценку не идёт |
| Метка с уровнем | `triage:opus/high …`, `!triage haiku …`, `!триаж max …` | уровень = явное указание (согласие на haiku/fable/low/max); для `triage:` — вплотную к двоеточию (`triage: high quality` — обычный текст), для `!triage` — через пробел |
| Фраза в тексте | «сделай триаж», «с триажем», «через typesafe-triage», "run triage" | вне кавычек, `кода` и пересказа; «почини баг в typesafe-triage» — не просьба. Ложное срабатывание безвредно: просто будет заметка |

## Гарантии качества (не ослаблять)

- haiku, fable, low и max применяются **без вопроса, но только по строгим критериям**; при малейшем сомнении — ближайший безопасный уровень (haiku → sonnet, fable → opus, low → medium, max → xhigh). Старое поведение с вопросами — `TYPESAFE_TRIAGE_CONFIRM=on` (тогда в `--run` нужны `--confirmed` / `--confirmed-effort`). Источники и правила — `references/sources.md`, независимые замеры — `references/benchmarks.md`.
- **Opus 5.5 — модель по умолчанию для трудной работы** (2.8): по документации Anthropic на дефолтном effort он равен Fable 5.1 на большинстве задач за пятую часть цены; независимые замеры (Artificial Analysis, Snorkel, Arena) того же порядка. Риск и необратимость сами по себе Fable не дают — это opus на `high`/`xhigh`.
- **fable** — только (а) **долгий горизонт** (часы автономной работы, вся кодовая база, многодневное исследование) при нагрузке ≥ 0,85, сложности и рассуждении ≥ 0,85, уверенности ≥ 0,8, согласии текста, без повтора и без кибер/био-тем (эксплойты, вредоносы, пентест, патогены, токсины — Fable их перенаправляет на другие модели; аудит уязвимостей собственного кода разрешён); (б) **после неудачи opus на high+ с причиной «не знала»**. Effort Fable — `medium` по умолчанию, `high` для самого тяжёлого, **xhigh и max автоматически никогда** (на замерах `max` не лучше `xhigh`, а цена растёт). `--run` на Fable списывает usage credits без запроса — поэтому нужен `--confirmed` (`TYPESAFE_TRIAGE_FABLE_RUN=on` отключает).
- **max** — только **opus** с долгим горизонтом, критичностью (риск наверху или уверенная необратимость), глубиной ≥ 0,85 и уверенностью ≥ 0,85, либо после неудачи на `xhigh`; на sonnet/haiku/fable — никогда. **xhigh** — только при основании (высокий риск, долгий горизонт, широкий охват, много файлов/пунктов, повтор), иначе `high`. После смены модели по причине «не знала» effort сбрасывается к умолчанию модели (`medium`; `high` при риске) — а не копится.
- **haiku** — только уверенно простое чтение/механика (≥ 0,8) с риском ≤ 0,25, уверенностью ≥ 0,7 либо пустой верхней половиной шкал, коротким ТЗ (≤ 2 шагов, ≤ 700 знаков, без логов), без диагностики, повторов, слов риска (кроме чистого чтения при риске ≤ 0,15); после неудачи — не haiku; effort haiku — `medium`..`high` (low — только чистое чтение). **low** — только уверенно лёгкое (глубина TypeSafe ≤ 0,15, уверенность ≥ 0,7). Без ответа TypeSafe haiku и fable недоступны.
- **Причина неудачи**: «не знала» (выдумала, не поняла, не тот подход) → модель +1 (opus на high+ → fable), effort не копится; «не старалась» (пропустила файл, не запустила тесты, бросила) → effort глубже, модель прежняя. Точные правки и вопросы по коду сомнением TypeSafe на ступень не поднимаются.
- Согласованность осей: haiku не выше `high`; sonnet не выше `xhigh`; при высокой цене ошибки effort не ниже `high` при любой модели (Fable — `medium`..`high`); чисто механическая работа — не выше `medium` даже на opus; opus+low — только для объёмной механики.
- Вверх — легко, вниз — только при уверенных ответах. История сессии («опять не работает», повтор того же запроса) поднимает effort не больше чем на 2 ступени; `max` — только opus после `xhigh`. Обсуждение моделей и уровней («сравни эффективность effort max и xhigh», «применение модели Fable») — не указание.

Как считается модель — [references/levels.md](references/levels.md); effort — [references/effort.md](references/effort.md); действие — [references/action.md](references/action.md).

## Если ты субагент

Запущен через `Agent` или `--run` — этот скилл **не применять**: не запускать триаж, не делегировать «наверх», не менять уровень и effort. Если задача слишком сложна — скажи об этом в отчёте («нужен более сильный исполнитель / больше effort»). Строку `Co-Authored-By` в коммитах ставь **из своей системной инструкции атрибуции** (твоя фактическая модель), а не модель оркестратора из брифа. В агенте `--run` хук молчит сам (`TYPESAFE_TRIAGE_CHILD=1`), вложенный `--run` запрещён.

Кто решает, когда работа идёт по SuperPowers (процесс — SuperPowers, модель и effort — триаж), — [references/superpowers.md](references/superpowers.md).

## Вызов через Skill

Имя зависит от установки: **плагин** — `typesafe-triage:typesafe-triage`, **копия** в `~/.claude/skills` — `typesafe-triage`. Список скиллов Claude Code составляет при старте сессии: после установки, переноса или удаления копии в открытой сессии остаётся «призрак» (`Unknown skill`) до `/reload-plugins` или перезапуска. Пока так — запускай скрипт по пути (`--where`). `--check` печатает правильное имя и находит причины «призраков» (битая ссылка, резервная копия внутри `~/.claude/skills`, копия рядом с плагином).

## Запуск вручную

Скрипты — в `scripts/` рядом с этим файлом: `${CLAUDE_SKILL_DIR}/scripts` (Claude Code подставляет каталог скилла при загрузке; у плагина это `${CLAUDE_PLUGIN_ROOT}/scripts`, папка версии меняется при обновлении — не запоминай путь). Только стандартная библиотека Python; ключ — `TYPESAFE_API_KEY`.

```bash
S="${CLAUDE_SKILL_DIR}/scripts"
python3 $S/typesafe_triage.py --where                      # фактический путь скрипта, установка, хуки в settings.json, имя для Skill
python3 $S/typesafe_triage.py --check                      # ключ, сеть; хук зарегистрирован? (settings + плагины), имя для Skill, команды починки
#   код: 0 — всё в порядке; 1 — TypeSafe не ответил; 3 — TypeSafe ответил, но хук не зарегистрирован или сломан
python3 $S/typesafe_triage.py "текст задачи"               # JSON: модель, effort, действие (action), причины, метрики, сигналы
python3 $S/typesafe_triage.py --set-agent-effort yes|no|auto   # есть ли у инструмента Agent параметр effort
python3 $S/typesafe_triage.py --batch tasks.json [--json] [--prompts]   # пакет подзадач (ниже)
python3 $S/typesafe_triage.py --fact <id> --model opus --effort high --tokens 550000 --minutes 25 --outcome ok   # факт (ниже)
python3 $S/typesafe_triage.py --report [--days N] [--json]   # меняет ли триаж что-то на практике: решения, цена, задержка, вызовы Agent из стенограмм (локально)
python3 $S/typesafe_triage.py --verify [--remote]          # файлы скилла против SHA256SUMS (и против файла сумм тега на GitHub)
python3 $S/typesafe_triage.py --scan "текст"               # какие секреты найдёт проверка (виды и числа, значения не печатаются; код 3 — отправка заблокирована)
python3 $S/typesafe_triage.py --digest "текст"             # что именно уйдёт в TypeSafe (со строкой «активная задача», если она будет)
python3 $S/typesafe_triage.py --signals "текст"            # локальные сигналы (обе оси) и явные указания, без сети
python3 $S/typesafe_triage.py --status | --resume | --pause "причина" | --set-budget 5
python3 $S/typesafe_triage.py --run "текст задачи"         # триаж + отдельный агент `claude -p --model <m> --effort <e>`
#   --readonly | --edit | --allow "Bash(python3 -m pytest:*)"   права агента (без --edit в -p агент не может править файлы)
#   --tier haiku|sonnet|opus|fable   --confirmed          модель вручную; haiku/fable — только с --confirmed
#   --effort low|medium|high|xhigh|max   --confirmed-effort   effort вручную; low/max — только с --confirmed-effort
#   --budget USD   --dry-run (показать модель, effort и команду, ничего не запускать)
python3 $S/typesafe_triage.py --selftest [--heuristic]     # эталонные задачи: модель и effort против ожидаемого диапазона
python3 $S/typesafe_triage.py --calibrate [--heuristic] [--split train|holdout] [--cache файл] [--facts файл]
python3 -m pytest $S -q -p no:cacheprovider                # все офлайн-тесты
```

`--run` запускает **отдельный процесс** без истории диалога: весь контекст — в тексте задачи (через stdin). `--confirmed` / `--confirmed-effort` ставить **только** после явного согласия пользователя (явное указание в самом тексте задачи — тоже согласие).

## Пакет подзадач (оркестратор): `--batch`

Несколько подзадач (пакеты issues, шаги плана) — одним вызовом: `--batch tasks.json`, файл — список `{"id", "task", "paths": [...]}` (необязательно `goal`, `context`, `criteria`, `constraints`, `report`). Вывод: таблица `{id, model, effort, confidence, reasons}`; порядок запуска — задачи с **пересекающимися `paths`** (тот же файл, папка-родитель, маска) — «**выполнять последовательно**», остальные — параллельно, без `paths` — «не проверено»; текст **одного** `AskUserQuestion` на все подтверждения пакета (не больше четырёх вопросов: haiku, fable, effort low, effort max); готовые `Agent(description, model, effort, isolation="worktree", run_in_background, prompt)` для «да» и «нет»; промпты исполнителей по шаблону [references/executor-prompt.md](references/executor-prompt.md) (`--prompts`, в `--json` — всегда). Строка `Co-Authored-By` — у каждого исполнителя своя (его фактическая модель).

## Журнал проекта и факты (калибровка, опция)

`TYPESAFE_TRIAGE_PROJECT_LOG=on` (или путь) либо флаг `--project-log[=ПУТЬ]` у ручных команд и `--batch` — решения пишутся ещё и в `triage-log.jsonl` в корне проекта: id, хеш сессии, тип, модель, effort, уверенность, действие и «ожидаемый расход» (медиана прошлых фактов; без фактов — не придумывается). **Текста запроса там нет.** С включённым журналом в хвосте строки заметки — `id …`. После делегированной подзадачи запиши факт: `--fact <id> --model … --effort … --tokens … [--minutes …] --outcome ok|review|rework|escalated|fail [--review-issues N]` (токены и минуты — из уведомления о завершении агента). `--calibrate` сводит факты по (модель, effort) и показывает «недооценку по факту»; на код возврата это не влияет. По умолчанию журнал выключен; добавьте `triage-log.jsonl` в `.gitignore`, если не хотите его коммитить.

**Автозапись факта** (2.4, опция, выкл.): `TYPESAFE_TRIAGE_AUTO_FACT=on` вместе с журналом проекта — хук плагина (`PostToolUse` на `Agent`, `SubagentStop`) сам пишет модель, effort, токены, минуты и число вызовов инструментов делегированного агента (только числа из документированных полей хуков; тексты не читаются). Если заметка просит — добавь в `description` агента метку `triage:<id>`: так факт привязывается к решению и при параллельных агентах. Исход после проверки — по-прежнему `--fact <id> --outcome …` (дополняет автоматический факт). Подробно — [references/action.md](references/action.md) → «Автозапись факта».

## Квоты крайних случаев (2.9): Fable и effort max

Правила выбора говорят, *когда* задача подходит под Fable или `max`; квота ограничивает, *сколько раз* это происходит автоматически. Исчерпана — `fable → opus`, `max → xhigh`, в заметке строка «Квота крайних случаев исчерпана». Не молча и без вопросов.

- Считаются только **автоматические** выборы. Явная просьба пользователя («на fable», «effort max») не блокируется и в квоту не входит.
- По умолчанию: Fable 1 в сутки и 3 в неделю, `max` 2 и 6. `TYPESAFE_TRIAGE_FABLE_LIMIT` / `TYPESAFE_TRIAGE_MAX_LIMIT` (или `fable_limit` / `max_limit` в `config.json`): `1/3` (сутки/неделя), `2` (сутки, неделя = ×7), `0` — никогда автоматически, `off` — без ограничения.
- Повтор хука на тот же запрос (ручной хук + плагин) квоту второй раз не тратит. Состояние — `extremes.json` рядом с `state.json`, без текстов запросов.
- Выбранный крайний случай получает в заметке указание вести работу **этапами**: после каждого — короткий отчёт (готово, остаток, расход), без параллельных агентов на этом уровне. `--run` на fable или с `--effort max` всегда идёт с `--max-budget-usd` (по умолчанию $10, `TYPESAFE_TRIAGE_EXTREME_BUDGET_USD` или `--budget`).
- `--extremes` — квоты и расход за окна.

## Сбои, баланс и расходы

Защита `typesafe_guard.py`: нет средств / ключ не принят / доступ запрещён → **жёсткая пауза** до `--resume`; сбои сервиса → временная пауза 1 мин → 2 → 4 … → 1 ч (до паузы — один быстрый повтор при 5xx/529); локальный потолок расходов (по умолчанию $2 в месяц). Пользователь видит `systemMessage`, модель — «ВАЖНО (TypeSafe)». Пока пауза — обе оси по локальным сигналам. Хук **никогда не блокирует** запрос и не падает; любой отказ — строка «TypeSafe-триаж пропущен: <причина>». Подробности — [references/guard.md](references/guard.md).

## Приватность и выключатели

- В TypeSafe уходит только **дайджест текста запроса до 4500 знаков** (секреты и персональные данные маскируются — пароли на русском и английском, seed-фразы, ключи, токены, карты, e-mail, телефоны; запрос с приватным ключом, seed-фразой или номером карты не отправляется вовсе, политика — `TYPESAFE_TRIAGE_SECRETS=block|strict|mask`, проверка вручную — `--scan`); вопросы effort идут **в том же запросе**. Для короткого продолжения — ещё одна строка «активная задача» (первый открытый пункт `TASKS.md`, до 200 знаков); выключить — `TYPESAFE_TRIAGE_CONTEXT=off`. Окружение, история сессии и **сведения из стенограммы** (только модель, effort, версия Claude Code, был ли успешный `Agent` с `effort`, с 2.4 — счётчики вызовов инструментов по видам, накопленных фактов, реплик и токенов контекста; текст сообщений не читается) считаются **локально** и не отправляются; `TYPESAFE_TRIAGE_SESSION_MODEL=<модель>|unknown` — задать модель сессии самому или не определять.
- Выключить: пустой файл **`.typesafe-triage-off`** в каталоге проекта (или выше) либо **`TYPESAFE_TRIAGE=off`**. `--pause` отключает только TypeSafe.
- Журнал `~/.claude/typesafe-triage/log.jsonl` (0600): начало запроса с маскировкой, модель, effort, действие, причины, хеш сессии; пропуски, отказы и молчание «реже» — без текста (время, хеш, длина, причина).

Подробно — [references/privacy.md](references/privacy.md).

## Как подстраивать

Пороги и веса — константы вверху `typesafe_triage.py` (модель), `triage_effort.py` (effort), `triage_heuristics.py` (словари сигналов) и `triage_action.py` (действие: пороги «небольшая/большая задача», порядок правил). Любое изменение модели и effort — через `--calibrate --split train`, затем проверка на отложенной части `--split holdout`; «ниже ожидаемого» должно быть 0. Факты из журнала проекта — подсказка, где оценка занижена. Вопросы к TypeSafe — `SCORES`, `FLAGS`, `EFFORT_SCORES`, `EFFORT_FLAGS`: одна мысль на вопрос, уровни шкалы — ситуации с примерами; перед правкой перечитать https://docs.typesafe.ai.
