# TypeSafe-триаж задач разработки (глобальный)

Короткая оценка каждой задачи по разработке ПО через TypeSafe (модель Jev: типизированные ответы и вероятности, ~100 мс, копейки). Из ответов **код** (не модель) выводит совет: какого уровня модели достаточно — `haiku`, `sonnet` или `opus`. Работает во всех репозиториях и сессиях.

## Когда применять

- **Да:** написание и правка кода, отладка, рефакторинг, тесты, сборка, скрипты, работа с репозиторием и issue, планирование технических задач, вопросы «как устроен этот код».
- **Нет:** вопросы и разговоры вне разработки (погода, письма, рецепты, общие знания). Хук сам это определяет вопросом `software_dev` и молчит.
- Короткие реплики («да», «продолжай») и команды `/…` хук пропускает (меньше 40 символов).

## Что происходит автоматически

Глобальный хук `UserPromptSubmit` (в `~/.claude/settings.json`) вызывает `scripts/typesafe_triage.py --hook`. Если задача — разработка, к запросу добавляется заметка «TypeSafe-триаж: рекомендованная модель — …». Нет ключа, сети, ответа или это не разработка — хук молчит, модель не меняется.

## Как применять заметку

Основную сессию Claude Code переключить нельзя: нет ни поля в хуке, ни метода (проверено по документации); только `/model` руками. Поэтому «переключение» — это делегирование:

1. Рекомендация **не выше** твоей текущей модели (её видно из системного промпта) → ничего не делай.
2. Рекомендация **выше**, работа содержательная (анализ, проектирование, нетривиальная правка, поиск причины) → выполни её через инструмент `Agent` с `model=<рекомендация>` и **самодостаточным промптом** (цель, пути, ограничения проекта из CLAUDE.md, что вернуть). Результат прочитай и проверь сам.
3. Нужен диалог с пользователем, делегировать нельзя → одной строкой спроси через `AskUserQuestion`: продолжить на текущей модели или переключить `/model <рекомендация>`.
4. Мелкий вопрос, подтверждение, реплика → не делегируй и не напоминай.
5. Субагентам ставь уровень **не ниже рекомендованного**, а для содержательных подзадач — **не ниже твоей текущей модели**: рекомендация оценивает запрос целиком, а не каждую подзадачу, и не должна тихо понижать сложную часть работы.

## Гарантии качества (не ослаблять)

- **Fable** не рекомендуется и не запускается никогда (его включает только пользователь вручную). В скрипте это константа `TIERS` и тест.
- Совет не отменяет проверки: тесты, чтение результата субагента, проверка на данных; при сомнении — уровень выше.
- Вверх — легко, вниз — только при уверенных ответах и низком риске; низкая уверенность = шаг вверх (один раз). Haiku — только для чтения/механики с низким риском и уверенным «да» (≥ 0.8) на этих признаках. Правки правил данных и диагностика — не ниже sonnet уже при слабом признаке (≥ 0.4).
- Ошибка сети, ключа, таймаут = «рекомендации нет», а не «понизить».

## Запуск вручную

Скрипты лежат в `~/.claude/skills/typesafe-triage/scripts/` (только стандартная библиотека Python, ключ — `TYPESAFE_API_KEY` в окружении, у пользователя он в `~/.claude/settings.json` → `env`).

```bash
S=~/.claude/skills/typesafe-triage/scripts
python3 $S/typesafe_triage.py --check                      # диагностика: ключ, сеть, сертификаты
python3 $S/typesafe_triage.py --digest "текст"             # показать, что именно уйдёт в TypeSafe (или текст из stdin)
python3 $S/typesafe_triage.py --status                     # пауза (если есть), расходы за месяц, потолок
python3 $S/typesafe_triage.py --resume                     # снять паузу после пополнения баланса / исправления ключа
python3 $S/typesafe_triage.py --pause "причина"            # отключить TypeSafe вручную;  --set-budget 5  месячный потолок, USD
python3 $S/typesafe_triage.py "текст задачи"               # JSON: метрики, рекомендация, причины
python3 $S/typesafe_triage.py --run "текст задачи"         # триаж + отдельный агент `claude -p --model <уровень>`
#   --readonly  только читать/планировать (--permission-mode plan)
#   --edit      разрешить правку файлов в текущем каталоге (acceptEdits); БЕЗ --edit/--readonly агент в режиме -p не получает права
#               на запись и останавливается с просьбой о разрешении (проверено) — для задач с правками указывать --edit
#   --allow "Bash(python3 -m pytest:*)"  доп. разрешённые инструменты (можно несколько раз), например тесты и git
#   --tier haiku|sonnet|opus  вручную (fable отклоняется)   --budget USD  потолок расходов   --dry-run  показать команду и не запускать
python3 $S/typesafe_triage.py --selftest                   # прогон эталонных задач (triage_cases.json), нужна сеть
python3 -m pytest $S -q -p no:cacheprovider                # все офлайн-тесты (нужен pytest): политика, защита, сквозные на поддельном сервере
```

`--run` запускает **отдельный процесс** без истории диалога: весь контекст пишется в тексте задачи. Права вашего `defaultMode` в `-p` не наследуются. Задача идёт через stdin, рабочий каталог — текущий. Если рекомендации нет, берётся `sonnet`.

## Совместная работа с SuperPowers и субагентами (проверено опытом)

| Что | Факт |
|---|---|
| Хуки SuperPowers | только `SessionStart` (подставляет вводный скилл `using-superpowers`). Хука на запросы пользователя у него нет, общего состояния с нашим тоже: оба хука независимо добавляют контекст, прямого конфликта нет. |
| Хук триажа в субагентах (`Agent`, в т. ч. из SuperPowers) | **не срабатывает**: промпт субагента — не запрос пользователя (в журнале нет ни одного промпта субагентов; субагент заметки не видит). Никакого второго обращения в TypeSafe там нет. |
| Хук в дочернем `claude -p` (`--run`) | срабатывал бы (проверено), поэтому `--run` ставит в окружение агента `TYPESAFE_TRIAGE_CHILD=1`: хук там молчит, вложенный `--run` запрещён. Рекурсии и двойной оценки нет. |
| Скиллы в списке субагента | `typesafe-triage` и SuperPowers видны и субагентам — отсюда правило ниже. |

**Если ты субагент** (запущен через `Agent` или `--run`): этот скилл не применять — не запускать триаж, не делегировать «наверх», не менять уровень модели; модель выбрал тот, кто тебя запустил. Если задача кажется тебе слишком сложной для твоего уровня, скажи об этом в отчёте (статус «нужен более сильный исполнитель»), а не запускай другого агента.

**Чья модель главнее, когда работа идёт по SuperPowers.** У SuperPowers свой выбор модели по ролям (`subagent-driven-development` → *Model Selection*, `executing-plans`): «наименее мощная модель, которая справляется»; механические задачи — дешёвая, интеграция — стандартная, архитектура и итоговое ревью — самая сильная; **model указывать всегда явно**, пустое значение наследует модель сессии; ревьюерам и исполнителям по прозе — не ниже средней; в раундах исправлений 4–5 — на ступень выше застрявшего. Порядок приоритета:
1. Нельзя никогда (правило пользователя): **Fable** автоматически не выбирать. «Самая сильная доступная модель» у SuperPowers = **opus**.
2. Есть план SuperPowers → модели ролей берутся из его раздела Model Selection (он точнее: решает по каждой задаче). Совет триажа тут — вход для решения «делегировать ли всё» и страховка: если по совету триажа весь запрос тяжёлый (opus), роли «архитектура/итоговое ревью» не снижать.
3. Плана нет → правила триажа: уровень не ниже рекомендованного, для содержательных подзадач — не ниже текущей модели.
4. Общий для обоих набор защит качества: тесты, чтение результата субагента, проверка на данных; при сомнении — ступень выше.

## Сбои, баланс и расходы (защита `typesafe_guard.py`)

Баланс TypeSafe через API прочитать **нельзя** (эндпоинта нет, проверено), а документация не описывает ответ при нехватке средств. Поэтому защита опирается на то, что надёжно:

- **Нет средств / лимит / оплата** (HTTP 402; тело ответа со словами credit, balance, billing, payment, quota, insufficient…; 429 с признаками квоты), **ключ не принят** (401), **доступ запрещён** (403) → **жёсткая пауза**: запросы к TypeSafe прекращаются полностью, автоматических «проб» нет (чтобы не уйти в минус). Снять: исправить ситуацию на https://console.typesafe.ai и выполнить `--resume`. Пауза из-за ключа снимается сама, как только `TYPESAFE_API_KEY` изменится.
- **Сбои сервиса** (5xx, 529, лимит скорости 429, тайм-аут, нет сети) → временная пауза 5 мин → 10 → 20 … до 1 ч (или `Retry-After`, если он больше); после неё первый же запрос проверяет, ожил ли сервис. Пользователя предупреждают только при устойчивом сбое (3-й и 10-й подряд) и сообщают, когда сервис ожил.
- **Локальный потолок расходов** — предохранитель, а не баланс: входные токены из ответов API × публичная цена $0.042 за млн, по умолчанию **$2 в месяц** (`--set-budget USD`, 0 = без потолка); предупреждение на 80 %, на 100 % — пауза до следующего месяца или до `--resume` после увеличения потолка. Считает только запросы с этой машины.
- **Как узнаёт пользователь:** хук добавляет `systemMessage` (показывается в окне напрямую) и поручает мне сообщить об этом в начале ответа. Напоминание о жёсткой паузе — не чаще раза в 6 часов. Хук **никогда не блокирует** ваш запрос и не падает: при любой проблеме Claude Code работает как обычно, просто без совета.
- **Когда видишь заметку «ВАЖНО (TypeSafe)»:** в начале ответа одной-двумя строками передай пользователю её текст (что случилось и какая команда это исправит); дальше работай без совета по модели.
- Состояние и настройки: `~/.claude/typesafe-triage/` (`state.json`, `config.json`, `log.jsonl`; права 0600). `analyze_issues.py` (скилл `github-issue-structuring`) использует ту же защиту и при первой проблеме прекращает прогон.

## Выключатели и приватность

- **Размер.** Предел API — 64k токенов на запрос (иначе HTTP 400 `max_tokens_exceeded`; на практике ~20 тыс. знаков лога ≈ 14 тыс. токенов), а точность падает раньше от лишнего шума. Поэтому уходит не сам текст, а **дайджест до 4500 знаков**: короче 3000 — как есть; иначе большие вставки сжимаются (код в ```, серии из 20+ строк подряд, сплошные длинные строки без пробелов → начало и конец + пометка «пропущено N строк»), а сама просьба остаётся целиком; если всё ещё длинно — начало (55 %) и конец (45 %), середина заменяется пометкой. Сверхдлинный ввод (>100 тыс. знаков) сначала режется. Если сервис всё же ответил `max_tokens_exceeded` — один повтор с дайджестом до 1500 знаков; отказ по размеру не считается аварией (паузу хука не включает). Что именно уйдёт: `typesafe_triage.py --digest "текст"` (или текст из stdin). Агенту при `--run` задача передаётся целиком (потолок 400 тыс. знаков). Отдельного «предварительного запроса о применимости» нет сознательно: вопрос «это разработка?» (`software_dev`) идёт в том же запросе параллельно с остальными и не добавляет ни задержки, ни расхода.
- **В TypeSafe уходит каждый запрос от 40 символов** (классификация «это разработка?» тоже делается там), в том числе не про код; «молча пропускает» означает лишь отсутствие заметки, а не отсутствие отправки. Файлы проекта и данные не отправляются; строки, похожие на ключи, токены и пароли, заменяются на «[скрыто]». Для закрытых/рабочих репозиториев, где это недопустимо: положить пустой файл **`.typesafe-triage-off`** в каталог проекта (или выше) либо задать **`TYPESAFE_TRIAGE=off`**.
- Журнал решений (первые 200 символов с замаскированными секретами, метрики): `~/.claude/typesafe-triage/log.jsonl`, права 0600, только локально и только для задач разработки. По нему подстраиваются пороги.
- После сетевой ошибки хук на 5 минут перестаёт обращаться к TypeSafe (не тормозит работу); любая неожиданность в хуке = молчание.
- Сломался хук или нет ответа → `--check`. Типичная причина — у сборки Python нет корневых сертификатов; скрипт сам берёт системный пакет CA (проверка сертификата не отключается).

## Как подстраивать

Пороги — константы вверху скрипта (`LOAD_SONNET`, `LOAD_OPUS`, `CONF_*`, `WEIGHTS`). Любое изменение — через `--selftest` на `triage_cases.json` (добавляй туда реальные задачи с ожидаемым уровнем; важно, чтобы «ниже ожидаемого» и `DEVMISS` были 0). Вопросы к TypeSafe — словари `SCORES` и `FLAGS`: одна узкая мысль на вопрос, уровни шкалы — конкретные ситуации, не абстракции. Подробные правила формулировок — в живой документации https://docs.typesafe.ai (примитивы Choice / Noul / Score, confidence); перед правкой вопросов прочитать их, а не полагаться на память. Известные слабые места модели: арифметика, даты, длинный шумный вход, русский хуже английского — поэтому уверенность по русским задачам ниже, и это компенсируется шагом вверх.
