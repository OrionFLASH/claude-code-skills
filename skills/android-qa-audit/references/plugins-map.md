# Усилители: скилы, агенты, внешние инструменты

Реально доступные усилители определяет `check_env` (`env.json → enhancers` — скилы и агенты Claude Code; `env.json → optional` — внешние программы). **Используются только найденные.** Без них скил работает по собственным чек-листам — **собственный чек-лист выполняется всегда**, усилители только дополняют.

## Принципы
1. Скил-методику (SKILL.md усилителя) читает исполнитель и выполняет её шаги **сам**, через `adb_helpers.py` и под guard. Отчётные форматы усилителя не используются — выводы приводятся к `templates/finding.schema.json` (`sources: ["plugin:<имя>"]`).
2. Агент плагина запускается, только если ему можно передать блок правил (`safety-rules.md` §4) и он действует через наши скрипты. Иначе — не используется.
3. Дубли между выводом усилителя и своей проверкой сливает `fingerprint.py dedupe`.
4. Противоречия (усилитель: «ок», чек-лист: «дефект») — перепроверить на стенде; неясно — спросить.
5. В отчёте — таблица «усилитель, направления, вклад».

## Браузерные инструменты не нужны
Android-эмулятор и устройства управляются через adb: Playwright MCP, Claude in Chrome и `playwright-cli` для нативного приложения не используются. Исключение — **WebView-часть приложения** (экраны, которые рисует встроенный браузер):
- видна в `dump-ui` как дерево элементов WebView — обычно этого достаточно;
- если WebView отлаживаемый (debuggable-сборка или `setWebContentsDebuggingEnabled`), страницу можно открыть для чтения через Chrome DevTools: `adb forward tcp:9333 localabstract:webview_devtools_remote_<pid>` (выполняет пользователь или оркестратор после согласия) → `chrome://inspect`; только наблюдение (DOM, консоль, сеть), без действий в обход guard;
- веб-усилители (ниже, «только для WebView») применимы к таким экранам как методика.

## Таблица
| Направление | Усилитель | Как использовать | Что берём |
|-------------|-----------|------------------|-----------|
| ux, visual-ui | `ui-ux-pro-max` | прочитать SKILL.md, раздел про мобильные интерфейсы и UX-правила | критерии и обоснования находок |
| ux | `laws-of-ux`, `ux-heuristics` | справочники: законы UX (Фиттс, Хик, Миллер…), 10 эвристик Нильсена, шкала серьёзности | обоснования, оценка severity |
| ux, functional | `ux-audit` | методика «пройти как пользователь», персоны, доказательство взаимодействия; **браузерные шаги не выполнять** — заменить на `adb_helpers.py` | сценарии и вопросы к экранам |
| visual-ui | `ux-design-principles` | чек-листы визуального аудита | критерии визуальных дефектов |
| lifecycle-resilience, logic-state | `resilience-audit` (qa-skills) | категории: прерывания, двойные действия, тупики навигации, тайминги, офлайн; **без исходников** — только поведенческая часть | гипотезы для проверки на стенде |
| logic-state | `adversarial-audit` (qa-skills) | **только пассивно**: категории злоупотреблений бизнес-логикой как гипотезы для наблюдения; фазу активной проверки не запускать | гипотезы |
| functional (только WebView) | `mobile-workflow-generator` (qa-skills) | методика описания мобильных сценариев — как шаблон списка сценариев; генерацию Playwright-тестов не запускать | список сценариев |
| functional (только WebView) | `mobile-workflow-to-playwright` | не для нативного приложения; для WebView — только если пользователь отдельно просит веб-тесты (тогда это задача другого скила) | — |
| ux, visual-ui (только WebView) | агент `qa-skills:mobile-ux-auditor` | только для веб-части в браузере, по отдельной просьбе; нативные экраны — по своим чек-листам | мобильные UX-проверки веба |
| accessibility | агент `accessibility-auditor` (если есть) | только методика ARIA/WCAG для WebView; нативные — `checklists/accessibility.md` | — |
| accessibility | Accessibility Scanner (приложение Google на устройстве) | если пользователь сам установил на свой стенд — запустить вручную, результаты переписать в находки | подсказки по меткам, контрасту, целям |
| functional, logic-state | **Maestro** (`maestro`) | если установлен: сценарии YAML для повторяемых путей (`maestro test flow.yaml --device <serial>`); сценарий сначала пройти вручную под guard, в YAML — только проверенные безопасные шаги; запускать только на своём эмуляторе | повторяемые прогоны сценариев на всех ячейках |
| functional | **Appium** + драйвер uiautomator2 | если установлен: сложные жесты, ожидания, долгие сценарии на своём эмуляторе; те же условия, что для Maestro | — |
| — | python `uiautomator2` (openatx) | не нужен: скил использует `uiautomator dump` через adb; если есть — только чтение дерева | — |
| — | **scrcpy** | показать экран устройства пользователю (наблюдение, ручной вход) | — |
| — | **bundletool** | AAB → APK (`apk_info.py build-apks`), манифест AAB (`apk_info.py analyze app.aab`) | — |

Maestro, Appium и scrcpy действуют мимо guard: перед каждым их запуском — тот же список действий, что и для `adb_helpers.py` (никаких покупок, входа через внешние аккаунты, отправки сообщений); на реальных устройствах — только с согласием `full` и только наблюдение.

## Запрещено (не использовать никогда)
| Что | Почему |
|-----|--------|
| `qa-skills:adversarial-breaker`, `/run-qa adversarial` | активные атаки: инъекции, обход авторизации, удаления |
| `qa-skills:security-auditor` | смешивает пассивные и активные проверки без контроля |
| `perf-test` (opentest) и любые нагрузочные инструменты | нагрузочное тестирование сервера приложения |
| `security-scan`, сканеры уязвимостей, фаззеры интентов (drozer и т.п.) | активные атаки на компоненты приложения |
| `/run-qa` целиком | сам запускает агентов без правил скила |
| `submit-learnings` (qa-skills) | публикует issue в репозиторий плагина |
