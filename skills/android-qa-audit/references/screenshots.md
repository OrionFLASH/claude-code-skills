# Скриншоты с аннотациями

Каждая находка с визуальным проявлением получает **аннотированный скриншот**: сразу видно, где проблема и в чём она. Жирные красные рамки поверх интерфейса — неверный вид: они закрывают элемент и выглядят как ошибка оформления самого отчёта.

**Дефект виден во времени** (анимация, мерцание, зависание, реакция на жест, переход, потеря состояния, падение) — к скриншоту добавляется **короткий ролик без звука**: `adb_helpers.py clip … -- <шаги>`, те же отметки `--mark` и палитра, лента кадров для просмотра (`clips.md`). Скриншот остаётся всегда.

## Оформление (правила)
| Элемент | Как |
|---------|-----|
| Обводка | тонкий **пунктир** (~1,6 dp) с тёмной подложкой, скруглённые углы, отступ 4 dp от элемента |
| Стрелка | тонкая, с лёгким изгибом и маленьким наконечником — от подписи к рамке |
| Подпись | 1–2 строки, тёмная полупрозрачная плашка; значок вида: `✕` ошибка (`error`), `?` вопрос (`question`), `•` пояснение (`note`) |
| Цвет | автоматически из палитры **жёлтый `#FFD60A` / зелёный `#30D158` / фиолетовый `#BF5AF2`** — контрастнее фону вокруг элемента |
| Портретный снимок | подписи — в тёмном поле справа от снимка, интерфейс телефона не закрывается |

- **Не больше 3 отметок** на снимок; больше — разбить на несколько скриншотов.
- Подпись — **факт, а не оценка**, до ~60 символов: «Кнопка «Опустить» закрыта значком «?»», «Шрифт 2.0: текст обрезан», «Задумано? Нет светлой темы».
- Обводить то, что нужно увидеть; «элемент отсутствует» — обвести место, где он ожидался (`question` или `note`).
- Персональные данные — замаскировать **до** аннотации (`safety-rules.md` §5).

## Как снять
Координаты — **в пикселях снимка**, как границы в `dump-ui` (`[x1,y1][x2,y2]` → `x,y,w,h`; `dump-ui --texts` печатает готовый `box=x,y,w,h`, `find --text …` — поле `box`). Масштаб в dp — `density / 160` (420 dpi → 2,625), его считает скрипт.

```bash
python3 <SKILL_DIR>/scripts/adb_helpers.py screenshot <RUN_DIR>/screenshots/F-003-font.png --mark "text=Сохранить|Шрифт 2.0: подпись обрезана|error" --mark "80,1440,920,120|Кнопка ниже края|question" --serial emulator-5554 --run-dir <RUN_DIR>
python3 <SKILL_DIR>/scripts/annotate_android.py render --in <RUN_DIR>/screenshots/F-003-font.png --mark "80,1440,920,120|Кнопка ниже края|question" --density 420
python3 <SKILL_DIR>/scripts/annotate_android.py box --ui <RUN_DIR>/raw/ui-20261009-101500.xml --text "Сохранить"
python3 <SKILL_DIR>/scripts/finding.py add <RUN_DIR> --title "Настройки: подпись «Сохранить» обрезана при шрифте 2.0" --severity medium --direction visual-ui --type visual --screen com.example.app.SettingsActivity --step "Открыть «Настройки»" --step "Размер шрифта: максимальный" --expected "Подпись видна полностью" --actual "Подпись обрезана до «Сохр…»" --shot <RUN_DIR>/screenshots/F-003-font.png --mark "text=Сохр…|Подпись обрезана|error" --ui <RUN_DIR>/raw/ui-20261009-101500.xml --serial emulator-5554
```
- Отметка: `x,y,w,h|подпись|вид` или `text=…|…`, `desc=…|…`, `id=…|…` (элемент из свежего дерева или `--ui`); `x,y,w,h|@avoid` — область, которую подпись не закрывает.
- Рядом с оригиналом `F-NNN-….png` появляются `F-NNN-….spec.json` (рамки, подписи — для перерисовки без повторного воспроизведения: поправить подпись в spec и `annotate_android.py render` заново) и `F-NNN-…-annotated.png`.
- **Автопроверка**: подпись целиком в кадре, не закрывает другие рамки и подписи, цвет контрастен фону, отметок ≤ 3 — нарушения в `warnings` (код 1).
- **Обязательно посмотреть результат** (Read изображения) до ссылки в находке и отметить: `finding.py viewed <RUN_DIR> --id F-NNN`. `finding.py list` показывает непросмотренные аннотации.

## Контактный лист
Много снимков (прогон soak, обход экранов, аннотации всех находок) удобнее смотреть листом: миниатюры с подписями (имя файла и размер), **по 8 снимков на картинку** — один Read вместо восьми. Идея — `shot.js sheet` скила site-qa-audit; здесь своя `scripts/node/sheet.js` под портретные снимки телефона.
```bash
python3 <SKILL_DIR>/scripts/annotate_android.py sheet --dir <RUN_DIR>/screenshots --glob "*-annotated.png" --out <RUN_DIR>/screenshots/annotated-sheet.png
python3 <SKILL_DIR>/scripts/annotate_android.py sheet --soak <RUN_DIR>/raw/soak-rec60-emulator-5558.json --out <RUN_DIR>/screenshots/soak-rec60-sheet.png
python3 <SKILL_DIR>/scripts/annotate_android.py sheet <RUN_DIR>/screenshots/a.png <RUN_DIR>/screenshots/b.png --out <RUN_DIR>/screenshots/ab.png --cols 2 --per 4 --thumb 320
```
- Источник снимков: список файлов, `--dir` с `--glob` (естественный порядок: `t5m` раньше `t10m`) или `--soak` — снимки из сводки прогона. Больше `--per` — несколько листов `…-1.png`, `…-2.png`.
- Рядом всегда пишется `<имя>.html` — сетка со ссылками на оригиналы для человека (только стандартная библиотека). PNG-лист рисует Chromium через Playwright, как аннотации; без Node.js или Playwright — код 4 «не поддерживается», HTML-лист есть, модели — смотреть снимки по одному. `--html-only` — только HTML.
- Лист — для обзора; подозрительный снимок открыть целиком, прежде чем делать вывод или ссылаться на него в находке.

## В находке и черновике
`finding.py add/shot` пишет `shots: [{original, annotated, spec, marks, viewed}]` и `screenshots: [<annotated>, <original>]` (аннотированный — первым). `render_draft.py` показывает только аннотированный вариант (по `shots` или по соседнему файлу `<имя>-annotated.png`), оригинал — нет; ссылки на картинки в репозитории — `repo-sync.md` → «Вложения веткой».

## Что нужно для рисования
Рисует `scripts/node/annotate.js` — вендорная копия `annotate.js` скила site-qa-audit (не править здесь; обновлять копированием), в Chromium через Playwright, локально; контактный лист — `scripts/node/sheet.js` (своя копия идеи, те же зависимости):
```bash
cd <SKILL_DIR>/scripts/node && npm install && npx playwright install chromium     # один раз, с согласия пользователя
python3 <SKILL_DIR>/scripts/annotate_android.py check
```
Другая папка модулей — `ANDROID_QA_NODE_MODULES`, свой node — `ANDROID_QA_NODE`. Без Node.js или Playwright: «не поддерживается: …» (код 4), оригинал и spec сохранены — нарисовать позже, когда пользователь поставит зависимости.
