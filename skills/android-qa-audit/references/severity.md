# Критерии severity

Severity — о влиянии на пользователя и бизнес, не о сложности исправления. Сомнение между двумя уровнями → нижний, в `hypothesis` — что может быть выше. `info` — заметка без дефекта (не публикуется как issue, если пользователь не попросил).

| Уровень | Определение | Примеры |
|---------|-------------|---------|
| **Critical** | Приложение не запускается или падает в основном сценарии у большинства; потеря или утечка данных; угроза безопасности, видимая пассивно | падение при запуске на целевой версии; падение при сохранении основной сущности; токен или пароль в logcat релизной сборки; данные других пользователей на экране; `debuggable=true` в релизной сборке из магазина |
| **High** | Ключевая функция сломана для заметной группы (версия Android, тип устройства, конфигурация) или работает неправильно; ANR в основном сценарии; блокирующая проблема доступности | падение только на API 26 или только на слабом телефоне; потеря введённых данных при повороте или смерти процесса; кнопка «Далее» за краем экрана при шрифте 1.3; без разрешения на уведомления (API 33+) приложение зависает; холодный запуск > 5 с на обычном телефоне; основная кнопка без метки для TalkBack |
| **Medium** | Функция работает, но с заметной ошибкой или неудобством; есть обходной путь; нарушение доступности, не блокирующее сценарий | обрезанный текст в тёмной теме; цель нажатия 36 dp; утечка Activities после поворотов; jank > 10 % кадров на главном списке; нет сообщения при отсутствии сети; повторный запрос разрешения сразу после отказа; cleartext HTTP для API |
| **Low** | Косметика, мелкие несогласованности, улучшения | разные отступы у однотипных карточек; опечатка; лишняя анимация; иконка без метки при понятном тексте рядом; `allowBackup` без правил |
| **Info** | Наблюдение, предложение, вопрос | идея функции; «ведёт в браузер — не проверялось»; экспортируемый компонент без явной проблемы |

## Повышающие и понижающие факторы
- +1 уровень: в основном сценарии или на первом экране; на всех версиях/ячейках; регрессия (`REGRESSION`); воспроизводится всегда (repro_rate N/N).
- −1 уровень: только на редкой конфигурации при наличии обходного пути (очень слабый телефон 1 ГБ, шрифт 2.0, складной в развёрнутом виде); только при граничном вводе; воспроизвелось один раз из нескольких (`frequency: once` — указать в `hypothesis`).
- Падения: при запуске или в основном сценарии → Critical; во второстепенном экране → High; только при monkey без понятного пути воспроизведения → Medium с seed и строкой повтора.
- ANR: основной сценарий → High; редкий экран → Medium.
- Производительность (Android vitals): холодный запуск > 5 с, тёплый > 2 с, горячий > 1,5 с → High на обычном телефоне, Medium на слабом; jank: > 25 % медленных кадров → High, 10–25 % → Medium.
- Доступность: нет метки у основной кнопки или невозможно пройти сценарий с TalkBack → High; цель < 48 dp, контраст < 4.5:1 → Medium; best practice → Low.
- Пассивная безопасность: секреты и персональные данные в журналах → Critical (релиз) / High (отладочная сборка); `debuggable` в релизе → High; cleartext → Medium; `allowBackup` без правил, экспорт без явного вреда → Low / Info.

Для чужого репозитория — привести к их шкале (метки `priority:*`, `P0–P3`): `run-config.yaml → repos[].severity_map` (`critical: P0`, `high: P1`, …); `render_draft.py` ставит метку репозитория в заголовок и поле Severity.
