# Ролики находок (короткие скринкасты без звука)

Скриншот не показывает то, что происходит **во времени**: анимацию и мерцание, зависание, реакцию на жест и нажатие, переход, потерю состояния, поворот, падение и ANR. Ролик на 3–10 секунд показывает, что происходило (или не происходило) в момент ошибки, а с `--kind after` — что после исправления всё работает. Ролик — **дополнение** к аннотированному скриншоту, не замена: скриншот у находки остаётся всегда.

Общее ядро — `scripts/shared/qa_clips.py` (сжатие под бюджет, GIF, постер, лента кадров, запись в находку; вендоренная копия, не править); запись на устройстве — `scripts/clip_android.py` через подкоманды `adb_helpers.py`.

## Когда нужен ролик
| Режим (`clips.mode` в run-config, вопрос 7a опроса) | Когда записывать |
|---|---|
| `auto` (по умолчанию, Recommended) | дефект виден только во времени: анимация, мерцание, зависание, лаг, жест, долгое нажатие, переход, прокрутка, поворот, потеря состояния, клавиатура, тост, падение, ANR, гонка (`qa_clips.should_record(<описание>)`); направления `performance` и `lifecycle-resilience` — обычно да |
| `on` | для каждой находки, где это недорого (шаги воспроизводятся за секунды) |
| `off` | роликов нет |

Статичное — контраст, обрезка текста, перекрытие, размер шрифта, опечатка, перевод — **только скриншот**. Фразы запроса: «с видео», «запиши ролики» → `on`; «без видео», «без роликов» → `off` (`intake.py from-text`).

## Команды
```bash
python3 <SKILL_DIR>/scripts/adb_helpers.py clip-start --name F-003-menu --seconds 10 --serial emulator-5554 --run-dir <RUN_DIR>
python3 <SKILL_DIR>/scripts/adb_helpers.py tap --text "Меню" --serial emulator-5554 --run-dir <RUN_DIR>
python3 <SKILL_DIR>/scripts/adb_helpers.py clip-stop --finding F-003 --caption "Меню закрывается через 0,4 с" --kind error --mark "0,220,1080,900|Меню|error" --serial emulator-5554 --run-dir <RUN_DIR>
python3 <SKILL_DIR>/scripts/adb_helpers.py clip --name F-003-menu --seconds 8 --finding F-003 --caption "Меню закрывается само" --serial emulator-5554 --run-dir <RUN_DIR> -- tap --text "Меню" --expect-change --then wait 1 --then key BACK
python3 <SKILL_DIR>/scripts/adb_helpers.py clip --name F-003-menu --dry-run --serial emulator-5554 --run-dir <RUN_DIR> -- tap --text "Меню" --then wait 1
python3 <SKILL_DIR>/scripts/adb_helpers.py clip-stop --restore-only --serial emulator-5554 --run-dir <RUN_DIR>
python3 <SKILL_DIR>/scripts/finding.py clip-viewed <RUN_DIR> --id F-003 --file clips/F-003-menu.mp4
```
- **`clip-start`** — `adb shell screenrecord --time-limit N --size WxH --bit-rate B /sdcard/qa-clip-<name>.mp4` фоновым процессом хоста (adb держит запись, команда сразу возвращает управление). Размер — текущий экран с учётом поворота (`display_info`), короткая сторона `--size` (по умолчанию `clips.width` = 720), кратно 16. `--seconds` — страховочный лимит (по умолчанию `clips.max_seconds` = 10; screenrecord — до 180 с; обычно хватает 3–10 с). Состояние — `<RUN_DIR>/raw/clip-<serial>.json` (PID, пути, прежние `show_touches` / `pointer_location`, время старта). Запись уже идёт на этом стенде → код 2; осталось состояние прерванной записи → оно убирается (запись останавливается, файл с устройства удаляется, настройки возвращаются) и запись начинается заново.
- **`clip-stop`** — SIGINT процессу screenrecord на устройстве (`kill -2 <pid>`, PID — по `ps -A -o PID,ARGS` с именем своего файла; screenrecord дописывает moov и выходит), `adb pull` в `recordings/`, удаление с устройства, **возврат `show_touches`** (в `finally`: и при ошибке, и при прерывании), проверка «чёрного экрана», метки и подпись, сжатие `qa_clips.finalize` → `clips/<name>.mp4` (+ `.gif`, `-poster.png`, `-sheet.png`), запись в находку (`--finding`). `--step "…"` — шаги для записи в находке. Без `--finding` ролик остаётся в `clips/` — потом `finding.py clip`.
- **`clip … -- <шаг> --then <шаг> …`** — то же одной командой: старт → пауза `--lead` (0,5 с) → шаги → пауза `--tail` (1 с) → стоп. Каждый шаг — подкоманда `adb_helpers.py` с её опциями, выполняется **той же функцией с теми же проверками guard**, что и отдельная команда: нажатия, жесты, ввод, клавиши, `launch`, `rotate`, `dark-mode`, `font-scale`, `network`, `deeplink`, `screenshot`… и `wait S` (пауза). Шаги разбираются **до** начала записи (`--dry-run` — только разобрать). Шаг с запретом guard (код 3, `logs/blocked.jsonl`), с нужным подтверждением (код 2) или без guard (код 6) **не выполняется**, цепочка обрывается, запись останавливается, настройки возвращаются, ролик в находку не пишется. Шаг с кодом 4/5 (например, `--expect-change` не дождался изменения — это может быть сам дефект) записывается в `steps` и цепочка продолжается. `--confirm-steps` — выполнить шаги, требующие подтверждения, только после «да» пользователя на эти действия. Нельзя: `text --env` (секреты под запись), шторка уведомлений реального устройства.
- **`clip-stop --restore-only`** — без ролика: остановить запись, если идёт, удалить временный файл, вернуть настройки.

Код выхода: 0 — готово; 2 — неверный вызов, запись уже идёт, нужно подтверждение; 3 — запрет guard; 4 — не поддерживается на стенде; 5 — ошибка (в т.ч. «чёрный экран» без `--force`, ролик не финализирован); 6 — guard недоступен (стоп).

## Бюджет и формат
- Без звука всегда (`-an`), H.264 `yuv420p`, `faststart`; по умолчанию ≤ 10 с и ≤ 3 МБ, 720 px, 12 кадров/с, CRF 30; не влезло — лестница: CRF, ширина и кадры снижаются шагами. 5 с экрана телефона ≈ 0,2–0,6 МБ. GIF — если ролик ≤ 6 с и GIF ≤ 1,5 МБ (для вставки в issue).
- Ключи `clips:` в run-config (`templates/run-config.example.yaml`): `mode`, `max_seconds`, `max_mb`, `width`, `fps`, `format` (mp4 | gif | both), `gif_max_seconds`, `gif_max_mb`, `caption`, `touches`, `keep_raw` (оставить исходник в `recordings/`).
- Файлы: `clips/F-003-menu.mp4`, `.gif`, `-poster.png` (кадр из середины), `-sheet.png` (лента из 8 кадров). Одноимённый ролик не перезаписывается: `F-003-menu-2.mp4`.

## Метки и подпись в кадре
`--mark "x,y,w,h|подпись|вид"` — координаты **в пикселях экрана**, как у скриншотов (`dump-ui --texts` → `box=x,y,w,h`), или `text=…|…` / `desc=…|…` / `id=…|…` (элемент из дерева в конце записи); вид `error` (жёлтый `#FFD60A`), `question` / `note` (фиолетовый `#BF5AF2`), `ok` (зелёный `#30D158`); не больше 3 меток. Рамка — фильтр `drawbox` поверх кадров (тонкая, с тёмной подложкой; пунктира у `drawbox` нет). Подпись — короткий факт, как у скриншота: фильтр `drawtext`, если он есть в ffmpeg; иначе плашка PNG от Chromium (`scripts/node/plaque.js`, тот же Playwright, что у аннотаций) и фильтр `overlay` (freetype не нужен); нет ни того, ни другого — подпись **только в записи находки** (`clips[].caption`, предупреждение в выводе). Подпись в находке есть всегда.

## Проверка глазами — обязательна
Модель видео не смотрит: после записи открыть **ленту кадров** `clips/<name>-sheet.png` (Read) и убедиться, что на ролике то, что заявлено в находке, — потом `finding.py clip-viewed <RUN_DIR> --id F-NNN [--file clips/….mp4]` (или `finding.py viewed … --clips` вместе со скриншотами). Непросмотренный ролик в черновик issue и публикацию **не попадает** (`render_draft.py` выводит его в «Проверить», `validate_findings.py --publish` — ошибка). Без ffmpeg ленты нет: команда `clip` снимает скриншот после каждого шага (`clips/<name>-step-N.png`, поле `frames`) — их и смотреть.

## Показ касаний
`--touches auto` (по умолчанию, `clips.touches`): на эмуляторе этого прогона — `settings put system show_touches 1` (белые точки касаний в кадре); на реальном устройстве и чужом эмуляторе — нет. `--touches on` — явно (на устройстве guard спросит согласие, если оно не `full`), `off` — никогда. Прежнее значение сохраняется в состоянии и **возвращается всегда**: в `finally` у `clip-stop` / `clip`, при отказе старта, `clip-stop --restore-only`, при следующем `clip-start` / `clip-rolling start` (осиротевшее состояние) и при уборке (`avd_manager.py cleanup` первым шагом). Guard недоступен в момент возврата — настройка не трогается (fail closed), состояние остаётся с `pending_restore`, возврат повторяется командой `clip-stop --restore-only`.

## Непрерывная запись для падений (`clip-rolling`)
```bash
python3 <SKILL_DIR>/scripts/adb_helpers.py clip-rolling start --segment 8 --keep 3 --serial emulator-5554 --run-dir <RUN_DIR>
python3 <SKILL_DIR>/scripts/adb_helpers.py clip-rolling status --serial emulator-5554 --run-dir <RUN_DIR>
python3 <SKILL_DIR>/scripts/adb_helpers.py clip-rolling save --name F-007-crash --finding F-007 --last 10 --caption "Падение при повороте" --serial emulator-5554 --run-dir <RUN_DIR>
python3 <SKILL_DIR>/scripts/adb_helpers.py clip-rolling stop --serial emulator-5554 --run-dir <RUN_DIR>
```
- `start` запускает фоновый процесс хоста: сегменты screenrecord по `--segment` секунд один за другим (следующий стартует **до** скачивания предыдущего — пауза между сегментами минимальна), готовые сегменты — в `<RUN_DIR>/raw/rolling-<serial>/seg-N.mp4`, хранятся последние `--keep`, с устройства удаляются сразу. Состояние — `raw/rolling-<serial>.json` (PID фонового процесса, сегменты, «пульс»).
- `save` просит фон дописать текущий сегмент (там самый момент сбоя), склеивает последние сегменты (`ffmpeg concat`; без ffmpeg — только последний сегмент) и берёт последние ≈ `--last` секунд (не больше `clips.max_seconds`), дальше — как обычный ролик (чёрный экран, метки, бюджет, находка).
- `stop` останавливает фон (файл-запрос, затем SIGTERM; не ответил за 20 с — снимается), удаляет сегмент с устройства и локальные сегменты (`--keep-segments` — оставить), возвращает `show_touches`.
- **Обрыв связи и повтор**: фон ждёт возвращения устройства до ~60 с, потом статус `lost`; сегменты ограничены `--time-limit`, поэтому осиротевшая запись на устройстве сама заканчивается через ≤ `--segment` секунд. Повторный `start` при живом фоне — код 2; при мёртвом (PID нет или «пульс» старше `3 × segment + 60` с) — состояние убирается (последний сегмент с устройства, настройки) и запись начинается заново. Пока идёт `clip-rolling`, `clip-start` на этом стенде не запускается (и наоборот).
- **soak**: `adb_helpers.py soak … --clips-on-crash [--clips-segment 8] [--clips-last 10]` — непрерывная запись на весь прогон; процесс приложения проверяется каждые ~2 с, диалог «не отвечает» — каждые ~6 с; смерть, перезапуск процесса или ANR → `save` сразу (ролик `clips/soak-<tag>-<событие>-<мин>m.mp4`, в сводке `clips[]` и `events[].clip`); в конце — `stop` (`long-runs.md`).

## FLAG_SECURE и чёрный экран
Окна с `FLAG_SECURE` (банки, пароли, DRM-видео) screenrecord пишет чёрными. Доля почти чёрных кадров > 0,8 → «**чёрный экран: защищённое окно (FLAG_SECURE) или пустой кадр — ролик невозможен/бесполезен**», код 5, ролик в находку **не пишется**; `--force` — записать всё равно (с предупреждением). Это защита приложения, не дефект; в находке — скриншот и текст.

## Безопасность
Правила скриншотов плюс специфика видео (`safety-rules.md` → «Ролики»): не записывать ввод логинов, паролей, кодов, платёжных данных и вход в аккаунт — запись начинается **после** входа или на гостевом экране; `text --env` в шагах `clip` запрещён; личные уведомления — не в кадр (на реальном устройстве шторку под запись не открывать, уведомления очистить заранее, лучше — эмулятор с чистым профилем и тестовой учёткой). Звук не пишется никогда. Ролики **не коммитятся** в репозиторий пользователя: `<RUN_DIR>/.gitignore` (`clips/`, `recordings/`, `raw/rolling-*/`) пишется автоматически — даже при разрешении коммитить результаты. Публикация роликов (ветка вложений, issue) — только по тем же согласиям, что публикация скриншотов: ролик публично виден.

## Где появляется
| Где | Что |
|---|---|
| `findings.json` | `clips[]` (`file`, `gif`, `poster`, `sheet`, `kind`, `seconds`, `bytes`, `audio: false`, `caption`, `steps`, `sha256`, `viewed`, `marks`, `warning`…), путь дублируется в `recordings` |
| `finding.py` | `clip <RUN_DIR> --id F-003 --file clips/x.mp4 [--kind … --caption …]` (файл вне `clips/` сначала сжимается), `add … --clip …`, `clip-viewed`, `viewed --clips`, `list` — непросмотренные ролики |
| `validate_findings.py` | файл, размер и длительность по бюджету, звук (ошибка), sha256, GIF, просмотр (предупреждение; с `--publish` — ошибка) |
| `build_report.py report` | раздел «Ролики находок»: находка, вид, длительность, размер, просмотрен, подпись, ссылка (и ролики soak) |
| `render_draft.py` | только просмотренные: GIF inline + `[▶ ролик, 6 с, 0,4 МБ]` → mp4 (веткой — ссылка `blob/…?raw=true`) |
| `attachments.py` | ролики (mp4 и GIF) просмотренных находок едут в ветку вместе со скриншотами; `--no-clips` — без них |
| `export_results.py` | `--clips referenced` (по умолчанию) / `all` / `none` → `<dest>/clips/` |
| `avd_manager.py cleanup` | первым шагом — незавершённые записи (возврат настроек); `--delete-recordings` — `recordings/`, `raw/rolling-*/` и файлы `clips/`, на которые не ссылаются находки и soak |

## Ограничения Android и troubleshooting
| Симптом | Причина и что делать |
|---|---|
| код 4 «не поддерживается: screenrecord есть с API 19» | Android < 4.4 — скриншоты по шагам |
| код 4 «нет /system/bin/screenrecord» | урезанная прошивка, Android TV/Wear — скриншоты по шагам |
| код 4 «screenrecord не запустился … codec» | у эмулятора нет аппаратного кодека H.264: запустить с `-gpu host` (или `swiftshader_indirect`), уменьшить `--size` / `--bit-rate`; на устройстве — другой размер |
| «ролик не финализирован (нет moov)» | запись оборвалась без SIGINT (отключили кабель, упал adb) — повторить |
| «adb pull … failed to stat» | устройство отключилось или screenrecord не стартовал — `clip-stop --restore-only`, повторить |
| ролик короче шагов | шаги дольше `--seconds`: увеличить лимит (до 60) или сократить шаги |
| касаний не видно | `--touches on`; на устройстве — согласие пользователя; на некоторых прошивках точки не попадают в запись |
| поворот во время записи | старые версии screenrecord не поворачивают кадр — начать запись уже в нужной ориентации |
| `show_touches` остался включённым | `clip-stop --restore-only` (или `clip-rolling stop`); то же делает уборка |
| подписи нет в кадре | в ffmpeg нет `drawtext` и нет Chromium (`annotate_android.py check`) — подпись в находке; поставить ffmpeg с freetype или Node + Playwright (`INSTALL.md`) |
| нет GIF, постера, ленты | нет ffmpeg: `check_env` → «ffmpeg (ролики находок)»; установка — только с согласия (`INSTALL.md`) |

## Влияние на прогон
- **Время:** +10–25 с на ролик (запись 3–10 с, `pull`, сжатие, GIF, лента). `clip-rolling` — фоновый процесс и `pull` каждые `--segment` секунд (≈ 1–2 МБ на сегмент); замеры скорости с непрерывной записью не делать.
- **Место:** до ~3 МБ на ролик, 10–30 роликов ≈ 10–40 МБ в `clips/`; исходники удаляются (`keep_raw: false`), сегменты — при `stop`.
- **Токены:** лента кадров — одна картинка на ролик.
- **Устройство:** временные `/sdcard/qa-clip-*.mp4` и `/sdcard/qa-roll-*.mp4` удаляются после скачивания; меняется только `show_touches` (и возвращается).
