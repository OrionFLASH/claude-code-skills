# Опрос на входе

Цель — полный `run-config.yaml` (схема: `templates/run-config.example.yaml`) и согласие пользователя на план.

## Подтверждение намерения
Нужно, только если скил подхвачен **по смыслу запроса**, а не вызван явно. Явный вызов — команда `/android-qa-audit` (в ходе есть `<command-name>/android-qa-audit</command-name>`): подтверждение пропускается.

Первое действие скила — до `check_env`, создания папок и любых команд adb — один `AskUserQuestion`:
- вопрос: «Похоже, вы хотите протестировать Android-приложение <объект>. Запустить?»; в тексте пересказать понятое из запроса: файл (`app-release.apk`) или пакет, версии Android, устройства, направления, запреты — **только названное**, без догадок;
- варианты: «Да (Recommended)» / «Да, но сначала уточнить» / «Нет, это другое».

| Ответ | Что дальше |
|-------|------------|
| «Да» | обычный порядок работы; понятое из запроса не переспрашивать |
| «Да, но сначала уточнить» | опрос ниже с вопроса 1 «Что за приложение и для чего» |
| «Нет, это другое» | скил прекращает работу: **ничего не создавать** (ни `qa-runs/`, ни файлов, ни `check_env --json`), не вызывать adb и эмулятор; ответить на исходный запрос как обычно |
| нет ответа / непонятно | не начинать; один уточняющий вопрос |

Пример: «Похоже, вы хотите протестировать Android-приложение из `~/Downloads/app-release.apk` на Android 10 и 14 и на слабом телефоне, ничего не покупая. Запустить?»

Когда скил **не** подходит (и вопрос не нужен): разработка приложения, правка кода, написание тестов Espresso/UI Automator/Appium, сборка APK, сайт или веб-приложение в браузере (это `site-qa-audit`), нагрузочное тестирование и пентест.

## Правила опроса
- Инструмент `AskUserQuestion`, **по 1–3 вопроса за раз**, рекомендуемый вариант — первым с пометкой «(Recommended)». До 4 вариантов на вопрос и до 4 вопросов за вызов; длинные списки — несколькими вопросами в одном вызове по смысловым группам. «Свой вариант» — встроенный свободный ввод инструмента, отдельной кнопкой не добавлять.
- **Уже переданное в запросе не переспрашивать.** Сначала разобрать запрос: `scripts/intake.py from-text` (ниже) — путь к APK, пакет, версии Android, железо, вариации, направления, глубина, запреты, потоки, репозитории.
- Ответ «по умолчанию» / «как обычно» → значения по умолчанию из таблицы.
- Рекомендации — из фактов: версии Android — из `apk-info.json` (minSdk, targetSdk) и установленных образов; потоки — из `env.json → recommended_max_workers`; железо — из «для кого приложение».
- Секреты не спрашивать в чате: только **имена** переменных окружения. Если пользователь вставил пароль или токен — не повторять, предложить вынести в переменную.
- Порядок порций (что уже есть в запросе — пропустить): ① приложение: что это и для чего, откуда узнать → ② что тестируем, что успех → ③ версии Android, железо и настройки → ④ виды тестов, направления, глубина → ⑤ стенды, реальные устройства → ⑥ запреты → ⑦ потоки, репозитории и issues, куда записать итоги, режим.

## Папка прогона
`<RUN_DIR>` = `<OUTPUT_ROOT>/qa-runs/<YYYY-MM-DD>-<package>/`. Если за сегодня папка есть — суффикс `-2`, `-3`. Пока пакет неизвестен (APK ещё не разобран) — `apk_info.py` выводит JSON в stdout, файлы пишутся после выбора папки.

`<OUTPUT_ROOT>` (первое подходящее):
1. Путь, явно названный в запросе («сохрани в …») → без вопроса.
2. `output_dir` из повторяемого `run-config.yaml`.
3. Переменная окружения **`ANDROID_QA_OUTPUT_DIR`** (задаётся один раз, например в `env` файла `~/.claude/settings.json`; `INSTALL.md`) → без вопроса, путь показывается в сводке.
4. Иначе — **`<cwd>`**: результаты в `<cwd>/qa-runs/` (без вопроса; `.gitignore` — ниже). Если `<cwd>` — домашняя папка или репозиторий скилов, писать туда нельзя: **вопрос** «Куда сохранять результаты?» («Указать путь» / «Отмена»; подсказка — `ANDROID_QA_OUTPUT_DIR`).

APK и AAB копируются в `<RUN_DIR>/apk/` с `SHA256SUMS` (`apk_info.py --copy-to`), исходный файл не трогается. Никогда не писать результаты и APK в репозиторий скилов.

### Результаты и git — сразу, до создания `<RUN_DIR>`
**Правило: если пользователь в запросе явно не разрешил класть результаты в репозиторий, папка результатов обязана быть в `.gitignore`.** Вопроса «Добавить в .gitignore?» нет.
1. `git.allow_commit_results` — `true` только при явном разрешении в запросе или ответе: «положи результаты в репозиторий», «коммить результаты», «хочу коммитить qa-runs», «не добавляй qa-runs в .gitignore»; "commit the results", "keep the results in git". `intake.py from-text` распознаёт такие фразы (RU/EN) и ставит `true`; отрицание («не коммить результаты») и всё остальное — `false`. Сомнение — `false`.
2. `git.allow_commit_apk` — отдельное явное «да» на сборки и ключи («коммить APK», "commit the APK"); по умолчанию `false`: `*.apk`, `*.aab`, `*.apks`, `*.xapk`, `*.keystore`, `*.jks` игнорируются даже при `allow_commit_results: true`.
3. Как только известен `<OUTPUT_ROOT>` и **до создания `<RUN_DIR>`** (до `--copy-to`, `run-config.yaml`, журнала): `gitignore_helper.py ensure <OUTPUT_ROOT> [--allow-commit-results] [--allow-commit-apk]` (или `--text "<запрос>"` / `--config <прошлый run-config>` при повторе). `<OUTPUT_ROOT>` вне git — ничего; в git — нужные строки в `.gitignore` корня репозитория (`/<путь>/qa-runs/` и маски сборок), идемпотентно; разрешённое не трогается.
4. Код 1 — файлы `qa-runs/` уже в индексе git: `.gitignore` их не уберёт, скрипт их не удаляет. **Один** вопрос: «Убрать результаты из индекса git: `git rm -r --cached <путь>` (файлы останутся на диске)?» — «Да (Recommended)» → `gitignore_helper.py untrack <OUTPUT_ROOT> --yes` / «Нет, оставить». Коммит изменения — решение пользователя. Код 3 — строку перекрывает правило с «!»: показать `git check-ignore -v`.
5. В сводке перед «старт» — строка «git: qa-runs/ и сборки в .gitignore (<файл>)» или «git: разрешено коммитить результаты — .gitignore не менялся».

Папка из `report_destinations: folder` — другое место для **итоговых** файлов (возможно, внутри другого репозитория): туда копируются только `summary.md`, `report.md`, `findings.json` и скриншоты находок (`export_results.py`, `run-files.md`), а не папка прогона; `.gitignore` там не трогается.

**Повтор прогона:** если в `<OUTPUT_ROOT>/qa-runs/` есть прошлые `run-config.yaml` для того же пакета — первым вопросом: «Повторить конфиг от <дата>» / «Повторить, но изменить…» / «Новый опрос».

## Память о приложении
Как только известен пакет (после `apk_info.py`), — файл `<OUTPUT_ROOT>/qa-runs/.app-context/<package>/context.md` (формат — `templates/app-context.md`, правила хранения — `run-files.md`).
- **Есть**: прочитать, показать резюме в 3–6 строк (назначение, роли, основные сценарии, версия и дата изучения, источники) и спросить вместе с «Повтором прогона» (если он есть): «Использовать как есть (Recommended)» / «Обновить» / «Изучить заново» → `context.reuse: as-is | update | relearn`.
  - `as-is` — вопросы 1–1b не задавать (только уточнить цель этого прогона); контекст учитывать в плане и передавать исполнителям;
  - `update` — вопрос 1a с прошлыми источниками из `sources.json`; изучать только новое (новая версия APK, новые экраны);
  - `relearn` — полный опрос; прошлая версия сохраняется рядом как `context.prev.md`.
- **Нет**: `context.reuse: new`, вопросы 1–1b.

### 13. Репозиторий (на каждый)
1. `owner/repo` или URL. Сразу проверить доступ: `gh repo view owner/repo --json name,hasIssuesEnabled,viewerPermission` (только чтение).
2. Роли: `check` — только сверка; `write-new` — черновики/issues новых находок; `copies` — подробные копии всех находок своим шаблоном; `comment` — комментарии к существующим issues (недоработка, регрессия).
3. Шаблон: «Подробный шаблон скила `templates/issue-detailed.md` (Recommended)» / «Их шаблон из `.github/ISSUE_TEMPLATE/`» (прочитать через `gh api repos/owner/repo/contents/.github/ISSUE_TEMPLATE`).
4. Подробно / кратко; метки: только существующие / можно создавать / строкой в теле / без меток; дополнительные метки (`extra_labels`).
5. Подтверждение перед публикацией: включено всегда, пока пользователь явно не скажет иначе для своего репозитория.
6. Вложения: «Не прикладывать, ссылаться на локальную папку (Recommended)» / «Коммитить скриншоты и видео в репозиторий (нужен push)» → `attachments: none | commit`; logcat — выдержкой в теле, всегда замаскированный.
7. Раскрытие: «Подпись и маркер скила» / «Без упоминания скила и Claude» → `disclosure`, `marker`; шкала серьёзности репозитория → `severity_map`.
Режим по умолчанию — **dry-run**: только черновики в `drafts/`. Во внешние сервисы — ничего без явного «да» на сводную таблицу.

### 10. Какие действия делать нельзя: чек-лист (мультивыбор)
Базовые запреты (`safety-rules.md` §1) действуют всегда. Пункты ниже их уточняют текстами кнопок приложения или ужесточают; отмеченное → правила `rules` на подтверждение (таблица «пункт → правило»).

| Группа | Пункт | Правило |
|--------|-------|---------|
| Деньги и аккаунт | Покупки, подписки, оплата | уже базовый `purchase`; добавить тексты кнопок приложения с разведки («Оформить Premium», «Купить за …») |
| | Регистрация новых аккаунтов | `forbidden_actions: {texts: [Зарегистрироваться, Создать аккаунт, Sign up, Register]}` |
| | Выход из аккаунта | `forbidden_actions: {texts: [Выйти, Log out, Sign out]}` (по умолчанию — спросить) |
| | Не трогать профиль и настройки аккаунта | `forbidden_screens: ["(?i)(profile\|account\|settings)"]` + тексты пунктов меню |
| Данные | Удаление чего-либо (даже своих тестовых записей) | `forbidden_actions: {texts: [Удалить, Delete, Remove]}` — снимает возможность `preapproved_actions` |
| | Удалять записи, созданные прогоном, можно | `preapproved_actions: {texts: [Удалить, Delete], context: "<контекст списка>"}` |
| | Не загружать файлы и фото | `forbidden_packages: [com.android.documentsui, com.google.android.documentsui, com.google.android.providers.media.module]` + `forbidden_actions: {texts: [Загрузить, Upload, Прикрепить]}` |
| Люди | Отправка сообщений, отзывов, приглашений | уже `send-to-people` (спросить) → ужесточить до запрета: `forbidden_actions: {texts: [Отправить, Send, Опубликовать, Пригласить]}` |
| | Звонки, SMS, письма | уже базовый запрет (`calls-sms`, схемы `tel:`, `sms:`, `mailto:`) |
| Выход за пределы | Не открывать браузер и другие приложения | уже базовый: чужое приложение — назад; ссылки наружу только фиксировать |
| | Не включать геолокацию, камеру, микрофон, уведомления, Bluetooth; не сканировать QR; не включать точку доступа | `intake.py` делает сам: правило с типовыми текстами кнопок (RU+EN, `topic`, `review: «проверить на разведке»`), для камеры и QR — `forbidden_packages` камеры, для точки доступа — `forbidden_screens: ["(?i)tether\|hotspot"]`, для разрешений — `{texts: [Разрешить, Allow, While using the app…], exact: true, context: ["снимать фото", "take pictures"…]}` (в диалоге — только отказ) |
| Устройство | Не менять настройки устройства | только для реальных устройств и чужих AVD: `stands.consent.scope: app-only` |

Как срабатывает правило (`guard.py action`): `texts` — точный текст/contentDescription или подстрока длиннее 3 символов (`exact: true` — только точный текст: «Allow» не задевает «Don’t allow»); `ids` — resource-id (`btn_buy` или полный `com.example.app:id/btn_buy`); `screen_pattern` — регэксп по activity; `context` — **подстрока** текста экрана или диалога (или список подстрок — любая); правило без `texts`, `ids`, `descs` и `screen_pattern` не срабатывает.

### Запрет против сценария
Запрет пользователя может касаться **побочного эффекта** обычной кнопки: «не включать точку доступа» и «Создать комнату» (приложение само включает точку доступа), «не трогать камеру» и «Добавить игрока по QR», «не отправлять сообщения» и «Пригласить друзей». guard такие связи не видит — их ищет исполнитель:
1. **На разведке** (SKILL.md, шаг 6): по описанию приложения (`goal.what`, `context.sources`, память, магазин), разрешениям из `apk-info.json` (`CHANGE_WIFI_STATE`, `NEARBY_WIFI_DEVICES`, `CAMERA`, `RECORD_AUDIO`, `ACCESS_FINE_LOCATION`…) и текстам кнопок карты экранов выписать действия, которые могут вызвать запрещённое.
2. **До нажатия** — один вопрос на все найденные (`AskUserQuestion`, по действию): «„Создать комнату“ включает точку доступа (запрещено). Что делать?» — «Разрешить на эмуляторе (Recommended, если без этого не проверить основной сценарий)» / «Пропустить — не нажимать». На реальном устройстве — отдельный вопрос.
3. Решение записать: «разрешить» → `rules.preapproved_actions: {id, texts: [Создать комнату], source: "побочный эффект: точка доступа; разрешено пользователем на эмуляторе"}` (`preapproved_actions` снимает только confirm: если текст кнопки сам попал в `forbidden_actions` — после «да» убрать его из правила запрета); «пропустить» → `rules.forbidden_actions: {id, texts: [Создать комнату], source: "побочный эффект: точка доступа — запрещено"}`; затем `guard.py export` и `journal.py note <RUN_DIR> "Решение пользователя: …"`. В отчёте — «не проверено: запрет <правило>» для пропущенного.
4. Конфликт, найденный позже (кнопка не была на разведке), — тот же вопрос по ходу (шаг 10), до нажатия. Свободный текст запретов разбирается по `safety-rules.md` §2 → таблица «фраза → правило» на подтверждение.

## Черновик из свободного запроса
```bash
python3 <SKILL_DIR>/scripts/intake.py from-text --file <запрос.txt> --output-dir <OUTPUT_ROOT> --out <RUN_DIR>/run-config.yaml
python3 <SKILL_DIR>/scripts/intake.py from-text --text "Протестируй ~/Downloads/app.apk на Android 10 и 14, на слабом телефоне, не нажимай «Купить»" --json
```
Распознаёт: пути `.apk/.aab/.apks/.xapk` (с пробелами — в кавычках), пакет установленного приложения, версии («Android 13», «API 34»), железо (слабый телефон, N ГБ ОЗУ, N ядер, планшет, складной, малый экран; только «N ГБ ОЗУ» → `hardware: []` и свой профиль, без лишнего телефона 4 ГБ), вариации (тёмная тема, крупный шрифт, альбомная, RTL, язык, 3G/EDGE, офлайн, смена сети, низкий заряд, экономия, Doze, часовой пояс), виды тестов, направления, глубину, реальное устройство (→ один поток и вопрос о согласии), headless, запреты («не нажимай «…»» → `forbidden_actions`; «спрашивай перед …» → `require_confirmation_actions`; темы без текста кнопки — камера, QR и сканирование, точка доступа, микрофон, геолокация, уведомления, Bluetooth, контакты, в т.ч. «без геолокации» и перечисления «не трогай камеру, микрофон и геолокацию» → правила с типовыми текстами RU+EN, пакеты камеры, правило диалога разрешения и пометка «проверить на разведке»), репозитории, режим, потоки (не больше 4), явное разрешение коммитить результаты и APK (`git`). В начале файла — «Нужно уточнить» и «Проверить». Черновик **показать пользователю**, недостающее спросить. Пустой запрос — код 2.

## После опроса
1. Записать `run-config.yaml` (с `git.allow_commit_results` / `allow_commit_apk`), `guard.py export --config … --out <RUN_DIR>/rules.json`, `check_env.py --fast --json <RUN_DIR>/env.json`, `matrix.py build --config <RUN_DIR>/run-config.yaml`.
2. Показать **сводку**: приложение (пакет, версия, min/target), цель и критерий успеха, источники и память, версии Android и матрица (ячейки, потоки, время, образы к загрузке и их размер), стенды (эмуляторы, устройства и согласия), виды тестов и направления, глубина, запреты (базовые + разобранные; типовые тексты — «проверить на разведке»), куда не заходить, репозитории и режим (dry-run), куда записать итоги, папка результатов и git (что добавлено в `.gitignore`).
3. Ждать явного «старт» (или правок). Без «старт» прогон не начинается.
