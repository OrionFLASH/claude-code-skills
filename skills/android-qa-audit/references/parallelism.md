# Потоки: несколько эмуляторов и устройств одновременно

**Поток** = один стенд (эмулятор или устройство) + один исполнитель, который проходит свою очередь ячеек матрицы. Потоков — до `parallel.max_workers` (по умолчанию 2, **максимум 4**; больше 4 приводится к 4). Распределение — `device-matrix.json → threads` (`matrix.py build`): самые долгие ячейки раздаются первыми в наименее загруженный поток, ячейки одного устройства — в один поток.

## Главные ограничения
- **Один стенд — одно взаимодействие в момент времени.** Два исполнителя на одном эмуляторе мешают друг другу (общий экран, общий фокус, общий logcat). У каждого потока — свой `--serial`.
- **Аппаратное ускорение обязательно** (HVF / WHPX / KVM, `check_env`). Без него — 1 поток, и то медленно.
- **ОЗУ хоста:** эмулятор занимает ≈ ОЗУ AVD + 1 ГБ. Число потоков ≤ (свободная ОЗУ − 2 ГБ) / (ОЗУ AVD + 1 ГБ) и ≤ ядра CPU / 2; рекомендация — `env.json → recommended_max_workers`. Признаки перегрузки: `wait-boot` дольше 5 мин, ANR системы, «System UI isn't responding» — уменьшить число потоков.
- **Порты:** каждый эмулятор получает свой порт консоли (5554, 5556, …) — `avd_manager.py start` выбирает свободный и резервирует его в `stands.json` (блокировка файла, потоки не сталкиваются).
- **Один AVD — один экземпляр.** Второй экземпляр того же AVD — только `-read-only` (без сохранения изменений); обычно лучше отдельный AVD на ячейку.
- **Создание AVD и загрузка образов** — только оркестратор, до раздачи потоков. Исполнители AVD не создают, не удаляют и не трогают чужие стенды.

## Когда только один поток
- Единственный стенд — реальное устройство пользователя (или несколько ячеек на одном устройстве).
- Общий серверный аккаунт, который нельзя использовать с двух устройств одновременно (ограничение одной сессии, общие данные: корзина, черновики, «последнее устройство»).
- Сценарий с побочными эффектами на сервере, которые надо наблюдать по одному (рассылки, публичные записи) — их и так проверяют только с разрешения.
- Мало ресурсов (см. выше) или нет ускорения.

## Сколько потоков предлагать
| Ситуация | Рекомендация |
|----------|--------------|
| smoke (1 ячейка) | 1 |
| standard, 16+ ГБ ОЗУ, ускорение есть | 2 |
| deep, 32+ ГБ ОЗУ, 8+ ядер, ячеек ≥ 6 | 3–4 |
| реальное устройство + эмуляторы | устройство — свой поток, эмуляторы — по ресурсам |

## План по умолчанию
1. Оркестратор: образы (после согласия) → AVD всех ячеек → запуск стендов первой волны (по одному на поток) → установка APK.
2. Основной поток (оркестратор): ячейка `primary` — все направления и вариации; там же разведка и память о приложении.
3. Остальные потоки (субагенты): свои ячейки по очереди: `start` → `wait-boot` → `install` → направления ячейки → `stop` → следующая ячейка.
4. Фоном в каждом потоке: `logcat start` на своём стенде; после каждого сценария `crashes`.
5. Сведение: находки потоков `raw/findings-<поток>.json` → оркестратор → `findings.json` → `fingerprint.py compute` → `dedupe` (одна и та же проблема на разных версиях сливается, окружения — в `environment_list`).

## Задание субагенту (шаблон)
```text
Ты — исполнитель android-qa-audit, поток <wN>. Стенд: <SERIAL> (<own-emulator|real>), ячейки: <c03, c05> из <RUN_DIR>/device-matrix.json.
Всё — только через <SKILL_DIR>/scripts/adb_helpers.py … --serial <SERIAL> --run-dir <RUN_DIR> (и avd_manager.py start/wait-boot/stop
для своих ячеек, если оркестратор так поручил). Другие стенды не трогать. AVD не создавать и не удалять.
Приложение: <package> из <RUN_DIR>/apk/<файл>; контекст (сценарии, термины, «задумано так»):
<OUTPUT_ROOT>/qa-runs/.app-context/<package>/context.md — прочитать до начала.
Для каждой ячейки: вариации <список> (команды и сброс — device-matrix.json → variants), направления <список>,
чек-листы <SKILL_DIR>/references/checklists/<направление>.md — разделы <Smoke|Standard|Deep>.
Перед началом: logcat start; после каждого сценария: crashes; метрики: start-time --mode cold --runs 3, meminfo.
<БЛОК ПРАВИЛ из safety-rules.md §4, дословно, с RULES_TABLE>
Выход: <RUN_DIR>/raw/findings-<wN>.json — массив находок по templates/finding.schema.json (без id и fingerprint),
environment.cell = id ячейки, repro_rate после повтора; скриншоты <RUN_DIR>/screenshots/<wN>-*.png; «не проверено» —
в поле not_checked. Вопросы (код 2 от guard, «баг или задумано») — не решай сам, верни списком questions.
В конце: logcat stop; вернуть настройки вариаций; stop своих эмуляторов, если так поручено.
```

## Темп
- Пауза после каждого действия — `parallel.throttle_ms` (по умолчанию 500 мс) в каждом потоке.
- Приложение с сервером: суммарно не больше `max_workers` клиентов; ответы 429/503 или блокировка аккаунта — остановить все потоки, сообщить пользователю.
