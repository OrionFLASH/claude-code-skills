# Правила безопасности

Самый важный файл скила. **Раздел «Блок правил для исполнителей» (§4) дословно вставляется в задание каждого субагента и каждого агента плагина** — вместе с разобранными правилами пользователя из run-config.

## 1. Базовые запреты (всегда, отключить нельзя)

| # | Запрет | Реализация (`scripts/guard.py`) |
|---|--------|-------------------------------|
| A1 | Не совершать покупки, подписки, оплату, донаты; не вводить платёжные данные — **и в эмуляторе тоже** | `action` категория `purchase` → deny; «OK/Да» в диалоге Google Play/оплаты → deny (`base:dialog-confirm`); пакеты Google Play, кошельки → deny; resource-id `buy`, `pay`, `subscribe` → confirm |
| A2 | Не входить через внешние аккаунты (Google, Apple, VK, Яндекс, Telegram…), не добавлять аккаунты на устройство, не подтверждать доступ к аккаунту | категория `oauth`, кнопка провайдера рядом с «войти через…» → deny; пакет `com.google.android.gms` → deny; `cmd account` → deny |
| A3 | Не звонить, не отправлять SMS и письма — в эмуляторе тоже | категория `calls-sms`, deep links `tel:`, `sms:`, `mailto:`, `market:` → deny; `am start` с `CALL/DIAL/SENDTO` → deny; звонилка, SMS, почта, контакты → deny |
| A4 | Не отправлять сообщения, отзывы, жалобы, приглашения реальным людям без разрешения на **каждую** отправку | категория `send-to-people` → confirm (при контексте чата, отзыва, поддержки, приглашения, «поделиться») |
| A5 | Не удалять аккаунты и пользовательские данные; удаление записей в приложении — только с подтверждения | `account-destructive` → deny; `destructive` и иконка «×»/корзина → confirm; `preapproved_actions` снимает confirm только для данных, созданных прогоном |
| A6 | Не принимать соглашения за пользователя без его согласия | `agreement` → confirm (онбординг «Принять и продолжить» — спросить один раз или `preapproved_actions` на этот стенд) |
| A7 | Не выдавать приложению права администратора устройства, специальных возможностей, установки из неизвестных источников | `device-admin` → deny; `settings put secure enabled_accessibility_services`, `dpm`, `locksettings` → deny |
| A8 | Не взаимодействовать с чужими приложениями: браузер, Play Store, звонилка, мессенджеры; переход наружу — только зафиксировать и вернуться BACK | `package`: не тестируемое приложение и не системный интерфейс разрешений → deny; системные (настройки, камера, выбор файла) → confirm; `adb_helpers.py` пишет «покинуто приложение» в `blocked.jsonl` |
| A9 | Не трогать реальные устройства и чужие эмуляторы без явного разрешения; на них — только то, что разрешено (`stands.consent.scope`) | `adb`: стенд `real`/`foreign-emulator` без согласия → confirm; `read-only` → запрет любых изменений и нажатий; `app-only` → только тестируемое приложение; настройки устройства → confirm при `app-only` |
| A10 | Не менять и не удалять AVD пользователя; запускать его — только с разрешения и только `-read-only -no-snapshot-save` | `avd_manager.py`: свои AVD — только `qa-*` с меткой `android-qa-audit.json`; `delete`, `create --name` не `qa-*`, `start` чужого без `--allow-foreign` → отказ (код 3) |
| A11 | Никаких разрушительных adb-команд: сброс устройства, `rm` вне временных файлов скила, удаление/очистка/отключение **других** приложений, `reboot bootloader/recovery`, root на реальном устройстве, `backup/restore` | `adb`: → deny; `pm uninstall/clear/grant/revoke` — только для `app.package` |
| A12 | Никаких атак: инъекции, перебор, обход авторизации, вредные интенты в экспортируемые компоненты, нагрузка. Безопасность — только пассивно | плагины с активными атаками — в `banned` (`check_env`); экспортируемые компоненты только перечисляются (`apk_info.py`) |
| A13 | monkey и случайные нажатия — только на своём эмуляторе без аккаунтов | `monkey` без `-p <пакет>` → deny; на чужом стенде — confirm только при согласии `full`, иначе deny; есть аккаунты на устройстве → confirm |
| A14 | Маскировать секреты и персональные данные в отчётах, черновиках, журналах | `masking.py` в `logcat stop/dump`, `crashes`, `notifications`, `dump-ui`; `validate_findings.py` предупреждает |
| A15 | Учётные данные — только из переменных окружения; не печатать, не писать в журналы и отчёты; скриншоты экрана входа с введённым паролем не делать | `adb_helpers.py text --env QA_PASSWORD` вводит значение, не печатая его |

`guard.py` — помощник, а не замена суждению: если элемент **по смыслу** попадает под запрет (иконка корзины покупок без подписи, кнопка с ценой, нарисованная на canvas в игре и невидимая в дереве элементов), это запрет, даже если guard вернул allow. Перед нажатием по координатам на экранах без дерева элементов (игры, canvas, видео) — смотреть скриншот.

## 2. Пользовательские запреты

Пользователь пишет свободным текстом; скил разбирает его в правила `rules` run-config и **показывает на подтверждение** таблицей «фраза → правило».

| Поле | Что значит |
|------|-----------|
| `forbidden_packages` | приложения, с которыми нельзя взаимодействовать (выбор файла, камера, компаньон) |
| `forbidden_screens` | регэкспы по activity или названию экрана: туда не заходить, действия там — запрет |
| `forbidden_deeplinks` | регэкспы URI: не открывать |
| `forbidden_actions` | `texts`, `descs`, `ids`, `classes`, `package`, `screen_pattern`, `context` — действие не выполнять |
| `require_confirmation_actions` | те же поля — выполнять только после «да» пользователя в моменте |
| `preapproved_actions` | те же поля — заранее одобренные действия уровня confirm. **Запреты (deny) не снимают никогда** |
| `adb_require_confirmation` | регэкспы adb-команд, которые всегда спрашивать |
| `stands.consent` | согласие на реальное устройство или чужой эмулятор: `serial`, `scope: read-only \| app-only \| full` |

### Примеры разбора
| Фраза | Правило |
|-------|---------|
| «ничего не покупать» | уже A1; добавить тексты с разведки («Оформить Premium», «Купить за 199 ₽», «Попробовать 7 дней бесплатно») |
| «не публиковать посты» | `forbidden_actions: {id: U1, texts: [Опубликовать, Publish, Post]}` |
| «не трогать настройки аккаунта» | `forbidden_screens: ["(?i)(account\|profile)Settings"]` (activity — с разведки) |
| «на моём телефоне можно только ставить и удалять это приложение» | `stands.consent: [{serial: <serial>, scope: app-only}]` |
| «спрашивай перед удалением» | `require_confirmation_actions: {texts: [Удалить, Delete, Remove]}` |
| «удалять свои тестовые заметки можно» | `preapproved_actions: {texts: [Удалить, Delete], context: "<заголовок списка>"}` |
| «не открывай камеру» | `forbidden_packages: [com.android.camera2, com.google.android.GoogleCamera]` + `forbidden_actions: {texts: [Камера, Сфотографировать]}` |

Правило неоднозначно → вопрос с вариантами, а не догадка.

## 3. Применение

0. **Fail closed — сбой защиты не разрешение.** `guard.py`: решение — только коды 0 / 2 / 3; **код 4** («guard недоступен»: нет `--config` или файла, битый YAML, неверный регэксп в правилах, неверные аргументы, внутренняя ошибка), любой другой код, «No such file», пустой вывод — **СТОП**, действие не выполнять. `adb_helpers.py`: **код 6** — guard недоступен (конфиг не найден или не прочитан, неверное правило, ошибка guard), на устройстве ничего не выполнено — тоже СТОП; коды 4 («не поддерживается / элемент не найден») и 5 («не удалось») — обычные ответы, traceback или неизвестный код — СТОП.
1. **Перед каждым нажатием** — `adb_helpers.py tap|long-press --text/--id/--desc …` (или по координатам): скрипт снимает дерево элементов, находит элемент, передаёт в `guard.py` текст, contentDescription, resource-id, класс, пакет, экран (activity) и контекст (тексты экрана/диалога). Код 3 → не выполнено, запись в `logs/blocked.jsonl`; код 2 → спросить пользователя (одно действие — одно подтверждение, если не дано общее разрешение на класс действий), после «да» — тот же вызов с `--confirmed`.
2. **Перед каждой командой, меняющей устройство**, — только через подкоманды `adb_helpers.py` (они вызывают `guard.check_adb`). Свою adb-команду — сначала `guard.py adb "<аргументы>" --stand own-emulator|foreign-emulator|real --serial S --config <RUN_DIR>/run-config.yaml`.
3. **Deep links** — `adb_helpers.py deeplink <URI>` (проверка `guard.py deeplink`): `tel:`, `sms:`, `mailto:`, `market:` — запрет; домен не из deep links приложения → спросить (откроется браузер).
4. **После каждого действия** — смотреть пакет на переднем плане (`adb_helpers.py` выводит `focus`): открылось чужое приложение → `key BACK`, в отчёт «ведёт в <пакет> — не проверялось».
5. **Системные диалоги разрешений** приложения (пакет permissioncontroller) — часть теста: «Разрешить», «Только сейчас», «Запретить» можно нажимать. Диалог выбора аккаунта Google, покупки Google Play, «Активировать администратора» — запрет.
6. **Реальные устройства.** Перед первой командой на реальном устройстве — отдельный вопрос (intake, 9a) с моделью и serial. Без ответа устройство не используется. `read-only` — только `info`, `dump-ui`, `screenshot`, `logcat dump`, `crashes`, метрики. Сброс настроек вариаций по окончании — обязательно (`run-files.md` → «Уборка»).
7. **Чужие AVD** — только по разрешению: `avd_manager.py start <AVD> --allow-foreign` (принудительно `-read-only -no-snapshot-save`: изменения не сохраняются). Уже запущенный эмулятор пользователя — это `foreign-emulator`: как реальное устройство, нужно согласие.
8. **Запрещённое действие** не выполняется; в отчёт: «не проверено: запрет <rule> (<источник>)». Если без него не проверить важную функцию — спросить: пропустить / разрешить один раз / показать, как проверить вручную.
9. **Плагины и агенты**: только если их действия идут через `adb_helpers.py` или агент принимает блок §4. Агент, который сам кликает без guard или имеет активные атаки, — не используется (`plugins-map.md`).
10. **Вход в приложение**: тестовый аккаунт — значения из env (`app.login.username_env`, `password_env`) через `text --env`; вход пользователем — он вводит сам в окне эмулятора, скил ждёт «готово». Пароли и коды не печатать и не сохранять.
11. **Стенды потоков (реестр `stands.json`).** Один стенд — один исполнитель и одно действие за раз. Уже запущенный AVD не запускается второй раз (`avd_manager.py start` → код 3: работать в нём); лишние эмуляторы не запускать. Исполнитель запускает и останавливает **только свои** стенды: `start … --owner wN`, `stop … --owner wN` (чужой стенд → код 3). `adb kill-server` — запрещён всегда (обрывает все стенды и потоки, `guard.py`); `adb emu kill` — только своему эмулятору через `avd_manager.py stop`.
12. **Правовые и финансовые утверждения** (нормы права, санкции, штрафы — например, о разрешениях, персональных данных, рекламе в приложении): в находке — наблюдаемый факт, нормы — только «возможно применимо» в `legal.norms`; **вторая проверка другим исполнителем** (`recheck.py legal`) и пометка «требуется проверка юристом» (`render_draft.py` ставит сама); без этого не публиковать как факт (`recheck.py gate`).
13. **Флаги эмулятора и gRPC.** Дополнительные флаги — только `avd_manager.py start --extra-args` по белому списку (`guard.py emulator-args`, `stands.md`); gRPC эмулятора — **только с авторизацией** (`-grpc-use-token`, `--mic-inject`), открытый `-grpc <порт>` без неё — запрет. Токены gRPC, консоли эмулятора и любые другие — не печатать, не писать в журналы и отчёты (скрипты маскируют: `abcd…(N)` / `***`).
14. **Микрофон и камера хоста** — эмулятор начинает слышать или видеть устройства пользователя: `-allow-host-audio`, `adb emu avd hostmicon`, `-camera-* webcamN` — только после «да» (код 2 → `--confirmed`). Звуковые устройства и настройки хоста скил не устанавливает и не меняет.
15. **Нажатие без дерева** (`tap X Y --no-ui`) — только на экране, который исполнитель **видел на свежем скриншоте**, и только там, где смысл кнопки понятен по картинке: guard проверяет пакет и экран (и элемент из последнего дерева, если он есть), но не текст кнопки на анимированном экране.
16. **Системный выбор файла** (Documents UI) — системное приложение «спросить»: одно `--confirmed` на вызов `import-file` или `rules.preapproved_packages` на весь прогон после вопроса пользователю; запреты (`deny`) это не снимает. Файлы на устройство — только своими именами `qa-*` (`push-media`), удаляются только они.
17. **Сторонние приложения на эмулятор** (ADBKeyBoard) — только на свой эмулятор, только APK, который дал пользователь, и только после «да» (`ime install-adbkeyboard … --confirmed`). Ввод через буфер обмена эмулятора (`text --clipboard`) — не для секретов: буфер синхронизируется с хостом.
18. **Публикация без пометки об автоматизации** (`disclosure: none`) — только по просьбе пользователя; для чужого трекера — предупредить, что это может ввести мейнтейнеров в заблуждение (`repo-sync.md`). Вложения в репозиторий (`attachments.py push`) — только после «да» и только в выбранные пользователем репозиторий и ветку.
19. **Ролики (запись экрана, `clips.md`)** — только через `adb_helpers.py clip-start` / `clip-stop` / `clip` / `clip-rolling`: те же правила, что для скриншотов, плюс:
    - **не записывать** ввод логинов, паролей, кодов из SMS и e-mail, платёжных данных и сам вход в аккаунт: запись начинается **после** входа или на гостевом экране; `text --env` в шагах `clip` запрещён (код 2);
    - **личные уведомления** не попадают в кадр: на реальном устройстве шторку под запись не открывать (шаг `shade` в `clip` — код 2), уведомления очистить до записи; лучше — эмулятор с чистым профилем и тестовой учётной записью;
    - персональные данные на экране — до записи убрать или заменить тестовыми (маскировать видео задним числом скил не умеет); `FLAG_SECURE` (чёрный кадр) — не обходить;
    - звук не пишется никогда; показ касаний (`show_touches`) на реальном устройстве — только по явному `--touches on` и согласию, прежнее значение возвращается всегда (в т.ч. при ошибке и уборке);
    - ролики не коммитятся в репозиторий пользователя (`<RUN_DIR>/.gitignore`: `clips/`, `recordings/`), а **публикуются** (ветка вложений, issue) только по тем же согласиям, что скриншоты, — ролик публично виден; непросмотренный ролик (лента кадров не открыта) не публикуется.

## 4. Блок правил для исполнителей (вставлять дословно)

```text
ПРАВИЛА БЕЗОПАСНОСТИ android-qa-audit — обязательны, нарушение = остановка.
Конфиг прогона: <RUN_DIR>/run-config.yaml. Стенд: <SERIAL> (<STAND_KIND>). Скрипты: <SKILL_DIR>/scripts/.
0. ДО ПЕРВОГО ДЕЙСТВИЯ: python3 <SKILL_DIR>/scripts/guard.py selftest — код ≠ 0 или «No such file» = СТОП,
   ничего не делать, вернуть «SKILL_DIR/guard недоступен: <вывод>».
1. Любое нажатие и ввод — ТОЛЬКО через adb_helpers.py (tap/long-press/swipe/text/key) с --serial <SERIAL> --run-dir <RUN_DIR>.
   Код 3 — запрещено: не повторять, записать "не проверено: запрет <rule>". Код 2 — НЕ делать, вернуть оркестратору вопрос.
   FAIL CLOSED: adb_helpers.py код 6 / guard.py код 4 («guard недоступен»), traceback, неизвестный код, «No such file» =
   СТОП: действие не выполнять, дальше не продолжать, вернуть оркестратору «guard недоступен: <вывод>».
2. Любое изменение устройства (install, clear, настройки, сеть, батарея) — только подкомандами adb_helpers.py.
   Прямые adb shell, меняющие состояние, — запрещены. Чтение (dumpsys, getprop, logcat -d) — можно.
   adb kill-server — НИКОГДА; adb emu kill и stop — только своему стенду (avd_manager.py stop … --owner <wN>).
3. Никогда: покупки/подписки/оплата; вход через внешние аккаунты и добавление аккаунтов; звонки, SMS, письма;
   отправка сообщений/отзывов/приглашений реальным людям; удаление аккаунтов и чужих данных; права администратора
   и специальных возможностей; удаление/очистка других приложений; сброс устройства; атаки, инъекции, перебор.
4. Открылось чужое приложение (браузер, Play Store, звонилка) — сразу key BACK, записать "ведёт в <пакет>".
5. Не трогать другие эмуляторы и устройства, кроме <SERIAL>. AVD не создавать и не удалять — это делает оркестратор.
   Уже запущенный AVD второй раз не запускать (код 3 — работать в нём); лишние эмуляторы не запускать.
6. Пауза после каждого действия не меньше <THROTTLE_MS> мс; одно действие за раз.
7. Секреты, токены, e-mail, телефоны, персональные данные — маскировать в любом выводе (a***@e***.com, токен abcd…(40)).
8. Ввод для проверок — только безобидные значения: пусто, пробелы, длинный текст (ASCII), граничные числа.
9. Сомневаешься — не делай, верни вопрос.
10. Находки — НЕ файлами: блок ```qa-findings``` в последнем сообщении (ingest_findings.py example), у каждой — repro
    (аргументы adb_helpers.py для перезапуска проверки, например {"adb": ["find", "--text", "…"], "expect_exit": 0}).
    Нормы права и финансовые последствия — только «возможно применимо» в legal.norms, без вывода о нарушении.
11. tap X Y --no-ui — только после свежего screenshot этого экрана и только если смысл кнопки понятен по картинке.
    На стенде, где идёт фоновая задача soak (job status), не нажимать — только чтение. Микрофон/камера хоста,
    флаги эмулятора вне белого списка, установка сторонних APK — не делать, вернуть вопрос оркестратору.
12. Ролик — только adb_helpers.py clip-start/clip-stop/clip (шаги — через guard). Под запись НЕ вводить логины, пароли,
```

## 5. Маскирование

Перед записью в findings.json, отчёт, черновик, issue (`scripts/masking.py`; `logcat stop` и `dump` маскируют файл сами):
- e-mail → `a***@d***.tld`; телефоны → `***<последние 2 цифры>`; IMEI, Android ID, рекламный id → `***`;
- токены, ключи, JWT, значения `Authorization`, `api_key`, `password` → первые 4 символа + `…(длина)` или `***`;
- параметры URL `token=`, `key=`, `session=`, `code=`, `state=`, `password=` → `***`;
- имена и логины реальных людей на экранах → `<пользователь>`; скриншоты с персональными данными — не публиковать;
- serial реального устройства пользователя в публикуемых черновиках — не указывать (модель и версия Android достаточно).

## 6. Серьёзная утечка
Найдены действующий ключ или токен (в logcat, ресурсах, ответах), пароль или персональные данные других пользователей:
- находка — severity `critical`, `evidence.sensitive: true`;
- **публикация такой находки в публичные репозитории останавливается** — только вопрос пользователю («только в приватный репозиторий» / «только локальный отчёт» / «сообщить владельцу другим путём»);
- в черновиках и отчёте — только маскированное значение и место (тег logcat, экран), без скриншота с самим значением.
