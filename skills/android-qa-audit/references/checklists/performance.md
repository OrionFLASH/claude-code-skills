# performance — Производительность

Направление: `performance` · Инструменты: `<SKILL_DIR>/scripts/adb_helpers.py` (ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`; PKG — `app.package` из run-config): `start-time`, `gfxinfo`, `meminfo`, `size`, `batterystats`, `crashes`; `apk_info.py` (размер, ABI) · Усилители: Maestro или Appium — повторяемый сценарий для замеров, если установлены

## Цель
Измерить время запуска, плавность, память, размер и расход батареи и найти явные проблемы: медленный старт, рывки при прокрутке, рост памяти и утечки, тяжёлая работа на слабом железе и медленной сети. Числа на эмуляторе относительные: сравнивать ячейки и версии между собой, не выдавать их за показатели реальных устройств.

## Безопасность в этом направлении
- Перед каждым нажатием `adb_helpers.py tap …` guard.py проверяет действие сам: код 3 — запрет, записать «не проверено: запрет <rule>»; код 2 — спросить пользователя и повторить с `--confirmed` только после «да».
- Сценарии для замеров — только безопасные действия (просмотр, прокрутка, поиск, переходы); покупки, отправка сообщений реальным людям, звонки и SMS — никогда.
- `batterystats --reset` и смена сети на реальном устройстве — только с согласием из `stands.consent`; скорость сети — только на своём эмуляторе; `monkey` — только на своём эмуляторе без аккаунтов.
- Для jank анимации не выключать (`animations on`); замеры не смешивать с другими потоками на том же эмуляторе.

## Smoke
- [ ] `perf.cold-start` — `start-time PKG --mode cold --runs 5` → медиана TotalTime → дефект (ориентиры Android vitals): холодный ≥ 5 с — чрезмерно; заметно хуже прошлой версии или базовой ячейки.
- [ ] `perf.jank-main` — `gfxinfo PKG --reset` → 10 раз `scroll down` по главному списку → `gfxinfo PKG` → janky %, p50/p90/p99 → дефект: p90 > 16 мс на кадр при 60 Гц, высокий janky %, видимые рывки.
- [ ] `perf.memory-baseline` — `meminfo PKG` после запуска и после основного сценария → PSS, Java/Native heap, Views, Activities → базовая точка для сравнения.
- [ ] `perf.slow-ui` — операции дольше 1 с без индикатора, ответ на нажатие дольше 200 мс (по `screenrecord`) → дефект: «замёрзший» интерфейс; зависание с диалогом «не отвечает» оформить как `fn.anr`.

## Standard (в дополнение к smoke)
- [ ] `perf.warm-hot-start` — `start-time --mode warm --runs 5` и `--mode hot --runs 5` → дефект: тёплый ≥ 2 с, горячий ≥ 1,5 с.
- [ ] `perf.jank-screens` — `gfxinfo --reset` → тяжёлые экраны (списки с картинками, карты, анимации, переходы) → `gfxinfo` → дефект: p99 заметно выше, чем на главном списке, «замирания» кадров.
- [ ] `perf.memory-scenario` — основной сценарий 3 раза подряд, `meminfo` после каждого → дефект: PSS и heap растут с каждым повтором и не возвращаются.
- [ ] `perf.memory-rotation` — `meminfo` → 5 поворотов (`rotate landscape`/`rotate portrait`) → `meminfo` → дефект: растут Activities и Views (утечка, связано с `life.activity-leak`).
- [ ] `perf.app-size` — `size PKG` (приложение, данные, кэш) и размер APK из `apk-info.json` → дефект: несоразмерно большой размер, кэш растёт без предела после сценария.
- [ ] `perf.battery` — `batterystats PKG --reset` → 10 минут сценария или фона → `batterystats PKG` → дефект: удерживаемые wakelocks в фоне, заметный расход без активности.
- [ ] `perf.low-end` — ячейка low-end: `start-time`, `gfxinfo`, `meminfo` в том же сценарии → дефект: заметно хуже базовой ячейки, OutOfMemoryError в `crashes`, ANR.
- [ ] `perf.slow-network` — вариации `net-3g` и `net-edge` → основной сценарий → дефект: интерфейс блокируется ожиданием сети, нет индикаторов и отмены, таймаут без сообщения.

## Deep (в дополнение к standard)
- [ ] `perf.low-1gb` — ячейка low-1gb (API ≤ 29): запуск и основной сценарий → дефект: падения, постоянные перезапуски процесса.
- [ ] `perf.first-launch` — `clear`, `start-time --mode cold --runs 1` (первый запуск без кэша) против повторных → дефект: первый запуск в разы дольше без индикации.
- [ ] `perf.long-session` — 15 минут использования, `meminfo` и `gfxinfo` каждые 5 минут → дефект: деградация плавности и рост памяти со временем.
- [ ] `perf.background-battery` — приложение в фоне + `doze enter`, затем `batterystats` → дефект: пробуждения и wakelocks в Doze без причины.
- [ ] `perf.monkey-stress` — свой эмулятор: `monkey PKG --events 500 --seed 42 --throttle 300`, затем `meminfo`, `crashes` → дефект: падения, рост памяти.
- [ ] `perf.cache-growth` — `size PKG` до и после долгой прокрутки лент и картинок → дефект: кэш растёт без ограничения.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| ANR или падение по памяти на слабом железе | Critical / High |
| Холодный запуск ≥ 5 с на базовой ячейке | High |
| Утечка Activities: рост после каждого поворота | Medium |
| p90 кадра > 16 мс при прокрутке главного списка | Medium |
| Wakelocks в фоне, заметный расход батареи | Medium |
| Тёплый запуск ≥ 2 с | Medium / Low |
| Кэш растёт без предела | Low |

## Что записывать в находку
- Экран — activity из `current`; сценарий замера (шаги с чистого запуска, число повторов, жесты).
- Метрики в `metrics`: медиана и все значения TotalTime, janky %, p50/p90/p99, PSS и heap до/после, число Activities и Views, размер, оценка мА·ч.
- Окружение: API, профиль железа (RAM, ядра), вариация, сеть, ячейка матрицы `c01…`; эталон для сравнения (базовая ячейка или прошлая версия).
- repro_rate («3/3» — замер повторён 3 раза с тем же результатом).
- `screenrecord` для рывков; `logcat_excerpt` из `crashes` (замаскированный) для падений и ANR.
