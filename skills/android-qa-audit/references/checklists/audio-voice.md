# audio-voice — Аудио- и голосовые приложения (тематический чек-лист)

Не отдельное направление, а набор проверок поверх направлений `functional`, `logic-state`, `lifecycle-resilience`, `performance`, `ux`: включать, когда приложение записывает или обрабатывает звук (разрешение `RECORD_AUDIO`, `FOREGROUND_SERVICE_MICROPHONE`, диктофон, голосовые заметки, распознавание речи, звонки, музыка). Находки — с `direction` основного направления и `check_id` `audio.*`.

Инструменты: `adb_helpers.py mic-status` / `mic-inject` (`audio-input.md`), `soak` и `job` (`long-runs.md`), `push-media` + `import-file` (файлы), `notifications`, `meminfo`, `kill-bg`, `doze`, `network`; ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`.

## Безопасность в этом направлении
- Звук — только тестовый (своя запись пользователя, синтез речи на хосте) без персональных данных; записи и расшифровки с чужой речью не публиковать.
- Микрофон хоста (`hostmicon`, `-allow-host-audio`) — только после «да» пользователя; по умолчанию — путь gRPC или файл.
- Облачная расшифровка, загрузка в облако, вход в аккаунт — по правилам запретов (`safety-rules.md`), вход — пользователь сам.

## Smoke
- [ ] `audio.mic-path` — каким путём подаётся звук (`mic-status`): gRPC / loopback / только файл; при «только файл» — в отчёт «живой микрофон не проверялся».
- [ ] `audio.record-basic` — короткая запись (30–60 с) с речью (`mic-inject`) → индикатор уровня реагирует, таймер идёт, файл сохраняется, длительность ≈ записанной → дефект: нет уровня, файл пустой или короче.
- [ ] `audio.permission` — запрет микрофона (`revoke RECORD_AUDIO`) → понятное объяснение и путь к настройкам, без падения; повторный запрос → работает.
- [ ] `audio.silence` — тишина (без подачи звука, `mic-inject` файла с тишиной) → пустой результат или сообщение «очень тихо», а **не** мусорный текст распознавания.

## Standard (в дополнение к smoke)
- [ ] `audio.long-10-30-60` — записи 10 / 30 / 60 минут фоном (`job start … -- soak --minutes N --expect-text … --service …`) → не обрываются (`interrupted` — находка с минутой), PSS не растёт, файл ≈ N минут (`--expect-duration` / `--result-file`).
- [ ] `audio.screen-off` — запись с выключенным экраном (`--screen-off-at 3 --screen-on-at N-2`) → продолжается, уведомление записи на месте.
- [ ] `audio.background` — уход в фон во время записи и обработки (`key HOME`, другое приложение по разрешению) → продолжает работу, уведомление foreground-сервиса с прогрессом и «Отмена» (`notifications`: `ongoing`, `progress`, `actions`).
- [ ] `audio.process-death` — смерть процесса во время записи (`kill-bg`) → при следующем запуске запись восстановлена или понятно сообщено о потере; во время обработки — продолжение или повтор без дубля.
- [ ] `audio.import-formats` — импорт файлов разных форматов и длин (`push-media` + `import-file`: WAV, M4A/AAC, MP3, Ogg/Opus, моно/стерео, 8–48 кГц, 1 с / 10 мин / 60 мин) → поддерживаемые принимаются, остальные — понятное сообщение.
- [ ] `audio.parallel` — одновременно импорт и обработка, две обработки подряд → очередь или понятный запрет, без потери результата.
- [ ] `audio.languages` — речь на разных языках (если приложение их заявляет) и смешанная → результат на языке речи или честное «язык не поддерживается».
- [ ] `audio.quality` — сравнение распознанного с исходным текстом синтезированной речи (доля слов) на 1–2 файлах → резкое падение качества на длинном файле — находка.

## Deep (в дополнение к standard)
- [ ] `audio.storage-full` — мало места во время долгой записи (`df` в soak) → предупреждение и сохранение записанного, не порча файла.
- [ ] `audio.route-change` — смена маршрута звука (наушники/Bluetooth на эмуляторе — если доступно; иначе «не проверено: эмулятор») и входящий звонок (только эмулятор, `adb emu gsm call` — по разрешению пользователя) → запись на паузе или продолжается, без потери.
- [ ] `audio.doze` — долгая обработка в Doze (`doze enter`) → продолжение или понятная пауза; уведомление не «зависает».
- [ ] `audio.low-memory` — обработка на слабом профиле (2–4 ГБ) → без ANR и падений; время обработки — только на свободном хосте (`long-runs.md` → «Замеры времени»).
- [ ] `audio.timing` — время обработки файлов 1 / 10 / 30 / 60 минут на свободном хосте → таблица в отчёт (`soak` с `--service`, сводка «Длинные сценарии»).
