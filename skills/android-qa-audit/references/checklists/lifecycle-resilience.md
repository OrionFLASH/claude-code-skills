# lifecycle-resilience — Жизненный цикл и устойчивость

Направление: `lifecycle-resilience` · Инструменты: `<SKILL_DIR>/scripts/adb_helpers.py` (ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`; PKG — `app.package` из run-config): `rotate`, `key HOME|APP_SWITCH|BACK`, `kill-bg`, `trim-memory`, `doze`, `standby`, `network switch`, `shade`, `meminfo`, `crashes` · Усилители: «Не сохранять действия» в настройках разработчика эмулятора (вручную), Maestro — если установлен

## Цель
Проверить, что приложение переживает поворот, сворачивание, смерть процесса в фоне, нехватку памяти, смену конфигурации на лету, Doze и смену сети, не теряя введённые данные и положение пользователя, и что Activity не утекают.

## Безопасность в этом направлении
- Перед каждым нажатием `adb_helpers.py tap …` guard.py проверяет действие сам: код 3 — запрет, записать «не проверено: запрет <rule>»; код 2 — спросить пользователя и повторить с `--confirmed` только после «да».
- `kill-bg`, `trim-memory`, `standby` — только для тестируемого пакета. `doze`, смена конфигурации и сети на реальном устройстве — только с согласием из `stands.consent` (`scope: full`).
- «Не сохранять действия» (Developer options → Don't keep activities) — только на своём эмуляторе, включается вручную в настройках разработчика (командой скилла не меняется); после проверки выключить.
- Прерывания — только уведомления и шторка (`shade open|close`). Звонки и SMS не совершаются и не принимаются.
- Чужие приложения не трогать: если после `APP_SWITCH` в фокусе другое приложение — `key BACK`.

## Smoke
- [ ] `life.rotate-input` — ввести текст в поле (`text "qa-test" --into-id ID`), выбрать элемент, прокрутить → `rotate landscape`, `rotate portrait` → дефект: текст, выбор, позиция прокрутки или открытый диалог потеряны.
- [ ] `life.background-resume` — `key HOME`, пауза 10 с, возврат через `key APP_SWITCH` (выбор карточки — нажатие в лаунчере, guard спросит подтверждение) или `launch` без `--cold` → дефект: сброс на главный экран, потеря ввода, повторная загрузка без причины.
- [ ] `life.process-death` — на экране с введёнными данными `kill-bg PKG`, затем возврат через `key APP_SWITCH` или `launch` без `--cold` → `current`, `dump-ui`, `crashes` → дефект: падение, пустой экран, потеря данных, NullPointerException при восстановлении.
- [ ] `life.interruption` — посреди сценария `shade open`, `shade close`; приход уведомления → дефект: потеря состояния, двойная отправка, зависший индикатор.
- [ ] `life.back-reenter` — `key BACK` с главного экрана, затем `launch` → дефект: падение, повтор онбординга, «залипший» прошлый экран.

## Standard (в дополнение к smoke)
- [ ] `life.trim-memory` — `trim-memory RUNNING_CRITICAL PKG` на переднем плане, `trim-memory COMPLETE PKG` в фоне, возврат → дефект: падение, пустые экраны, потеря данных.
- [ ] `life.config-on-the-fly` — при открытом приложении: `font-scale 1.3`, `dark-mode on`, `locale de-DE PKG` (API 33+) → вернуться в приложение → дефект: падение, смешение языков, потеря ввода, тема применилась частично.
- [ ] `life.dont-keep-activities` — с включённым «Не сохранять действия» пройти 3–4 экрана вглубь, потом `key BACK` до главного → дефект: падение, пустые экраны, потеря данных на предыдущих экранах.
- [ ] `life.dialog-rotate` — открытые диалоги, нижние листы, меню → `rotate landscape` → дефект: диалог пропал, задублировался, потерял введённое.
- [ ] `life.network-switch` — `network switch` во время загрузки или сохранения → дефект: бесконечный индикатор, двойная отправка, нет повтора.
- [ ] `life.doze-standby` — приложение в фоне → `doze enter`, пауза, `doze exit`; `standby on PKG`, `standby off PKG` → вернуться → дефект: падение, синхронизация и напоминания не возобновились.
- [ ] `life.foreground-service` — длительные операции (загрузка, плеер, навигация, если есть): `key HOME` → `notifications` → дефект: нет уведомления сервиса, операция прервалась, уведомление не исчезает после окончания.
- [ ] `life.activity-leak` — `meminfo PKG` (Activities, Views) → 5 раз `rotate landscape`/`rotate portrait` и переходы вглубь и назад → `meminfo PKG` → дефект: число Activities растёт и не возвращается к исходному.
- [ ] `life.permission-revoke-bg` — приложение в фоне → `revoke PERM PKG` (система завершит процесс) → вернуться через `key APP_SWITCH` или `launch` → дефект: падение, тупик без повторного запроса разрешения.

## Deep (в дополнение к standard)
- [ ] `life.process-death-all` — `kill-bg` на каждом ключевом экране: глубоко в стеке, в середине формы, с открытым диалогом и фильтрами → дефект: любой из экранов не восстанавливается.
- [ ] `life.rotate-every-screen` — поворот на каждом экране сценария → дефект: падение или потеря состояния хотя бы на одном.
- [ ] `life.low-memory-cell` — ячейка low-end или low-1gb: переключение на системные настройки и обратно, `trim-memory` → дефект: частая потеря состояния, OutOfMemoryError в `crashes`.
- [ ] `life.long-background` — фон 30+ минут или `doze enter` на время → возврат → дефект: падение на истёкшей сессии, устаревшие данные без обновления.
- [ ] `life.update-while-running` — `install APK --replace` при открытом приложении → `launch` → дефект: падение, потеря данных, зависший процесс.
- [ ] `life.saver-mid-flow` — `battery saver-on` посреди сценария → дефект: прерванная операция без сообщения.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| Падение при восстановлении после смерти процесса | High |
| Потеря введённых данных формы при повороте | High / Medium |
| Утечка Activities: число растёт после каждого поворота | Medium |
| Двойная отправка после смены сети | Medium |
| Возврат на главный экран вместо прежнего после фона | Medium / Low |
| Потеря позиции прокрутки при повороте | Low |

## Что записывать в находку
- Экран — activity из `current` до и после события; элемент — `id=<resource-id>` или `text="…"` + класс.
- Событие жизненного цикла точно: команда (`kill-bg`, `trim-memory COMPLETE`, `rotate`, `doze enter`), пауза, способ возврата.
- Шаги с чистого запуска (`clear` → `launch --cold`); repro_rate («3/3»).
- Окружение: API, профиль железа, вариация, ячейка матрицы `c01…`.
- Скриншоты `screenshots/<id>-before.png` и `screenshots/<id>-after.png`; при падении — `logcat_excerpt` из `crashes` (замаскированный); для утечки — значения `meminfo` до и после.
