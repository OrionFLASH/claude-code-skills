# ux — Удобство (UX)

Направление: `ux` · Инструменты: `<SKILL_DIR>/scripts/adb_helpers.py` (ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`; PKG — `app.package` из run-config): `dump-ui`, `tap`, `swipe`, `key`, `screenshot`, `screenrecord` · Усилители: эвристики Нильсена, законы UX и рекомендации Material Design (как методика), Maestro — если установлен

## Цель
Пройти ключевые задачи приложения глазами разных пользователей и найти, где трудно, непонятно или долго: оценить по эвристикам Нильсена для мобильных, паттернам Material и платформенным конвенциям Android.

## Безопасность в этом направлении
- Перед каждым нажатием `adb_helpers.py tap …` guard.py проверяет действие сам: код 3 — запрет, записать «не проверено: запрет <rule>»; код 2 — спросить пользователя и повторить с `--confirmed` только после «да».
- Сценарии проходятся до последнего безопасного шага. Покупки, вход через внешние аккаунты, звонки, SMS, отправка сообщений реальным людям, удаление аккаунта — никогда; в находку: «сценарий пройден до шага N, дальше запрет <rule>».
- Диалоги подтверждения опасных действий только наблюдать и закрывать «Отмена» или `key BACK`.
- Чужие приложения (Play Store, браузер, звонилка) не трогать — сразу `key BACK`. Реальные устройства — только с согласием из `stands.consent`.

## Персоны
- **Новичок** — впервые открыл приложение, не знает терминов, пропускает подсказки.
- **Опытный** — знает, что ищет, хочет быстро: поиск, фильтры, недавнее, короткие пути.
- В deep дополнительно: **на ходу** (одна рука, медленная сеть) и **с ограничениями** (шрифт 2.0, TalkBack — совместно с accessibility).

## Smoke
- [ ] `ux.key-task` — 1–3 главные задачи из памяти приложения → пройти за новичка с чистого запуска (`clear`, `launch --cold`) → дефект: задача не решается или нужно больше двух «угадываний».
- [ ] `ux.steps-to-goal` — число нажатий и экранов до цели → дефект: заметно больше необходимого, лишние подтверждения и промежуточные экраны.
- [ ] `ux.feedback` — реакция на нажатие (pressed-состояние, индикатор, snackbar) → `screenrecord --seconds 5` во время `tap` → дефект: дольше 1 с ничего не меняется, нет подтверждения результата.
- [ ] `ux.error-messages` — понятность ошибок (сеть через `network offline`, неверный ввод) → дефект: технический текст, код без объяснения, нет подсказки, что делать.
- [ ] `ux.onboarding` — первый запуск: ясно, что это за приложение и что делать; онбординг можно пропустить; регистрация не требуется до показа ценности (если это не суть приложения) → дефект: тупик, навязчивые экраны, нет «Пропустить».

## Standard (в дополнение к smoke)
- [ ] `ux.h1`…`ux.h10` — эвристики Нильсена на каждом ключевом экране: h1 видимость состояния, h2 язык пользователя, h3 контроль и отмена, h4 единообразие и конвенции Android, h5 предотвращение ошибок, h6 узнавание вместо запоминания, h7 гибкость, h8 минимализм, h9 восстановление после ошибок, h10 помощь → каждое нарушение — находка `ux.h<N>`.
- [ ] `ux.back-behavior` — системный Back сначала закрывает клавиатуру, диалог, шторку, поиск, потом экран; Up ведёт к родителю; Back на главном экране выходит, а не возвращает к онбордингу или входу → `key BACK` + `current` → дефект: неожиданный переход.
- [ ] `ux.system-gestures` — жестовая навигация: элементы у левого и правого края и внизу не конфликтуют с жестами «назад» и «домой» → `swipe 5 Y 500 Y` от края, `screenshot` → дефект: свайп-меню или карусель у края перехватывает «назад», кнопки под полосой жестов.
- [ ] `ux.material-patterns` — нижняя панель 3–5 пунктов, главное действие заметно, snackbar с «Отменить» для обратимых действий, диалоги с понятными кнопками → дефект: нестандартный паттерн без причины, кнопки «ОК/Отмена» без смысла действия.
- [ ] `ux.reachability` — одна рука: центры главных кнопок из `dump-ui` в нижней половине экрана на профилях phone и large → дефект: частое действие только в верхнем углу без альтернативы.
- [ ] `ux.button-labels` — тексты кнопок — глаголы по смыслу действия, единая терминология, иконки без подписи угадываются → дефект: «ОК», «Далее» там, где нужно «Сохранить»; непонятная иконка на главном действии.
- [ ] `ux.empty-states` — пустые списки, «ничего не найдено», нет данных офлайн → дефект: пустой экран без объяснения и следующего шага.
- [ ] `ux.permission-rationale` — перед системным диалогом разрешения — объяснение, зачем оно; запрос в момент нужды; после отказа — понятный путь → дефект: запрос всех разрешений при старте, нет объяснения.
- [ ] `ux.loading` — на `network 3g`: скелетоны или индикатор для операций дольше 1 с, возможность отменить долгую операцию → дефект: «замёрзший» экран без индикатора.
- [ ] `ux.law-fitts-hick` — крупные и близкие цели для частых действий; не больше 7–9 равнозначных вариантов без группировки → дефект: мелкая цель рядом с частым действием, длинное меню без групп.
- [ ] `ux.destructive-confirm` — необратимые действия (очистка, выход, удаление локальных данных) спрашивают подтверждение или дают отмену → только наблюдать и закрыть диалог → дефект: нет подтверждения и нет отмены.

## Deep (в дополнение к standard)
- [ ] `ux.all-tasks` — все сценарии из памяти приложения за всех персон.
- [ ] `ux.persona-on-the-go` — те же задачи на `network edge` и в `rotate landscape` → дефект: задача требует двух рук или стабильной сети без причины.
- [ ] `ux.persona-a11y` — задачи на `font-scale 2.0` и с TalkBack (совместно с accessibility).
- [ ] `ux.large-screens` — профили tablet и fold: используется ли место (две панели, адаптивная сетка) → дефект: растянутый телефонный интерфейс, огромные пустые поля.
- [ ] `ux.resume-context` — возврат в приложение после `key HOME` и паузы: понятно, где пользователь и что было сделано → дефект: сброс на главный экран без причины.
- [ ] `ux.microcopy-tone` — тон и единообразие текстов (совместно с content-i18n).
- [ ] `ux.severity-rating` — каждому нарушению эвристики — оценка Нильсена 0–4 и перевод в severity.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| Главная задача приложения не решается новичком | High |
| Back с внутреннего экрана выходит из приложения или ведёт к онбордингу | Medium |
| Нет обратной связи после ключевого действия | Medium |
| Все разрешения запрашиваются при старте без объяснения | Medium |
| Непонятная иконка без подписи на главном действии | Medium / Low |
| Частое действие только в верхнем углу экрана | Low |
| Непоследовательные названия одного и того же | Low |

## Что записывать в находку
- Персону, задачу и шаг, на котором возникла проблема; фактическое и ожидаемое число шагов.
- Экран — activity из `current`; элемент — `id=<resource-id>` или `text="…"` + класс.
- Нарушенную эвристику или паттерн (`check_id`) и обоснование: почему это мешает.
- Окружение: API, профиль железа, вариация, ячейка матрицы `c01…`; repro_rate («3/3»).
- Скриншот `screenshots/<id>-….png` с местом проблемы или `screenrecord` для последовательности; конкретное предложение (текст кнопки, расположение, группировка).
