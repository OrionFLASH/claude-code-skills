# functional — Функциональность

Направление: `functional` · Инструменты: `<SKILL_DIR>/scripts/adb_helpers.py` (ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`; PKG по умолчанию — `app.package` из run-config), `apk_info.py` (`deep_links`, `permissions`), `guard.py` · Усилители: Maestro (повторяемые сценарии), Appium (uiautomator2) — если установлены пользователем

## Цель
Убедиться, что приложение запускается без падений, основные сценарии из памяти приложения и опроса проходят, а навигация, формы, поиск, списки, уведомления, deep links и разрешения работают. Падения и ANR фиксируются по logcat и dropbox.

## Безопасность в этом направлении
- Перед каждым нажатием `adb_helpers.py tap …` guard.py проверяет действие сам: код 3 — запрет, не выполнять и записать «не проверено: запрет <rule>»; код 2 — спросить пользователя и повторить с `--confirmed` только после «да».
- Покупки и подписки, вход через внешние аккаунты (Google, соцсети), звонки и SMS, отправка сообщений и форм реальным людям, удаление аккаунта — никогда. Формы проверяются до валидации, кнопка отправки не нажимается.
- Чужие приложения (Play Store, браузер, звонилка, почта) не трогать: если открылось — сразу `key BACK`, в находку «ведёт в <пакет> — не проверялось».
- Реальные устройства — только с согласием из run-config (`stands.consent`); `monkey` — только на своём эмуляторе без аккаунтов.
- Deep links — только через `adb_helpers.py deeplink` (внутри — `guard.py deeplink`); share и intent наружу — только зафиксировать, что открылось, и вернуться BACK.

## Smoke
- [ ] `fn.crash-on-launch` — чистый запуск → `logcat clear`, `clear`, `launch --cold`, `screenshot`, `crashes` → дефект: FATAL EXCEPTION, «Приложение остановлено», белый или чёрный экран дольше 10 с, выход на рабочий стол.
- [ ] `fn.main-flows` — 1–3 основных сценария из памяти приложения и опроса → `dump-ui`, `tap --text|--id` до последнего безопасного шага → дефект: сценарий не проходится, неверный результат, сообщение об ошибке.
- [ ] `fn.navigation` — Back/Up, нижняя панель, вкладки, боковое меню → каждый пункт, затем `key BACK`; `current` до и после → дефект: пункт не открывает экран или открывает не тот, Back с внутреннего экрана закрывает приложение, пустой экран.
- [ ] `fn.dead-buttons` — главные кнопки на ключевых экранах → `tap`, `dump-ui` и `screenshot` до и после → дефект: нет реакции, нет индикатора, ошибка.
- [ ] `fn.anr` — зависания → весь прогон под `logcat start`, в конце `crashes` → дефект: диалог «Приложение не отвечает», запись ANR в logcat или dropbox.
- [ ] `fn.network-error` — экран с загрузкой данных при `network offline`, затем `network online` → дефект: бесконечная загрузка, пустой экран без сообщения, падение, нет «Повторить».
- [ ] `fn.permissions-basic` — первый запрос опасных разрешений (`apk-info.json` → `permissions`) → когда появился диалог, отказать → дефект: запрос при старте без связи с действием, падение или тупик после отказа.

## Standard (в дополнение к smoke)
- [ ] `fn.forms-validation` — формы, не уходящие людям: пусто, только пробелы, неверный формат → `text "..." --into-id ID`, `key ENTER` → дефект: нет сообщения об ошибке, принимается некорректное, отвергается корректное.
- [ ] `fn.edge-input` — краевой ввод: 500+ символов, спецсимволы `<>'"&%`, `0`, `-1`, максимум из подсказки поля → `text` (только ASCII; кириллица — `--translit` или `--adbkeyboard`, emoji — вручную в окне эмулятора или ADBKeyBoard с согласия) → дефект: падение, молчаливая обрезка, поломка вёрстки, неверное число.
- [ ] `fn.search-filters` — поиск: существующее слово, «ничего не найдено», пустой запрос; фильтры по одному, комбинация, сброс → дефект: результаты не по запросу, нет пустого состояния, сброс не работает, счётчик врёт.
- [ ] `fn.lists` — списки: `scroll down` до конца, подгрузка, обновление жестом (`swipe`), пустые состояния → дефект: дубли, пропуски, бесконечный индикатор, пустой экран без пояснения.
- [ ] `fn.slow-network` — основные сценарии на `network 3g` и `network edge` (только свой эмулятор) → дефект: таймаут без сообщения, двойная отправка, зависший индикатор.
- [ ] `fn.deeplinks` — каждый URI из `apk-info.json` → `deep_links`: `deeplink URI --package PKG` при закрытом и открытом приложении → дефект: не тот экран, падение, пустой экран, браузер вместо приложения для доменов из `app.deeplink_hosts`.
- [ ] `fn.notifications` — уведомления, которые приложение шлёт само (напоминание, загрузка) → вызвать безопасным действием, `notifications`, `shade open`, `tap` по уведомлению → дефект: не приходит, открывает не тот экран, дублируется.
- [ ] `fn.permissions-flows` — отказ, «Только в этот раз», повторный запрос, `revoke PERM` во время работы и после перезапуска, `grant PERM` → дефект: падение, нет пути в настройки, функция молча не работает.
- [ ] `fn.install-update` — `install APK` на чистый стенд; при наличии старой версии — установить её, создать данные, `install NEW.apk --replace`; затем `clear` и `launch --cold` → дефект: ошибка установки, потеря данных при обновлении, падение после `clear`.
- [ ] `fn.share-intents` — «Поделиться», «Открыть в…», карта → `current` после нажатия (ожидается системный выбор или нужный пакет), сразу `key BACK`; кнопки звонка, SMS и письма не нажимаются (запрет guard) — только зафиксировать, что они есть → дефект: падение, ничего не происходит.

## Deep (в дополнение к standard)
- [ ] `fn.every-clickable` — все интерактивные элементы каждого экрана из `dump-ui --json F` → `tap --id|--text` через guard → дефект: нет реакции, падение, ошибка.
- [ ] `fn.monkey` — свой эмулятор без аккаунтов: `monkey PKG --events 500 --seed 42 --throttle 300`, затем `crashes` → дефект: падение или ANR (seed записать для воспроизведения).
- [ ] `fn.uninstall-reinstall` — `uninstall PKG`, `install APK`, `launch --cold`; отдельно `uninstall --keep-data` и повторная установка → дефект: ошибка первого запуска, данные не восстанавливаются или восстанавливаются там, где не должны.
- [ ] `fn.deeplinks-edge` — deep links по образцу из манифеста с несуществующим id, пустым параметром, лишним сегментом → дефект: падение вместо экрана ошибки.
- [ ] `fn.permissions-denied-forever` — двойной отказ («больше не спрашивать») → дефект: функция заблокирована без объяснения и пути в настройки.
- [ ] `fn.automation` — повтор основных сценариев через Maestro или Appium (если установлены) на всех ячейках матрицы → дефект: сценарий проходит на одной ячейке и падает на другой.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| Падение при запуске или в основном сценарии (FATAL EXCEPTION) | Critical |
| ANR в основном сценарии | High |
| Основной сценарий не проходится; deep link из манифеста открывает пустой экран | High |
| Потеря данных пользователя при обновлении поверх старой версии | High |
| После отказа в разрешении функция молча не работает, нет пути в настройки | Medium |
| Нет сообщения об ошибке сети, бесконечная загрузка | Medium |
| Поле принимает некорректное значение | Medium / Low |
| Кнопка без видимой реакции на второстепенном экране | Low |

## Что записывать в находку
- Экран — activity из `current`; элемент — `id=<resource-id>` или `text="…"` + класс из `dump-ui`.
- Шаги с чистого запуска (`clear` → `launch --cold` → нажатия по тексту или id), ожидаемое и фактическое; repro_rate («3/3»).
- Окружение: API, профиль железа, вариация, ячейка матрицы `c01…`.
- Падение или ANR: тип (crash, anr, native), время, `logcat_excerpt` из `crashes` (замаскированный; проверить, что нет токенов и e-mail).
- Скриншоты `screenshots/<id>-before.png` и `screenshots/<id>-after.png`; для нестабильного — `screenrecord --seconds 20`.
- Для monkey — seed, число событий; для deep link — точный URI.
