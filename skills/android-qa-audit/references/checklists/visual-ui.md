# visual-ui — Визуальная часть и интерфейс

Направление: `visual-ui` · Инструменты: `<SKILL_DIR>/scripts/adb_helpers.py` (ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`; PKG — `app.package` из run-config): `dump-ui` (кандидаты `visual.*`), `screenshot`, `screenrecord`, `dark-mode`, `rotate`; `matrix.py variants` · Усилители: рекомендации Material Design (как эталон), Maestro или Appium (скриншоты по сценарию) — если установлены

## Цель
Найти визуальные дефекты на каждом ключевом экране: обрезанный текст, перекрытия, выход за экран, сбитые отступы и сетку, неаккуратные иконки, проблемы тёмной темы, неверные состояния элементов, конфликты с системными барами и вырезом.

## Безопасность в этом направлении
- Перед каждым нажатием `adb_helpers.py tap …` guard.py проверяет действие сам: код 3 — запрет, записать «не проверено: запрет <rule>»; код 2 — спросить пользователя и повторить с `--confirmed` только после «да».
- Чтобы увидеть состояние элемента, не нажимать опасные кнопки (оплата, отправка, удаление): их вид оценивается по скриншоту без нажатия.
- `dark-mode`, `rotate`, `density` на реальном устройстве — только с согласием из `stands.consent`; после проверки вернуть настройки (`dark-mode off`, `rotate portrait`, `density reset`).
- Экран с FLAG_SECURE не снимается (`screenshot` вернёт ошибку) — это не дефект; записать «скриншот запрещён приложением».

## Smoke
- [ ] `visual.reference-shots` — эталонные скриншоты ключевых экранов в базовой вариации → `screenshot screenshots/visual-<экран>-<ячейка>.png` → основа для сравнения по ячейкам и вариациям.
- [ ] `visual.text-ellipsized` — кандидаты из `dump-ui` (текст с многоточием) → подтвердить по скриншоту → дефект: обрезан смысл (название, цена, кнопка); норма — длинное описание в карточке.
- [ ] `visual.overlap` — кандидаты из `dump-ui` (пересечение интерактивных элементов) → подтвердить по скриншоту → дефект: элементы видимо налезают, один перекрывает другой.
- [ ] `visual.offscreen` — кандидаты из `dump-ui` (границы за краем экрана) → подтвердить по скриншоту → дефект: кнопка или текст недоступны без прокрутки, которой нет.
- [ ] `visual.insets` — статус-бар, панель навигации, вырез камеры → `screenshot` → дефект: контент или кнопки под системными барами, текст под вырезом, двойные отступы.
- [ ] `visual.images` — изображения и иконки → дефект: растянуты, размыты, пиксельные, заглушка вместо картинки, обрезаны важные части.

## Standard (в дополнение к smoke)
- [ ] `visual.spacing-grid` — отступы и выравнивание по сетке (кратность 4/8 dp, одинаковые поля карточек) → сравнение скриншотов экранов → дефект: «прыгающие» отступы, разное выравнивание однотипных блоков.
- [ ] `visual.typography` — иерархия шрифтов, начертания, межстрочный интервал единообразны → дефект: три разных размера для одного уровня заголовка, наезжающие строки.
- [ ] `visual.icons` — единый стиль и размер иконок, чёткость, соответствие смыслу → дефект: смешение стилей (контурные и залитые), размытые растровые иконки.
- [ ] `visual.dark-theme` — `dark-mode on`, `stop`, `launch`, скриншоты тех же экранов → дефект: «белые пятна» (светлые карточки, диалоги, WebView), тёмный текст на тёмном фоне, невидимые иконки и разделители.
- [ ] `visual.states` — disabled (по `dump-ui`: `enabled=false` должно отличаться визуально), checked и selected, focused (`key TAB`), pressed (`screenrecord --seconds 5` во время `tap`) → дефект: состояние не видно или неотличимо.
- [ ] `visual.keyboard` — `tap` по полю ввода внизу экрана, `screenshot` → дефект: клавиатура закрывает поле или кнопку отправки, экран не прокручивается.
- [ ] `visual.landscape` — `rotate landscape` на ключевых экранах → дефект: вёрстка ломается, контент обрезан, кнопки вне экрана.
- [ ] `visual.edge-to-edge` — API 35+ (на targetSdk 35+ edge-to-edge обязателен): сравнить скриншоты экрана на API 34 и 35+ → дефект: верхняя панель под статус-баром, нижние кнопки под панелью жестов.
- [ ] `visual.dialogs-sheets` — диалоги, нижние листы, меню на малом экране и в альбомной ориентации → дефект: не помещаются, кнопки диалога за краем, нет прокрутки внутри.
- [ ] `visual.loading-states` — скелетоны, индикаторы, заглушки на `network 3g` → дефект: «скачок» вёрстки после загрузки, индикатор поверх контента.

## Deep (в дополнение к standard)
- [ ] `visual.consistency` — сравнение всех экранов: цвета, радиусы, тени, кнопки одного типа выглядят одинаково.
- [ ] `visual.variants-matrix` — эталонные экраны во всех вариациях ячейки (`font-2.0`, `display-large`, `dark-font`, `rtl`) → повтор кандидатов `dump-ui` в каждой.
- [ ] `visual.small-large` — профили small (720×1280), tablet, fold → дефект: обрезка на малом экране, растянутые элементы на планшете.
- [ ] `visual.splash` — экран запуска (API 31+: системный splash с иконкой) → дефект: обрезанная или пиксельная иконка, двойной splash, белая вспышка в тёмной теме.
- [ ] `visual.notification-icon` — малая иконка уведомления в шторке (`shade open`, `screenshot`) → дефект: серый или белый квадрат вместо силуэта.
- [ ] `visual.transitions` — анимации переходов (`screenrecord --seconds 10`) → дефект: мерцание, «прыжки» элементов, кадр с пустым экраном.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| Главная кнопка за краем экрана или под панелью навигации, недоступна | High |
| Кнопка или текст перекрыты, действие трудно выполнить | Medium |
| «Белые пятна» и нечитаемый текст в тёмной теме | Medium |
| Обрезано название или цена | Medium |
| Клавиатура закрывает поле ввода | Medium |
| Сбитые отступы, разные стили иконок | Low |
| Серый квадрат вместо иконки уведомления | Low |

## Что записывать в находку
- Экран — activity из `current`; элемент — `id=<resource-id>` или `text="…"` + класс; для кандидатов `dump-ui` — исходный check_id и границы элемента.
- Скриншот с проблемой `screenshots/<id>-<ячейка>.png` и, если есть, эталон из другой вариации для сравнения.
- Окружение: API, профиль железа (`WxH@dpi`), вариация (тема, шрифт, ориентация), ячейка матрицы `c01…`.
- Шаги с чистого запуска до экрана; repro_rate («3/3»).
- Ожидаемый вид (по соседним экранам или Material) — конкретно: «отступ 16 dp как у остальных карточек».
