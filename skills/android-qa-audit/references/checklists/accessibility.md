# accessibility — Доступность

Направление: `accessibility` · Инструменты: `<SKILL_DIR>/scripts/adb_helpers.py` (ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`; PKG — `app.package` из run-config): `dump-ui` (кандидаты `a11y.*`, флаги checked, enabled, focused, password), `font-scale`, `key TAB|DPAD_DOWN|ENTER`, `animations`, `screenshot` · Усилители: TalkBack (только свой эмулятор, включается вручную в настройках устройства), Accessibility Scanner (если установлен пользователем)

## Цель
Проверить, что приложением можно пользоваться с TalkBack, крупным шрифтом, клавиатурой и без анимаций: у элементов есть понятные метки, цели нажатия достаточного размера, контраст достаточен, состояния передаются не только цветом. Ориентир — WCAG 2.2 AA и рекомендации Android по доступности.

## Безопасность в этом направлении
- Перед каждым нажатием `adb_helpers.py tap …` guard.py проверяет действие сам: код 3 — запрет, записать «не проверено: запрет <rule>»; код 2 — спросить пользователя и повторить с `--confirmed` только после «да».
- `key ENTER` и двойное касание в TalkBack активируют элемент в фокусе: перед ними проверить его текст вручную — `guard.py action --text "<текст>" --config <RUN_DIR>/run-config.yaml`. `key TAB` и перемещение фокуса безопасны.
- TalkBack и Accessibility Scanner — только на своём эмуляторе; после проверки TalkBack выключить. На реальных устройствах настройки доступности не меняются.
- Покупки, вход через внешние аккаунты, звонки, SMS, отправка сообщений реальным людям — никогда, в том числе через TalkBack.

## Smoke
- [ ] `a11y.missing-label` — кандидаты `dump-ui` (интерактивный элемент без text, contentDescription и текста детей) → подтвердить по скриншоту, что это значимая кнопка или иконка → дефект: TalkBack прочитает «кнопка» без названия.
- [ ] `a11y.touch-target` — кандидаты `dump-ui` (цель меньше 48×48 dp без кликабельного родителя) → подтвердить по скриншоту и пробному `tap` у края элемента → дефект: мелкая цель для частого действия.
- [ ] `a11y.font-2.0` — `font-scale 2.0`, `stop`, `launch` → ключевые экраны, `dump-ui`, `screenshot` → дефект: текст обрезан или не увеличился (размеры не в sp), кнопки недоступны.
- [ ] `a11y.contrast` — оценка по скриншотам ключевых экранов: обычный текст ≥ 4.5:1, крупный (от 18 sp или 14 sp полужирный), иконки и границы полей ≥ 3:1 → сравнить цвета пикселей текста и фона → дефект: явная нехватка контраста (указать оценку как приблизительную).
- [ ] `a11y.label-quality` — метки из `dump-ui` осмысленны → дефект: «button1», «image», «ic_back», имя файла, одинаковые метки у разных кнопок.

## Standard (в дополнение к smoke)
- [ ] `a11y.focus-order` — серия `key TAB` или `key DPAD_DOWN` с `dump-ui` (флаг `focused`) и `screenshot` → дефект: элемент недостижим, порядок прыгает, фокус не виден, ловушка фокуса.
- [ ] `a11y.states` — переключатели, флажки, вкладки: `checked`, `selected`, `enabled` в `dump-ui` совпадают с видимым состоянием → дефект: TalkBack не узнает, что флажок отмечен или кнопка неактивна.
- [ ] `a11y.not-color-only` — ошибки, обязательные поля, статусы → дефект: различаются только цветом, без значка или текста.
- [ ] `a11y.keyboard-fields` — `tap` по полю: клавиатура открывается, действие IME (Далее/Готово через `key ENTER` или `key TAB`) переводит фокус на следующее поле; у пароля `password=true` → дефект: фокус не переходит, клавиатура закрывает поле.
- [ ] `a11y.form-errors` — сообщения об ошибках рядом с полем и текстом, а не только подсветкой → дефект: ошибка только цветом рамки или во всплывающем сообщении, которое быстро исчезает.
- [ ] `a11y.animations` — `animations off` → основной сценарий → дефект: интерфейс зависает в промежуточном состоянии, важная информация только в анимации; после проверки `animations on`.
- [ ] `a11y.talkback` — свой эмулятор, TalkBack включён вручную: свайпами пройти ключевой экран и основной сценарий → дефект: элемент пропускается, читается бессмысленно, действие недоступно, нет навигации по заголовкам.
- [ ] `a11y.custom-controls` — слайдеры, рейтинги, свайп-действия, карусели → дефект: нет альтернативы жесту (кнопки), нет роли и действия для TalkBack.
- [ ] `a11y.scanner` — Accessibility Scanner на ключевых экранах (если установлен пользователем) → каждое замечание подтвердить и оформить в `a11y.*`.

## Deep (в дополнение к standard)
- [ ] `a11y.font-display-max` — `font-scale 2.0` вместе с вариацией `display-large` на всех экранах → дефект: потеря контента или действий.
- [ ] `a11y.talkback-all-flows` — все основные сценарии только с TalkBack → дефект: сценарий невозможно завершить.
- [ ] `a11y.orientation` — оба положения экрана поддержаны (WCAG 1.3.4) → дефект: блокировка ориентации без необходимости.
- [ ] `a11y.timing` — snackbar с действием, таймауты, автопрокрутка каруселей → дефект: действие исчезает раньше, чем успеет пользователь TalkBack; нет паузы.
- [ ] `a11y.dark-contrast` — контраст в тёмной теме (`dark-mode on`) по тем же правилам.
- [ ] `a11y.media` — субтитры у видео, нет автоплея со звуком.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| Основной сценарий невозможно пройти с TalkBack | High |
| Главная кнопка-иконка без метки (`a11y.missing-label`) | High / Medium |
| Текст обрезается при шрифте 2.0, действие недоступно | High / Medium |
| Контраст основного текста заметно ниже 4.5:1 | Medium |
| Цель нажатия меньше 48×48 dp у частого действия | Low / Medium |
| Состояние передаётся только цветом | Medium |
| Неосмысленная метка («ic_back») | Low |

## Что записывать в находку
- Экран — activity из `current`; элемент — `id=<resource-id>` или `text="…"` + класс; размер в dp для `a11y.touch-target`.
- Критерий WCAG 2.2 (номер и уровень) и что прочитал TalkBack (если проверялось).
- Шаги с чистого запуска (`clear` → `launch --cold`), для фокуса — последовательность клавиш; repro_rate («3/3»).
- Окружение: API, профиль железа, вариация (шрифт, тема), ячейка матрицы `c01…`.
- Скриншот `screenshots/<id>-….png` с отмеченным элементом; для контраста — цвета текста и фона и оценка отношения.
