# logic-state — Логика и состояние

Направление: `logic-state` · Инструменты: `<SKILL_DIR>/scripts/adb_helpers.py` (ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`; PKG — `app.package` из run-config), `matrix.py variants` (offline, net-3g, net-edge, net-switch, timezone) · Усилители: Maestro (повтор сценария с проверкой данных), Appium (uiautomator2) — если установлены

## Цель
Проверить, что данные и состояние приложения согласованы: сохраняются между экранами и запусками, не дублируются при повторных нажатиях и медленной сети, корректно ведут себя офлайн, при повторе после ошибки, при смене часового пояса и после очистки данных.

## Безопасность в этом направлении
- Перед каждым нажатием `adb_helpers.py tap …` guard.py проверяет действие сам: код 3 — запрет, записать «не проверено: запрет <rule>»; код 2 — спросить пользователя и повторить с `--confirmed` только после «да».
- Двойные нажатия и повторы — только на безопасных действиях (избранное, локальная заметка, фильтр, черновик). Оплата, отправка сообщений реальным людям, звонки, SMS, удаление аккаунта — никогда, даже «одним нажатием».
- Создавать и менять данные — только локально или в тестовом аккаунте из run-config; чужие записи не трогать.
- `clear`, `timezone`, `network` на реальном устройстве — только с согласием из `stands.consent`; скорость сети — только на своём эмуляторе.

## Smoke
- [ ] `logic.persist-screens` — данные, введённые или выбранные на экране, видны на следующем и при возврате (`key BACK`) → `dump-ui` до и после → дефект: значение пропало, сброшено к умолчанию, показано старое.
- [ ] `logic.persist-relaunch` — сохранённое (настройки, избранное, черновик) после `stop` и `launch` → дефект: данные пропали или откатились.
- [ ] `logic.double-tap` — два `tap` подряд по одной кнопке безопасного действия → `dump-ui` → дефект: две записи, два открытых экрана, двойной переход, счётчик +2.
- [ ] `logic.back-depth` — пройти 4–5 экранов вглубь, затем `key BACK` по одному с `current` → дефект: стек нарушен, повтор экрана, возврат к онбордингу или входу, потеря введённого.
- [ ] `logic.consistency` — счётчики, бейджи, итоги, суммы совпадают с содержимым списков и деталей → дефект: расхождение чисел между экранами.

## Standard (в дополнение к smoke)
- [ ] `logic.race-slow-net` — на `network edge`: быстро переключать вкладки, фильтры, поисковые запросы → дефект: показан результат прошлого запроса, смешаны данные, индикатор завис.
- [ ] `logic.offline-cache` — `network offline` после загрузки данных → дефект: пустой экран вместо кэша, нет пометки «нет сети» или «данные устарели», действие офлайн теряется без предупреждения.
- [ ] `logic.retry-after-error` — `network offline` → ошибка → `network online` → «Повторить» → дефект: повтор не работает, запрос ушёл дважды, состояние формы потеряно.
- [ ] `logic.sync` — изменить элемент в деталях → вернуться в список, обновить жестом (`swipe`) → дефект: список не обновился, изменения откатились после обновления.
- [ ] `logic.filters-state` — фильтры, сортировка и позиция прокрутки при возврате из деталей → дефект: сброс к началу списка, фильтр потерян без причины.
- [ ] `logic.edit-cancel` — начать редактирование и отменить (`key BACK`, «Отмена») → дефект: изменения сохранились, нет предупреждения о несохранённых данных там, где оно ожидается.
- [ ] `logic.timezone` — `timezone Asia/Tokyo` (вариация `timezone`), `stop`, `launch` → даты, «сегодня/вчера», время событий и напоминаний → дефект: сдвиг дат, неверный день, время в UTC без пометки.
- [ ] `logic.after-clear` — `clear`, `launch --cold` → дефект: падение, остатки прежних данных или входа, онбординг не показан там, где ожидается.
- [ ] `logic.notification-entry` — открыть экран из уведомления, затем `key BACK` → дефект: выход из приложения вместо главного экрана, дубль экрана в стеке.

## Deep (в дополнение к standard)
- [ ] `logic.date-boundary` — `timezone Pacific/Kiritimati` и `timezone Pacific/Pago_Pago` (разные календарные дни) → дефект: события «сегодня» не совпадают, сортировка по дате ломается, отрицательные интервалы.
- [ ] `logic.offline-queue` — действие офлайн → вариация `net-switch` → дефект: действие отправлено дважды, потеряно, конфликт без сообщения.
- [ ] `logic.update-migration` — установить старую версию (если дана), создать данные, `install NEW.apk --replace` → дефект: данные потеряны, искажены, настройки сброшены.
- [ ] `logic.numbers` — суммы, округления, проценты, единицы (граничные значения из `fn.edge-input`) → дефект: неверный итог, `NaN`, `-0`, переполнение.
- [ ] `logic.deeplink-over-state` — deep link (`deeplink URI --package PKG`) при открытой заполненной форме → дефект: введённое потеряно без предупреждения, стек сломан.
- [ ] `logic.long-idle` — приложение в фоне 30+ минут (или `doze enter`/`doze exit`) → вернуться → дефект: устаревшие данные без обновления, падение на истёкшей сессии.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| Потеря пользовательских данных после перезапуска или обновления | Critical |
| Двойной тап создаёт дубль записи или двойной заказ в тестовом сценарии | High |
| Результаты прошлого запроса на медленной сети показаны как текущие | High / Medium |
| Неверная дата или день из-за часового пояса | Medium |
| Позиция списка и фильтры сбрасываются при возврате | Low |
| Счётчик в бейдже расходится со списком | Low / Medium |

## Что записывать в находку
- Экран — activity из `current`; элемент — `id=<resource-id>` или `text="…"` + класс; значения до и после (из `dump-ui`).
- Шаги с чистого запуска (`clear` → `launch --cold`), точная последовательность и паузы (для гонок — профиль сети и интервал между нажатиями); repro_rate («2/5» для гонок — норма записать как есть).
- Окружение: API, профиль железа, вариация (`offline`, `net-edge`, `timezone`), часовой пояс, ячейка матрицы `c01…`.
- Скриншоты `screenshots/<id>-before.png`, `screenshots/<id>-after.png`; для гонок — `screenrecord --seconds 20`.
- `logcat_excerpt` (замаскированный), если есть ошибки запросов или исключения.
