# security-passive — Пассивная безопасность

Направление: `security-passive` · Инструменты: `<SKILL_DIR>/scripts/apk_info.py analyze <apk> --out <RUN_DIR>/apk-info.json` и `apk_info.py summary <RUN_DIR>/apk-info.json` (манифест, подпись apksigner, `risks`), `adb_helpers.py` (ниже без пути и общих опций `--serial S --run-dir <RUN_DIR>`): `logcat`, `permissions`, `screenshot`, `dump-ui`, `notifications` · Усилители: нет — только пассивное наблюдение

## Цель
Найти то, что видно без атак: опасные флаги сборки и манифеста, проблемы подписи, незашифрованный трафик, секреты и персональные данные в logcat, лишние разрешения и экспортируемые компоненты, незащищённые экраны с чувствительными данными.

## Безопасность в этом направлении — ЖЁСТКИЕ ОГРАНИЧЕНИЯ
- Только чтение APK, манифеста, logcat, дерева UI и обычное использование приложения. Каждое нажатие — через `adb_helpers.py tap …` (код 3 — «не проверено: запрет <rule>», код 2 — спросить и повторить с `--confirmed` только после «да»).
- **Запрещено**: перебор паролей и кодов, инъекции (SQL, интенты с подменёнными данными, пути), обход авторизации (в том числе прямой запуск внутренних activity), root-манипуляции (su, remount, перехват с подменой сертификатов, Frida), вмешательство в чужие данные и аккаунты.
- Экспортируемые компоненты только перечисляются и оцениваются по манифесту; интенты в них не отправляются.
- Секреты, токены, e-mail, телефоны маскируются в находках, отчётах и issues: первые 4 символа + `…` + длина. Полные значения не сохраняются даже в `raw/` и `logs/`.
- Серьёзная утечка (действующий ключ, чужие персональные данные) — остановить публикацию в открытые репозитории и спросить пользователя.

## Smoke
- [ ] `sec.debuggable` — кандидат из `risks` (`android:debuggable=true`) → сверить с тем, что сборка заявлена как релизная → дефект: отладочная сборка выдаётся за релиз.
- [ ] `sec.test-only` — кандидат из `risks` (`android:testOnly=true`) → дефект для релизной сборки.
- [ ] `sec.signature-invalid` — подпись не проходит проверку apksigner (`risks`) → дефект: повреждённый или неверно подписанный APK.
- [ ] `sec.debug-signature` — подпись отладочным сертификатом (CN=Android Debug) → дефект для релиза.
- [ ] `sec.cleartext` — кандидат из `risks` (cleartext разрешён явно или по умолчанию для targetSdk) + `logcat dump --package PKG` во время основного сценария: строки с `http://` → дефект: запросы к API или вход по HTTP.
- [ ] `sec.logcat-secrets` — `logcat start` на весь сценарий, затем `logcat dump` → поиск `token`, `Bearer`, `password`, `Authorization`, `@`, номеров телефонов → дефект: секреты или персональные данные в журнале (записать замаскированно).

## Standard (в дополнение к smoke)
- [ ] `sec.allow-backup` — `allowBackup` без правил резервирования (кандидат из `risks`) → дефект: данные приложения попадают в резервную копию без ограничений (Low).
- [ ] `sec.exported-component` — каждый экспортированный компонент без разрешения из `risks` и `apk-info.json` → `components` → оценить по имени и intent-filter, нужен ли экспорт (launcher, deep links, приём «Поделиться» — норма) → дефект: экспорт служебных activity, сервисов, receiver и особенно provider без разрешения.
- [ ] `sec.special-permissions` — особые разрешения из `risks` (наложение поверх окон, доступ ко всем файлам, установка пакетов и т.п.) → сверить с функциями приложения → дефект: нет понятной причины.
- [ ] `sec.permissions-excess` — опасные разрешения из `apk-info.json` и `permissions PKG` → дефект: разрешение не нужно ни одной функции; запрос до того, как функция понадобилась.
- [ ] `sec.flag-secure` — экраны с паролями, платёжными данными, документами, кодами подтверждения → `screenshot` (ошибка «FLAG_SECURE?» — ожидаемо и правильно) → дефект: такой экран снимается свободно (Low, рекомендация).
- [ ] `sec.recents-preview` — на чувствительном экране `key APP_SWITCH`, `screenshot` → дефект: данные видны в превью «Недавних».
- [ ] `sec.password-fields` — поля пароля и кодов в `dump-ui` имеют `password=true` → дефект: пароль отображается открытым текстом без кнопки «показать».
- [ ] `sec.notification-content` — `notifications PKG` и `shade open` → дефект: коды, суммы, личные сообщения целиком в уведомлениях без настройки скрытия.
- [ ] `sec.target-sdk` — минимально допустимый targetSdk: кандидат `compat.target-sdk` из `risks` → отметить здесь как риск устаревших мер защиты, оформить в compatibility.

## Deep (в дополнение к standard)
- [ ] `sec.error-disclosure` — сообщения об ошибках в UI и тостах → дефект: stack trace, SQL, внутренние адреса серверов, версии библиотек.
- [ ] `sec.session-after-clear` — после `clear` и `launch --cold` → дефект: сессия сохранилась (вход без данных), если это не ожидаемое поведение.
- [ ] `sec.logout-back` — тестовый аккаунт: выйти (через guard), затем `key BACK` → дефект: видны экраны с личными данными.
- [ ] `sec.deeplink-schemes` — `deep_links` из `apk-info.json`: собственные схемы (`myapp://`) и https без проверки домена → дефект (Info/Low): ссылку может перехватить другое приложение; только по манифесту, без попыток перехвата.
- [ ] `sec.clipboard` — копирование кодов, паролей, токенов в буфер → дефект: чувствительное значение копируется без необходимости.
- [ ] `sec.third-party-logs` — теги сторонних SDK в logcat с идентификаторами пользователя → записать замаскированно.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| Действующий токен или чужие персональные данные в logcat | Critical (не публиковать в открытые репозитории, спросить пользователя) |
| Релизная сборка с `debuggable=true`, подпись не проходит проверку | High |
| Вход или API по HTTP (`http://` в logcat) | High / Medium |
| Экспортированный provider или служебный компонент без разрешения | Medium |
| Особые разрешения без понятной причины | Medium / Info |
| allowBackup без правил, нет FLAG_SECURE на экране с платёжными данными | Low |
| Собственная схема deep link без проверки домена | Info |

## Что записывать в находку
- Источник: поле из `apk-info.json` (`risks`, `components`, `permissions`, `signature`) или строка logcat с временем и тегом.
- Экран — activity из `current`, если находка связана с UI; шаги с чистого запуска; repro_rate («3/3»).
- Значения секретов и персональных данных — только **замаскированно** (`eyJh…(812)`); `logcat_excerpt` — после маскирования.
- Окружение: API, профиль железа, ячейка матрицы `c01…`; скриншот `screenshots/<id>-….png` для UI-находок.
- Рекомендацию (например, `android:exported="false"`, `network_security_config` без cleartext, правила `dataExtractionRules`) и пометку «пассивная проверка, без активного тестирования».
