# Матрица глубины

Матрицу строит `scripts/matrix.py build --config <RUN_DIR>/run-config.yaml` (env.json и apk-info.json берутся из той же папки) → `device-matrix.json`; `matrix.py show` — таблица для пользователя, `matrix.py variants` — вариации и команды за ними.

**Ячейка** = версия Android (API) × профиль железа (отдельный AVD или устройство). **Вариации** (тёмная тема, шрифт, поворот, язык, сеть, батарея) — настройки на уже запущенном стенде, без отдельного AVD.

| Параметр | smoke | standard | deep |
|----------|-------|----------|------|
| Версии Android | 1: targetSdk (или ближайшая установленная ≤ target+1 — без загрузки) | 3: нижняя (minSdk, не ниже 24 на arm64 / 21 на x86_64), середина (29–34), targetSdk | до 7: нижняя, 29, 31, 33, 34, target, последняя установленная |
| Железо | телефон 4 ГБ, 4 ядра | + слабый: 720×1280, 2 ГБ, 2 ядра (на нижней и целевой версии) | + малый экран, планшет, складной (API ≥ 32) на целевой версии |
| Ячеек (обычно) | 1 | 4–5 | 10–12 |
| Вариации на основной ячейке | — | тёмная тема + шрифт 1.3, альбомная, 3G, без сети | + шрифт 2.0, масштаб экрана, RTL, EDGE, смена сети, низкий заряд, экономия, Doze, часовой пояс |
| Остальные ячейки | — | только базовые настройки | только базовые (full — все вариации) |
| Направления на основной ячейке | все выбранные | все выбранные | все выбранные |
| Направления на остальных | — | functional, visual-ui, device-config-compat, compatibility, lifecycle-resilience, performance, accessibility (из выбранных) | то же |
| Чек-листы | разделы «Smoke» | «Smoke» + «Standard» | все разделы |
| Сценарии | запуск, основной путь, навигация, падения | все основные задачи, разрешения, уведомления, deep links | + граничный ввод, прерывания, гонки, обновление поверх старой версии |
| Жизненный цикл | поворот, свернуть-развернуть | + смерть процесса в фоне, trim-memory, смена темы и языка на лету | + Doze/standby, смена сети во время запроса, «Не сохранять действия» (вручную) |
| Производительность | холодный запуск ×3 | холодный/тёплый ×5, память до/после, jank на списках | + батарея, low-end, рост памяти после 10 поворотов |
| monkey (если выбран) | 300 событий, seed 42 | 500 событий, 2 seed | 1000+ событий, 3 seed, на low-end |
| Доступность | дерево элементов на ключевых экранах | все экраны: метки, цели 48 dp, шрифт 1.3 | + шрифт 2.0, TalkBack вручную, контраст по скриншотам |
| Скриншоты | на каждую находку | + эталон каждого экрана на основной ячейке | + на каждой вариации |
| Ориентировочное время | 20–40 мин | 1,5–3 ч (2 потока) | 4–8 ч (2–4 потока) |

`matrix.mode: full` — полное произведение версий и железа (много ячеек; только по явной просьбе). Явный список версий (`android.apis: [26, 33, 35]`) или железа (`devices.hardware`, `devices.custom`) главнее таблицы. `include_latest` / `include_min` добавляют последнюю установленную версию и minSdk.

## Свои AVD, профиль 8 ГБ и свои ячейки
- **Существующие AVD скила переиспользуются.** Если среди AVD `qa-*` с меткой скила есть такой же по API, ОЗУ, ядрам и профилю устройства — ячейка берёт его (`stand.existing: true`, «(есть)» в таблице, `resources.avds_existing`), а не создаёт новый. Свой AVD того же API с другими параметрами — подсказка в «Примечаниях»: «взять вместо: `devices.hardware: [<имя>]`».
- **Имя своего AVD как профиль железа**: `devices.hardware: [qa-api34-pixel7-8gb-4c]` — ОЗУ, ядра, профиль и API берутся из его `config.ini`, ячейка — только на его API. AVD пользователя так не берутся (только `stands.use_avds`, с разрешения, `-read-only`).
- **Профили:** `phone` (4 ГБ), `phone-8gb` (8 ГБ, 4 ядра), `low-end`, `low-1gb`, `small`, `large`, `tablet`, `fold`; свои — `devices.custom` («8 ГБ ОЗУ» в запросе → `hardware: []` + свой профиль 8 ГБ).
- **Свои ячейки со сценарием** — `matrix.cells`: долгая запись, обработка большого файла, работа в фоне:
  ```yaml
  matrix:
    cells:
      - id: rec60
        api: 34
        hardware: phone-8gb            # или имя своего AVD qa-…
        scenario: запись 60 мин, экран выключен
        manual_minutes: 10             # работа агента: старт, проверка, оформление
        background_minutes: 60         # фоновая задача (adb_helpers.py job … -- soak)
  ```
  Ячейка `custom`; в таблице — «≈ ручное + фон», итог `time: {manual_minutes, background_minutes}` и строка «Время: ручная работа ≈ N мин + фоновые задачи ≈ M мин». Фоновые задачи идут, пока агент работает с другим стендом (`long-runs.md`), поэтому общее время меньше суммы.

## Образы и время
- Ячейки, для которых образа нет, помечены «скачать»; список и оценка размера — в `resources.images_to_install` (≈ 1–2 ГБ загрузки на образ). Загрузка — только после согласия; без согласия ячейка заменяется ближайшей установленной версией или пропускается с пометкой «не проверено: нет образа».
- Первый запуск AVD — холодная загрузка 1–3 мин; далее — по `wait-boot`.
- Реальные устройства (`stands.use_devices`) и разрешённые чужие AVD (`stands.use_avds`) добавляются отдельными ячейками и закрепляются за одним потоком.

## Связь с направлениями
- Пункт чек-листа не предусмотрен для глубины — не выполнять.
- `compatibility` — сравнение поведения между ячейками разных API (что есть на одной версии и нет на другой): при smoke только если пользователь сам назвал несколько версий.
- `device-config-compat` при smoke — только поворот и тёмная тема на основной ячейке.
- `security-passive` — один раз на основной ячейке (по APK и журналам), не на каждой версии.
