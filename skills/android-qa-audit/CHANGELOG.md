# Журнал изменений android-qa-audit

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — SemVer, теги `android-qa-audit/vX.Y.Z`.

## [1.2.0] — 2026-10-09
По отзыву реального исследовательского прогона голосового приложения (три эмулятора, записи до 60 минут, публикация в чужой трекер по его формам; issues #13–#21). Новые поля run-config и находок необязательные: старые `run-config.yaml` и `findings.json` проходят без изменений. Изменение поведения: `tap --text` при нескольких равноценных совпадениях больше не нажимает первое — код 2 и `ambiguous: N matches` (выбрать `--index`); `disclosure: full` теперь называется `tool` (старое значение принимается), а `none` убирает и скрытый маркер.

### Добавлено
- **Звук в микрофон эмулятора** (`references/audio-input.md`): `adb_helpers.py mic-status` / `mic-inject --wav … [--via auto|grpc|loopback|file] [--loop N] [--at-sec N] [--duration S]` — три пути по порядку, недоступный путь отвечает «не поддерживается: <причина>» и называет следующий. Путь 1 — gRPC `EmulatorController/injectAudio` с токеном: `avd_manager.py start <AVD> --mic-inject` (`-grpc <свободный порт> -grpc-use-token`, звук не выключается), токен читается из discovery-файла эмулятора (`adb emu avd discoverypath`, `grpc.token`) и передаётся как `authorization: Bearer …`, нигде не печатается. `scripts/grpc_emu.py` — клиент gRPC на стандартной библиотеке (HTTP/2 h2c, HPACK с Хаффманом, управление потоком), без `grpcio`. Путь 2 — виртуальное аудиоустройство хоста (BlackHole / Loopback / snd-aloop / VB-Cable): только проверка (`check_env`) и воспроизведение, если пользователь сам выбрал устройство; `adb emu avd hostmicon` — с подтверждением. Путь 3 — `push-media` + `import-file`.
- **Флаги эмулятора**: `avd_manager.py start --extra-args "…"` по белому списку `guard.py emulator-args` (gRPC — только с `-grpc-use-token` / `-grpc-use-jwt`; микрофон и камера хоста, прокси, tcpdump — после «да», `--confirmed`; образы, `-qemu`, `-writable-system`, `-selinux` — запрет), `--keep-audio`.
- **Экраны без дерева элементов**: `tap X Y --no-ui` / `long-press … --no-ui` (guard по пакету и экрану переднего плана, элемент — из последнего снимка дерева этого стенда, если он свежий; скриншот до нажатия; запись в `actions.jsonl`), `dump-ui --retry N` и `--ignore-animations`.
- **Тексты и поиск**: `dump-ui --texts` (все тексты целиком, границы и `box` для разметки), `--grep`; `find` с `box`; ранжирование совпадений `tap` (точный текст, кликабельный элемент, короткий текст), `ambiguous: N matches`; `--expect-text` / `--expect-gone` / `--expect-change` / `--wait` — нажатие прошло, но экран не изменился → код 5; `scroll` сообщает `changed`; `launch --wait-focus`.
- **Долгие сценарии** (`references/long-runs.md`): `adb_helpers.py soak` — старт, **предусловие** (`--expect-text`, `--service`; не выполнено → `invalid` сразу), метрики по таймеру в `raw/soak-*.jsonl` (PSS, свободное место, фокус, PID, сервис, батарея, тепловой статус, загрузка хоста), скриншоты, выключение и включение экрана, стоп, проверка итога (длительность на экране, длительность файла WAV/MP4/Ogg), статусы `ok` / `interrupted` / `result-mismatch` / `invalid` / `stopped`; `adb_helpers.py job start|status|stop|log|list` — фоновые задачи (`raw/jobs/`, `logs/job-*.log`, строка в журнале). `build_report.py` — раздел «Длинные сценарии».
- **Аннотированные скриншоты** (`references/screenshots.md`): `scripts/annotate_android.py` (пиксели снимка → dp по density, элементы по тексту из дерева, автопроверка; рисует `scripts/node/annotate.js` — вендорная копия из site-qa-audit), `adb_helpers.py screenshot --mark "x,y,w,h|подпись|error"`; `scripts/finding.py add/shot/viewed/list` — находка со скриншотом и разметкой без ручного JSON; в схеме `shots` (`original`, `annotated`, `spec`, `marks`, `viewed`); черновики показывают аннотированный снимок вместо оригинала.
- **Публикация** (`references/repo-sync.md`): их формы issue — `issue_forms.py fetch/show/map/render` и `render_draft.py --form auto|PATH --form-map map.json` (тело как из веб-формы, точные варианты выпадающих списков, обязательные поля и флажки — в «Проверить»); документы «уже известно» — `known_docs.py fetch/check/set` (кандидаты с цитатой, статус `KNOWN` — не публикуется, раздел в отчёте); вложения веткой — `attachments.py plan/push --yes/verify` через contents API (без локального клона), ссылки `blob/<ветка>/…?raw=true`, `repos[].attachments: branch`; `disclosure: tool|none` в run-config (`publish.disclosure`, `repos[]`) и опросе, по умолчанию `tool`; `none` — без подписи, маркеров и меток инструмента, для чужого трекера — предупреждение (`repos[].ours: true` — свой); трейлеры коммитов Claude Code не затрагиваются; «человеческие» шаги — `--human-steps` / `steps: human`. Общий код — новые модули `shared/scripts/qa_issueforms.py`, `qa_known.py`, `qa_attachments.py`.
- **Файлы и ввод**: `push-media` (файл → `/sdcard/<папка>/qa-<имя>` + медиасканер, `--remove`), `import-file --name … --folder …` для системного выбора файла (папки, повторы, прокрутка; одно `--confirmed` на весь импорт), `rules.preapproved_packages` (системное приложение «спросить» — на весь прогон после одного вопроса; запреты не снимает); `text --clipboard` (кириллица через буфер обмена эмулятора по gRPC, не для секретов); `ime status` / `ime install-adbkeyboard --apk …` (APK даёт пользователь, только свой эмулятор, после «да»).
- **Уведомления**: `notifications` возвращает все активные уведомления пакета — постоянные и foreground-сервиса, `category`, `flags`, `ongoing`, прогресс (`progress`, `progress_max`, `percent`), `actions`, — пропускает архив; `foreground_services` из `dumpsys activity services`. Чек-лист `ux.progress-notification`.
- **logcat**: шумовые теги эмулятора (`EGL_emulation`, `BufferPoolAccessor*`, `HostConnection`… уровней V/D/I) отбрасываются и считаются, `--keep-noise`, `logcat.noise_tags`; `logcat stop|dump --summary` — уровни, теги, различные ошибки, падения.
- **Замеры и хост**: каждая метрика пишет загрузку хоста (эмуляторов рядом, load average); `start-time` и отчёт помечают замеры рядом с другими эмуляторами; `parallelism.md` — замеры скорости только на свободном хосте, долгие ожидания — фоновые задачи, а не субагенты.
- **Матрица**: свои AVD `qa-*` с теми же параметрами переиспользуются (`stand.existing`), имя своего AVD — профиль железа (на его API), профиль `phone-8gb`, `matrix.cells` со сценарием и временем «ручное + фон», подсказки о своих AVD того же API.
- **Опрос**: лёгкий режим `intake.py from-text --lite` (только неясное одним вопросом и план, затем сразу работа); скил, названный в запросе по имени, — явный вызов без вопроса-подтверждения; подсказки для кириллицы и голосовых приложений; `publish.disclosure`.
- **Обёртка** `scripts/qa <serial> <команда> …` (и `qa.ps1`) вместо переменных-команд, которые zsh не делит на слова; примеры в документации переписаны; тест проверяет, что таких примеров нет.
- Тематический чек-лист `references/checklists/audio-voice.md`; `--journal-done "<пункт>"` у всех команд `adb_helpers.py`; `wait-boot` печатает `"ready": true` и «готов».

### Исправлено
- `notifications` не видел уведомление foreground-сервиса с прогрессом (ложное «уведомлений нет»): разбор по всем записям пакета, CRLF, извлечение `extras` по строкам.
- `tap` требовал рабочий `dump-ui` даже для нажатия по координатам — теперь `--no-ui`; `tap --text` попадал в абзац диалога вместо кнопки — ранжирование и `ambiguous`.
- `check_env`: adb вне PATH — больше не WARN (скил вызывает adb по полному пути).
- Сообщения об ошибках gRPC и журналы эмулятора могли содержать токен — маскируются (`masking.py`: `token=`/`grpc.token=` и точные известные секреты).
- `guard.py` принимает цель, начинающуюся с «-» (`guard.py emulator-args "-allow-host-audio"`).

### Тесты
- `tests/v12.sh` (вызывается из `unit.sh`): поддельный сервер gRPC на HTTP/2 (`helpers/fake_grpc.py`: Bearer-токен, Хаффман, окно потока) и примеры RFC 7541; поддельные `gh` (формы, документы, contents API), `node` (annotate.js), сценарии экранов в фейковом adb (`FAKE_ADB_UI_FLOW`: выбор файла, запись, диалог), сбои `uiautomator dump`, исчезающий сервис и процесс, `pull` файла итога; `helpers/doc_zsh.py` — нет примеров, ломающихся в zsh.

## [1.1.0] — 2026-10-09
Перенос применимого из обратной связи по site-qa-audit (08–09.10.2026). Новые поля run-config и схемы находок необязательные: старые `run-config.yaml` и `findings.json` проходят без изменений. Намеренно несовместимое: guard больше не «пропускает» при сбое.

### Безопасность (исправлено)
- **Fail closed.** `guard.py`: нет `--config` или файла, битый YAML, неверный регэксп в правилах (`forbidden_screens`, `forbidden_deeplinks`, `adb_require_confirmation`, `screen_pattern`), неверные аргументы (раньше код 2 argparse читался как «confirm»), внутренняя ошибка — `{"decision": "unavailable"}` и **код 4**; без `--config` решения больше не выдаются. `adb_helpers.py`: конфиг указан, но не найден или не прочитан, неверное правило, ошибка guard — **код 6**, ничего не выполняется (4 у него по-прежнему «не поддерживается / не найдено»). Блок правил §4 и задание исполнителю: эти коды, traceback, «No such file» = СТОП; до работы — `guard.py selftest`.
- **Стенды потоков (вместо реестра вкладок).** `avd_manager.py start` не запускает уже запущенный AVD второй раз (код 3: работать в нём), `--owner wN` записывает поток в `stands.json`, `stop --owner wN` не останавливает стенд другого потока (код 3). `guard.py`: `adb kill-server` — всегда запрет (обрывает все стенды и потоки).

### Добавлено
- **Находки текстом.** Исполнитель возвращает блок ```` ```qa-findings ```` в последнем сообщении (файлы не пишет); `scripts/ingest_findings.py` — проверка по схеме, id, `not_checked`, `questions.json`, сообщение в `raw/messages/` (общий модуль `shared/scripts/qa_ingest.py`).
- **Независимая перепроверка до публикации.** Поле `repro` у находки (`{"adb": [аргументы adb_helpers.py], "expect_exit"|"expect"}` или `{"argv"}` скрипта скила); `scripts/recheck.py` (`run --subst SERIAL=…` — дважды, `set` — ручная проверка другим исполнителем, `legal`, `gate`); `build_report.py publish-table` — колонка «Перепроверка», без подтверждения — «НЕ публиковать» (общий модуль `qa_recheck.py`).
- **Прямая публикация** (`publish_mode: direct`): `scripts/direct_publish.py` (`check` — gate и дубли через `fingerprint.py match` по выгрузке `raw/issues-*.json`, `record` → `published.json`, `next`, `status`); `repo-sync.md` §4a; `render_draft.py detailed --body-only` (общий модуль `qa_direct.py`).
- **Юридическое.** Нормы права и финансовые последствия — только «возможно применимо» (`legal.norms`), вторая проверка другим исполнителем (`recheck.py legal`), «требуется проверка юристом» в черновике (`render_draft.py`, раздел «Правовые нормы»); без этого gate закрыт. SKILL.md, `safety-rules.md` §3 п. 12.
- Схема находки: `repro`, `recheck`, `legal`, `ingested`, `source_id`. `parallelism.md`: реестр стендов, находки блоком, независимая перепроверка, новое задание исполнителю. `INSTALL.md`: обновление через маркетплейс по шагам.

### Тесты
- `tests/unit.sh`: fail closed `guard.py` (без конфига, нет файла, аргументы, регэксп) и `adb_helpers.py` (код 6, на устройстве ничего не выполнено), `adb kill-server`, повторный `start` того же AVD и `stop` чужого потока, `ingest_findings.py`, `recheck.py` на фейковом adb (confirmed / not-reproduced / refused, gate, ручная и правовая проверка), `direct_publish.py`, `render_draft.py --body-only`, колонка «Перепроверка». Тест запуска эмулятора больше не предполагает, что порт 5556 свободен на машине (берёт фактический serial).

## [1.0.1] — 2026-10-08
Исправления по первому боевому прогону (smoke, API 34, эмулятор скила) и правило «результаты по умолчанию в `.gitignore`». Старые `run-config.yaml` и `findings.json` работают без изменений.

### Исправлено
- `adb_helpers.py crashes`: падение чужого процесса больше не засчитывается приложению. Падение приложения — только его процесс («Process: <pkg>[:…]» или PID приложения по «Start proc» и `ps`), ANR — только «ANR in <pkg>»; падения других процессов (UiAutomation от `dump-ui` — `java.lang.RuntimeException: Bad file descriptor`, сервисы Google, system_server, другие приложения) — отдельным списком `other_processes` с `owner` (`tool` / `system` / `other-app`) и `related_to_app` (WebView, запущенный для приложения). `raw/crashes-<serial>.json` — `{package, items, other_processes}`; `build_report.py` читает и старый формат, чужие падения показывает отдельной таблицей и не считает в итоге. Dropbox: точное имя процесса, дубль события из logcat не добавляется.
- `adb_helpers.py dump-ui` после `rotate`: размер экрана — по повороту самого дампа (`<hierarchy rotation>` + `wm size`), запасной путь — `dumpsys window displays` (`cur=WxH`, `mRotation` / `mCurrentRotation`) и `dumpsys input` (`SurfaceOrientation` или `Viewport … orientation`); на Android 13+ строки `SurfaceOrientation` нет, из-за этого в альбомной ориентации были ложные `visual.offscreen`. Системные панели и вырез входят в размер экрана. `rotate` ждёт поворота до 5 с и возвращает фактический размер, `rotation_index`, `applied`.
- `matrix.py`: `devices.hardware: []` с непустым `devices.custom` — только свои профили (без лишней ячейки «телефон 4 ГБ»); оба пустые — по глубине; `null` — как раньше. Первый профиль — основной (primary). `intake.py`: запрос «N ГБ ОЗУ» без названных профилей даёт `hardware: []` и свой профиль.
- `avd_manager.py install-image` принимает `--run-dir`: образ (установленный или уже имевшийся) записывается в `stands.json → images_installed` и строкой в `journal.md`; шаг плана `create` показывает `--run-dir`.
- Шум «integer expression expected» от ранней сборки Java (`25-ea`) в `sdkmanager`/`avdmanager`: скрывается, если команда завершилась с кодом 0 (`sdkutil.run_sdk_tool`), с короткой пометкой «безвредно»; при ошибке вывод целиком. `check_env` (без `--fast`) запускает `sdkmanager --version` и отмечает в строке cmdline-tools, что шум безвреден.
- `masking.py`: `password="false"` в дампе uiautomator больше не превращается в `password="***"` (это флаг, не секрет); `find_unmasked` его не отмечает.
- `guard.py`: `ime set/enable/disable` — изменение устройства (раньше считалось чтением).

### Добавлено
- `adb_helpers.py text`: для не-ASCII по умолчанию — отказ с подсказкой; `--translit` — латинская транслитерация (кириллица, украинские буквы, акценты; в выводе `translit: true` и `typed`); `--adbkeyboard` — через ADBKeyBoard, только на эмуляторе скила и только если он уже установлен (`ime set` → `ADB_INPUT_B64` → прежняя клавиатура возвращается).
- `adb_helpers.py logcat start/dump`: по умолчанию только приложение (PID его процессов с обновлением при перезапуске — по «Start proc» и опросу `ps`, строки с именем пакета, продолжения многострочных записей); `--all` — весь журнал устройства. `crashes` по-прежнему читает полный журнал.
- `intake.py from-text`: запреты без текста кнопки по темам — камера, QR и сканирование, точка доступа, микрофон, геолокация, уведомления, Bluetooth, контакты (в т.ч. «без геолокации» и перечисления «не трогай камеру, микрофон и геолокацию»; «…, но проверь …» — не запрет) — сразу правила с типовыми текстами RU+EN (`topic`, `review: «проверить на разведке»`), пакеты камеры в `forbidden_packages`, экраны точки доступа в `forbidden_screens` и правило системного диалога разрешения (`exact: true`, только отказ). `guard.py`: в правилах пользователя `exact: true` (только точный текст) и `context` списком.
- Правило «запрет против сценария» (`intake.md`, SKILL.md — разведка и вопросы по ходу): действия с запрещённым побочным эффектом («Создать комнату» включает точку доступа) выявляются на разведке по описанию, разрешениям и текстам кнопок; вопрос заранее «Разрешить на эмуляторе / Пропустить», решение — в `preapproved_actions` / `forbidden_actions` и журнал.
- Результаты и git: если пользователь явно не разрешил класть результаты в репозиторий, `qa-runs/` обязана быть в `.gitignore`. `gitignore_helper.py ensure <OUTPUT_ROOT>` — сразу после выбора папки и до создания `<RUN_DIR>` (папки может ещё не быть): `qa-runs/` и `*.apk`, `*.aab`, `*.apks`, `*.xapk`, `*.keystore`, `*.jks` в `.gitignore` репозитория; `git.allow_commit_results` (по умолчанию `false`, `intake.py` распознаёт явное разрешение RU/EN) и отдельный `git.allow_commit_apk`. Уже отслеживаемые файлы `qa-runs/` не удаляются: код 1, команда `git rm -r --cached` и один вопрос → `untrack --yes`. Вопрос «Добавить в .gitignore?» в конце прогона убран.
- `export_results.py` (`report_destinations: folder`): в `<path>/<YYYY-MM-DD>-<package>/` копируются только `summary.md`, `report.md`, `findings.json` и скриншоты находок — без `apk/`, `logs/` (logcat), `raw/`, видео и черновиков; конфликт имён — код 1 без записи, `--overwrite` после «да».
- SKILL.md, INSTALL.md, README: после установки скил виден только в новой сессии Claude Code (в текущей — «Unknown skill»); как продолжить в той же сессии — прочитать SKILL.md и идти по шагам. INSTALL.md: рекомендация JDK 17 или 21.

### Тесты
- `tests/unit.sh` — 148 проверок (было 110): падение UiAutomation на фрагменте реального logcat и разбор по процессам, logcat с фильтром и `--all`, поворот и `dump-ui` на альбомном дампе 2400×1080, `text --translit/--adbkeyboard`, матрица с `hardware: []`, `install-image --run-dir` и шум Java -ea, темы запретов в `intake` и их проверка `guard`, `git` в `intake` и `commit_permission`, `gitignore_helper ensure/untrack`, `export_results`, все примеры команд из документации (`tests/helpers/doc_commands.py`).

## [1.0.0] — 2026-10-08
Первая версия: QA-тестирование Android-приложений по APK / split APK / `.apks` / AAB или установленному пакету на эмуляторах и устройствах через adb. «Брат» `site-qa-audit` по структуре: подтверждение намерения, опрос, память о приложении, безопасность через guard, матрица и потоки, журнал, отчёт, черновики issues, gitignore, уборка. Статус — «в разработке»: на реальном эмуляторе и устройстве не прогонялся (проверено офлайн на фейковом adb и SDK и только чтением на машине с Android SDK).

### Добавлено
- Запуск по `/android-qa-audit` и по смыслу запроса (RU/EN-триггеры в `description`, когда не использовать); при автозапуске — вопрос «Похоже, вы хотите протестировать Android-приложение … Запустить?», при «Нет» ничего не создаётся.
- Опрос (`references/intake.md`): что за приложение и для чего, источники, вход, что тестируем и успех, версии Android (рекомендация из minSdk/targetSdk), конфигурации (ОЗУ, ядра, диск, экран, шрифт, тема, ориентация, язык и RTL, сеть, батарея, Doze, часовой пояс), виды тестов, 11 направлений, глубина, стенды и согласие на реальные устройства, запреты, потоки (1–4), GitHub issues, куда записать итоги. `scripts/intake.py from-text` — черновик run-config из свободного запроса.
- Разбор приложения `scripts/apk_info.py`: aapt2/aapt (badging + xmltree манифеста), apksigner; пакет, версии, SDK, разрешения (опасные, особые, с какого API запрашиваются), launcher, ABI и совместимость с эмулятором хоста, debuggable, allowBackup, cleartext, экспортируемые компоненты (с правилами по умолчанию), deep links, подпись, кандидаты пассивной безопасности; `.apks`/`.xapk`, AAB через bundletool (`build-apks`), установленное приложение (`installed --pull-to`); копия APK в папке прогона с `SHA256SUMS`.
- Стенды `scripts/avd_manager.py`: список AVD с владельцем (свои — `qa-*` + метка `android-qa-audit.json`), образы и их загрузка через sdkmanager (план с оценкой размера, `--yes` и лицензии — только с согласия), создание AVD с ОЗУ/ядрами/диском/экраном/density, запуск (свободный порт, headless, cold boot, снимки, скорость сети, язык, часовой пояс), ожидание загрузки, остановка только своих эмуляторов, удаление только своих AVD, уборка по `stands.json`; чужие AVD — только `--allow-foreign` с `-read-only`.
- Управление устройством `scripts/adb_helpers.py`: установка/обновление/удаление/очистка, запуск и время старта (cold/warm/hot), смерть процесса в фоне, trim-memory, deep links; дерево элементов uiautomator с кандидатами (`a11y.missing-label`, `a11y.touch-target` 48 dp, `visual.offscreen`, `visual.overlap`, `visual.text-ellipsized`), нажатия по тексту/id/описанию, свайпы, ввод (секреты из переменных окружения не печатаются), клавиши, скриншоты, видео; поворот, шрифт, масштаб экрана, тёмная тема, язык приложения, часовой пояс, сеть (режим полёта, Wi-Fi, скорость эмулятора), батарея, экономия, Doze, standby, анимации; разрешения, уведомления; logcat (фоновая запись с маскированием), падения и ANR (logcat + dropbox), meminfo, gfxinfo, batterystats, размер, monkey с seed.
- Безопасность `scripts/guard.py` (коды 0/2/3, как `url_guard` у сайта): базовые запреты (покупки, вход через внешние аккаунты, звонки и SMS — и в эмуляторе, отправка людям — спросить, удаление аккаунта, администратор устройства, чужие приложения), правила пользователя (`forbidden_packages`, `forbidden_screens`, `forbidden_deeplinks`, `forbidden_actions`, `require_confirmation_actions`, `preapproved_actions`, `adb_require_confirmation`), классификация adb-команд (чтение / приложение / устройство / запрет) × стенд (свой эмулятор / чужой эмулятор / реальное устройство) × согласие (`read-only`, `app-only`, `full`); журнал `logs/blocked.jsonl`; `selftest` (63 случая). `scripts/masking.py` — маскирование.
- Матрица `scripts/matrix.py`: API × железо × вариации по глубине (smoke / standard / deep, `references/depth-matrix.md`), `matrix.mode: full`, реальные устройства и чужие AVD отдельными ячейками, распределение по потокам (до 4, по ОЗУ хоста и рекомендации `check_env`).
- Окружение `scripts/check_env.py` (+ `.sh`, `.ps1`): Java, SDK (в т.ч. найден, но не в PATH — строки для zsh и PowerShell), adb, emulator, cmdline-tools, build-tools, образы и ABI, AVD, устройства (unauthorized/offline), ускорение (HVF/WHPX/KVM), ОЗУ, ядра, диск, рекомендация потоков, bundletool, scrcpy, Maestro, Appium, gh, `ANDROID_QA_OUTPUT_DIR`, усилители и запрещённые плагины.
- Находки и отчёт: `templates/finding.schema.json` (Android-поля: экран, окружение с API, профилем, ОЗУ, ABI, стендом, ячейкой; `repro_rate`, `crash`, `logcat_excerpt`, `recordings`), `validate_findings.py`, `fingerprint.py` (отпечаток по направлению, пункту, пакету, экрану, элементу; сверка с выгрузкой `gh issue list`), `render_draft.py` (черновики issues и `index.md` с командами `gh`, ничего не публикует; disclosure, marker, severity_map, вложения), `build_report.py` (report, summary, publish-table: матрица, падения, метрики, кандидаты APK, запреты).
- Память о приложении `<OUTPUT_ROOT>/qa-runs/.app-context/<package>/context.md` + `sources.json` (`templates/app-context.md`): «как есть / обновить / изучить заново», без секретов и персональных данных.
- Общие модули репозитория `shared/scripts/runjournal.py` (журнал прогона, тот же, что `site-qa-audit/scripts/journal.py`) и `shared/scripts/qa_gitignore.py` (несколько шаблонов, режимы gitignore/exclude/keep); обёртки `scripts/journal.py`, `scripts/gitignore_helper.py` (по умолчанию `qa-runs/`, `*.apk`, `*.aab`, `*.apks`, `*.keystore`).
- Справочники: setup, intake, safety-rules, stands, device-control, depth-matrix, parallelism, plugins-map, severity, repo-sync, run-files, checklists (11 направлений: functional, logic-state, ux, visual-ui, device-config-compat, lifecycle-resilience, accessibility, performance, security-passive, compatibility, content-i18n).
- `INSTALL.md` — установка и обновление для macOS, Windows и Linux: JDK, Android SDK (Android Studio или command-line tools, brew/winget), переменные окружения, лицензии, ускорение, образы, AVD, необязательные программы, скил (маркетплейс, клон + `tools/install.*`, копия), частые проблемы и коды `INSTALL_FAILED_*`, промпты для Claude Code.

### Тесты
- `tests/unit.sh`: офлайн, фейковые adb и SDK (`tests/helpers/fake_adb.py`, `fake_tools.py`), изолированные HOME и AVD; синтаксис Python 3.9; guard, apk_info (aapt2 и aapt), avd_manager (создание, запуск, остановка, отказ для чужих AVD, уборка), adb_helpers (запреты нажатий и adb, реальные устройства и согласие, разбор метрик, падений, monkey), matrix, intake, validate/fingerprint/render_draft/build_report, gitignore_helper, маскирование, универсальность.
