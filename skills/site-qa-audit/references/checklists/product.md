# product — Продуктовые предложения

Направление: `product` · Инструменты: итоги разведки и всех остальных направлений, скриншоты, Playwright MCP для уточнений · Усилители: `ux-audit`, `frontend-design` (предложения по редизайну), `ui-audit-redesign`, `ux-heuristics`, `laws-of-ux`

## Цель
Перевести наблюдения в продуктовые артефакты: user stories с критериями приёмки, предложения для пользователей и обоснованные предложения по пересмотру интерфейса с приоритетом «эффект / усилия».

## Безопасность в этом направлении
- Направление аналитическое: новых рискованных действий не требует. Уточняющие проверки в браузере — по тем же правилам `url_guard`.
- Не придумывать бизнес-факты: аудитория, метрики, цели — только то, что видно на сайте или сообщил пользователь. Предположения помечать как гипотезы.

## Формат артефактов
- **User story** — по `templates/user-story.md`: «Как <роль>, я хочу <действие>, чтобы <ценность>» + критерии приёмки в виде Given/When/Then (Дано / Когда / Тогда) + связанные находки (id) + приоритет.
- **Предложение по интерфейсу** — проблема (с id находок) → предложение → обоснование (эвристика, закон UX, данные прогона) → эффект (высокий/средний/низкий) → усилия (высокие/средние/низкие) → квадрант:

| | Усилия низкие | Усилия высокие |
|---|---|---|
| **Эффект высокий** | Quick win — делать первым | Major project — планировать |
| **Эффект низкий** | Fill-in — по возможности | Thankless — не делать |

## Smoke
- [ ] `prod.top-issues-summary` — 3–5 главных проблем прогона, сформулированные с точки зрения пользователя (что он теряет).
- [ ] `prod.quick-wins` — до 5 предложений Quick win на основе находок smoke.

## Standard (в дополнение к smoke)
- [ ] `prod.user-stories-core` — user stories для ключевых задач, где найдены проблемы (3–10 штук), с критериями приёмки, которые закрывают найденные дефекты.
- [ ] `prod.user-proposals` — предложения для пользователей: чего не хватает в сценариях (сохранить, поделиться, сравнить, уведомить, фильтр, экспорт) — с обоснованием из прогона (где пользователь «упирается»).
- [ ] `prod.ui-proposals` — предложения по интерфейсу с матрицей эффект/усилия (по находкам ux и visual-ui).
- [ ] `prod.consistency-proposals` — единые компоненты и тексты: что стандартизировать.

## Deep (в дополнение к standard)
- [ ] `prod.user-stories-full` — user stories по всем персонам (новичок, опытный, мобильный, с ограничениями) и всем ключевым сценариям.
- [ ] `prod.redesign` — пересмотр ключевых экранов: текущие проблемы (скриншоты) → направление редизайна (иерархия, навигация, компоновка) с опорой на `frontend-design` и `ui-audit-redesign`; без макетов, словами и, при необходимости, схемой.
- [ ] `prod.ia-proposals` — пересмотр информационной архитектуры (меню, разделы, названия) с обоснованием по законам Хика и Миллера.
- [ ] `prod.onboarding-proposals` — первый опыт: что понять за первые 10 секунд, подсказки, пустые состояния.
- [ ] `prod.accessibility-roadmap` — план исправлений доступности по приоритету (из accessibility).
- [ ] `prod.performance-roadmap` — план по скорости (из performance): что даст наибольший прирост LCP/CLS.
- [ ] `prod.metrics` — какие метрики покажут эффект предложений (конверсия шага, время до цели, доля ошибок) — как гипотезы.

## Типовые находки и severity
Продуктовые артефакты — не дефекты, у них **приоритет**, а не severity. В `findings.json` они идут с `type: "proposal"` или `type: "user-story"` и `severity: "info"`, а приоритет — в поле `priority`: `quick-win` | `major-project` | `fill-in` | `thankless`.

| Пример | Приоритет |
|---|---|
| Переименовать кнопку главного действия в понятный глагол | Quick win |
| Добавить фильтры в URL, чтобы делиться результатами | Quick win / Major project |
| Переработать навигацию из 14 пунктов в 5 групп | Major project |
| Анимация логотипа | Thankless |

## Что записывать в находку
- Связанные id находок других направлений (`related`) — предложение должно опираться на наблюдения.
- Для user story: роль, действие, ценность, критерии приёмки (Given/When/Then), приоритет.
- Для предложения: проблема, предложение, обоснование (эвристика/закон/метрика), эффект, усилия, квадрант, скриншоты «как сейчас».
- Пометку «гипотеза», если обоснование не опирается на данные прогона.
