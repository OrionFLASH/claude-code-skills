# seo-content — SEO и контент

Направление: `seo-content` · Инструменты: `node/links.js` (мета по страницам, дубли), `node/headers.js` (robots.txt, sitemap), `node/lighthouse.js` (категория SEO), Playwright MCP (отрисованный SPA-контент, тексты) · Усилители: собственные скрипты; при наличии — скилы семейства `seo-*` как справочник

## Цель
Проверить, что страницы корректно описаны для поисковиков и соцсетей, а тексты — без опечаток, ошибок перевода и фактических противоречий.

## Безопасность в этом направлении
- Только чтение: GET-запросы `links.js`/`headers.js` с паузой (`--throttle`). Обход ограничен `allowed_domains` и лимитом страниц.
- Ошибки в данных фиксируются как наблюдение «на странице A указано X, на странице B — Y», без утверждений о том, что верно, если источник истины неизвестен.

## Smoke
- [ ] `seo.title` — у ключевых страниц есть уникальный `<title>` разумной длины (~30–60 символов) → `links.js` (`meta.title`, `seo.missingTitle`).
- [ ] `seo.description` — meta description есть (~70–160 символов) → `seo.missingDescription`.
- [ ] `seo.robots-txt` — `/robots.txt` доступен и не закрывает весь сайт случайно (`headers.js` `robots.disallowAll`) → дефект: `Disallow: /` на боевом сайте (Critical для SEO).
- [ ] `seo.noindex` — нет `noindex` на страницах, которые должны индексироваться (`meta.robots`, заголовок `X-Robots-Tag`).
- [ ] `seo.h1` — один осмысленный h1 на странице (`seo.h1Problems`; для SPA — проверить в браузере, статический HTML может быть пуст).
- [ ] `seo.typos-key` — опечатки в заголовках, меню и CTA ключевых страниц (чтение текста через `browser_snapshot`).

## Standard (в дополнение к smoke)
- [ ] `seo.duplicate-title` / `seo.duplicate-description` — дубли (`seo.duplicateTitles`, `seo.duplicateDescriptions`).
- [ ] `seo.canonical` — canonical есть, абсолютный, указывает на себя или на правильную версию; нет canonical на 404/редирект.
- [ ] `seo.sitemap` — `sitemap.xml` (из robots или по умолчанию) доступен, содержит реальные URL, без 404 и редиректов (сверить выборку с `links.js`).
- [ ] `seo.open-graph` — `og:title`, `og:description`, `og:image` (абсолютный URL, доступен), `og:url`, `twitter:card`.
- [ ] `seo.lang` — `lang` страницы соответствует языку контента.
- [ ] `seo.img-alt` — изображения без alt (`meta.imgNoAlt`; связано с accessibility — сливать).
- [ ] `seo.structured-data` — наличие JSON-LD (`meta.jsonLd`) для подходящих типов страниц (организация, хлебные крошки, товары, статьи).
- [ ] `seo.lighthouse-seo` — категория SEO Lighthouse < 0.9 → разобрать проваленные аудиты.
- [ ] `seo.spa-rendering` — контент SPA: сравнить статический HTML (`links.js`) и отрисованный (браузер) — если основной текст есть только после JS, отметить риск индексации.
- [ ] `seo.typos` — опечатки и грамматика в основных текстах страниц.
- [ ] `seo.data-consistency` — фактические противоречия: одинаковые сущности (цены, даты, контакты, числа, названия) различаются между страницами, списком и карточкой, картой и списком.

## Deep (в дополнение к standard)
- [ ] `seo.hreflang` — для мультиязычных сайтов: взаимные ссылки, корректные коды языков и регионов, `x-default`, URL существуют.
- [ ] `seo.translation` — качество перевода: непереведённые фрагменты, машинный перевод, смешение языков, неверные форматы дат и чисел для локали.
- [ ] `seo.url-structure` — человекочитаемые URL, без дублей с `/` и без, с параметрами и без (canonical решает?), редиректы http→https и www↔без www единообразны.
- [ ] `seo.redirect-chains` — цепочки редиректов > 1 шага (`links.js` finalUrl vs url).
- [ ] `seo.thin-content` — страницы почти без текста, пустые категории.
- [ ] `seo.internal-linking` — «сиротские» страницы из sitemap, на которые нет внутренних ссылок.
- [ ] `seo.favicon-manifest` — favicon, web manifest.
- [ ] `seo.facts-check` — фактические ошибки в данных, которые можно проверить по самому сайту или общеизвестным фактам (дни недели у дат, суммы, единицы измерения); при сомнении — помечать как вопрос к пользователю.

## Типовые находки и severity
| Пример | Severity |
|---|---|
| `Disallow: /` или `noindex` на всём боевом сайте | Critical |
| Противоречивые данные (цены, даты, контакты) между страницами | High / Medium |
| Нет title или description на ключевых страницах; дубли title по всему сайту | Medium |
| Контент SPA виден только после JS | Medium |
| Нет OG-изображения, нет canonical | Low |
| Опечатка в основном тексте | Low (Medium, если в заголовке или CTA) |

## Что записывать в находку
- URL, текущее значение поля (title, description, canonical и т.п.) и проблему; для дублей — список URL.
- Для опечаток и перевода: точная цитата, предлагаемая правка, местоположение (блок или селектор).
- Для противоречий данных: оба значения с URL и скриншотами обоих мест.
- Источник: `raw/links.json`, `raw/headers.json`, Lighthouse SEO.
