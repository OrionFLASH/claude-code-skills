# ux — Удобство (UX)

Направление: `ux` · Инструменты: Playwright MCP (прохождение сценариев), скриншоты · Усилители: `ux-audit` (UX walkthrough как методика), opentest `ux-test`, `ux-heuristics`, `laws-of-ux`

## Цель
Пройти ключевые задачи глазами разных пользователей и найти, где им трудно, непонятно или долго: оценить по эвристикам Нильсена и законам UX.

## Безопасность в этом направлении
- Сценарии проходятся до последнего безопасного шага. Шаги оплаты, отправки людям, OAuth и удаления не выполняются: в находку пишется «сценарий пройден до шага N, дальше запрет <rule>».
- `ux-audit` требует «доказательства взаимодействия» (набрать, кликнуть, отправить). Отправку заменяем проверкой валидации, все клики идут через `url_guard`.

## Персоны
- **Новичок** — впервые на сайте, не знает терминов, пришёл с главной или из поиска на внутреннюю страницу.
- **Опытный** — знает, что ищет, хочет быстро: прямые ссылки, поиск, фильтры, горячие клавиши.
- В deep дополнительно: **мобильный в спешке** (одна рука, плохая сеть) и **пользователь с ограничениями** (клавиатура, увеличение 200%).

## Smoke
- [ ] `ux.key-task` — 1–3 главные задачи сайта (определить на разведке: «найти X», «посмотреть Y») → пройти за новичка → дефект: задача не решается, нужно больше 2 «угадываний».
- [ ] `ux.steps-to-goal` — число шагов (кликов, экранов) до цели → дефект: заметно больше необходимого, лишние подтверждения.
- [ ] `ux.feedback` — обратная связь на действие (загрузка, успех, ошибка) → дефект: после клика ничего не меняется дольше 1 с, нет индикатора, нет подтверждения.
- [ ] `ux.error-messages` — понятность ошибок → дефект: технический текст, код без объяснения, нет подсказки, что делать.
- [ ] `ux.first-screen` — ясно ли с первого экрана, что это за сайт и что делать → дефект: нет заголовка или ценности, CTA не виден.

## Standard (в дополнение к smoke)
Эвристики Нильсена — для каждой ключевой страницы и сценария отметить нарушения:
- [ ] `ux.h1-status-visibility` — видимость состояния системы (загрузка, где я, что выбрано).
- [ ] `ux.h2-real-world-match` — язык пользователя, а не системы; привычные метафоры и иконки.
- [ ] `ux.h3-user-control` — отмена, «Назад», выход из модальных окон и мастеров.
- [ ] `ux.h4-consistency` — одинаковые элементы называются и ведут себя одинаково; соответствие платформенным конвенциям.
- [ ] `ux.h5-error-prevention` — подтверждения опасных действий, ограничения ввода, разумные значения по умолчанию.
- [ ] `ux.h6-recognition` — видимые варианты вместо запоминания (подсказки, недавние, автодополнение).
- [ ] `ux.h7-flexibility` — ускорители для опытных (поиск, фильтры, клавиши, сохранённые настройки).
- [ ] `ux.h8-minimalism` — нет лишнего, визуальный шум не мешает главному.
- [ ] `ux.h9-error-recovery` — понятные ошибки с выходом из ситуации.
- [ ] `ux.h10-help` — помощь и подсказки там, где нужны.

Законы UX:
- [ ] `ux.law-fitts` — важные цели крупные и близко к месту внимания; маленькие цели рядом с частыми действиями — дефект.
- [ ] `ux.law-hick` — число вариантов в меню и выборе; больше 7–9 равнозначных без группировки — дефект.
- [ ] `ux.law-miller` — порции информации, группировка длинных списков и форм.
- [ ] `ux.law-jakob` — соответствие ожиданиям от похожих сайтов (логотип ведёт на главную, корзина справа вверху, поиск с лупой и т.п.).
- [ ] `ux.law-other` — по ситуации: Тесслер (сложность на системе, а не на пользователе), Доэрти (ответ < 400 мс), закон эффекта пиковой точки и конца, закон близости и общей области (Гештальт).

Тексты и иконки:
- [ ] `ux.copy-clarity` — заголовки, кнопки, подписи: понятность, глаголы на кнопках, единая терминология.
- [ ] `ux.icon-clarity` — иконки без подписей понятны? (проверка: можно ли угадать действие без тултипа).
- [ ] `ux.empty-states` — пустые списки, «ничего не найдено» с подсказкой, что делать.
- [ ] `ux.persona-expert` — сценарий за опытного: прямой путь, поиск, фильтры, переход по URL.

## Deep (в дополнение к standard)
- [ ] `ux.all-tasks` — все сценарии, найденные на разведке, за всех персон.
- [ ] `ux.persona-mobile` — те же задачи на 375 px с медленной сетью.
- [ ] `ux.persona-a11y` — задачи только с клавиатуры и при увеличении 200% (совместно с accessibility).
- [ ] `ux.onboarding` — первое посещение: подсказки, туры, баннеры cookies (не принимать соглашения — только закрыть, если есть «закрыть»; иначе отметить, что баннер блокирует контент).
- [ ] `ux.information-architecture` — структура меню, хлебные крошки, понятность разделов, тест «где я?» на каждой странице.
- [ ] `ux.microcopy-tone` — тон и единообразие текстов, ошибки перевода (совместно с seo-content).
- [ ] `ux.severity-rating` — для каждого нарушения эвристики выставить оценку Нильсена 0–4 и привести к нашей severity.

## Типовые находки и severity
| Пример | Severity |
|---|---|
| Главная задача сайта не решается новичком | High |
| Нет обратной связи после ключевого действия | Medium |
| Неочевидная иконка без подписи на главном действии | Medium |
| 12 равнозначных пунктов меню без группировки | Low / Medium |
| Непоследовательные названия одного и того же | Low |

## Что записывать в находку
- Персону, задачу и шаг, на котором возникла проблема; число шагов фактическое и ожидаемое.
- Нарушенную эвристику или закон (`check_id`) и **обоснование**: почему это мешает.
- Скриншот с местом проблемы, при необходимости — последовательность скриншотов.
- Предложение по исправлению (конкретное: текст кнопки, расположение, группировка).
