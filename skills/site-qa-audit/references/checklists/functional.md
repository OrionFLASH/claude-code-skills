# functional — Функциональность

Направление: `functional` · Инструменты: Playwright MCP (последовательно) / playwright-cli (параллельные потоки), `node/links.js` · Усилители: opentest `e2e-test`, `ux-audit` (режим QA sweep — только как методика), browser-devtools `qa-tester` (если включён)

## Цель
Убедиться, что всё, что выглядит интерактивным, работает: ссылки ведут куда нужно, формы, поиск и фильтры дают корректный результат, интерактивные компоненты (включая карты) отвечают на действия, а в консоли и сети нет ошибок.

## Безопасность в этом направлении
- Каждый клик, отправку формы и переход проверять через `url_guard.py action` / `url_guard.py nav`. При `deny` не выполнять и записать «не проверено: запрет <rule>». При `confirm` — спросить пользователя.
- Формы, которые уходят реальным людям (обратная связь, сообщения, жалобы, комментарии, отзывы, приглашения), **не отправлять**. Можно проверить валидацию на клиенте: заполнить поля, увести фокус, посмотреть сообщения об ошибках. Кнопку отправки не нажимать.
- Поиск и фильтры безопасны: это GET-запросы без побочных эффектов.
- Покупки, оплата, подписки, OAuth («Войти через…») — базовый запрет. Проверяется только наличие и вид кнопки, клик не выполняется.
- Внешние ссылки не открывать. Записать «ведёт на X — не проверялось», статус проверит `links.js --check-external`.
- Новые вкладки на чужие домены сразу закрывать (`browser_tabs close`).

## Smoke
- [ ] `fn.page-loads` — ключевые страницы открываются → `browser_navigate` + `browser_snapshot` → дефект: пустая страница, ошибка, бесконечная загрузка дольше 15 с.
- [ ] `fn.console-errors` — ошибки JS → `browser_console_messages` (level error) после загрузки и после действий → дефект: любая uncaught-ошибка или error-сообщение.
- [ ] `fn.network-errors` — ответы 4xx/5xx → `browser_network_requests` → дефект: 5xx на любом запросе; 4xx на собственных ресурсах и API сайта (кроме ожидаемых 401 до входа).
- [ ] `fn.nav-main` — главное меню и шапка → кликнуть каждый пункт → дефект: пункт никуда не ведёт, ведёт на 404, ведёт не туда.
- [ ] `fn.broken-links` — битые внутренние ссылки → `node/links.js START --rules rules.json` (`broken[]`) → дефект: 4xx/5xx/0.
- [ ] `fn.primary-cta` — главные кнопки действия на ключевых страницах → клик (через guard) → дефект: нет реакции, ошибка, неверный результат.
- [ ] `fn.search-basic` — поиск (если есть) → запрос с заведомо существующим словом с сайта → дефект: нет результатов, ошибка, результаты не по запросу.
- [ ] `fn.form-validation` — основная форма → пустая отправка (только если форма не уходит людям) или проверка подсказок → дефект: нет сообщений об ошибках, неверные сообщения.

## Standard (в дополнение к smoke)
- [ ] `fn.links-all-pages` — ссылки на всех найденных страницах до лимита → `links.js --max-pages <limit>` → дефект: битые ссылки, ссылки на `#` без действия.
- [ ] `fn.404-page` — несуществующий URL сайта (`/qa-audit-nonexistent-<дата>`) → дефект: нет 404-страницы, ответ 200 вместо 404 (soft 404), нет пути назад.
- [ ] `fn.filters` — фильтры и сортировки → применить по одному, комбинацию, сброс → дефект: результат не соответствует фильтру, сброс не работает, счётчик врёт.
- [ ] `fn.search-edge` — поиск: пустой запрос, нет результатов, регистр, опечатка → дефект: ошибка, нет состояния «ничего не найдено».
- [ ] `fn.pagination` — пагинация и «показать ещё» → дефект: дубли, пропуски, повтор первой страницы.
- [ ] `fn.interactive-components` — вкладки, аккордеоны, модальные окна, выпадающие меню, слайдеры, тултипы → открыть/закрыть, Esc, клик вне → дефект: не открывается, не закрывается, заблокирован скролл после закрытия.
- [ ] `fn.map-zoom` — карты: зум кнопками и колесом → дефект: не масштабирует, тайлы не грузятся (серые квадраты, 4xx тайлов в сети).
- [ ] `fn.map-pan` — карты: перетаскивание (`browser_drag`) → дефект: не двигается, «прыгает».
- [ ] `fn.map-markers` — маркеры и кластеры → клик → дефект: попап не открывается, данные в попапе пустые или неверные, кластер не раскрывается.
- [ ] `fn.map-popups` — попапы → закрытие, ссылки внутри → дефект: не закрываются, ведут на 404.
- [ ] `fn.map-layers` — переключатель слоёв и легенда → дефект: слой не включается, легенда не соответствует.
- [ ] `fn.downloads` — ссылки на файлы (PDF и т.п.) → HEAD-статус и тип → дефект: 404, неверный content-type.
- [ ] `fn.media` — видео, аудио, встраивания → запуск → дефект: не воспроизводится, ошибка в консоли.

## Deep (в дополнение к standard)
- [ ] `fn.every-clickable` — каждый кликабельный элемент на всех страницах (из `browser_snapshot`: role button/link/checkbox/tab…) → клик через guard → дефект: нет реакции, ошибка.
- [ ] `fn.external-links` — `links.js --check-external` → дефект: внешние 4xx/5xx/DNS.
- [ ] `fn.anchors` — якорные ссылки `#id` → дефект: целевого элемента нет.
- [ ] `fn.forms-all` — все формы, не уходящие людям: обязательные поля, маски, автозаполнение, сообщения сервера → дефект: принимается некорректное, отвергается корректное.
- [ ] `fn.map-deep` — карта: границы зума, поиск по карте, геолокация (разрешение не выдавать), полноэкранный режим, работа на мобильной ширине.
- [ ] `fn.print` — печатная версия (`browser_emulate_media` media=print + скриншот) → дефект: важный контент обрезан.
- [ ] `fn.offline-message` — поведение при потере сети на SPA (`playwright-cli network-state-set offline`) → дефект: белый экран без сообщения.

## Типовые находки и severity
| Пример | Severity (см. `references/severity.md`) |
|---|---|
| Основная функция (поиск, каталог, карта) не работает | Critical |
| 5xx на ключевой странице, uncaught-ошибка ломает интерфейс | High |
| Битая ссылка в главном меню | High |
| Фильтр даёт неверный результат | High / Medium |
| Битая ссылка в подвале или тексте | Medium |
| Ошибка в консоли без видимого эффекта | Low |
| Soft 404 | Low / Medium |

## Что записывать в находку
- URL, шаги воспроизведения (кликами, с текстом элементов), локатор элемента (`role` + accessible name из snapshot, при необходимости CSS).
- Выдержка из `browser_console_messages` (только относящиеся к шагу сообщения), запросы из `browser_network_requests` (метод, URL без токенов, статус).
- Скриншот до и после действия: `screenshots/<id>-before.png`, `<id>-after.png`.
- Окружение: браузер, ширина, авторизован или нет.
- Для карт: уровень зума и координаты или видимый регион, какие тайлы упали.
