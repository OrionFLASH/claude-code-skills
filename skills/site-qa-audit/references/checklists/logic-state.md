# logic-state — Логика и состояние

Направление: `logic-state` · Инструменты: Playwright MCP / playwright-cli, `browser_evaluate` · Усилители: qa-skills `resilience-audit` и `adversarial-audit` (**только пассивно**: без интерактивной проверки атак; агент `adversarial-breaker` запрещён)

## Цель
Найти, где приложение ломается от обычного «неидеального» поведения: «Назад», обновление страницы, прямые ссылки, повторные и быстрые клики, прерванные действия, необычный, но безобидный ввод.

## Безопасность в этом направлении
- Двойные и быстрые клики — **только по безопасным элементам**: навигация, фильтры, вкладки, «показать ещё», добавление в локальный список. Кнопки с решением `confirm` или `deny` в `url_guard` (оплата, отправка, удаление, сохранение настроек) не кликать повторно и не кликать вообще без разрешения.
- Ввод — только безобидные граничные значения: пустая строка, пробелы, очень длинный текст (5 000 символов), эмодзи, кириллица и иероглифы, RTL, ведущие нули, отрицательные и дробные числа, даты на границах. **Никаких инъекций**: `<script>`, `' OR`, `../`, шаблонных выражений и т.п.
- localStorage и cookies только **читать** (`browser_evaluate`). Менять разрешено лишь в собственной изолированной сессии для проверки восстановления, и только данные, созданные самим тестом.
- Гонки воспроизводить только на безопасных действиях (переключение фильтров, навигация).

## Smoke
- [ ] `ls.back-button` — «Назад» после 2–3 переходов → `browser_navigate_back` → дефект: выход с сайта, потеря состояния, пустая страница, двойной шаг.
- [ ] `ls.reload` — обновление на ключевых страницах и после действий → `browser_navigate` на тот же URL → дефект: потеря введённого (где ожидается сохранение), ошибка, другое содержимое.
- [ ] `ls.deep-link` — прямой переход на внутренний URL (новая сессия) → дефект: 404 на маршрут SPA, редирект на главную, пустой экран.
- [ ] `ls.dead-end` — тупики: страница без пути назад или дальше → обход по snapshot → дефект: нет навигации, нет ссылки на главную.
- [ ] `ls.empty-input` — пустой ввод в поиске и основных полях → дефект: ошибка, необработанное исключение.

## Standard (в дополнение к smoke)
- [ ] `ls.url-state` — фильтры, вкладки, сортировка, пагинация отражаются в URL → применить, скопировать URL, открыть в новой сессии → дефект: состояние не восстанавливается или URL не меняется (если ожидается шаринг).
- [ ] `ls.history-state` — «Назад»/«Вперёд» после смены фильтров → дефект: URL и содержимое расходятся.
- [ ] `ls.double-click` — двойной клик по безопасным действиям → дефект: двойное добавление, дубли запросов с разным результатом, сломанный UI.
- [ ] `ls.fast-clicks` — быстрые клики по вкладкам или фильтрам (5 раз за 1 с) → дефект: показан результат не последнего клика (гонка), зависший индикатор загрузки.
- [ ] `ls.boundary-input` — граничные значения: длинный текст, эмодзи, Unicode, пробелы по краям, max/min числа → дефект: обрезка без предупреждения, поломка вёрстки, ошибка, искажение символов.
- [ ] `ls.invalid-input` — некорректный формат (буквы в числовом поле, неверная дата, e-mail без @) → дефект: принимается молча или ошибка без объяснения.
- [ ] `ls.storage-read` — `browser_evaluate(() => ({ls: Object.keys(localStorage), cookies: document.cookie.split(';').map(c => c.split('=')[0].trim())}))` → дефект: в хранилище персональные данные или токены в открытом виде (записать, **значения маскировать**), ключи растут без ограничения.
- [ ] `ls.persistence` — то, что пользователь ожидает сохранённым (тема, язык, список, черновик), переживает перезагрузку → дефект: сбрасывается.
- [ ] `ls.interrupted-action` — прервать действие: уйти со страницы во время загрузки, закрыть модальное окно посреди шага, «Назад» на середине мастера → дефект: подвешенное состояние, дубли, потеря данных без предупреждения.

## Deep (в дополнение к standard)
- [ ] `ls.multi-tab` — то же состояние в двух вкладках одной сессии (playwright-cli `tab-new`) → изменить в одной, обновить другую → дефект: рассинхрон, перезапись.
- [ ] `ls.session-expiry` — авторизованная зона: очистить cookies сессии в изолированной сессии и продолжить → дефект: ошибка вместо перехода на вход, потеря введённого.
- [ ] `ls.race-navigation` — переход на другую страницу до завершения загрузки данных → дефект: данные предыдущей страницы показываются на новой.
- [ ] `ls.slow-network` — замедлить сеть (playwright-cli или `browser_run_code_unsafe` с route-задержкой только для своей сессии) → дефект: нет индикатора, повторные отправки, таймауты без сообщения.
- [ ] `ls.offline-recovery` — офлайн и восстановление → дефект: нет повторной попытки, вечный спиннер.
- [ ] `ls.unicode-urls` — URL с кириллицей, пробелами, `+`, кодированными символами в параметрах поиска → дефект: 500, искажение.
- [ ] `ls.resilience-review` — прогнать `resilience-audit` в пассивном режиме (без интерактивной проверки), его гипотезы проверить вручную под guard.

## Типовые находки и severity
| Пример | Severity |
|---|---|
| Действие выполняется дважды и создаёт дубли данных | High |
| Deep-link на раздел SPA даёт 404 | High |
| «Назад» уводит с сайта или ломает страницу | Medium |
| Фильтры не попадают в URL, ими нельзя поделиться | Medium / Low |
| Длинный текст ломает вёрстку | Low / Medium |
| Токен в localStorage в открытом виде | Medium (передать и в security-passive) |

## Что записывать в находку
- Точную последовательность действий с таймингом (для гонок: «5 кликов за 1 с»), URL до и после.
- Состояние хранилища **до и после** (только ключи и маскированные значения).
- Введённые значения (граничные — указать длину и класс символов, длинный текст не вставлять целиком).
- Консоль и сеть на момент сбоя, скриншоты до и после.
