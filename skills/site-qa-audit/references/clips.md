# Ролики находок (короткие, без звука)

Скриншот не показывает то, что происходит во времени: анимацию, мерцание, зависание, реакцию на нажатие, переход, потерю состояния. Ролик на 3–8 с показывает, **что происходило в момент ошибки и что не происходило**, а с `--kind after` — что после исправления всё работает. Ролик — **дополнение** к аннотированному скриншоту (`screenshots.md`), не замена: у находки всегда есть скриншот.

## Когда записывать
| `clips.mode` (run-config, опрос — `intake.md`, вопрос 9b) | Что делать |
|---|---|
| `auto` (по умолчанию) | ролик, только когда дефект виден во времени: анимация, мерцание, зависание, «не реагирует», переход, прокрутка, всплывающее и исчезающее, гонка, потеря состояния. Статичное (контраст, обрезка, перекрытие, шрифт, опечатка, метатеги) — только скриншот. Спорно — `clips.py policy "<текст находки>"` |
| `on` | для каждой находки, где это недорого (есть шаги воспроизведения, 1–2 минуты на ролик) |
| `off` | без роликов |

Фразы запроса: «с видео», «запиши ролики» → `on`; «без видео», «без роликов» → `off` (`intake.py from-text`). Режим `auto`: роликов обычно 10–30 % находок.

## Как записать
1. Шаги воспроизведения — в файл `<RUN_DIR>/setup/F-NNN-steps.js` (те же действия, что в `steps` находки, **только через `guarded`**):
```js
module.exports = async ({ page, guarded, clip }) => {
  await guarded.click('#menu-btn');          // правила guard.js: запрещённое не выполняется
  await clip.wait(1200);                     // дать дефекту проявиться
  // clip.caption('После клика меню пропадает', 'error'); clip.step('Прокрутка вниз');
};
```
Подготовка, которая не нужна в кадре (прокрутка к месту, открыть вкладку), — в `--prepare <файл.js>` с той же сигнатурой.
2. Запись — `clip.js` (те же флаги устройства, входа и правил, что у `shot.js`):
```bash
node <SKILL_DIR>/scripts/node/clip.js --url https://example.com/ --out <RUN_DIR>/clips/F-004-menu.mp4 \
  --setup <RUN_DIR>/setup/F-004-steps.js --caption "Меню закрывается само через 0,6 с" \
  "#menu|Меню|error" "#menu-btn|Нажатие|note" --mask ".email,#phone" \
  --rules <RUN_DIR>/rules.json --log <RUN_DIR>/logs/blocked.jsonl --finding F-004 --run-dir <RUN_DIR>
# телефон и вход пользователя: --device pixel7 --state <RUN_DIR>/logs/auth-state.json
# вкладка браузера пользователя (auth: manual-cdp): ничего не чистится, перехода нет без --url
node <SKILL_DIR>/scripts/node/clip.js --cdp http://127.0.0.1:9222 --page-match example.com \
  --out <RUN_DIR>/clips/F-007-toast.mp4 --setup <RUN_DIR>/setup/F-007-steps.js --caption "Тост исчезает за 0,3 с" \
  --rules <RUN_DIR>/rules.json --finding F-007 --run-dir <RUN_DIR>
# проверка после исправления: --kind after (зелёная плашка ✓), пассивное наблюдение без действий: --read-only
```
- Цель — `селектор|подпись|kind` (kind: `error` / `question` / `note` / `ok`): пунктирная рамка и плашка с подписью, тот же стиль и палитра, что у аннотированных скриншотов (`#FFD60A` / `#30D158` / `#BF5AF2`, не жирно). Рамка следит за элементом весь ролик; пока элемента нет на экране — рамки нет. Селекторы CSS и `iframe … >>> …` рисуются в самой странице, селекторы Playwright (`text=…`, `role=…`) — по координатам из node.
- `--caption` — короткий факт (как подпись скриншота), держится **весь ролик** в плашке внизу слева (наверху, если внизу цель); под ним — последний шаг («▸ Нажать «Меню»»), появляется после первого шага. Значок и цвет — по `--kind`: `error` ✕ жёлтый, `note` • фиолетовый, `ok`/`after` ✓ зелёный. Подпись также записывается в `clips[].caption`.
- Курсор: точка следует за мышью, круг — в момент нажатия (Playwright курсор не рисует); перед кликом курсор плавно подводится к цели. `--no-cursor` — без него.
- `--mask` (и `clips.mask` в run-config) — CSS-размытие селекторов **до первого кадра** (почта, телефон, имена, номера заказов). Внутри iframe маска не работает — такие данные не показывать в кадре.
- Длительность — не больше `--seconds` (по умолчанию `clips.max_seconds`, 10 с): перед шагами 0,4 с исходного состояния, после последнего шага — `--hold` мс (по умолчанию 1000), чтобы результат был виден. Не уложились — ролик обрезается, предупреждение.
3. После записи `clip.js` сам вызывает `clips.py finalize`: сжатие под бюджет, GIF (ролик до 8 с, если GIF ≤ 1,5 МБ), постер, лента из 8 кадров; с `--finding` — запись в `findings[].clips[]` (и путь в `recordings[]`). Вывод — одна строка JSON `{ok, clip, files, warnings, recorder, cdp, steps}`; файлы `clips/<имя>.mp4`, `.gif`, `-poster.png`, `-sheet.png`.
4. **Посмотреть ленту кадров** (Read `clips/<имя>-sheet.png`): на ней должно быть то, что заявлено в находке (шаг, реакция, дефект, рамка и подпись читаются). Только после этого:
```bash
python3 <SKILL_DIR>/scripts/clips.py viewed <RUN_DIR> --id F-004 --file clips/F-004-menu.mp4
```
Непросмотренный ролик (`viewed: false`) в черновики issues и публикацию не попадает. На ленте не то — перезаписать (тот же `--out` заменяет файл и запись в находке).

Коды выхода `clip.js`: 0 — готово; 1 — готово с предупреждением (не уложились в бюджет или время, нет ffmpeg, шаг запрещён guard); 2 — ошибка входа (флаги, шаги упали); 3 — запись запрещена (вход, оплата, ввод секрета, действие требует подтверждения); 4 — guard или Playwright недоступны (fail closed; `check_env`).

## Механизм записи
- **`page.screencast`** (новые версии Playwright; в скиле — 1.63): запись включается непосредственно перед шагами и выключается после `--hold`. Работает и в своём браузере скрипта, и **во вкладке пользователя по CDP**: вкладка не перезагружается, cookies и хранилище не трогаются, после записи разметка и маска удаляются; вкладка в фоне выводится на передний план (в `notes`).
- **`recordVideo` контекста** — запасной путь, если в установленном Playwright нет screencast: только свой браузер (не CDP), ролик обрезается до шагов (`--start` при сжатии). По CDP без screencast — код 4 с советом обновить Playwright.
- `python3 <SKILL_DIR>/scripts/clips.py caps` — что умеет окружение (ffmpeg, кодеки, screencast); `check_env` показывает то же строками ffmpeg / ffprobe / Playwright screencast.

## Бюджет и формат
| Ключ `clips:` | По умолчанию | Смысл |
|---|---|---|
| `max_seconds` | 10 | длительность, с (цель 3–8) |
| `max_mb` | 3 | размер; вложение GitHub — до 10 МБ |
| `width` / `fps` | 720 / 12 | после сжатия; лестница: H.264 `yuv420p`, без звука, `faststart`, CRF 30 → меньше качество, ширина и кадры до бюджета |
| `format` | both | mp4 + GIF для коротких; `mp4` — без GIF |
| `gif_max_seconds` / `gif_max_mb` | 8 / 1,5 | GIF только для коротких и лёгких — встраивается в issue |
| `caption` | true | подпись в кадре |
| `keep_raw` | false | сырой webm — в `<RUN_DIR>/recordings/` (иначе удаляется из временной папки) |
| `mask` | [] | селекторы для размытия |

Типично: 4 с десктопа 1440×900 → 0,01–0,3 МБ; телефон 5 с — 0,2–0,6 МБ. **Звук не записывается никогда.**

## Безопасность (кратко; полностью — `safety-rules.md` §5b)
- **Не записываются**: страницы входа и оплаты (пути и хосты `url_guard`, `rules.read_only_urls`, `/login`, `/signin`, `/checkout`, `/payment` …), экран с видимым полем пароля, карты или одноразового кода, ввод в такое поле. Проверка — до записи, при каждом переходе, каждые 0,4 с и в конце; сработала — запись останавливается, файл удаляется, код 3. Записывать **после входа** (`--state` / `--cdp`) или на гостевом экране.
- Все действия шагов — через `guarded` (`browser-guard.md`): deny — шаг не выполнен (в `warnings` и `blocked.jsonl`), confirm — остановка и вопрос пользователю (код 3), guard недоступен — код 4. `--read-only` — никаких действий, только наблюдение.
- Персональные данные — маска до записи; что нельзя замаскировать — не показывать.
- Публикация роликов — только по тем же согласиям, что публикация скриншотов (`repo-sync.md`, `web-upload.md`), и только просмотренных. `evidence.sensitive` — не публикуется.
- Ролики не коммитятся: `clips/` и `recordings/` — в `<RUN_DIR>/.gitignore` (делает `finalize`; вручную — `clips.py ignore <RUN_DIR>`).

## Команды `clips.py`
```bash
python3 <SKILL_DIR>/scripts/clips.py check <RUN_DIR>                     # все ролики: файл, размер, длительность, звук, sha, просмотр
python3 <SKILL_DIR>/scripts/clips.py list <RUN_DIR>                      # ролики по находкам
python3 <SKILL_DIR>/scripts/clips.py viewed <RUN_DIR> --id F-004         # после Read ленты кадров
python3 <SKILL_DIR>/scripts/clips.py sheet <RUN_DIR> --id F-004          # пересобрать ленту кадров (--frames 12)
python3 <SKILL_DIR>/scripts/clips.py policy "Тост мерцает при закрытии" --run-dir <RUN_DIR>   # нужен ли ролик
python3 <SKILL_DIR>/scripts/clips.py caps                                # ffmpeg, кодеки, Playwright screencast
# свой ролик (например, из playwright-cli video-start): сжать, GIF, постер, лента кадров, запись в находку
python3 <SKILL_DIR>/scripts/clips.py finalize <RUN_DIR> --src /tmp/raw.webm --name F-004-menu \
  --caption "Меню закрывается само" --kind error --finding F-004
```
Исполнитель (субагент) возвращает ролик в блоке `qa-findings` — полем `clips` (запись из вывода `clip.js` или путь `clips/…mp4`); `ingest_findings.py` принимает только файлы внутри `<RUN_DIR>` с расширением ролика, больше бюджета — с предупреждением.

## Где используется
- `build_report.py report|summary` — раздел «Ролики находок» (находка, вид, длительность, размер, файл, постер, просмотрен); без роликов раздела нет.
- `render_draft.py` — в «Доказательствах» GIF inline и ссылка `[▶ ролик, 6 с, 0,4 МБ](…mp4)`, только `viewed: true`; с `--screenshot-base` — из той же ветки.
- `publish_shots.py push` — mp4 и GIF в ту же ветку и папку, что скриншоты; `local` — в `<RUN_DIR>/results/clips/` и тот же архив.
- `node/publish_web.mjs` / `comment_web.mjs` — `.mp4` как вложение (GitHub показывает плеер); больше 10 МБ — отказ до открытия браузера (`--max-attach-mb` для платных планов).
- `export_results.py --clips referenced|all|none` (по умолчанию referenced) — копии в `<dest>/clips/`.

## Если что-то не так
| Симптом | Причина и что делать |
|---|---|
| `ffmpeg не найден — ролик не сжат` | ролик сохранён как есть (webm), без GIF, постера и ленты; поставить ffmpeg (`INSTALL.md`, только с согласия) или `QA_FFMPEG=<путь>`; без ленты — посмотреть скриншоты шагов и `clips.py viewed … --force` |
| код 3 «поле пароля» / «страница входа» | записывать после входа (`--state`, `--cdp`) или на гостевом экране; страницы входа и оплаты не записываются |
| код 4 | `rules.json` не прочитан или Playwright не установлен: `check_env`, `cd <SKILL_DIR>/scripts/node && npm install` |
| по CDP код 4 «требует page.screencast» | старый Playwright: обновить пакет скила или записывать в эмуляции (`--device` / `--size`) |
| нет рамки или подписи | страница запрещает встраивание (CSP) — предупреждение; рамка появляется, только когда элемент виден |
| «не уложились в 3,0 МБ» | сократить `--seconds`, `--hold` или область (`--size` меньше) |
| «ролик почти весь чёрный» | вкладка свёрнута или страница не отрисована — открыть окно, повторить |
| на ленте не то, что в находке | исправить шаги (`--setup`), задержку (`clip.wait`) и перезаписать; `viewed` не ставить |

## Влияние на прогон
- **Время:** +10–25 с на ролик (запись 3–10 с + сжатие, GIF, лента кадров ≈ 2–5 с).
- **Место:** до `max_mb` на ролик (обычно намного меньше); 20 роликов ≈ 1–40 МБ в `clips/` (не в репозитории).
- **Токены:** одна картинка ленты кадров на ролик (как контактный лист), видео модель не смотрит.
- **Зависимости:** ffmpeg необязателен (рекомендуется), Playwright скила уже есть.
