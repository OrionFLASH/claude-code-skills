# Карта плагинов и скилов-усилителей

Реально доступные усилители определяет `check_env` (`env.json → enhancers`). **Используются только найденные.** Без них скил работает по собственным чек-листам.

## Принципы
1. **Собственный чек-лист выполняется всегда**, плагины только дополняют.
2. Скил-методику (SKILL.md усилителя) читает исполнитель и выполняет её шаги **сам**, через наши инструменты и под `url_guard`. Отчётные форматы усилителя не используются — выводы приводятся к `templates/finding.schema.json` (`source: plugin:<name>`).
3. Агент плагина запускается, только если ему можно передать блок правил (`safety-rules.md` §4) и он выполняет действия через проверяемые инструменты. Иначе — не используется в этом направлении.
4. Дубли между выводом плагина и своей проверкой сливает `fingerprint.py dedupe`; у слитой находки `sources` содержит оба источника.
5. Выводы противоречат (плагин: «ок», свой чек-лист: «дефект» или наоборот) → перепроверить вручную в браузере; неясно — спросить пользователя.
6. В отчёте — таблица «какой усилитель, в каких направлениях, сколько находок дал».

## Запрещено (не использовать никогда)
| Что | Почему |
|-----|--------|
| `qa-skills:adversarial-breaker`, `/run-qa adversarial` | активные атаки: XSS/SQL-payload, обход авторизации, удаления |
| `qa-skills:security-auditor` в части браузерных атак | использовать нельзя целиком: смешивает пассивные и активные проверки без контроля |
| opentest `perf-test` | k6 — нагрузочное тестирование |
| opentest `security-scan`, `api-test` с мутациями | сканер / изменение данных |
| `/run-qa` целиком | сам диспетчеризует агентов без наших правил; брать только отдельные агенты из таблицы |
| `submit-learnings` (qa-skills) | публикует issue в репозиторий плагина |

## browser-devtools-mcp
Установлен, но **отключён** (свои 2 MCP, свой Chromium, подменяет главного агента, телеметрия). Использовать, только если пользователь сам включил его на прогон (`claude plugin enable browser-devtools-mcp@browser-devtools`, `TELEMETRY_ENABLE=false`) — тогда его агенты получают блок правил и работают последовательно, не одновременно с MCP-потоком Playwright.
