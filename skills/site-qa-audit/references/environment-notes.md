## Флаги Playwright MCP (0.0.83, из `--help`)
| Флаг | Есть | Семантика |
|------|------|-----------|
| `--isolated` | да | профиль в памяти, состояние теряется при закрытии; начальное состояние — `--storage-state` |
| `--allowed-origins` | да | список через `;`, формат `https://host:port` или `http://host:*`. **Не граница безопасности**, редиректы не учитывает. Ломает CDN/тайлы, если не перечислить их — в скиле не используем |
| `--blocked-origins` | да | список через `;`, проверяется раньше allowlist. Тоже не граница безопасности — дополняет `url_guard`, а не заменяет |
| `--headless` | да | по умолчанию браузер **видимый** |
| `--viewport-size` | да | `1280x720` |
| `--browser` | да | chrome / firefox / webkit / msedge; по умолчанию канал chrome (системный Google Chrome) |
| прочее | | `--user-data-dir`, `--save-session`, `--output-dir`, `--device "iPhone 15"`, `--storage-state`, `--secrets <dotenv>`, `--caps vision,pdf,devtools` |

Официальный плагин запускает MCP **без флагов**: видимый Chrome, постоянный профиль. Флаги на лету не меняются — `--blocked-origins` работает, только если пользователь сам добавил отдельный MCP с этим флагом. Поэтому основная защита — `url_guard.py` перед каждым переходом и действием.

## Параллельность (опыт: 2 субагента одновременно)
**Playwright MCP — ненадёжно.** Все субагенты сессии делят один MCP-сервер и одну «текущую вкладку»:
- агент B после навигации агента A увидел у себя чужую страницу (todomvc вместо svgomg);
- закрытие вкладки «по индексу» одним агентом закрыло страницу другого;
- первая навигация получила `net::ERR_ABORTED` из-за конкурентного перехода.

**playwright-cli — надёжно.** Сессии `playwright-cli -s=<имя>` — отдельные браузеры с in-memory профилем; две сессии параллельно возвращали каждая свой URL без пересечений.

**Решение:**
- Браузерные проверки через Playwright MCP — **последовательно**, одним исполнителем.
- Параллельные браузерные потоки — только субагенты, каждый со своей сессией `playwright-cli -s=qa-<поток>` (без MCP). По умолчанию `max_workers = 2` браузерных потока + MCP-поток оркестратора.
- Небраузерные проверки (`node/headers.js`, `links.js`, `lighthouse.js`, `a11y.js`, gh) — параллельно (фоновые процессы), у каждого свой браузер.
- Если `playwright-cli` нет — `max_workers = 1` для браузера.

## Firefox
Firefox 155 (сборка playwright 1.63) на macOS 27 не стартует: `Could not find profile folder` — в headless, headed и persistent-режимах, в песочнице и без неё. Не исправляется переустановкой. До обновления playwright кросс-браузерность = Chromium + WebKit; в отчёте пишется «Firefox: не проверено — браузер не запускается в окружении». `check_env` реально запускает каждый браузер и определяет это сам.

## Песочница Claude Code
Внутри песочницы Bash нет доступа к профилю Chrome (`Operation not permitted`), а браузеры из node-скриптов запускаются. Если скрипт падает на запуске браузера — повторить вне песочницы.

## Установленные усилители и решения
| Что | Как стоит | Решение |
|-----|-----------|---------|
| ux-audit (jezweb dev-tools) | копия скила + команда `/ux-audit` в `~/.claude` | только методика; сам «прокликивает и отправляет всё» — исполняем его шаги нашим агентом под `url_guard` |
| e2e-test, ux-test (opentest) | копии в `~/.claude/skills` | инструкции без скриптов; используют старые имена инструментов MCP (`browser_fill` → `browser_type`/`browser_fill_form`) |
| a11y-test, perf-test (opentest) | **не ставились** | perf-test = k6 (нагрузка, запрещено); a11y-test заменён `node/a11y.js` |
| ux-heuristics, laws-of-ux, ux-design-principles, ui-audit-redesign | копии в `~/.claude/skills` | знания/чек-листы, браузер не трогают |
| qa-skills (neonwatty) | плагин `qa-skills@neonwatty-qa` + `@playwright/cli` | adversarial-audit и resilience-audit — только пассивно (без интерактивной проверки); агент `adversarial-breaker` и `/run-qa adversarial` **запрещены** |
| browser-devtools-mcp | плагин установлен и **отключён** | 2 своих MCP + свой Chromium, `settings.json` назначает свой главный агент, телеметрия по умолчанию. Включать вручную под конкретный прогон, с `TELEMETRY_ENABLE=false`; не одновременно с MCP-потоком Playwright |
| frontend-design | официальный плагин | предложения по редизайну |
| Claude in Chrome | не был настроен на момент проверки | см. `setup.md`; режим «текущий экран» — когда `check_env` видит native host |

Источник каждой копии скила — файл `.source` в его папке (репозиторий, путь, коммит).
