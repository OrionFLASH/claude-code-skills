# Опрос на входе

Цель — получить полный `run-config.yaml` (схема: `templates/run-config.example.yaml`).

## Правила опроса
- Спрашивать инструментом вопросов с вариантами (`AskUserQuestion`), **по 1–3 вопроса за раз**, рекомендуемый вариант — первым с пометкой «(Recommended)».
- **Уже переданное в запросе не переспрашивать.** Сначала разобрать запрос пользователя: URL, глубина, направления, репозитории, запреты, режим — всё, что можно извлечь.
- Ответ «по умолчанию» / «как обычно» → брать значения по умолчанию из таблицы ниже.
- Секреты не спрашивать в чате: только **имена** переменных окружения. Если пользователь вставил пароль/токен в чат — не повторять его, предложить вынести в env.

## Папка прогона
`./qa-runs/<YYYY-MM-DD>-<host>/` в текущей рабочей папке (не в репозитории скилов). Если за сегодня папка есть — суффикс `-2`, `-3`.
```
run-config.yaml  env.json  rules.json  findings.json  matches.json  report.md
screenshots/  logs/  drafts/  raw/ (вывод node-скриптов и плагинов)
```
Кэш issues общий для прогонов: `./qa-runs/.cache/issues/`.

**Повтор прогона:** если в `./qa-runs/` есть прошлые `run-config.yaml` для того же хоста — первым вопросом предложить: «Повторить конфиг от <дата>» / «Повторить, но изменить…» / «Новый опрос».

## Вопросы (порядок и варианты)

| # | Вопрос | Варианты | По умолчанию |
|---|--------|----------|--------------|
| 1 | Стартовый URL(ы) | свободный ввод (один или несколько) | — (обязательно) |
| 2 | Разрешённые домены для навигации | «Домен и поддомены (Recommended)» / «Только этот хост» / «Указать список» | `<host>`, `*.<host>` |
| 3 | Авторизация | «Не нужна» / «Тестовый аккаунт (env)» / «Войду сам в окне браузера» | не нужна |
| 3a | (если тестовый аккаунт) имена переменных | `QA_USERNAME` / `QA_PASSWORD` или свои | `QA_USERNAME`, `QA_PASSWORD` |
| 4 | Охват | «Весь сайт» / «Раздел (префикс URL)» / «Список URL» / «Только текущий экран» | весь сайт |
| 5 | Направления (мультивыбор) | «Все» + 10 направлений (по 4 на вопрос: functional, logic-state, ux, visual-ui / responsive-cross-browser, accessibility, performance, seo-content / security-passive, product) | все |
| 6 | Глубина | «smoke» / «standard (Recommended)» / «deep» | standard |
| 6a | (standard) лимит страниц | 20 / 50 / 100 / свой | 50 |
| 7 | Устройства и браузеры | «По глубине (Recommended)» — показать что это значит из `depth-matrix.md` / «Изменить» | по глубине |
| 8 | Репозитории | «Без репозиториев» / «Добавить репозиторий» (повторять) | без |
| 9 | Запреты | свободный текст + чек-лист частых пунктов (мультивыбор) | только базовые |
| 10 | Плагины | «Все установленные (Recommended)» / «Выбрать» / «Только собственные чек-листы» | все установленные |
| 11 | Язык отчётов и issues | «Русский» / «English» / «Язык репозитория» | русский |
| 12 | Параллельные потоки | число; показать рекомендацию из `environment-notes.md` | 2 (браузерных через playwright-cli) |
| 13 | Режим | «dry-run — черновики вместо публикации» / «Боевой» | dry-run, если есть репозитории с записью; иначе неважно |

### 8. Репозиторий (на каждый)
1. URL (`https://github.com/owner/repo` или `owner/repo`).
2. Роли (мультивыбор):
   - `check` — только сверка;
   - `write-new` — сверка и запись **новых** находок по **их** шаблону;
   - `copies` — подробные копии **всех** находок **своим** шаблоном (`templates/issue-detailed.md`);
   - `comment` — комментарии к существующим issues (FIXED-INSUFFICIENT, REGRESSION).
3. Стиль: кратко / подробно.
4. Метки: только существующие / можно создавать свои / писать строкой в теле.
5. Подтверждение перед публикацией: включено (по умолчанию) / выключено (предлагать только для своего репозитория — где у пользователя admin).
6. Скриншоты: коммитить в этот репозиторий (`runs/<дата>/`) / не класть.

Сразу после ввода — `fetch_issues.py meta owner/repo` и сверка прав с ролями по таблице `repo-sync.md` §1 (issues включены; метки — `triage`; скриншоты — `push`). Если прав не хватает — сообщить и предложить: понизить роль до `check` / указать другой репозиторий / оставить черновики в `drafts/`.

### 9. Чек-лист частых запретов (мультивыбор, в дополнение к свободному тексту)
- Не выходить за домен (строго один хост)
- Не входить через внешние аккаунты (Steam, Google, Discord…) — уже в базовых, но можно указать конкретные
- Не трогать раздел профиля/аккаунта
- Не отправлять формы обратной связи / комментарии / сообщения
- Не менять язык/регион/валюту
- Не загружать файлы
- Спрашивать перед любым удалением
- Не нажимать рекламу и партнёрские ссылки

Свободный текст разбирается по `safety-rules.md` §2 → таблица «фраза → правило» на подтверждение.

## После опроса
1. Записать `run-config.yaml` (через `miniyaml.dump` или вручную по шаблону), затем `url_guard.py export --config … --out rules.json`.
2. Показать **сводку**: URL, домены, авторизация, охват, направления, глубина → устройства/браузеры, репозитории и роли, запреты (базовые + разобранные), плагины, язык, потоки, режим.
3. Ждать явного «старт» (или правок). Без «старт» прогон не начинается.
