# Детекторы раскладки: перекрытия, достижимость, iframe

Детерминированные проверки вместо «найти наложения глазами по скриншоту». Результат — JSON в `<RUN_DIR>/raw/`; находки из него оформляются как обычно (`finding.schema.json`), скриншот — `shot.js` с теми же селекторами.

Общие параметры обоих детекторов: `--sizes 1280x720,1024x768,768x1024,720x450`, `--device pixel7,iphone15,ipad,pixel7-landscape` (каталог — `devices-auth.md`), `--frames all|main`, `--rules rules.json`, `--log blocked.jsonl`, `--setup setup.js` (действия перед проверкой, через `guardedPage`), `--state auth-state.json` или `--cdp URL` (вход пользователя), `--out файл.json`.

## Перекрытия: `node/occlusion.js`
```bash
node <SKILL_DIR>/scripts/node/occlusion.js https://example.com/ \
  --sizes 1440x813,1024x768,720x450 --device pixel7,iphone15 --frames all \
  --rules <RUN_DIR>/rules.json --out <RUN_DIR>/raw/occlusion.json
```
Алгоритм:
1. Видимые интерактивные элементы (`a[href]`, `button`, поля, `[role=button|link|checkbox|tab|…]`, `[tabindex]`, `[onclick]`), без `display:none`, `visibility:hidden`, `opacity:0`.
2. **Только видимая часть**: рамка ∩ окно ∩ области прокручиваемых/обрезающих предков. Строки списка, ушедшие за край контейнера с `overflow`, не проверяются — отсюда нет ложных срабатываний «список под закреплённой панелью».
3. `document.elementFromPoint` в 5 точках (центр и 4 точки со смещением 25 % от краёв — внутри скруглённых кнопок). Верхний элемент — сам элемент, его потомок, предок или его `<label>` → чисто.
4. Иначе пара «закрыт / закрывает»: закрывающий — ближайший интерактивный предок верхнего элемента или позиционированный контейнер; площадь — пересечение видимой части с рамкой закрывающего (`area {x, y, w, h, px}`), `zIndex` и `position` обоих, `points` — сколько точек из 5 закрыто.
5. **Временное перекрытие** (не дефект): закрывающий закреплён (`fixed`/`sticky`), а прокрутка пользователем (контейнеры `overflow:auto|scroll` и документ) выводит элемент из-под него. Проверяется прокруткой с восстановлением позиции; считается в `transient`.
6. `--frames all`: элементы iframe проверяются внутри кадра и затем по документу-родителю (точки, чистые внутри кадра, должны попадать в `<iframe>`; иначе пара `crossFrame: true` — например, тост страницы поверх кнопки приложения). Координаты — в CSS px окна страницы (смещение кадра с рамкой и отступами прибавлено).

Пример результата: `{"occluded": {"selector": "#whole-map", "name": "Вся карта", "box": [1388,733,40,40]}, "occluder": {"selector": "#bell", "zIndex": 1250, "position": "fixed"}, "area": {"w": 36, "h": 20, "px": 720}, "points": 2}`.

Что не ловит: перекрытие элементами с `pointer-events: none` (визуально закрыто, но клик проходит) — это проверяется глазами по скриншоту; наложение текста на текст без интерактивных элементов.

## Достижимость: `node/reachability.js`
```bash
node <SKILL_DIR>/scripts/node/reachability.js https://example.com/ \
  --sizes 720x450,863x360 --device pixel7-landscape,iphone15-landscape --out <RUN_DIR>/raw/reachability.json
```
**Обязательный прогон**: окна высотой до 450 px и альбомная ориентация телефонов (без `--sizes/--device` берутся `720x450` и `pixel7-landscape`).

Для каждого видимого интерактивного элемента, рамка которого видна меньше чем на 90 % (окно ∩ обрезающие предки):
1. **Структура**: прокручиваемые предки (`scrollHeight > clientHeight`, `overflow-y`, признак `user` — может ли их прокрутить пользователь; у корня `overflow:hidden` → нет).
2. **Колесо мыши** над видимой частью ближайшего обрезающего контейнера (или центром окна), шаг — оставшееся расстояние (300–1500 px), до 12 шагов или пока ничего не двигается.
3. **Жест** `Input.synthesizeScrollGesture` (touch на сенсорных устройствах, иначе mouse), только Chromium; выполняется, если колесо не помогло.
4. Позиции прокрутки восстанавливаются после каждого элемента (`scrollIntoView` не используется: он прокручивает и `overflow:hidden`, чего пользователь сделать не может).

Итог: `verdict` «достижим» / «недостижим» / «не проверено» (ни колесо, ни жест недоступны), `wheel`, `gesture` (`skipped`, если хватило колеса), `scrollers`, `side` (below/above/right/left/clipped). Элементы с той же цепочкой прокрутки и стороной после двух одинаковых результатов получают вердикт без повторной прокрутки (`inferred: true`). `--max 40` — лимит на кадр.

Мобильный WebKit (iPhone, iPad) не поддерживает колесо и CDP-жесты: детектор эмулирует то же устройство в Chromium и пишет `engineNote`. Реальный WebKit проверяйте `device_context.js` + скриншотом.

Пример находки: «В альбомной ориентации 863×360 кнопка "Только ненайденные" на y=568 недостижима: корень `overflow:hidden`, `scrollHeight` 707 при `clientHeight` 360, колесо и жест её не двигают».

## Iframe во всех детекторах (`--frames all`)
| Скрипт | Что делает с кадрами |
|--------|----------------------|
| `occlusion.js`, `reachability.js` | проверка внутри каждого видимого кадра, координаты со смещением кадра; occlusion — ещё и перекрытие кадра элементами страницы |
| `a11y.js` | по умолчанию `all`: axe заходит в iframe; в результате `text: {main, frames[], total}` и `note`, если текст страницы < 500 символов, а основное — во фреймах (признак вложенного приложения). `--frames main` — iframe исключены |
| `links.js` | `--frames all`: документы `<iframe src>` в пределах `allowed_domains` обходятся как страницы (`frameOf`) |
| `shot.js`, `snap_mcp.js` | селекторы внутри кадра: `iframe#app >>> button.save` (вложенные кадры — несколько `>>>`); координаты кадра прибавляются автоматически |
| `probe.js` | не применимо (проверка запуска браузеров) |

API для своих сценариев: `require('<SKILL_DIR>/scripts/node/frames.js')` → `listFrames(page, 'all')` (кадры со смещением), `locate(page, 'iframe#app >>> sel')`, `pageText(page)`.
