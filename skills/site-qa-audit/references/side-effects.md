# Побочные эффекты и инварианты

Некоторые действия на сайте имеют последствия за пределами теста: загруженный файл попадает в публичный рейтинг, включается рассылка, создаётся публичная запись, в браузере остаётся локальная копия. Оценки текста кнопки (`url_guard action`) для них мало: защитный элемент может называться иначе, появиться только после действия или не появиться вовсе.

Пример из реального прогона: помощник искал флажок «Чужой сейв», сайт переименовал его в «Чужое сохранение». Флажок не нашёлся и не был отмечен, файл загрузился около 12 раз и попал в публичный рейтинг. Плюс в браузере осталась локальная копия («Запомнить»).

## В run-config
```yaml
side_effects:
  - id: SE1
    action: upload                 # upload | click | check
    target: "#upload"              # селектор; ">>>" — внутрь iframe
    effect: "сохранение попадает в публичный рейтинг без флажка «Чужое сохранение»"
    leaves: ["локальная копия сохранения в браузере (кнопка «Запомнить»)"]
invariants:
  - id: INV1
    after: SE1                     # id эффекта или тип действия (upload)
    within_ms: 5000
    require:
      role: checkbox
      name: "Чуж(ой|ое)"           # регэксп по доступному имени/подписи, без учёта регистра
      state: checked               # present | checked | unchecked | absent
      ensure: false                # true — раннер сам отметит появившийся неотмеченный флажок (через guard)
      only_after_action: true      # до действия элемента быть не должно
    vocabulary: "Чужое сохранение" # точное название в прошлый раз (словарь интерфейса)
    else: abort                    # abort — остановиться и предупредить; warn — записать и продолжить
```
Регэксп в `name` — защита от переименования («Чуж(ой|ое)»), `vocabulary` — сигнал, что название всё же поменялось.

### Диалог из радио-кнопок после действия
Защита бывает не флажком, а **диалогом**: после выбора файла сайт спрашивает «Моё / Чужое, только посмотреть» и «Запомнить / Не сейчас», а после «Готово» в панели появляется флажок «Чужое сохранение». Описание:
```yaml
invariants:
  - id: INV2
    after: SE1
    within_ms: 20000               # ожидание первого варианта диалога
    dialog:
      choose:                      # по порядку; role: radio (role=radio или input[type=radio]) + регэксп имени, или selector
        - name: "Чуж(ой|ое)"
        - name: "Не сейчас"
      confirm:                     # кнопка применения выбора
        role: button
        name: "^Готово$"
      then:                        # что должно быть после подтверждения (поля как у require)
        role: checkbox
        name: "Чуж(ой|ое)"
        state: checked
        within_ms: 10000
    vocabulary: "Чужое сохранение" # сравнивается с подписью, найденной по then
    else: abort
```
Порядок: каждый вариант ищется и нажимается через guard; выбран он, только если `aria-checked="true"` (или свойство `checked`). Вариант не появился, не выбрался после нажатия или guard не дал его нажать → **остановка до «Готово»** (кнопка подтверждения не нажимается), код 3. После «Готово» проверяется `then` (флажок в панели есть и отмечен); нет — остановка. В preflight первый вариант диалога не должен быть виден до действия. Флажок с ролью `checkbox`/`radio` на `div` (ARIA) теперь тоже читается по `aria-checked`.

## Команды (`scripts/node/invariants.js`)
```bash
# предполётная проверка словаря интерфейса (до первого действия с эффектом)
node <SKILL_DIR>/scripts/node/invariants.js preflight --config <RUN_DIR>/run-config.yaml --url https://example.com/upload \
  --run-dir <RUN_DIR> --prev-vocab <OUTPUT_ROOT>/qa-runs/<прошлый прогон>/vocabulary.json
# действие с эффектом под наблюдением
node <SKILL_DIR>/scripts/node/invariants.js exec --config <RUN_DIR>/run-config.yaml --effect SE1 \
  --url https://example.com/upload --file <путь к тестовому файлу> --run-dir <RUN_DIR> --rules <RUN_DIR>/rules.json
# ручная запись (действие сделано через MCP или пользователем)
node <SKILL_DIR>/scripts/node/invariants.js log --run-dir <RUN_DIR> --effect SE1 --what "включено «Запомнить»" --left "локальная копия в браузере"
```
`exec` также принимает `--cdp URL` (вкладка пользователя с входом, `--page-match`), `--setup setup.js`, `--device`.

Порядок `exec`:
1. **Preflight**: защитные элементы, которые должны быть до действия, ищутся по `selector` или `role` + `name`; их подписи сравниваются с `vocabulary` и с `vocabulary.json` прошлого прогона. Не найден, переименован или (для `only_after_action`) уже есть до действия → действие **не выполняется**, код 2, вопрос пользователю.
2. Действие через `guardedPage` (правила безопасности действуют).
3. Наблюдение каждые 100 мс до `within_ms`: элемент появился? в нужном состоянии? (`ensure` — отметить).
4. Нарушение и `else: abort` → код 3, `alert` в stderr («Прогон остановлен… Осталось: …»), строка «ОСТАНОВЛЕНО» в `side_effects.md`. Прогон дальше не идёт: сообщить пользователю, что эффект мог произойти и что проверить вручную.
5. Название защитного элемента изменилось, но инвариант выполнен → код 2 и вопрос («тот же элемент?»), прежде чем повторять действие.

Коды: 0 — выполнено, инварианты соблюдены; 2 — нужен ответ пользователя; 3 — остановка.

В своих сценариях: `runSideEffect(page, guarded, cfg, 'SE1', { file, runDir })`. `guardedPage(page, rules, { sideEffects: cfg.side_effects })` не даст выполнить действие над целью эффекта в обход раннера (confirm `side_effect:SE1`).

## Журнал `<RUN_DIR>/side_effects.md`
Таблица: время, эффект, действие (что загружено/включено), результат (выполнено / ОСТАНОВЛЕНО / НЕ выполнено), инвариант, **что осталось** (локальные копии, скрытые записи, включённые настройки). Пишется на каждое действие с эффектом, включая остановленные. Раздел целиком переносится в `report.md` — пользователь должен явно видеть, что осталось в браузере и на сайте после прогона.

`vocabulary.json` в папке прогона — словарь защитных элементов (`{INV1: {observed, when, at}}`); для следующего прогона передаётся как `--prev-vocab`.
