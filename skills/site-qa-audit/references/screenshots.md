# Скриншоты с аннотациями

Каждая находка с визуальным проявлением получает **аннотированный скриншот**: на нём сразу видно, где проблема и в чём она.

## Оформление (правила)
| Элемент | Как | Зачем |
|---------|-----|-------|
| Обводка | пунктир 1,6 px с тонкой тёмной подложкой, скруглённые углы, отступ 4 px от элемента | не жирно, не перекрывает сам элемент |
| Стрелка | 1,5 px, лёгкий изгиб, маленький наконечник; от ближнего края подписи к ближнему краю обводки | аккуратно показывает связь подписи и элемента |
| Подпись | 1–2 строки (≤ 3), тёмная полупрозрачная плашка, рамка и значок цветом аннотации: `✕` ошибка, `?` вопрос, `•` пояснение | коротко, что не так или в чём вопрос |
| Цвет | авто из палитры **жёлтый `#FFD60A` / зелёный `#30D158` / фиолетовый `#BF5AF2`** — тот, что контрастнее фону вокруг элемента и не совпадает с ним по тону | видно на любом скриншоте |

Размещение подписи — автоматически: не перекрывает обведённые элементы, области `avoid` и другие подписи; выбирает спокойный фон (без текста и мелких деталей); стрелки не пересекаются друг с другом и с чужими обводками; подпись ближе к элементу.

Текст подписи — **конкретный факт, не оценка**: «Контраст 3,19:1 — нужно 4,5:1», «Enter открывает 3-й пункт, а не этот», «Кнопка 15 px в высоту», «Задумано? DLC по умолчанию». До ~60 символов.

## Как снять
1. Подготовить состояние страницы (открыть меню, ввести запрос и т.д.).
2. **Playwright MCP** — `scripts/snap_mcp.js` через `browser_run_code_unsafe` (заменить `__OUT__` на абсолютный путь `<RUN_DIR>/screenshots/F-NNN-<кратко>.png`, `__TARGETS__` — на список целей). Он делает скриншот области просмотра и возвращает координаты элементов. `"row": true` — обвести всю строку/карточку, а не только текст.
3. Сохранить ответ в `<RUN_DIR>/screenshots/F-NNN-<кратко>.spec.json`; при необходимости добавить `avoid` — области, которые подпись не должна закрывать (например, весь список результатов).
4. `node <SKILL_DIR>/scripts/node/annotate.js --in <png> --spec <spec.json>` → `<имя>-annotated.png`. В ответе — выбранный цвет и место подписи; `overlapCost` > 100 — подпись легла неудачно: добавить `avoid`, сократить текст или задать `color` вручную.
5. **Посмотреть результат** (Read изображения) перед тем, как ссылаться на него в находке.

Для `playwright-cli` и node-скриптов — то же самое: координаты через `getBoundingClientRect()` в момент скриншота (скриншот области просмотра, `scale: css`), затем `annotate.js`.

Элемент внутри iframe (MCP и `shot.js`): селектор `iframe#app >>> button.save` — координаты кадра прибавляются автоматически, рамку числами задавать не нужно.

## Без MCP: `shot.js` (CDP или Playwright) — снимок и разметка в одном вызове
`scripts/snap_cdp.js` — то же, что `scripts/node/shot.js` (CDP-аналог `snap_mcp.js`).
```bash
# вкладка браузера пользователя, к которому подключились по CDP (auth: manual-cdp): ничего не чистится, перехода нет
node <SKILL_DIR>/scripts/node/shot.js --cdp http://127.0.0.1:9222 --page-match example.com \
  --out <RUN_DIR>/screenshots/F-001-bell.png \
  "#bell|Колокольчик закрывает «Вся карта» (36×20)|error" ".legend|@avoid" "rect:0,0,300,60|@avoid"
# эмулированное устройство со входом пользователя и подготовкой состояния
node <SKILL_DIR>/scripts/node/shot.js --cdp http://127.0.0.1:9222 --device pixel7 --url https://example.com/ \
  --setup <RUN_DIR>/setup/open-drawer.js --rules <RUN_DIR>/rules.json --out <RUN_DIR>/screenshots/F-002-drawer.png \
  "role=button[name=\"Как найти\"]|Перекрыта колокольчиком|error"
```
- Цель — `селектор|подпись|kind[|row]` (kind: `error` / `question` / `note`; `row` — обвести строку/карточку). Селектор — CSS/Playwright, `iframe … >>> …` или `rect:x,y,w,h`.
- `селектор|@avoid` / `rect:…|@avoid` — зоны, которые подпись не закрывает.
- `--setup файл.js`: `module.exports = async ({ page, guarded }) => { await guarded.click('text=Слои'); }` — действия через guard (`browser-guard.md`).
- Без `--cdp`: `--url` (+ `--device` / `--size 1440x813`, `--state auth-state.json`).

Автоматика:
1. **Соседи в avoid**: видимые интерактивные элементы ближе 260 px к целям (кроме самих целей, их предков и потомков) добавляются в `avoid` (`autoAvoid` в ответе; `--no-neighbors` — выключить).
2. **Перебор**: если `overlapCost` любой подписи > `--max-cost` (100) или подпись закрывает чужие рамки — пробуются ширины подписи 240/180/320/140 px (в каждой — 112 положений вокруг элемента); берётся лучший вариант.
3. **Автопроверка** (без чтения картинки глазами): подпись целиком внутри снимка (`inside`), не закрывает рамки других элементов, `avoid` и другие подписи (`covers` = 0), цвет контрастен фону вокруг рамки (`contrast` ≥ 2). Нарушения — в `warnings`, `ok: false`. Не найденные цели — в `missing`/`warnings`, файл `-annotated` тогда не создаётся.
4. **Контактный лист**: пакет снимков → одна картинка на 6–9 штук для просмотра одним взглядом:
```bash
node <SKILL_DIR>/scripts/node/shot.js --batch <RUN_DIR>/screenshots/shots.json --dir <RUN_DIR>/screenshots [--cdp …] [--sheet contact.png]
#   shots.json: [{"name": "F-001-bell", "url": "https://example.com/", "device": "pixel7", "setup": "s.js", "targets": ["#bell|Подпись|error"]}]
node <SKILL_DIR>/scripts/node/shot.js sheet --out <RUN_DIR>/screenshots/contact.png --per 9 <RUN_DIR>/screenshots/*-annotated.png
```
Контактный лист просматривается (Read) вместо каждого снимка; снимки с `warnings` — открыть отдельно.

## Правила
- Одна находка — 1–3 аннотации на скриншот; больше — разбить на несколько скриншотов.
- Обводить то, что нужно увидеть: при «элемент отсутствует/не виден» обводить место, где он ожидался (`kind: "question"` или `"note"`).
- Оригинал (`F-NNN-….png`) сохраняется рядом с аннотированным; в находке в `screenshots` первым идёт `-annotated.png`, затем оригинал. Черновики issues показывают только аннотированный вариант.
- Персональные данные на скриншоте маскируются **до** аннотации (`safety-rules.md` §5).
- Скриншоты — по абсолютным путям `<RUN_DIR>/screenshots/` (относительные пути MCP разрешаются от папки запуска Claude Code).
