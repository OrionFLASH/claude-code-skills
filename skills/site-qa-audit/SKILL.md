# site-qa-audit

Универсальный QA-аудит сайта через браузер. Скил не содержит конкретных сайтов, репозиториев и учётных данных — всё получает на входе.

**Частые команды** (подробно — ниже и в `references/`):
```bash
# скриншот с рамками по селекторам DOM и подписями (несколько целей на кадре; телефон — подписи в поле справа)
node <SKILL_DIR>/scripts/node/shot.js --url https://example.com/ --out <RUN_DIR>/screenshots/F-001-menu.png \
  "#menu|Меню перекрывает поиск" ".search|@avoid" [--device pixel7] [--locales de-DE,ar-SA] [--rules <RUN_DIR>/rules.json]
python3 <SKILL_DIR>/scripts/url_guard.py nav <URL> --config <RUN_DIR>/run-config.yaml   # 0 allow, 2 confirm, 3 deny, 4 СТОП
node <SKILL_DIR>/scripts/node/targets.js <URL> --device pixel7     # «N из M меньше 24×24 по типам» одной строкой
python3 <SKILL_DIR>/scripts/brief.py <RUN_DIR> --thread qa-ux --directions ux --minutes 25   # задание исполнителю целиком
python3 <SKILL_DIR>/scripts/ingest_findings.py <RUN_DIR> --from <сообщение исполнителя>   # находки из блока qa-findings
python3 <SKILL_DIR>/scripts/thread_coverage.py again <RUN_DIR>             # вторая волна по «не проверено»
python3 <SKILL_DIR>/scripts/browser_mode.py set <RUN_DIR> --headed  # окно браузера видно — для всего прогона
python3 <SKILL_DIR>/scripts/recheck.py run <RUN_DIR>                # независимая перепроверка до публикации
```

`<SKILL_DIR>` — папка установленного скила: `python3 <папка этого файла>/scripts/skill_dir.py` печатает её (переменная `SITE_QA_AUDIT_DIR` → установленный плагин → `~/.claude/skills`; не рабочая копия репозитория), `check_env` показывает её первой строкой. Сразу после создания `<RUN_DIR>` скил копируется в прогон: `skill_snapshot.py <RUN_DIR> --update-config` → `<RUN_DIR>/skill` (`node_modules` — жёсткими ссылками), и **дальше `SKILL_DIR` прогона — эта копия** (`run-config.yaml → skill_dir`, в заданиях исполнителей): обновление плагина посреди прогона её не трогает. `<RUN_DIR>` — `<OUTPUT_ROOT>/qa-runs/<YYYY-MM-DD>-<host>/`; `<OUTPUT_ROOT>` — путь из запроса, иначе `SITE_QA_OUTPUT_DIR`, иначе `<cwd>` — результаты в `<cwd>/qa-runs/` (`references/intake.md` → «Папка прогона»). Не в репозитории скилов.

**Локальное приложение** (HTML на диске, `file://`, без сервера) проверяется так же, как сайт: копия в `<RUN_DIR>/app` (`local_app.py copy <папка> <RUN_DIR> --update-config`), `site.local_roots` в run-config, все детекторы — `--url file:///…`; guard пускает только внутрь каталога (`..`, симлинки, соседние папки — запрет) — `references/local-files.md`. Через Playwright MCP — только отдельный сервер прогона с guard в каждой вкладке: `browser_mode.py mcp <RUN_DIR> --check` (добавляет его пользователь).

**Одно место для всего.** Всё, что порождает прогон, лежит только в `<RUN_DIR>`: `run-config.yaml`, выгрузка issues, находки, перепроверки, скриншоты (в т.ч. разовые), вывод своих скриптов проекта. Не создавать `findings/`, `screenshots/`, `reports/` в корне проекта. Исключение одно: скриншоты, которые пользователь выбрал коммитить (`screenshots: commit`). Свои разовые скрипты принимают папку вывода аргументом (`<RUN_DIR>/raw`, `<RUN_DIR>/screenshots`), а не хардкодят путь в проект.

**Скил установлен только что** — он виден лишь в новой сессии Claude Code: в той, где его поставили, `/site-qa-audit` и вызов скила дают «Unknown skill». Продолжить в той же сессии можно: прочитать этот файл (`<SKILL_DIR>/SKILL.md`) и идти по «Порядку работы» вручную, скрипты — по полным путям (`INSTALL.md` → «Проверка»).

## Запуск: подтверждение намерения
- **Явный вызов** — пользователь набрал `/site-qa-audit` (в ходе есть `<command-name>/site-qa-audit</command-name>`): подтверждение не нужно, сразу «Порядок работы».
- **Скил подхвачен по смыслу запроса** (без команды): **первым действием**, до `check_env`, файлов и браузера — один вопрос `AskUserQuestion`: «Похоже, вы хотите протестировать <что понято: URL или интерфейс>. Запустить QA-аудит?» В тексте вопроса пересказать понятое: объект, направления, устройства, запреты — только то, что названо. Варианты: «Да, запустить аудит (Recommended)» / «Да, но сначала уточнить задачу» / «Нет, это другое».
  - «Да» → обычный порядок, понятое из запроса не переспрашивать; «уточнить» → опрос с вопроса «Что именно тестируем»;
  - «Нет» → скил прекращает работу и **ничего не создаёт** (ни папок, ни файлов, ни проверок), запрос выполняется как обычный, без скила. Нет ответа — не начинать.
  Подробно — `references/intake.md` → «Подтверждение намерения».
- **Автопилот** — явный вызов с подробной задачей и словом «автопилот» / «без вопросов» / `--autopilot` (или `autopilot: true` в повторяемом run-config): без подтверждения, опроса и «старт»; недостающее — значения по умолчанию (`intake.py from-text … --autopilot --journal <RUN_DIR>`), каждое решение — `journal.py decide … --auto`. Запреты, fail closed, dry-run без явного разрешения публиковать — без изменений; confirm-действия не выполняются, а копятся в `questions.json`. Вопрос — только если без него нельзя (нет URL, некуда писать) — `intake.md` → «Автопилот».

## Главное правило
**Безопасность важнее полноты.** До любых действий в браузере прочитай `references/safety-rules.md`. Перед каждым переходом и каждым кликом/отправкой/подтверждением — `scripts/url_guard.py` (`nav` / `action`). При работе через Playwright/CDP (node-скрипты, setup.js, shot.js) правила применяет `scripts/node/guard.js` автоматически (`guardContext` + `guardedPage`, журнал `<RUN_DIR>/logs/blocked.jsonl`) — `references/browser-guard.md`. Действия с побочными эффектами (загрузка с публичным результатом, рассылки, привязки) — только через `node/invariants.js exec` под инвариантами из run-config (флажок или диалог из радио-кнопок) — `references/side-effects.md`. Блок правил §4 — дословно в задание каждого субагента и агента плагина, с фактическим `<SKILL_DIR>`. Запрещённое не выполняется, а попадает в отчёт как «не проверено: запрет <правило>».

**Fail closed — сбой защиты не разрешение.** Решение guard — только коды 0 / 2 / 3. Код 4 («guard недоступен»), любой другой код, «No such file», пустой вывод = **стоп**: переход и действие не выполнять, сообщить. Node-скрипт с кодом 4 — то же. Страницы входа и покупки — только чтением (`url_guard.py nav --read-only`), не `curl` мимо guard.

**Правовые и финансовые утверждения** (нормы права, санкции, штрафы, налоги): в находке — наблюдаемый факт, нормы — только «возможно применимо» (`legal.norms`); **вторая проверка другим исполнителем** (`recheck.py legal`) и пометка «требуется проверка юристом» в тексте; без них не публиковать как факт (`safety-rules.md` §6a, `checklists/legal-ui.md`).

**Журнал** `<RUN_DIR>/journal.md` (`scripts/journal.py`, `references/run-files.md`): после каждого крупного шага — `done`, новые задачи — `todo`. В новой сессии сначала `journal.py status <RUN_DIR>` и продолжить с первого открытого пункта.

В командах не использовать разделители из знаков равенства (`echo =====`): в zsh они ломают команду (`environment-notes.md` → «Оболочка zsh»).

## Порядок работы

1. **Окружение** — `references/setup.md`: `scripts/check_env.sh` (Windows: `check_env.ps1`). Первая строка — `SKILL_DIR: <путь>`: этот путь (не рабочая копия, не «как в прошлый раз») — в run-config и во все задания. Обязательное не в порядке → предложить исправление; глобальные установки только после подтверждения; нужен перезапуск Claude Code → сказать и остановиться. Какие браузерные инструменты есть именно в этой сессии: `check_env.sh --browser-tools-only --session-tools "<имена своих инструментов через запятую>"`.
2. **Опрос и конфиг** — `references/intake.md`. **Папка и git — до первой записи файлов:** `<OUTPUT_ROOT>` (`intake.md` → «Папка прогона»); разрешение коммитить результаты — только явное в запросе («коммить результаты», «положи результаты в репозиторий»; `intake.py from-text --text … --json` → `git`), иначе `false`. Сразу `scripts/gitignore_helper.py ensure <OUTPUT_ROOT> [--allow-commit-results]`: если `<OUTPUT_ROOT>` в git-репозитории, `qa-runs/` попадает в его `.gitignore` без вопроса; код 1 — файлы `qa-runs/` уже в индексе: **один** вопрос «Убрать их из индекса git (`git rm -r --cached …`, файлы останутся на диске)?» → `untrack <OUTPUT_ROOT> --yes` только после «да». Только потом создавать `<RUN_DIR>` — и сразу копия скила: `skill_snapshot.py <RUN_DIR> --update-config` (дальше `SKILL_DIR` — `<RUN_DIR>/skill`); локальное приложение — `local_app.py copy <папка> <RUN_DIR> --update-config` (черновик `intake.py from-text` в эту папку сам берёт обе копии). **Затем память о сайте**: как только известен хост, найти `<OUTPUT_ROOT>/qa-runs/.site-context/<host>/context.md`; есть — прочитать, показать резюме в 3–6 строк (назначение, роли, сценарии, дата и источники) и спросить «Использовать как есть (Recommended)» / «Обновить» / «Изучить заново» → `context.reuse` (`intake.md` → «Память о сайте»). Если запрос — свободный текст с параметрами, сначала `scripts/intake.py from-text --file <запрос> --output-dir <OUTPUT_ROOT> --out <RUN_DIR>/run-config.yaml`: черновик показать пользователю, недостающее спросить (`intake.md` → «Черновик из свободного запроса»). Сразу завести журнал: `scripts/journal.py init <RUN_DIR> --todo …`. Спросить недостающее (по 1–3 вопроса, с вариантами), не переспрашивать переданное: что тестируем и что считать успехом (`goal`), **какие варианты данных и стенды есть** (`variants` — каждый входит в охват), куда не переходить, вход, устройства, окно браузера (`browser.headed`), глубина, откуда узнать о сайте (`context`), запреты, потоки (1–4), куда записать итоги (`report_destinations`). Разобрать запреты пользователя в правила (`safety-rules.md` §2) и показать на подтверждение. Побочные эффекты и защита — вопрос из `intake.md` («Побочные эффекты») → `side_effects` / `invariants`. Записать `<RUN_DIR>/run-config.yaml` (схема — `templates/run-config.example.yaml`), `url_guard.py export … --out <RUN_DIR>/rules.json`, повторить `check_env --fast --no-browsers --json <RUN_DIR>/env.json`. Показать сводку, ждать «старт».
3. **Репозитории** — `references/repo-sync.md` §1–2: права (`fetch_issues.py meta`), шаблоны и CONTRIBUTING (`read_templates.py fetch`), выгрузка всех issues с комментариями (`fetch_issues.py sync`), реестр (`fetch_issues.py registry`). Прочитать документы, которые скачал `read_templates.py fetch` (ссылки из форм и config.yml); шкалу серьёзности записать в `repos[].severity_map`. Перепроверка заявленных исправлений: `claims.py extract` → `claims.py plan` → `<RUN_DIR>/claims-plan.md` (`references/claims.md`); по сводке «Предусловия аккаунта» **сразу** спросить, какие состояния доступны (гость / без Pro / с Pro), и разбить план на проходы по состояниям (`intake.md`, вопрос 5b). Не хватает прав на роль → сообщить, предложить варианты.
4. **Разведка**: **чистое состояние** — если `auth.mode` не `manual-cdp`: профиль Playwright MCP постоянный, поэтому на старте для целевого origin записать и очистить cookies/localStorage тестового браузера (`browser_run_code_unsafe`: `page.context().clearCookies()` + `localStorage.clear()`), если прогон без авторизации или вход ещё не выполнен. При `auth: manual-cdp` (пользователь уже вошёл в своём Chrome, CDP `http://127.0.0.1:9222`) **ничего не очищать и никуда не переходить без нужды**: присоединиться по CDP, состояние для устройств — `node/device_context.js state --cdp … --rules <RUN_DIR>/rules.json --out <RUN_DIR>/logs/auth-state.json` (только cookie `allowed_domains` + localStorage/sessionStorage открытых вкладок сайта, файл 600; `references/devices-auth.md`). Телефон — только эмуляция с касаниями (`pixel7`, `WxH@mobile`; `media.touchValid`), иначе мобильные измерения недействительны. Все пути файлов для MCP (скриншоты, снимки) — **абсолютные** `<RUN_DIR>/…`: относительные разрешаются от папки запуска Claude Code. Открыть стартовые URL (Playwright MCP; локальное приложение `file://` MCP не открывает — разведка node-скриптами и `playwright-cli`, `local-files.md`); при охвате «только эти страницы» или запрете переходов — сразу включить **замок навигации** `scripts/nav_lock.js` (`safety-rules.md` §3.11). Затем в фоне `node/links.js` (карта, внешние ссылки). Собрать: карту страниц и шаблонов, ключевые элементы и сценарии, формы, интерактивные компоненты, сторонние источники ресурсов (`browser_network_requests` → хосты), вложенные приложения во iframe. Уточнить тексты запрещённых кнопок на языках сайта. Показать карту, план (направления × страницы × устройства по `references/depth-matrix.md`) и список сторонних ресурсов; спросить исключения → `scope.exclude_patterns`.
   **Контекст сайта** (`context.reuse` не `as-is`): изучить источники из `context.sources` — сам сайт по ссылкам (под `url_guard`), документацию/FAQ (только чтение; чужой домен — без браузера, через загрузку страницы, или с разрешения добавить в `allowed_domains`), GitHub-репозиторий (`gh`, только чтение: README, docs, заголовки issues), файл на диске, описание из чата; учесть `context.notes`. Записать **до прогона** `<OUTPUT_ROOT>/qa-runs/.site-context/<host>/context.md` по `templates/site-context.md` (назначение, роли и состояния аккаунта, основные сценарии, терминология, особенности и ограничения, источники и дата) и `sources.json`; путь к нему передать исполнителям. Не сохранять секреты, cookies, e-mail, имена людей и данные личных кабинетов (`references/run-files.md` → «Память о сайте»).
5. **Прогон** — `references/parallelism.md` + `references/plugins-map.md` + `references/checklists/<направление>.md`:
   - скриптовые проверки в фоне (`node/headers.js`, `links.js`, `a11y.js`, `lighthouse.js` → `<RUN_DIR>/raw/`);
   - детекторы раскладки в фоне (`references/layout-detectors.md`): `node/occlusion.js` (перекрытия, по `--sizes 1440x900,1024x768,768x1024,720x450` и `--device pixel7,iphone15`) и `node/reachability.js` (достижимость; обязательно низкие окна ≤ 450 px и landscape) → `<RUN_DIR>/raw/`; страницы с приложением во iframe — `--frames all` во всех детекторах (a11y.js — по умолчанию);
   - MCP-поток (оркестратор): functional, logic-state и сценарии с состоянием;
   - CLI-потоки (субагенты, `playwright-cli -s=qa-<id>`, до `parallel.max_workers`: по умолчанию 2, **максимум 4**): остальные браузерные направления, группы страниц и независимые гипотезы одновременно; общая сессия входа (`manual`, `manual-cdp`) — один браузерный поток (`parallelism.md`). **Задание — `brief.py`** (блок правил §4 дословно, срез реестра issues, формат результата, окно, лимит **20–30 минут** на поток; поток регистрируется для метрик). Исполнитель закрывает **только свою** сессию (никаких `close-all`/`kill-all`), открывает её с `--config <RUN_DIR>/playwright-cli.json`, держит одну вкладку на профиль устройства (`scripts/tabs.py`; node-скрипты с `--rules <RUN_DIR>/rules.json --owner <qa-id>` регистрируют свои вкладки сами), каждую проверку guard пишет в `--trace <RUN_DIR>/logs/guard-<qa-id>.jsonl`, находки возвращает **блоком ```` ```qa-findings ```` в последнем сообщении** (массив, файлы не пишет), у каждой находки — `repro` и `dup_check`; оркестратор: `ingest_findings.py <RUN_DIR> --from <сообщение> --thread <qa-id>` → **место правды** `findings/<qa-id>.json` + `coverage/<qa-id>.md` (пересказ в сообщении не нужен; повторное уведомление ничего не меняет);
   - окно браузера — одно на прогон: пользователь попросил «с открытым окном» / «в фоне» → `browser_mode.py set <RUN_DIR> --headed|--headless` (node-скрипты берут режим сами, исполнителям — переоткрыть свою сессию);
   - устройства со входом пользователя — `node/device_context.js run --devices … --state …`, строго последовательно (общая сессия — `parallelism.md` «Когда параллельные потоки запрещены»);
   - действия с побочными эффектами — только `node/invariants.js exec` (перед первым — `invariants.js preflight`: словарь защитных элементов сверяется с прошлым прогоном, расхождение → остановка и вопрос); каждое действие — строка в `<RUN_DIR>/side_effects.md` (что загружено/включено, что осталось в браузере);
   - собственный чек-лист выполняется всегда; усилители из `env.json → enhancers` только дополняют; запрещённые (`banned`) не используются;
   - `legal-ui` (если выбрано): `node/legal_guest.js` (гость в чистом профиле, `--locales`), страницы входа и покупки — `--read-only`; RTL — `node/rtl.js`; цели нажатия — `node/targets.js`.
   Каждая находка → `<RUN_DIR>/findings.json` по `templates/finding.schema.json` (id, direction, check_id, type, severity по `references/severity.md`, title, url, element, steps, expected, actual, environment, screenshots, console, network, hypothesis, suggestion, sources, **repro** — как перезапустить измерение одной командой; по возможности frequency, account_state, platform; для перепроверки — claim_ref {repo, number, quote}; оценка внешней системы — triage; поля чужой формы — target_forms {repo: {area, severity_label}}; правовые нормы — legal). Секреты и персональные данные — маскировать сразу. Скриншоты находок — **аннотированные**: пунктирная обводка, тонкая стрелка, короткая подпись, цвет авто (жёлтый/зелёный/фиолетовый) — `references/screenshots.md`: в Playwright MCP `scripts/snap_mcp.js` + `scripts/node/annotate.js`; без MCP (CDP/Playwright) — `scripts/node/shot.js` (= `snap_cdp.js`): снимок, координаты, разметка, автопроверка и контактный лист в одном вызове. Статический обход (`links.js`) не видит контент SPA: его SEO/структурные сигналы (нет h1, пустые meta) подтверждать в браузере перед записью находки.
6. **Дедупликация**: свести находки субагентов (`ingest_findings.py`), плагинов и скриптов; `fingerprint.py compute` → `fingerprint.py dedupe` → `validate_findings.py findings.json` (схема, дубли id, плейсхолдеры, немаскированные e-mail/токены; результат исполнителя — `--array`). Противоречия между источниками — перепроверить вручную, неясно — спросить.
   **Охват и вторая волна**: `thread_coverage.py summary <RUN_DIR>` — время, страницы, проверенные действия и элементы по потокам (автоматически); «не проверено» не оставлять списком в сводке — `thread_coverage.py again <RUN_DIR>` раскладывает его по потокам следующей волны (запреты — на решение пользователя) → `brief.py … --items waves/<n>/<поток>.json` (`parallelism.md`).
   **Независимая перепроверка — обязательна до публикации** (`parallelism.md` → «Независимая перепроверка»): `recheck.py run <RUN_DIR>` воспроизводит каждую находку дважды по `repro`; что не перезапускается скриптом — другой исполнитель и `recheck.py set … --by "…"`; правовые нормы — `recheck.py legal`. `recheck.py gate <RUN_DIR>` — без подтверждения находка не публикуется (не подтвердилась — в отчёт «не подтвердилось»).
7. **Сверка** — `repo-sync.md` §2–3: `fingerprint.py match findings.json registry.json --out matches.json`, кандидатов прочитать и проверить вручную; присвоить статусы NEW / DUPLICATE-OPEN / FIXED-OK / FIXED-INSUFFICIENT / REGRESSION / ALREADY-COPIED / UNSURE-MATCH. Отдельно перепроверить все issues с заявленным исправлением по плану `claims-plan.md`; результат каждого — `claims.py set` (FIXED-OK / FIXED-INSUFFICIENT / REGRESSION / NOT-CHECKED с причиной).
8. **Вопросы по ходу** (не копить до конца, если блокируют): баг или задумано; нужен вход; запрет блокирует важную проверку; совпадение под вопросом; confirm-действие от `url_guard`/`guard.js`; расхождение словаря интерфейса или нарушенный инвариант.
9. **Публикация** — `repo-sync.md` §4: сводная таблица `build_report.py publish-table <RUN_DIR>` (с политикой `closed_claims` и колонкой «Перепроверка») → подтверждение (если включено) → по ролям: их шаблон (`read_templates.py render … --format body`) / своя подробная копия (`render_draft.py detailed --config <RUN_DIR>/run-config.yaml --repo owner/repo`) / комментарии (`render_draft.py comment …`). Раскрытие, ссылки, маркер и шкала серьёзности берутся из `repos[]` (`disclosure`, `cross_links`, `marker`, `severity_map`). Скриншоты — по `screenshots` репозитория: `commit` (свой репозиторий, `push`) или `web-upload` (чужой/приватный: `node/publish_web.mjs` для issue, `node/comment_web.mjs` для комментария, в браузере пользователя с выполненным входом по CDP; по умолчанию dry-run, реально — `--confirm-publish` после «да»; `references/web-upload.md`). `guard.js` к браузеру GitHub не применяется (правила прогона описывают проверяемый сайт): защита там — замок хоста `--base-url`, нажимается только кнопка ровно «Comment», Close/Reopen — никогда, согласие `--confirm-publish`. Лимиты API. В dry-run — только черновики в `<RUN_DIR>/drafts/`. **Одна первопричина — один issue**: `render_draft.py suggest-groups` → проверить `groups.yaml` → `render_draft.py group … --map groups.yaml --run-dir <RUN_DIR>` (проявления таблицей, маркер на каждую находку); мелкие находки одной темы — `group` / `groups`. В каждом issue — блок «Как проверить» (из `verify` / `repro`); заготовка регрессионного теста — `e2e_stub.py`. Скриншоты в приватный репозиторий с правом push — без браузера: `publish_shots.py plan` (заранее проверяет gh, вход, доступ, push) → `push … --confirm-push` (своя ветка, `--screenshot-base` для черновиков); без push — веб-форма; ничего из этого — `publish_shots.py local` (скриншоты при отчёте в `results/`, строка для issue); вход в GitHub делает только пользователь, скил его не автоматизирует; в уже созданный issue — `node/publish_web.mjs --attach-to <N>` (по одному номеру). **Прямая публикация** (`publish_mode: direct`, если пользователь просит «сразу в репозиторий»): по одной находке «`recheck.py run` → `direct_publish.py check` (дубли) → issue → скриншоты → `direct_publish.py record`» без накопления черновиков (`repo-sync.md` §4a).
10. **Отчёт** — `build_report.py report <RUN_DIR>` → `<RUN_DIR>/report.md` (находки, таблица перепроверки «№, статус, что проверено, чем», side_effects.md, сработавшие запреты из blocked.jsonl) и `build_report.py summary <RUN_DIR>` → `<RUN_DIR>/summary.md` (сводка: итог, статистика, направления); при необходимости дописать итог вручную (`templates/run-report.md`), вывод — по `goal.success` (список проблем / прошли ли сценарии / есть ли блокеры релиза); при репозитории-копии — итоговый issue. Обязательно: статистика по статусам и severity, сводка по направлениям, что не проверено и почему, сработавшие запреты, содержимое side_effects.md (что осталось в браузере и на сайте), задействованные плагины.
11. **Итоги, память, уборка** (`references/run-files.md`):
   - **Куда записать итоги** — по `report_destinations` (по умолчанию только `<RUN_DIR>`): `folder` — `scripts/export_results.py <RUN_DIR> --to <path>`: в `<path>/<YYYY-MM-DD>-<host>/` только итоговые файлы (`summary.md`, `report.md`, `findings.json`, скриншоты находок), не папка прогона с `raw/`, `logs/`; `github` — существующая логика `repo-sync.md` §4–5 (итоговый issue со сводкой, подтверждение по сводной таблице, в dry-run — черновик в `drafts/`); `artifact` — если в сессии есть инструмент `Artifact`, опубликовать страницу из `report.md` (без `evidence.sensitive`, секретов и персональных данных), иначе пропуск; `custom` — описанное пользователем, после подтверждения. В конце `report.md` дописать раздел «Куда записаны итоги» (путь, ссылка или «пропущено: причина»), затем копировать в папки.
   - **Память о сайте** — дополнить `.site-context/<host>/context.md`: новые сценарии, термины, ответы «баг или задумано», известные проблемы, дата и строка в «Истории»; обновить `sources.json`. Без секретов и персональных данных.
   - **qa-runs/ и git** — уже настроено в шаге 2 (`gitignore_helper.py ensure`), вопроса про `.gitignore` в конце нет.
   - Удалить файл состояния входа (`node/device_context.js state-rm --out <RUN_DIR>/logs/auth-state.json`), закрыть **свои** вкладки и сессии (`tabs.py cleanup <RUN_DIR>` → `--yes`; `playwright-cli -s=qa-<id> close` по каждой своей сессии, не `close-all`), отметить в журнале завершение.

## Режимы охвата
- **Весь сайт / раздел / список URL** — как выше.
- **Только текущий экран** — Claude in Chrome во вкладке пользователя, если доступен (`setup.md`), иначе URL экрана в Playwright. Только наблюдение; действия — под теми же правилами.
- **Перепроверка исправлений** — шаги 1–3 и 7 по `claims.md` без полного обхода; итог — таблица перепроверки в report.md.
- **Локальное приложение (`file://`)** — как сайт, по `local-files.md` (копия в `<RUN_DIR>/app`, `local_roots`, `headers.js`/`lighthouse.js` — не применимо).
- **После доработок** — `fix-cycle.md`: тест, падающий до правки (`e2e_stub.py`; прогон скилом — `node/e2e_run.js … --expect fail`, после правки — `--expect pass`, три раза), проверка на всех вариантах данных и стендах, три прогона нового e2e, **обязательное независимое ревью диффа** отдельным агентом (только чтение), закрытие с «что изменено / чем проверено».
