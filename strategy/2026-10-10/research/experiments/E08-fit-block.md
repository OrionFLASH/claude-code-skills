# E08. Блок «кому подходит» на входе README
Предложение: P033 «Блок «кому подходит, что потребуется, сколько стоит прогон, лицензия» на входе README» · Ставка: быстрая победа воронки (из набора ставки 1) · Тип: опрос (тест понимания на панели), можно в одной сессии с E01

Обоснование не повторяется: `data/proposals.json` → P033; ставка 1 — `build/strategy-facts.md`, раздел «Три главные ставки».

## Гипотеза
Если на входе README поставить короткую таблицу «кому подходит / что потребуется / ориентир расхода на прогон / лицензия для компаний / чего скил не делает», то доля читателей, верно отвечающих на ≥ 3 из 4 вопросов о пригодности после 60 секунд, вырастет с ≈ 20 % [допущение] до ≥ 70 % (MDE +50 п.п.), потому что сейчас требований и стоимости наверху нет, а лицензия описана в конце README (README.md:79-89).

## Метрики
- **Основная:** доля респондентов, верно ответивших на ≥ 3 из 4 вопросов: (1) что нужно иметь и поставить (Claude Code; для site-qa-audit — Node и Playwright); (2) порядок расхода на прогон (в пределах указанного ориентира); (3) можно ли использовать в работе на компанию без разрешения автора (верно: нет); (4) чего скил не делает (хотя бы одно ограничение). Бинарная на респондента; ключ ответов записан до первой сессии.
- **Вспомогательные:** самооценка «это для меня / не для меня» и её совпадение с профилем респондента (есть ли Claude Code и задачи QA); время чтения; оставшиеся вопросы дословно.
- **Защитные (с порогом):** (а) ответ «можно на работе без разрешения» — 0 из 8; любой такой ответ → остановка и правка текста лицензии; (б) ориентир расхода воспринят как гарантия — не больше 1 из 8 (текст обязан говорить «ориентир ±50 % [оценка]», P001 риски); (в) блок не длиннее 8 строк [допущение] — иначе он вытесняет верх README и ухудшает E01.

## Дизайн
- **Почему не A/B.** README один для всех, внешних установок нет (расчёт ниже).
- **Панель:** те же 8 человек, что в E01 (экономия набора), вопросы E08 — после вопросов E01 в той же сессии; если E01 провалился и верх переписывается — отдельная панель из 8 человек.
- **Протокол:** 60 секунд на верх README с блоком, затем 4 вопроса и самооценка. Числа для блока (требования, ориентир расхода) — из реальных прогонов (дешёвая проверка P001 и протоколы E02), помечены как оценка.
- **После публикации:** до/после по отказам после установки не измерить (нет телеметрии и внешних установок) — фиксируется только качественно: внешние Issues вида «не знал, что нужен X» (база 0 [факт: внешних Issues нет, бриф прогона]).

## Размер выборки и длительность
**Почему A/B на воронке невозможен.** Метрика «отказ после установки», p1 = 0,60 [допущение: 1 − `signup_to_active` 0,40, `data/model.json`, base], MDE −0,10 → p2 = 0,50; α = 0,05 (z = 1,96), мощность 80 % (z = 0,84):

n = (1,96 + 0,84)² × (0,60 × 0,40 + 0,50 × 0,50) / 0,10² = 7,84 × 0,49 / 0,01 ≈ **385 на группу**.

Установок в день — 0 внешних [факт: `build/strategy-facts.md`, «Что уже есть»]; в базовом сценарии ≈ 0,33 в день [допущение: `data/model.json`, base, `monthly[0].signups` = 10] → 2 × 385 / 0,33 ≈ 2 300 дней. Вывод: тест понимания.

**Тест понимания (одна выборка, точный биномиальный критерий).** H0: p ≤ 0,2 [допущение], H1: p = 0,7; n = 8; порог — **≥ 5 из 8**.
- α_факт = P(X ≥ 5 | n = 8, p = 0,2) = 0,010.
- Мощность = P(X ≥ 5 | n = 8, p = 0,7) = 0,81.
- Две независимые панели (старый и новый вход): n = 7,84 × (0,2 × 0,8 + 0,7 × 0,3) / 0,5² = 7,84 × 0,37 / 0,25 ≈ 11,6 → 12 на группу, 24 человека — сверх доступной панели [допущение].

**Длительность:** вместе с E01 — 8 сессий при ≈ 1,5 в день [допущение] → **7 дней** (минимум).

## Критерий остановки
- Вывод — после 8-й сессии. Досрочный провал — когда набрано 4 неверных результата (≥ 5 из 8 недостижимо); досрочного успеха нет.
- Защитная (а) — немедленная остановка, правка текста, новая панель; сессии до правки в анализ не идут.

## Решение по итогам
- **Победа** (≥ 5 из 8, защитные в норме): блок публикуется; английская версия — в README.en (P069) и в описания заявок каталогов (E04) как «требования и ограничения».
- **Проигрыш** (≤ 3 из 8): найти самый проваленный вопрос; лицензия (3) → переписать строку лицензии и передать ответы в E03; расход (2) → дождаться чисел P001; повтор на 8 новых людях.
- **Ничья** (4 из 8): блок публикуется (вреда нет при соблюдённых защитных), слабая строка переписывается и проверяется на следующей панели.

## Риски и этика
- Не вводить в заблуждение: ориентир расхода — с меткой «оценка» и диапазоном; честный список «чего скил не делает».
- Текст лицензии — не юридическая консультация (как README.md:89).
- Приватность: ответы обезличены и хранятся локально. Платящих нет — влияние не применимо.

## Что нужно для запуска
- **События аналитики:** телеметрии нет; таблица ответов (респондент, 4 вопроса, самооценка, время).
- **Флаги:** не нужны.
- **Тексты:** блок (RU, затем EN); числа ориентира из P001 и E02 с меткой «оценка»; ключ ответов.
- **Дизайн:** макет не нужен.
- **Предусловия:** ориентиры расхода сняты хотя бы с 3 прогонов (дешёвая проверка P001).
