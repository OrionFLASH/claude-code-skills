# E02. Quickstart: первый результат без помощи автора
Предложение: P032 «Quickstart «первый результат за 5 минут» для каждого скила: промпт и ожидаемый вывод» · Ставка: 1 · Тип: модерируемый тест на панели с порогом (замена A/B)

Обоснование не повторяется: `data/proposals.json` → P032; ставка 1 — `build/strategy-facts.md`, раздел «Три главные ставки».

## Гипотеза
Если дать страницу quickstart из трёх шагов (установка, готовый промпт smoke по учебной цели, что появится в папке результатов и сколько займёт), то доля новых пользователей, получивших первый отчёт site-qa-audit без помощи автора, вырастет с ≈ 40 % [допущение: `data/model.json`, base, `signup_to_active`] до ≥ 90 % (MDE +50 п.п.), потому что сейчас путь разнесён по INSTALL.md скилов и включает ручной `npm install` (README.md:44).

## Метрики
- **Основная:** доля участников, получивших ожидаемый вывод quickstart (`report.md` и `summary.md` в папке прогона smoke) без подсказок автора и не дольше заявленного в quickstart времени × 2. Бинарная на участника.
- **Вспомогательные:** время от первого шага до вывода (медиана; цель — ≤ 5 минут на шаги после установки); число «застреваний» (> 60 секунд без продвижения) и их места; число обращений к автору; расход прогона (`/cost` или `total_cost_usd`) — входные числа для P001 и E08.
- **Защитные (с порогом):** (а) прогон идёт только по учебной цели из `skills/site-qa-audit/tests/dry-run-todomvc.md` (demo.playwright.dev/todomvc, «безопасная цель для самопроверки») — 0 переходов за её домен (`logs/blocked.jsonl`); нарушение → остановка сессии; (б) расход прогона у участника не выше ориентира quickstart × 1,5 [допущение]; превышение у 2 участников → остановить тест и пересчитать ориентир; (в) 0 публикаций (режим dry-run по умолчанию).

## Дизайн
- **Почему не A/B.** Внешних установок нет — делить нечего (расчёт ниже).
- **Панель:** 6 участников с установленным Claude Code [допущение: доступны в окружении владельца], не видевшие репозиторий; свой компьютер и своя ОС (записать ОС, версию Claude Code, версию плагина).
- **Скил:** site-qa-audit — флагман и предмет Show HN (P024). Остальные скилы — по 1 участнику, только качественно, вне основной метрики.
- **Протокол:** участник получает только ссылку на quickstart и думает вслух; автор молчит. Подсказка автора = провал по основной метрике, но сессия продолжается ради списка проблем. Секундомер и запись шагов.
- **Выявление проблем:** при 6 участниках вероятность хотя бы раз увидеть проблему, которая встречается у 31 % пользователей, равна 1 − 0,69⁶ ≈ 0,89 [оценка: модель Нильсена–Ландауэра, 31 % — их средняя частота].
- **Порядок:** после E01 (верх README уже понятен); участники E01 допустимы — E02 начинается со страницы quickstart.

## Размер выборки и длительность
**Почему A/B невозможен.** p1 = 0,40 [допущение: `data/model.json`, base, `signup_to_active`], p2 = 0,80 [допущение: целевая доля первых прогонов с отчётом, ставка 3 в `build/strategy-facts.md`], MDE +0,40; α = 0,05 (z = 1,96), мощность 80 % (z = 0,84):

n = (1,96 + 0,84)² × (0,40 × 0,60 + 0,80 × 0,20) / 0,40² = 7,84 × 0,40 / 0,16 = 19,6 → **20 на группу**.

Установок в день на входе — 0 внешних [факт: внешних пользователей нет, `build/strategy-facts.md`, «Что уже есть»]; в базовом сценарии 10 установок в месяц ≈ 0,33 в день [допущение: `data/model.json`, base, `monthly[0].signups`] → 2 × 20 / 0,33 ≈ 120 дней > 6 недель. Вывод: панель с порогом.

**Тест на панели (одна выборка, точный биномиальный критерий).** H0: p ≤ 0,4; H1: p = 0,9; n = 6; порог — **≥ 5 из 6**.
- α_факт = P(X ≥ 5 | n = 6, p = 0,4) = 0,041.
- Мощность = P(X ≥ 5 | n = 6, p = 0,9) = 0,89. Честное ограничение: при истинных 0,8 мощность лишь 0,66 — тест ловит только большой эффект.

**Длительность:** 6 сессий по 30–40 минут при ≈ 1 сессии в день [допущение] → 6 дней → **7 дней** (минимум), максимум 14.

## Критерий остановки
- Вывод — после 6-й сессии. Досрочный провал — когда набрано 2 провала (≥ 5 из 6 уже недостижимо); досрочного успеха нет.
- Если за 14 дней меньше 6 сессий — решать по заранее записанной таблице: n = 5 → порог 5 из 5 (α = 0,010).
- Защитная (а) — немедленная остановка сессии; защитная (б) у 2 участников — остановка теста до пересчёта ориентира.

## Решение по итогам
- **Победа** (≥ 5 из 6): ссылка на quickstart — в верх README; ориентиры времени и расхода — в блок E08; открываются ворота «можно попробовать» для E05.
- **Проигрыш** (≤ 3 из 6 или досрочный провал): два самых частых блокера — в работу (ожидаемо `npm install`/Playwright → поднять P060); повтор на 6 новых участниках.
- **Ничья** (4 из 6): quickstart публикуется (лучше разрозненных INSTALL.md [допущение]), самый частый блокер исправляется, но ворота E05 не открываются до повторного теста на 6 новых участниках.

## Риски и этика
- Участник тратит свой лимит токенов — заранее назвать ориентир расхода, участие добровольное, можно отказаться в любой момент.
- Цель прогона — только учебный стенд; никаких чужих боевых сайтов и публикаций.
- Приватность: запись экрана только с согласия; в протокол не попадают ключи, пути домашней папки, имена; данные локально вне репозитория.
- Платящих нет — влияние не применимо.
