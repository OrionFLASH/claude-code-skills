# E01. README-витрина: понятно ли за 60 секунд
Предложение: P029 «Переделать README в витрину: ценность в одной фразе, GIF, установка в три строки» (GIF — из P030) · Ставка: 1 · Тип: опрос (тест понимания на панели) + до/после

Обоснование не повторяется: `data/proposals.json` → P029, P030; ставка 1 — `build/strategy-facts.md`, раздел «Три главные ставки».

## Гипотеза
Если верх README заменить на фразу ценности, GIF первой минуты и установку в три строки, то доля людей, которые после 60 секунд просмотра верно называют, что делает проект и как его поставить, вырастет с ≈ 40 % [допущение] до ≥ 80 % (MDE +40 п.п.), потому что сейчас README начинается со слов «Личная коллекция скилов» (README.md:3) и не показывает результата работы.

## Метрики
- **Основная:** доля респондентов, верно ответивших на оба вопроса после 60 секунд на верхнем экране README: (1) «что делает этот репозиторий» — назван хотя бы один скил и его результат (например, QA сайта → отчёт и черновики issues); (2) «как поставить» — названа команда `/plugin marketplace add` или место, где она написана. Бинарная на респондента; оценка по ключу ответов, записанному до первой сессии.
- **Вспомогательные:** (а) намерение попробовать — доля ответов 4–5 на шкале 1–5 «насколько вероятно, что вы поставите»; (б) секунды до первого верного ответа; (в) до/после по GitHub (снимки P043): внешние уникальные посетители за 14 дней = `views.uniques − 1` (владелец — один уникальный [допущение]), внешние звёзды.
- **Защитные (с порогом):** (а) неверное прочтение лицензии — респондент считает, что можно использовать в работе на компанию без разрешения: не больше 1 из 8, при 2 и более — остановка и правка текста; (б) GIF ≤ 1,5 МБ [оценка: P030] и без чужих сайтов и ключей — иначе не публиковать; (в) ни одного обещания сверх существующего (английских отчётов нет) — проверка по чек-листу до публикации.

## Дизайн
- **Почему не A/B.** GitHub показывает один README всем — разделить посетителей по группам нечем; внешнего трафика нет (расчёт ниже). Замена — тест понимания на панели плюс до/после по публичным сигналам.
- **Панель:** 8 человек [допущение: доступны в окружении владельца] — разработчики, знакомые с Claude Code или похожими агентами, не видевшие репозиторий и не участвовавшие в разработке.
- **Протокол:** показать новый верх README (до таблицы скилов) на 60 секунд, затем убрать; 3 вопроса: что делает, как поставить, вероятность установки 1–5. Ответы записывать дословно; спорные ответы засчитываются по ключу и не в пользу гипотезы. Если сессия совмещена с E08 — сначала вопросы E01.
- **Калибровка базы (по желанию):** 3 других человека смотрят текущий верх. Если ≥ 2 из 3 отвечают верно — база выше допущения: H0 поднимается до 0,6, порог — 8 из 8 (α = 0,6⁸ = 0,017).
- **До/после:** окно «до» — 14 дней до публикации (снимок P043 в день T0), окно «после» — 14 дней после; источник — GitHub Traffic API (хранит 14 дней).
- **Где:** верх `README.md`; для README.en.md (P069) — 2 англоязычных респондента, только качественно, вне основной метрики.

## Размер выборки и длительность
**Почему A/B на реальном трафике невозможен.** Метрика «визит → установка», p1 = 0,05 [допущение: `data/model.json`, base, `visit_to_signup`], MDE +0,03 → p2 = 0,08; α = 0,05 (z = 1,96), мощность 80 % (z = 0,84):

n = (1,96 + 0,84)² × (0,05 × 0,95 + 0,08 × 0,92) / 0,03² = 7,84 × (0,0475 + 0,0736) / 0,0009 = 7,84 × 0,1211 / 0,0009 ≈ **1 055 на группу**.

Трафик на входе ≈ 0 внешних посетителей в день [факт: 36 просмотров и 1 уникальный — владелец — за 14 дней, gh api traffic 2026-10-10, `research/product-understanding.md:13`]. Даже в базовом сценарии 200 посетителей в месяц ≈ 6,7 в день [допущение: `data/model.json`, base] → 2 × 1 055 / 6,7 ≈ 316 дней > 6 недель. С MDE +0,10 (p2 = 0,15): n = 7,84 × (0,0475 + 0,1275) / 0,01 ≈ 138 на группу → 2 × 138 / 6,7 ≈ 41 день — на границе 6 недель и всё равно без механизма разделения. Вывод: меняем метрику на понимание и дизайн на панель.

**Тест понимания (одна выборка, точный биномиальный критерий).** H0: p ≤ 0,4 [допущение: понимание текущего верха], H1: p = 0,8; n = 8; порог успеха — **≥ 6 из 8**.
- α_факт = P(X ≥ 6 | n = 8, p = 0,4) = 0,050.
- Мощность = P(X ≥ 6 | n = 8, p = 0,8) = 0,80.
- Для сравнения, две независимые панели (старый и новый верх): n = 7,84 × (0,4 × 0,6 + 0,8 × 0,2) / 0,4² = 7,84 × 0,40 / 0,16 = 19,6 → 20 на группу, 40 человек — сверх возможностей solo [допущение], поэтому одна панель с базой-допущением и калибровкой.

**Длительность:** 8 сессий по ≈ 10 минут при ≈ 1,5 сессии в день [допущение] → 8 / 1,5 ≈ 5,3 дня → **7 дней** (минимум); до/после — 14 + 14 дней.

## Критерий остановки
- Вывод — только после 8-й сессии. Досрочный вывод «провал» допустим, когда набрано 3 неверных ответа (≥ 6 из 8 уже недостижимо): это определено заранее и не завышает α. Досрочного «успеха» нет — оставшиеся сессии нужны для качественных ответов.
- Если за 7 дней набрано меньше 8 сессий — продлить до 14 дней; если и тогда меньше, решать на фактическом n по заранее записанной таблице: n = 6 → порог 5 из 6 (α = 0,041); n = 7 → 6 из 7 (α = 0,019).
- Защитная (а) сработала (2 неверных прочтения лицензии) — остановить, править текст, новая панель.
- До/после — решение только в конце 14-дневного окна, без промежуточных выводов.

## Решение по итогам
- **Победа** (≥ 6 из 8, защитные в норме): витрина остаётся; верх README замораживается до окон E04 и E05, чтобы не смешивать эффекты; разблокируются P069, P018, P019.
- **Проигрыш** (≤ 4 из 8 или досрочный провал): по дословным ответам найти непонятый элемент (фраза ценности, GIF или установка), переписать только его и повторить на 8 новых людях.
- **Ничья** (5 из 8): новый верх оставить (не хуже текущего [допущение]), фразу ценности заменить формулировкой из ответов респондентов и проверить на 5 новых людях с порогом 5 из 5 (α = 0,4⁵ = 0,010).
- До/после: если к 2026-11-30 внешних уникальных < 20 за 14 дней и внешних звёзд 0 — применяется критерий отказа ставки 1 (`build/strategy-facts.md`, «Критерии отказа»).

## Риски и этика
- Тёмные паттерны не используются: никаких выдуманных отзывов, счётчиков и «звёзд от друзей»; GIF — из реального прогона на безопасной учебной цели.
- Респондентов не просят ставить звёзды: это исказит до/после и противоречит правилам площадок.
- Приватность: устное согласие, запись экрана только с согласия, ответы обезличены (Р1…Р8) и хранятся локально вне репозитория.
- Платящих нет (монетизации нет — `build/strategy-facts.md`) — влияние на платящих не применимо.
