# Понимание продукта: claude-code-skills

Дата: 2026-10-10 · источники: репозиторий (`repo_scan.py`, `repo_facts.py`), `gh` (только чтение), README/CHANGELOG/CONVENTIONS. Метки: `[факт: источник]`, `[оценка]`, `[допущение]`.

## Что это
Публичный репозиторий-маркетплейс плагинов Claude Code (`.claude-plugin/marketplace.json`): **четыре скила**, каждый — отдельный плагин со своими `SKILL.md`, скриптами, справочниками, тестами, хуками и `INSTALL.md`. Репозиторий создан 2026-10-07 [факт: gh api], 181 коммит за 4 дня (07.10 — 12, 08.10 — 35, 09.10 — 113, 10.10 — 21) [факт: git log], 39 тегов версий [факт: git tag]. Автор и единственный контрибьютор — OrionFLASH (95 из 95 issues — его собственные) [факт: gh issue list].
**Тип:** `devtool` (плагины/скилы для AI-ассистента для разработчиков и QA/продакт-ролей) с акцентами `oss` (код публичный, но лицензия не OSI) и `bot/plugin` (дистрибуция через каталог/маркетплейс) [допущение, подтверждено структурой].

## JTBD и аудитория
- **QA/разработчик-одиночка или небольшая команда**, которому нужно «проверить сайт/Android-приложение без исходников и без ручной рутины, получить воспроизводимые находки и черновики issues» (site-qa-audit, android-qa-audit).
- **Пользователь Claude Code**, который хочет «чтобы агент сам выбирал модель и effort под задачу и не жёг токены» (typesafe-triage; хук `UserPromptSubmit`).
- **Основатель/продакт/соло-разработчик**, которому нужна «стратегия роста по своему репозиторию с доказательствами и отслеживанием выполнения» (product-strategy).
- Аудитория подтверждённо измерена только в одном человеке: за 14 дней 36 просмотров репозитория, 1 уникальный посетитель; 0 звёзд, 0 форков, 1 наблюдатель [факт: gh api traffic, 2026-10-10]. Внешний спрос — **неизвестен**.

## Распространение (блок для решения о публикации)
- Видимость: **public**; лицензия **PolyForm Noncommercial 1.0.0** (не OSI; коммерческое использование — только с разрешения автора, запрос через Issues) [факт: LICENSE, README «Лицензия»]. Бейджи «open source» нет — README честно пишет «не open-source в смысле OSI».
- Установка: `/plugin marketplace add OrionFLASH/claude-code-skills` → `/plugin install <скил>@claude-code-skills` либо симлинки `tools/install.sh` [факт: README]. Подробные `INSTALL.md` со вставляемыми промптами — у 4 скилов.
- Темы GitHub: нет; описание: «Мои скилы для Claude Code: маркетплейс плагинов»; релизов GitHub Releases нет (только теги) [факт: gh api].
- Платформы: macOS и Windows заявлены (`tools/*.ps1`, junction); Linux у android-qa-audit в INSTALL. Тесты под Windows — частично.
- Отслеживаемых секретов: 0 [факт: repo-facts].
- CI: **нет** (`.github/` отсутствует) — проверки (`tools/validate.sh`, `tests/`) запускаются вручную [факт: ls].
- Демо/сайт/скриншоты в README: нет; записанных GIF «как это выглядит» в README нет.

## Сильные стороны
1. **Глубина**: скилы покрывают целые процессы (QA сайта и Android, триаж моделей, стратегия), с запретами безопасности (guard, url_guard), dry-run по умолчанию, журналами и перепроверкой.
2. **Универсальность без привязки**: нет конкретных сайтов/учёток в скилах, всё на входе.
3. **Инженерная дисциплина**: CONVENTIONS, валидатор, CHANGELOG на каждый скил, теги версий, SHA256SUMS, тесты (~600), PolyForm-лицензия.
4. **Связка скилов**: typesafe-triage → выбирает модель для субагентов остальных; site/android-qa → issues; product-strategy ← issues/PR (отслеживание). Это уже зачаток «семейства».
5. Обратная связь реальными прогонами (krut.top, handoff) → быстрые итерации.

## Пробелы и риски
1. **Нулевое внешнее присутствие**: 0 звёзд, нет тем, нет скриншотов/GIF в README, нет страницы-витрины, нет примеров вывода (отчёт, страница стратегии) для просмотра без установки.
2. **Нет CI и сквозных тестов на чистой машине**; Windows-поддержка не подтверждена автоматически.
3. **Огромные SKILL.md/INSTALL** (длина → токены на каждый вызов); высокая стоимость запуска (десятки субагентов).
4. **Лицензия NC** ограничивает распространение в корпоративной среде (главный платёжеспособный сегмент QA).
5. **Зависимость от экосистемы**: формат плагинов Claude Code, внешний сервис TypeSafe (ключ), `gh`, Playwright, adb; изменения платформы ломают скилы.
6. **Единственный разработчик** — шина фактора 1; риск выгорания при темпе 100+ коммитов/день.
7. Дублирование знаний между скилами (QA-ядро site/android — часть вынесена в `shared/`, часть дублируется).

## Тип и акценты (фаза 3)
Тип: **devtool** (плагины/скилы для AI-ассистента) + **oss-подобное распространение** (публичный репозиторий, лицензия NC) + **plugin/bot-каталог** (дистрибуция через маркетплейс Claude Code). Профиль `zero-budget-solo`.
**Главные рычаги (5–7):**
1. Видимость и доверие: README-витрина, GIF/скриншоты, примеры результатов, темы GitHub, релизы.
2. Время до первого результата: установка одной командой, «первый успех за 5 минут», демо-прогон без своих данных.
3. Дистрибуция в каталогах (Anthropic plugin directory, awesome-списки, сообщества Claude Code, skills.sh-подобные витрины) и кросс-платформенность (формат Agent Skills / AGENTS.md).
4. Качество и CI: автопроверки, матрица ОС, воспроизводимые тесты, подписи релизов.
5. Фокус портфеля: что держать флагманом (2–3 скила) и что вынести в «лабораторию».
6. Стоимость запуска (токены): лёгкие режимы, кэш, бюджет-гард — главный барьер принятия.
7. Решение о лицензии/модели устойчивости (NC vs open core vs спонсорство) — ключевая развилка владельца.
**Неприменимые/заменённые категории:** `monetization` — сведена к устойчивости (спонсорство, услуги, гранты); `localization` — RU/EN документация, не интерфейс; `acquisition` — только бесплатные каналы.
**Особые риски:** правила площадок (самопродвижение на Reddit/HN/Habr), формат плагинов Claude Code меняется, лицензия NC несовместима со многими каталогами/корпоративной политикой, зависимость от платного сервиса TypeSafe (ключ).
**Гипотезы главных ставок (до оценки):**
1. «Витрина + первый успех»: превратить репозиторий из личной папки в продукт, который можно понять за 60 секунд (GIF, примеры отчётов, `curl|install`).
2. «Флагман»: выбрать один скил (вероятно site-qa-audit или typesafe-triage) и довести до уровня «лучший в категории», остальные — как экосистема вокруг.
3. «Кросс-агентная переносимость»: сделать скилы доступными вне Claude Code (Agent Skills стандарт), расширив аудиторию.
4. «Оставить личным инструментом» — законный исход, если спрос внешний не подтвердится за 60 дней.
