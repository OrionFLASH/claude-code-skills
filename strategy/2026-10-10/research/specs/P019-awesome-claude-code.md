# P019. Подать по одному плагину в awesome-claude-code после 21.10.2026
Приоритет: P0 · Горизонт: now · Предпосылки: P029, P069, P030, P042 · Связанные: P018, P020, P054, P028, P050 · Макет: не предусмотрен (дизайн выключен выбором, у продукта нет UI)

Обоснование — P019 в реестре, раздел 10 стратегии; правила площадки — `research/communities.md` (awesome-claude-code, ban_risk 2). Здесь — как подготовить и подать. Подачу выполняет владелец через веб-форму: ИИ ничего не публикует (`build/strategy-facts.md`, «Запреты»).

## Проблема
- Репозитория нет в списке awesome-claude-code (55,4 тыс. звёзд) [факт: https://github.com/hesreallyhim/awesome-claude-code, 2026-10-10].
- Правила приёма: только веб-форма issue, подаёт человек (не gh CLI и не PR); ресурс старше 14 дней с активной разработкой или от 100 звёзд; один ресурс на заявку; описание — что делает, без рекламы [факт: https://raw.githubusercontent.com/hesreallyhim/awesome-claude-code/main/CONTRIBUTING.md, data/communities.json].
- Репозиторий создан 2026-10-07 [факт: gh api], звёзд 0 → ранняя дата подачи 2026-10-21 [ДОПУЩЕНИЕ: выведена из даты создания, правило проверить в день подачи — data/fact-check.json].
- Куратор оценивает ресурс по README, а список англоязычный (`research/gap-audit.md`: P019 ← P029, P019 ← G7-01 = P069) [факт].

## Цель и метрики успеха
- **Основная:** ≥ 1 из 4 заявок принята к 2027-01-31 [ДОПУЩЕНИЕ: порог ставки 2]; отказ — нормальный исход (cheap_test реестра).
- **Вспомогательные:** переходы из списка — referrer `github.com` с путём списка в снимках P043; +20..100 переходов в месяц после принятия [ДОПУЩЕНИЕ: из реестра].
- **Защитные:** 0 нарушений формата (форма, один ресурс, без эмодзи и рекламы, без просьб о голосах); 0 заявок через gh CLI или PR.

## Решение
1. **В день подачи (не раньше 2026-10-21)** перечитать CONTRIBUTING и шаблон формы — условия могли измениться.
2. **Четыре однострочных описания на английском** — сухо, «что делает», без эмодзи и оценочных слов. Черновики (финальная формулировка — из P054/P028):
   - typesafe-triage — «A UserPromptSubmit hook that suggests a Claude model tier and reasoning effort for each task, using local signals or the TypeSafe API.» [черновик]
   - site-qa-audit — «Browser-based QA audit of a website or local web app (functional, accessibility, performance, SEO) that writes findings and GitHub issue drafts; dry-run by default.» [черновик]
   - product-strategy — «Builds a product growth strategy from the current repository: proposal registry with RICE/ICE/WSJF scores, roadmap, HTML/XLSX/PPTX outputs, progress tracking.» [черновик]
   - android-qa-audit — «QA of an Android APK on emulators via adb: device and OS matrix, accessibility and performance checks, findings with screenshots and issue drafts.» [черновик]
   В каждом описании или в поле заметок формы — что отчёты и вопросы скилов на русском (до P053) [решение: честность для англоязычного списка].
3. **Порядок и паузы:** typesafe-triage → site-qa-audit → product-strategy → android-qa-audit; следующая заявка — после ответа по предыдущей или не раньше чем через 7 дней [ДОПУЩЕНИЕ: пауза, чтобы не выглядеть массовой рассылкой].
4. **Ссылка в заявке** — на карточку скила в `README.en.md` (P069) или папку скила; не на корень с русским README.
5. **Учёт:** каждая заявка и ответ — строки в журнале событий P043.

**Не входит:** официальный каталог (P018); автоиндексы и агрегаторы (P020); смежные awesome-списки Playwright, a11y, Android (P050); любые просьбы поддержать заявку голосами, упоминания в соцсетях ради ускорения.

## Пользовательские сценарии
1. Как владелец, я хочу подать заявку, соответствующую правилам, чтобы её не закрыли по формату.
   - Given дата ≥ 2026-10-21 (или ≥ 100 звёзд) и CONTRIBUTING перечитан в этот день; When заполняю веб-форму issue вручную; Then заявка содержит один ресурс, одну строку описания без эмодзи и рекламы, ссылку на ресурс.
2. Как куратор списка, я хочу по ссылке быстро понять ресурс.
   - Given ссылка из заявки; When открываю её; Then вижу англоязычное описание, медиа (P030), установку и честные ограничения (язык отчётов, лицензия).
3. Как читатель списка, я хочу по строке понять, нужен ли мне ресурс.
   - Given строка в списке; When читаю её; Then понимаю, что делает плагин, без маркетинговых слов.
4. Как владелец, получивший отказ или молчание, я хочу не нарушить правила повторной активностью.
   - Given заявка без ответа; When прошло 30 дней [ДОПУЩЕНИЕ]; Then не дублирую заявку и не прошу голоса; записываю `catalog_decision` = no_response и подаю следующий плагин.

## Требования
**Функциональные**
- F1. Подача только через веб-форму issue, вручную, по одному ресурсу.
- F2. Перед подачей выполнены P029, P069, P030 и решение P042 (`scores.json → blocked_by`); ссылка — на англоязычную витрину.
- F3. Описание: одна строка, ≤ 200 знаков [ДОПУЩЕНИЕ: уточнить по шаблону формы], без эмодзи, превосходных степеней и призывов.
- F4. Паузы между заявками (п. 3 «Решения»).
- F5. Журнал подач и ответов (P043).

**Нефункциональные**
- Соответствие правилам площадки — главный критерий; при сомнении — не подавать.
- Точность: описания не обещают английских отчётов и «одной команды» для site-qa-audit до P060.
- i18n: описания на английском; упоминание русского интерфейса скилов.

## Риски и меры
- Нарушение формата → отказ: перечитать правила в день подачи, одна строка, форма вручную.
- Дата допуска — допущение → проверка в день подачи; если правило другое, подать при выполнении условия.
- Список англоязычный, а скилы русскоязычные → честная пометка; ссылка на README.en.md.
- Отбор курируемый, ответ не гарантирован (P019.risks) → ожидание не блокирует остальные каналы.
- Переименование после принятия ломает ссылку → решающая часть P028 до первой заявки (К3).
