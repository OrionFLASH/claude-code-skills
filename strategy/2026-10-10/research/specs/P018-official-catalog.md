# P018. Подать плагины в официальный каталог anthropics/claude-plugins-official
Приоритет: P0 · Горизонт: now · Предпосылки: P029, P069, P030, P042, P054 · Связанные: P028 и P060 (мягкий порядок), P059, P019, P020, P033, P032 · Макет: не предусмотрен (дизайн выключен выбором, у продукта нет UI)

Обоснование — P018 в реестре, раздел 10 стратегии; правила площадки — `research/communities.md` (claude-plugins-official, ban_risk 1). Здесь — как подготовить и подать. Подачу выполняет владелец: ИИ ничего не публикует и не отправляет (`build/strategy-facts.md`, «Запреты»).

## Проблема
- Плагины доступны только через собственный маркетплейс (`.claude-plugin/marketplace.json:3`); в официальный каталог не подавались [факт: P018.current_feature].
- Официальный каталог принимает внешние плагины через форму приёма по ссылке из README каталога; критерии — «quality and security standards», без подробностей; одобренные попадают в `/external_plugins` [факт: https://github.com/anthropics/claude-plugins-official, data/communities.json, 2026-10-10].
- То, что увидит ревьюер, сейчас работает против заявки: README начинается с «Личная коллекция скилов» (`README.md:3`), описания плагинов только на русском (`.claude-plugin/marketplace.json:12`, `:35`, `:60`, `:78`), английского README нет, медиа нет [факт].
- site-qa-audit после установки и каждого обновления требует ручного `npm install` в папке новой версии (`README.md:44`, `skills/site-qa-audit/SKILL.md:181`) — первый пользователь из каталога получит нерабочий скил (конфликт К8, `research/gap-audit.md`) [факт].
- Лицензия PolyForm Noncommercial не OSI; совместимость с приёмом каталога не проверена [допущение: P018.risks].

## Цель и метрики успеха
- **Основная:** ≥ 1 плагин принят в каталог к 2027-01-31 (порог критерия отказа ставки 2, `build/strategy-facts.md`) [ДОПУЩЕНИЕ: из стратегии]; реестр ожидает 1–2 из 4 [ДОПУЩЕНИЕ].
- **Вспомогательные:** referrer `github.com` с путём каталога и рост `clones.uniques` в 14 дней после одобрения (снимки P043); число итераций по замечаниям ≤ 2 на плагин [оценка].
- **Защитные:** 0 нарушений правил площадки (одна заявка — один плагин, только через форму); после одобрения — 0 внешних Issues «не устанавливается» без ответа дольше 7 дней [ДОПУЩЕНИЕ: SLA из P039]; лицензия в заявке описана точно.

## Решение
**Порядок подачи** (рекомендация `research/gap-audit.md`, К8):
1. **typesafe-triage** — только Python, работает без ключа на локальных сигналах (`skills/typesafe-triage/README.md:29`, `:37`). Особое внимание в заявке: хук `UserPromptSubmit` отправляет текст запросов от 40 символов во внешний сервис TypeSafe, если задан ключ (`skills/typesafe-triage/README.md:87`) — раскрыть прямо и указать выключатели (`skills/typesafe-triage/README.md:38`, `skills/typesafe-triage/references/privacy.md`).
2. **product-strategy** — Python 3.10+, демо без токенов (`skills/product-strategy/INSTALL.md:158-165`); после выхода из статуса «в разработке» или с честной пометкой.
3. **site-qa-audit** — только после P060 (без ручного `npm install`) или с явным шагом установки в описании; зависит от официального плагина Playwright MCP (`skills/site-qa-audit/INSTALL.md:171`).
4. **android-qa-audit** — последним (статус «в разработке», тяжёлое окружение).

**Пакет заявки на плагин** (готовится заранее, хранится в черновике владельца):
- Название и одна фраза на английском (из P054/P028), ссылка на `README.en.md` (P069) и карточку скила, медиа (P030).
- **Safety**: dry-run по умолчанию; запреты и проверки (`skills/site-qa-audit/references/safety-rules.md`, `skills/site-qa-audit/references/browser-guard.md`, `skills/android-qa-audit/references/safety-rules.md`, `skills/product-strategy/references/safety.md`); публикация в GitHub — только по явному согласию (`README.md:60`); секреты — только через переменные окружения (`CONVENTIONS.md:22`); проверка секретов в validate (`tools/lib/skillsrepo.py:221`).
- **Data flow**: что уходит наружу (TypeSafe — по ключу; GitHub — по согласию), что остаётся локально (`README.md:48`).
- **Quality**: число тестов, статус CI (бейдж P059 — усиливает, но не обязателен), CHANGELOG и SemVer (`CONVENTIONS.md:29-32`), контрольные суммы `SHA256SUMS` у typesafe-triage.
- **License**: PolyForm Noncommercial 1.0.0, SPDX в манифестах (`.claude-plugin/marketplace.json:30`), коммерческое использование — по запросу автора; формулировка — по решению P042.
- **Requirements**: из блока P033.

**Процесс:** прочитать актуальные критерии по форме из README каталога → подать первый плагин → записать ответ и замечания в журнал (`catalog_submission`, `catalog_decision` в `events-manual.csv` P043) → исправить → следующий плагин не раньше ответа по первому.

**Не входит:** подача в awesome-claude-code (P019) и автоиндексы (P020); переименование (P028 — решить до первой подачи, иначе листинг закрепит имя, К3); смена лицензии (P042 — только решение, текст лицензии меняет владелец); любые просьбы о голосах и продвижение заявки.

## Пользовательские сценарии
1. Как владелец, я хочу подать typesafe-triage с полным пакетом, чтобы снизить шанс отказа по «безопасности».
   - Given готовы P029, P069, P030, P054 и решение P042; When заполняю форму каталога; Then в заявке есть ссылка на README.en.md, раздел Safety, раскрытие отправки данных в TypeSafe и точное описание лицензии; заявка — один плагин.
2. Как ревьюер каталога, я хочу за 5 минут понять, что делает плагин и какие у него риски.
   - Given ссылка из заявки; When открываю README.en.md и Safety; Then вижу, что плагин делает, какие данные и куда уходят, как выключить, как проверить локально.
3. Как пользователь из `/plugin → Discover`, я хочу поставить плагин и сразу получить результат.
   - Given плагин одобрен; When ставлю его из каталога и следую быстрому старту (P032); Then первый результат без шагов, не описанных в README (для site-qa-audit — после P060 или с явным шагом `npm install`).
4. Как владелец, получивший отказ, я хочу понять причину и решить, подавать ли снова.
   - Given ответ каталога; When записываю его в журнал (`catalog_decision`: плагин, итог, причина); Then если причина — лицензия, вопрос уходит в P042 (критерий отказа ставки 2), иначе — исправление и повторная подача.

## Требования
**Функциональные**
- F1. Перед первой подачей выполнены: P029, P069, P030 (медиа), P054 (EN `description`), решение P042; решающая часть P028.
- F2. Один плагин на заявку; порядок — typesafe-triage → product-strategy → site-qa-audit (после P060) → android-qa-audit.
- F3. Пакет заявки (см. «Решение») — по шаблону, одинаковому для всех плагинов.
- F4. Каждая подача и ответ записываются в журнал событий P043.
- F5. Ничего не отправляется автоматически: форму заполняет владелец.

**Нефункциональные**
- Точность: только проверяемые утверждения (тесты, CI, лицензия); без обещаний английских отчётов до P053.
- Приватность: в заявке и в README.en.md — описание отправки данных в TypeSafe; без личных путей и e-mail.
- i18n: заявка и описание — на английском; документация скилов остаётся на русском (это указать честно).

## Риски и меры
- Отказ из-за лицензии NC → решение P042 до подачи; при отказе по лицензии — вынести вопрос владельцу (критерий отказа ставки 2).
- Отказ из-за хука, отправляющего запросы во внешний сервис → полное раскрытие, выключатели, работа без ключа по умолчанию; при отказе — подавать другие плагины.
- Первый пользователь упирается в `npm install` → site-qa-audit только после P060 (К8).
- Переименование после листинга ломает установку → P028 до первой подачи (К3).
- Долгое ожидание ответа → следующий плагин не раньше ответа по первому; параллельно — P019, P020.

## План выпуска
- Флаг не нужен (внешний процесс). Последовательные заявки, по одному плагину.
- Этап 0: готовность предпосылок (P029, P069, P030, P042, P054, решающая часть P028).
- Этап 1: typesafe-triage → ответ → исправления.
- Этап 2: product-strategy.
- Этап 3: site-qa-audit — после P060.
- Этап 4: android-qa-audit — после выхода из статуса «в разработке».
- A/B: нет.
- Откат: отзыв заявки по процедуре каталога [ДОПУЩЕНИЕ: процедура не описана в открытых правилах].
