# P030. GIF и ролики первой минуты из реальных прогонов существующими утилитами
Приоритет: P0 · Горизонт: now · Предпосылки: нет (`blocked_by` пуст) · Связанные: P029, P069, P032, P070, P033, P025, P018, P019 · Макет: не предусмотрен (дизайн выключен выбором, у продукта нет UI)

Обоснование — P030 в реестре, раздел 10 стратегии. Здесь — только как сделать.

## Проблема
- Посетитель репозитория решает «ставить или нет» по README, где нет ни одного изображения: `README.md:1-117` — только текст и таблица с описаниями по 300–600 знаков (`README.md:12-15`) [факт: README.md, 2026-10-10].
- Результат каждого скила — файлы и заметки в терминале (отчёт `report.md`, черновики issues, заметка «ДЕЙСТВИЕ: …», HTML-страница). По тексту понять, как это выглядит, трудно [оценка].
- Инструменты для роликов уже есть, но ни одного готового медиафайла нет: `qa_clips.to_gif` (`shared/scripts/qa_clips.py:12`, реализация `:389`), CLI `qa_clips.py gif` (`shared/scripts/qa_clips.py:608-614`), запись находки `clip.js --format mp4|gif|both` (`skills/site-qa-audit/scripts/node/clip.js:10`) [факт: код, 2026-10-10].
- P030 — предпосылка для 12 предложений (P029, P069, P018, P019, P024, P025 и др.) [факт: data/scores.json → unlocks].

## Цель и метрики успеха
- **Основная (выход):** в `docs/media/` лежат 4 медиафайла — по одному на скил; каждый понятен без звука и без чтения README. Критерий: 3 из 3 человек, не знакомых с проектом, по медиафайлу называют, что делает скил, не дольше чем за 10 с [оценка; метод — cheap_test из реестра].
- **Основная (исход):** доля клонов от просмотров README за 14 дней (`clones.uniques / views.uniques` по снимкам P043) после выхода README с медиа выше, чем до него; целевой прирост +10..30 % относительно базы [ДОПУЩЕНИЕ: из реестра; база почти нулевая — 1 уникальный посетитель за 14 дней, факт: gh api traffic, 2026-10-10], вывод делать не раньше чем через 4 недели снимков.
- **Вспомогательные:** число просмотров `README.md` и `README.en.md` в popular paths (P043); вопросы «как это выглядит» в Issues — 0 [оценка].
- **Защитные:** суммарный размер `docs/media/` ≤ 6 МБ и прирост истории git от всех перезаписей ≤ 10 МБ [ДОПУЩЕНИЕ]; 0 кадров с ключами, e-mail, абсолютными путями с именем пользователя, чужими сайтами (кроме публичных демо-стендов, `CONVENTIONS.md:21`).

## Решение
Четыре медиафайла из реальных прогонов, по готовым утилитам репозитория, без новых зависимостей:

| Скил | Что в кадре | Чем снять | Формат |
|---|---|---|---|
| site-qa-audit | находка на публичном стенде demo.playwright.dev/todomvc (например, «нет подтверждения при Clear completed», ожидаемая находка из `skills/site-qa-audit/tests/dry-run-todomvc.md:22`) → черновик issue | dry-run по `skills/site-qa-audit/tests/dry-run-todomvc.md:7`; ролик находки — `clip.js … --format both` (`skills/site-qa-audit/scripts/node/clip.js:10`), сжатие и GIF — `clips.py finalize` (`skills/site-qa-audit/scripts/node/clip.js:25`); черновик — снимок `drafts/copies/*.md` | GIF ≤ 5 с + PNG черновика |
| android-qa-audit | сценарий на эмуляторе: запуск приложения → нажатие → находка с рамкой | `adb_helpers.py clip` (screenrecord, `skills/android-qa-audit/README.md:158`), запасной путь — ролик из скриншотов (`clip --fallback auto`) или аннотированный PNG (`annotate_android.py`) | GIF ≤ 5 с |
| typesafe-triage | заметка «ДЕЙСТВИЕ: …» с хвостом «[TypeSafe-триаж: модель/effort; …]» в ответ на обычный запрос (`skills/typesafe-triage/INSTALL.md:350`) | снимок окна терминала системным средством ОС | PNG (статичный текст читается лучше GIF) |
| product-strategy | прокрутка интерактивной страницы: резюме → реестр с фильтром → Гант | страница демо-прогона `make_demo.py` (вымышленные данные с пометкой «демо», `skills/product-strategy/scripts/make_demo.py:2-4`) → запись экрана → `qa_clips.py compress` и `qa_clips.py gif` | GIF ≤ 5 с |

Один прогон site-qa-audit на todomvc обслуживает сразу P030 (GIF), P032 (проверка quickstart), P033 (замер времени и токенов) и P070 (пример отчёта) — снимать в одном прогоне.

**Не входит:** звук и озвучка; видеохостинги; монтаж в сторонних редакторах; mp4 в README; английские подписи в кадре (подписи — в Markdown под картинкой, поэтому одни и те же файлы служат RU и EN, P069); вставка в README (это P029).

## Пользовательские сценарии
1. Как посетитель README, я хочу за 10 секунд увидеть результат site-qa-audit, чтобы решить, ставить ли его.
   - Given README с медиа из P029; When открываю страницу репозитория на github.com; Then GIF проигрывается без клика, весит ≤ 1,5 МБ, длится ≤ 5 с, под ним строка «что показано» и откуда (стенд, глубина, версия скила).
2. Как пользователь экранного чтеца, я хочу понимать содержание медиа, чтобы не терять информацию.
   - Given медиа в README; When фокус на изображении; Then alt-текст описывает действие и результат одной фразой («Скил находит … и пишет черновик issue»), а не «gif».
3. Как владелец, я хочу перезаписать медиа после изменения интерфейса скила, повторив те же шаги, чтобы не восстанавливать процесс по памяти.
   - Given строка источника под медиа (команда, версия скила, дата); When повторяю шаги на новой версии; Then получаю файл того же формата и бюджета с тем же именем.
4. Как владелец, я хочу гарантировать, что в кадре нет секретов, чтобы не опубликовать лишнее.
   - Given готовый ролик; When строю ленту кадров `qa_clips.py sheet` (`shared/scripts/qa_clips.py:14`) и просматриваю её; Then в кадрах нет ключей (`TYPESAFE_API_KEY`), e-mail, путей `/Users/<имя>`, чужих сайтов, логинов.
5. Как посетитель с чувствительностью к движению, я не хочу бесконечно мигающих картинок.
   - Given GIF в README; When он проигрывается; Then цикл ≤ 5 с без вспышек чаще 3 раз в секунду (порог паузы для движущегося контента — WCAG 2.2.2, тот же критерий проверяет сам скил: `skills/site-qa-audit/references/checklists/accessibility.md:34`).

## Требования
**Функциональные**
- F1. Файлы: `docs/media/site-qa-audit-finding.gif`, `docs/media/site-qa-audit-draft.png`, `docs/media/android-qa-audit.gif`, `docs/media/typesafe-triage-note.png`, `docs/media/product-strategy-page.gif`; имена стабильные (перезапись не ломает ссылки README и README.en.md).
- F2. GIF: ≤ 1,5 МБ (умолчание `gif_max_mb`, `shared/scripts/qa_clips.py:46`), ≤ 5 с, ширина 480–720 px; при превышении — лестница ширины и кадров в `to_gif` (`shared/scripts/qa_clips.py:389`) или обрезка сценария, а не повышение бюджета.
- F3. PNG: ≤ 300 КБ, ширина ≤ 1200 px [ДОПУЩЕНИЕ: читаемо в README на десктопе].
- F4. Для каждого файла — строка источника (в Markdown под медиа): скил и версия, цель (публичный стенд или демо-данные), команда, дата.
- F5. Только публичные демо-стенды и вымышленные данные: demo.playwright.dev (разрешён `CONVENTIONS.md:21`), демо-прогон product-strategy; для Android — собственное тестовое приложение или системное приложение образа эмулятора (см. «Открытые вопросы»).

**Нефункциональные**
- Приватность: обязательная проверка ленты кадров перед коммитом (сценарий 4); в терминале перед снимком — чистое окно без истории команд с путями и ключами.
- Доступность: alt-текст на каждый файл; цикл ≤ 5 с; без вспышек.
- i18n: в кадре — интерфейс как есть (скилы пишут по-русски), без вшитых подписей на одном языке, если без них понятно; плашку подписи `clip.js` (`--caption`) не использовать или делать нейтральной (символы ✕/✓) — подписи в Markdown на RU и EN.
- Производительность: суммарный вес медиа на странице README ≤ 6 МБ.

## Риски и меры
- Прогон site-qa-audit тратит токены и время → один dry-run smoke на todomvc на четыре предложения (P030, P032, P033, P070) [оценка].
- Эмулятор не пишет видео (нет кодека на arm64 API ≤ 30, `skills/android-qa-audit/README.md:158`) → образ API 34, `--gpu host` или ролик из скриншотов; крайний вариант — аннотированный PNG.
- Нет ffmpeg — GIF не строится (`shared/scripts/qa_clips.py:393-395`) → поставить ffmpeg на машину владельца (`skills/site-qa-audit/INSTALL.md:174`).
- Медиа устаревает после смены вывода скила → перезапись при MAJOR-версии скила (`CONVENTIONS.md:32`), по строке источника (F4).
- Раздувание истории git → не больше одной перезаписи на файл за минорную версию; при необходимости уменьшать ширину, а не множить версии.
- Утечка данных в кадр → обязательная лента кадров (сценарий 4).
