# P070. Статический хостинг демо на GitHub Pages: страница стратегии и индекс примеров
Приоритет: P0 · Горизонт: now · Предпосылки: нет (`blocked_by` пуст) · Связанные: P031, P043, P030, P032, P029, P069, P024, P050, P023 · Макет: не предусмотрен (дизайн выключен выбором, у продукта нет UI)

## Проблема
- Посмотреть результат скила без установки Claude Code негде: примеров вывода в репозитории нет, Pages выключен (`has_pages=false`) [факт: gh api, 2026-10-10; P070.current_feature].
- Главный результат product-strategy — HTML-страница (`skills/product-strategy/README.md:8`), а github.com показывает HTML-файл исходным кодом [факт: P070.evidence]; самодостаточная страница бывает очень тяжёлой (пример на 29 МБ упомянут в `docs/skill-handoff.md:5`), для этого в сборке есть `--lite` (`skills/product-strategy/scripts/build_html.py:12-17`).
- Отчёт site-qa-audit — Markdown (`report.md`, `summary.md`: `skills/site-qa-audit/SKILL.md:92`, шаблон `skills/site-qa-audit/templates/run-report.md:1`) — GitHub отрисует его без хостинга, но в шапку отчёта попадает абсолютный путь папки прогона (`skills/site-qa-audit/scripts/build_report.py:233`, поле «Папка прогона»), то есть имя пользователя и структура диска [факт: код].
- Если публиковать Pages из папки `/docs` main, на сайт попадут и рабочие файлы `docs/plans/*.md`, `docs/skill-handoff.md` (там личные данные автора, `research/gap-audit.md` → «Чистая история») [факт: ls docs, 2026-10-10].
- Страница стратегии этого прогона ещё не собрана (фаза 9 не выполнена, `build/STATUS.md`), а в ней будут ответы владельца (`research/questions-owner.md` встраивается в страницу — `skills/product-strategy/scripts/build_html.py:1588`) [факт].

## Цель и метрики успеха
- **Основная:** посетитель без входа в GitHub и без Claude Code открывает (а) страницу стратегии на Pages и (б) пример QA-отчёта в Markdown — проверка в приватном окне браузера, 2 из 2 ссылок открываются [оценка; cheap_test реестра].
- **Исход:** просмотры `docs/examples/README.md` ≥ 10 % от просмотров корня (popular paths, снимки P043) [ДОПУЩЕНИЕ: из реестра]; доля посетителей, увидевших результат без установки, +10..20 п. п. [ДОПУЩЕНИЕ: прямого измерения нет, прокси — тот же показатель].
- **Защитные:** 0 абсолютных путей, e-mail, ответов владельца, не предназначенных для публики, и чужих скриншотов на опубликованных страницах (проверка поиском перед публикацией); вес истории main не растёт от страницы стратегии (она живёт в отдельной ветке); сайт Pages ≤ 50 МБ [ДОПУЩЕНИЕ: с запасом к лимиту 1 ГБ из P070.evidence].

## Решение
1. **Источник Pages — сиротская ветка `gh-pages`** (не `/docs` в main): в неё попадает только демо, рабочие файлы `docs/` не публикуются, тяжёлые страницы не раздувают историю main.
   Состав ветки: `index.html` (короткая страница-индекс со ссылками на примеры и на репозиторий), `strategy/index.html` + `strategy/assets/` (облегчённая сборка `--lite`), `.nojekyll` (чтобы Pages не обрабатывал файлы Jekyll и отдал `assets/` как есть [ДОПУЩЕНИЕ: стандартное поведение Pages]).
2. **Страница стратегии.** Вариант по умолчанию — страница этого прогона (стратегия самого claude-code-skills) после фазы 9: `build_all.py <OUT> --lite` (`skills/product-strategy/scripts/build_all.py:125`) или `build_html.py <OUT> --lite` (`skills/product-strategy/scripts/build_html.py:4475`), затем ручная проверка приватности (поиск `/Users/`, `@`, раздел вопросов владельцу, `run-config`). Запасной вариант — страница демо-прогона `make_demo.py` (вымышленные данные с пометкой «демо», `skills/product-strategy/scripts/make_demo.py:2-4`): публикуется, если проверка приватности не пройдена или фаза 9 ещё не готова. Скриншотов конкурентов в этом прогоне нет (`competitors/shots/` пуст), поэтому шаг реестра «проверить скриншоты конкурентов» сводится к проверке, что их нет.
3. **Пример QA-отчёта — Markdown в main**: `docs/examples/site-qa-todomvc/` из dry-run на публичном стенде (тот же прогон, что для P030/P032/P033): экспорт `export_results.py <RUN_DIR> --to docs/examples --name site-qa-todomvc` (`skills/site-qa-audit/scripts/export_results.py:6-8` — только итоговые файлы: `summary.md`, `report.md`, `findings.json`, скриншоты и ролики находок), затем замена абсолютного пути папки прогона на `<RUN_DIR>` в `report.md` и `summary.md`.
4. **Индекс `docs/examples/README.md`** в main: что за примеры, когда и какой версией скила сделаны, пометка «пример», ссылки на Pages (стратегия) и на Markdown-отчёт. Этот файл виден в popular paths (P043) — точка измерения без сторонней аналитики.
5. Ссылки на индекс — из README (P029, карточки скилов) и README.en.md (P069).

**Не входит:** HTML-отчёт site-qa-audit (P005); флаг `--public` в `build_html.py` для автоматического вырезания ответов владельца (кандидат в отдельное предложение, если ручная проверка окажется дорогой); свой домен; сторонняя аналитика и cookie; публикация через GitHub Actions (можно позже, после P059); пример android-qa-audit (нет публичного APK — открытый вопрос).

## Пользовательские сценарии
1. Как посетитель каталога без Claude Code, я хочу открыть пример стратегии, чтобы понять, что получу.
   - Given ссылка «Пример стратегии» в README; When открываю её в приватном окне; Then загружается страница `strategy/` сайта Pages проекта (адрес вида `<владелец>.github.io/<репозиторий>/strategy/`) [ДОПУЩЕНИЕ: адрес по умолчанию для сайта проекта], страница работает офлайн-логикой без ошибок в консоли, картинки из `assets/` грузятся.
2. Как QA-инженер, я хочу прочитать настоящий отчёт site-qa-audit, чтобы оценить качество находок.
   - Given `docs/examples/README.md`; When перехожу к `site-qa-todomvc/report.md`; Then GitHub показывает отчёт со скриншотами находок; в тексте нет абсолютных путей и личных данных; сверху пометка «пример: dry-run, demo.playwright.dev, версия скила X.Y.Z».
3. Как владелец, я хочу обновить пример после новой версии скила, не трогая историю main тяжёлыми файлами.
   - Given новая сборка страницы; When коммичу её в `gh-pages` и пушу; Then Pages обновляется, история main не меняется.
4. Как владелец, я хочу быть уверен, что ничего личного не ушло на сайт.
   - Given собранная страница и экспорт отчёта; When запускаю поиск по шаблонам (`/Users/`, `C:\Users\`, `@` вне доменов-примеров, «вопросы владельцу», `run-config`); Then 0 совпадений, иначе публикация останавливается и выбирается запасной вариант (демо).
5. Как владелец, я хочу видеть, сколько людей открывают примеры.
   - Given индекс в main; When смотрю снимок P043; Then вижу path `…/blob/main/docs/examples/README.md` в popular paths с count и uniques.

## Требования
**Функциональные**
- F1. Pages включён на ветке `gh-pages`, корень; ветка сиротская (без истории main).
- F2. Страница стратегии собрана с `--lite`, ≤ 8 МБ HTML (цель `--lite` из `skills/product-strategy/scripts/build_all.py:125`) и ≤ 50 МБ вместе с `assets/`.
- F3. Пример QA-отчёта — только итоговые файлы `export_results.py`; без `raw/`, `logs/`, `drafts/` (`skills/site-qa-audit/scripts/export_results.py:2-3`).
- F4. Замена абсолютных путей на `<RUN_DIR>` в экспортированных `.md`; проверка поиском (сценарий 4) — обязательный шаг перед коммитом.
- F5. Индекс `docs/examples/README.md` с пометкой «пример», датой, версией скила и ссылками.
- F6. Источник примера — только публичный стенд (`CONVENTIONS.md:21`) или вымышленные данные.

**Нефункциональные**
- Приватность: F4; ответы владельца на странице стратегии — только то, что владелец согласен показать (решение в «Открытых вопросах»).
- Скорость: страница стратегии открывается за ≤ 3 с на широкополосном соединении [ДОПУЩЕНИЕ]; без внешних CDN, кроме уже используемых сборкой.
- Доступность: индекс — обычный Markdown с понятными ссылками; страница стратегии — как собирает `build_html.py` (без изменений в этом объёме).
- i18n: индекс — RU с одной строкой EN (для англоязычных каналов); страница — на языке прогона (RU).

## Затрагиваемые части системы
- Новое в main: `docs/examples/README.md`, `docs/examples/site-qa-todomvc/` (`report.md`, `summary.md`, `findings.json`, `screenshots/`, при наличии `clips/`).
- Новое: ветка `gh-pages` (`index.html`, `strategy/index.html`, `strategy/assets/`, `.nojekyll`); настройка Settings → Pages (делает владелец).
- Используются без изменений: `skills/product-strategy/scripts/build_html.py:12-17`, `:4475` (`--lite`), `skills/product-strategy/scripts/build_all.py:125`, `skills/product-strategy/scripts/make_demo.py:2-7`, `skills/site-qa-audit/scripts/export_results.py:6-8`, `skills/site-qa-audit/tests/dry-run-todomvc.md:7`.

- `.gitignore:6` (`qa-runs/`) — экспорт идёт в `docs/examples/`, вне игнорируемой папки; `.gitignore` не меняется.
- `README.md`, `README.en.md` — ссылки на индекс (P029, P069).

## Риски и меры
- Личные данные на странице стратегии → проверка поиском, запасной вариант «демо» (сценарий 4).
- Абсолютный путь в отчёте → F4.
- Пример устаревает с новыми версиями скилов → пометка версии и даты; обновление при MINOR site-qa-audit или после пересборки стратегии.
- Публикация из `/docs` раскрыла бы рабочие файлы → только `gh-pages`.
- Тяжёлая страница → `--lite`; при превышении бюджета — демо-страница с меньшим числом предложений (`make_demo.py --proposals`).
