# P043. Еженедельный снимок публичных сигналов GitHub в CSV: просмотры, клоны, источники, звёзды
Приоритет: P0 · Горизонт: now · Предпосылки: нет (`blocked_by` пуст) · Связанные: P044, P047, P024, P071, P038, P059, все спецификации топа (их метрики считаются по этим снимкам) · Макет: не предусмотрен (дизайн выключен выбором, у продукта нет UI)

Обоснование — P043 в реестре, раздел 10 стратегии; окно хранения трафика GitHub (14 дней) — в `evidence` P043 реестра. Здесь — только как сделать.

## Проблема
- Все данные о спросе — один ручной срез: 36 просмотров и 1 уникальный посетитель за 14 дней, 0 звёзд, 0 форков, 1 наблюдатель [факт: gh api traffic, 2026-10-10; `research/product-understanding.md`].
- GitHub отдаёт просмотры, клоны, источники и популярные страницы только за последние 14 дней; без регулярных снимков история теряется [факт: P043.evidence].
- В `tools/` только установка, создание каркаса и проверка (`README.md:91-115`), скрипта статистики нет [факт]; North Star стратегии (уникальные клонеры за 14 дней без владельца) и метрики всех спецификаций топа опираются на эти снимки [факт: build/strategy-facts.md].
- GitHub Releases в репозитории нет (только теги), поэтому поле «загрузки релизов» из реестра сейчас всегда пустое [факт: `research/gap-audit.md`, «Устаревшие допущения»].

## Цель и метрики успеха
- **Основная:** 0 потерянных дней истории трафика с даты первого снимка (каждый день из окна 14 дней попал в CSV хотя бы одним снимком) [факт-метрика: проверяется по CSV].
- **Вспомогательные:** покрытие воронки «визит → клон → звезда/вопрос» данными — 3 из 4 этапов [оценка: из реестра; «установка из каталога» GitHub не видит]; время на снимок ≤ 1 мин владельца в неделю [оценка].
- **Защитные:** токен `gh` нигде не сохраняется и не печатается; CSV не попадает в репозиторий; скрипт только читает (ни одного запроса, меняющего состояние).

## Решение
Скрипт на стандартной библиотеке Python, по образцу `tools/validate.sh` → `tools/lib/skillsrepo.py` (тонкие обёртки sh/ps1, логика в Python, `CONVENTIONS.md:35-36`):

- `tools/stats.sh` и `tools/stats.ps1` — обёртки (поиск Python через `shared/scripts/find-python.sh:3-5` и `shared/scripts/find-python.ps1:3-9`).
- `tools/lib/stats_snapshot.py` — логика. Данные берёт вызовом `gh api` (подпроцесс; аутентификация — у `gh`, скрипт токен не видит):
  - `repos/{owner}/{repo}/traffic/views` и `…/traffic/clones` — по дням (`timestamp`, `count`, `uniques`) и итоги за 14 дней;
  - `…/traffic/popular/referrers` и `…/traffic/popular/paths` — агрегаты за 14 дней;
  - `repos/{owner}/{repo}` — звёзды, форки, наблюдатели (`subscribers_count`), открытые issues;
  - `…/releases` — сумма `download_count` ассетов; пока релизов нет, поле пустое (не 0).
- Хранение — каталог вне репозитория: `$CCS_STATS_DIR`, по умолчанию `~/.claude-code-skills-stats/` [ДОПУЩЕНИЕ: путь уточнить у владельца]. Файлы (UTF-8, заголовок, разделитель `,`):
  - `daily.csv` — `date, views, views_uniques, clones, clones_uniques, snapshot_at`; **upsert по дате**: перекрывающиеся окна сливаются, за неполный текущий день берётся более поздний снимок;
  - `referrers.csv` — `snapshot_date, referrer, count, uniques`;
  - `paths.csv` — `snapshot_date, path, title, count, uniques`;
  - `repo.csv` — `snapshot_date, stars, forks, watchers, open_issues, release_downloads, views_14d, views_uniques_14d, clones_14d, clones_uniques_14d`;
  - `events-manual.csv` — `date, event, properties` — ручной журнал событий из других спецификаций (`readme_released`, `catalog_submission`, `quickstart_test`, `media_published` …); скрипт только создаёт файл с заголовком и умеет добавить строку (`--note`).
- Контроль пропусков: если последний снимок старше 10 дней — предупреждение «окно сужается»; старше 14 — сообщение, сколько дней потеряно (по `daily.csv`).
- «Без владельца»: GitHub не исключает владельца из `uniques`; скрипт пишет сырые числа, а в сводке печатает и `uniques − 1` с пометкой [ДОПУЩЕНИЕ: владелец заходит в репозиторий хотя бы раз за окно] — так считает North Star.
- Короткая сводка в терминал: неделя к неделе по просмотрам, клонам, звёздам; топ-5 источников и страниц.
- Запуск раз в неделю: напоминание или задание планировщика ОС (cron/launchd на macOS, планировщик заданий Windows) [ДОПУЩЕНИЕ: предпочтение владельца]; `/loop` работает только при открытой сессии, а облачная routine не видит локальный `gh` и CSV — поэтому основной путь локальный (рецепт — P038).

**Не входит:** дашборд и графики (данные потом читают P044 и сама стратегия); поиск упоминаний и форков (P047); телеметрия скилов (P045, только по согласию); загрузка CSV куда-либо; отдельное предложение о GitHub Releases.

## Пользовательские сценарии
1. Как владелец, я хочу раз в неделю одной командой сохранить сигналы GitHub, чтобы не терять историю.
   - Given `gh auth status` — вход выполнен, права push на репозиторий; When запускаю `tools/stats.sh`; Then в `daily.csv` появились или обновились строки за 14 дней, в `repo.csv`, `referrers.csv`, `paths.csv` — строки с датой снимка; в терминале — сводка и путь к каталогу.
2. Как владелец, пропустивший неделю, я хочу знать, потеряна ли история.
   - Given последний снимок 12 дней назад; When запускаю скрипт; Then вижу предупреждение «окно сужается», данные дописаны без дублей; Given 20 дней — вижу «потеряно 6 дней: …».
3. Как владелец, я хочу записать событие (подал заявку в каталог), чтобы потом сопоставить его с трафиком.
   - Given каталог статистики; When запускаю `tools/stats.sh --note catalog_submission "catalog=awesome-claude-code plugin=site-qa-audit"`; Then в `events-manual.csv` добавлена строка с датой.
4. Как владелец без входа в gh или без прав push, я хочу понятную ошибку, а не трассировку.
   - Given `gh` не авторизован (или 403 на `traffic`); When запускаю скрипт; Then код возврата 2 и подсказка `gh auth login` / «traffic доступен только с правами push»; файлы не меняются.
5. Как автор стратегии (P044), я хочу читать данные без парсинга JSON.
   - Given CSV за 8 недель; When открываю `daily.csv` в Excel или `csv`-модулем; Then одна строка на дату, без дублей, числа — целые.

## Требования
**Функциональные**
- F1. Подкоманды/флаги: без аргументов — снимок и сводка; `--dir PATH` (иначе `$CCS_STATS_DIR`, иначе умолчание); `--repo OWNER/REPO` (по умолчанию из `git remote` текущего клона); `--note EVENT "PROPS"`; `--dry-run` (печатает, что записал бы); `--json` (сводка JSON).
- F2. Upsert `daily.csv` по дате — идемпотентно: повторный запуск в тот же день не создаёт дублей.
- F3. Только GET-запросы через `gh api`; никаких `-X POST/PATCH/DELETE`.
- F4. Предупреждения о пропуске (> 10 и > 14 дней) и подсчёт потерянных дней.
- F5. Коды возврата: 0 — готово; 1 — готово с предупреждением (пропуск, частичный ответ); 2 — ошибка входа или доступа.
- F6. Файлы и каталог создаются при первом запуске; запись атомарная (временный файл → переименование).

**Нефункциональные**
- Приватность: каталог вне репозитория; при `--dir` внутри git-репозитория — отказ с подсказкой (по аналогии с защитой `qa-runs/` в site-qa-audit, `skills/site-qa-audit/README.md:64`), если не передан `--allow-in-repo`.
- Безопасность: токен не читается и не логируется; вывод `gh` с ошибкой печатается без заголовков авторизации.
- Совместимость: Python 3.8+, только стандартная библиотека (как `tools/lib/skillsrepo.py:8`); macOS, Linux, Windows (обёртка ps1).
- Скорость: ≤ 10 с на снимок при нормальной сети [оценка: 6 запросов].
- i18n: сообщения на русском (`CONVENTIONS.md:50-51`), имена колонок — английские идентификаторы.

## Риски и меры
- Пропуск недель → предупреждения F4, планировщик ОС; при пропуске > 14 дней — честная запись потерянных дат.
- Права: traffic требует push → у владельца есть [ДОПУЩЕНИЕ: `research/gap-audit.md`]; иначе код 2 с подсказкой.
- Изменение формата ответа GitHub → тест на фикстурах ловит падение разбора; неизвестные поля игнорируются.
- `uniques − 1` искажает при малых числах → в CSV только сырые значения; поправка — в сводке и в тексте стратегии с меткой.
- Сумма дневных `uniques` ≠ уникальные за 14 дней → в сводке использовать итог за окно из ответа API, а не сумму дней.
