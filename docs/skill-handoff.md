## 2. Четыре волны дополнений заказчика (после сдачи)

### Волна 1 — «Где стратегия и почему папка не там»
- Папка создана по ТЗ в `~/dev/MyProject/krut-growth-strategy/`, а заказчик ожидал её **внутри** репозитория аудита. Решение: перенос папки внутрь репо, удаление внутреннего `.git`, относительная ссылка `node_modules → ../node_modules`, правка путей в README/REPORT, ветка `docs/krut-growth-strategy` → merge → push. Сохранено в память как правило: рабочие папки новых задач создавать внутри репозитория.
- Урок для скилла: **в начале уточнить/зафиксировать место папки и показать, где лежит главный результат** (текст стратегии, HTML, PPTX, PDF, XLSX, REPORT).

### Волна 2 — «Перерисуй все экраны под новый дизайн сайта»
Заказчик прислал три Issue с референсным дизайном (прозрачная верхняя полоса, вариант T + плавающие кнопки, вариант G; аватар с меню справа вверху; значки «Золото и камень» вместо точек) и попросил: все экранные формы в стратегии перерисовать в этом стиле («стекло»), текст стратегии не менять, старые точки-маркеры не использовать, модальные окна и левую панель тоже стеклянные; «если стекло мешает читать — выбрать непрозрачный вариант»; использовать несколько агентов и скилл TypeSafe.

Что сделано (порядок):
1. Прочитаны Issue через `gh issue view` (только чтение); найдены исходники эскизов (HTML-макеты в репозитории аудита, рендеры в `screenshots/`, тайлы карты и набор SVG-иконок в scratchpad прошлой сессии).
2. Собран **общий набор стилей** `mockups/glass.css` + `mockups/kit.js` + `mockups/assets/tiles/` (42 тайла карты): полоса T, стеклянная левая панель, плавающие кнопки и счётчик, меню аватара, модалки/панели/карточки, мобильная шапка и док, 35 SVG-иконок «золото на камне», маршрут пунктиром с нумерованными камнями. Демо-экран `mockups/_base.html` отрендерен и проверен глазами до раздачи агентам.
3. Написан бриф `build/screens-brief.md` (источники, подключение набора, правила стиля, чек-лист сдачи).
4. Четыре субагента (opus) перерисовали 18 макетов параллельно (по 4–6 файлов), пятый написал проверки: `scripts/audit_screens.mjs` (DOM-аудит: полоса у верхнего края с размытием, аватар справа, стеклянная панель, нет старой шапки, плавающие кнопки, только новые метки, нет непрозрачных окон, бейдж концепта, контраст текста на стекле над светлым и тёмным фоном) и `scripts/typesafe_screens.py` (оценка Jev по фактам аудита: P(соответствует), P(старое осталось), риск читаемости, рекомендация фона).
5. По отчётам агентов исправлены баги набора (регистр `data-*` атрибутов, подвал DS, `nowrap` кнопок, бейдж поверх счётчика, конфликт имён классов `.pro`), контраст поднят в наборе (muted-токены .48 → .74, плотнее фон плавающих элементов) — 18/18 экранов прошли.

Решение, которое стоит закрепить: **скриншоты текущего состояния (факт аудита) не заменять концептами**; тайлы карты из игры — только для внутреннего обсуждения (IP-риск), отметить в отчёте.

## 3. Порядок работы по фазам (как было на самом деле)

Ниже — фактическая последовательность с инструментами. Время указано ориентировочно по сессии.

### Фаза 0. Подготовка (30 мин)
- Создать папку и подпапки `research/ data/ mockups/ deliverables/ build/ charts/ scripts/`, скопировать ТЗ в `build/PROMPT.md`, завести `TASKS.md` (чек-лист по фазам) и `build/STATUS.md`.
- Ветка `feature/…` или `docs/…` от `main` **до первой правки**.
- Проверить инструменты: Node 22 + Playwright (в соседнем репо — символическая ссылка `node_modules`), Python 3.14 с pandas/matplotlib/openpyxl/markdown/certifi/defusedxml/lxml, `gh` (авторизован, только чтение), pptxgenjs (локально в `build/pptx-node/`).
- Проверить наличие требуемых скиллов (`typesafe-triangke` не найден → честно зафиксировать, применить запасную методику; TypeSafe Jev API как отдельная дополнительная оценка).
- Написать спецификацию и план (`docs/superpowers/specs/…-design.md`, `docs/superpowers/plans/…md`) через скиллы brainstorming/writing-plans.

### Фаза 1. Аудит сайтов (1 ч, скрипт + 1 агент)
- `scripts/audit-sites.mjs` (Playwright): оба сайта × десктоп 1440×900 / мобайл 390×844 / EN × 9 страниц + шаги гостевой воронки; собирает meta/OG/hreflang/JSON-LD/тайминги/сторонние домены/cookie, **design-токены из computed CSS** (цвета, радиусы, шрифт) и скриншоты в `mockups/current/`.
- Результат: `data/audit/{pages,funnels,summary}.json`, `research/audit-facts.md`, `research/audit-ux-cro.md`, `research/site-text/*.md` (plain text страниц для цитирования).
- Токены из аудита → `mockups/tokens.css` — основа всех макетов и палитры графиков.

### Фаза 2. Спрос из Issues (30 мин)
- `gh issue list/view` (read-only) → `research/issues-raw.json` → `scripts/issues_to_csv.py` → `research/issues-demand.csv` (тип, сегмент, сигнал, ожидание, упущенная выгода) + `issues-summary.md`.
- Чекпоинт в STATUS. Важное наблюдение: 161 из 162 Issues были от собственного QA-аудита заказчика → слабый внешний сигнал, класс доказательств C.

### Фаза 3. Рынок (2–3 ч, 5 агентов параллельно, medium)
Пять субагентов R1–R5 с одинаковой структурой выдачи (`research/*.md` + `data/*.csv` + `data/sources-rN.csv` с URL, датой, названием, для чего использован):
- R1 конкуренты (24 ER + 24 DS: матрица функций, цены, жалобы, что перенять/не повторять),
- R2 сообщества (43 площадки с правилами самопромо и риском бана),
- R3 запросы (123 ключа RU/EN, автоподсказки; объёмы только там, где доступны) + онлайн Steam,
- R4 календарь событий (29),
- R5 право/IP/приватность/платежи (14 провайдеров).
Графики исследования: `scripts/charts_research.py` (steam-online, keywords-volume/clusters, events-calendar, competitors-heatmaps).

### Фаза 4. Реестр (2 ч, 6 агентов-генераторов)
- `data/proposal-schema.json` — схема поля (id, title, category, game, description, rationale, evidence[{kind,url,title,note,checked}], evidence_class, current_feature, effect_kpi, steps[{what,where,how,doc_url}], dependencies, effort_days[min,max], cost_money{min,max,currency,note}, risks{}, time_to_first_result, cheap_test, scores{value,cost,risk,confidence}, kano, season_fit, tags, source_id).
- Общий бриф `build/registry-brief.md`; шесть генераторов G1–G6 по категориям → `data/proposals-draft-G*.json` (126 кандидатов).
- `scripts/merge_proposals.py`: дедупликация по Жаккару + ручная карта семантических дублей `MANUAL_DROP`, запись `merged_from`, перенумерация → `data/proposals.json` (112).
- `scripts/check_registry.py`: обязательные поля, минимумы по категориям, ≥60 % A/B, формат URL, длина цитат (<15 слов; исключение для примеров UI-текста по регулярке).

### Фаза 5. Оценка (1 ч)
- `scripts/score.py`: взвешенные индексы ценности/усилия/риска; уверенность = 0,6·E(класс) + 0,25·проверяемость + 0,15·(6−разброс)/5; RICE = reach×impact×conf/effort; ICE; WSJF; composite = 0,30·n(RICE)+0,20·n(ICE)+0,25·n(WSJF)+0,25·n(risk-adj); квадранты по медианам; P0 = топ-15 %, **но только из квадрантов «Быстрая победа»/«Крупная ставка»** (иначе P0 забивают дешёвые заполнители); метки; чувствительность ±50 % весов (торнадо, устойчивость топ-20) → `data/scores.json|csv`, `sensitivity.json`, `methodology-weights.json`.
- `scripts/validate_scores.py` — независимый пересчёт (нормализация неокруглённых величин, сортировка по `round(_, 9)` и id, допуск на ничьи 1e-6).
- `scripts/typesafe_eval.py` → `data/typesafe-jev.json` (9 узких вопросов на предложение: noul/score/choice), `scripts/jev_report.py` → корреляции с экспертными шкалами. Ключ только из переменной окружения, в файлы не попадает.
- Графики оценки `scripts/charts_scores.py` (матрица усилие–влияние, пузырьковая, тепловая карта топ-30, радары топ-10, Парето, торнадо, распределение), `scripts/model.py` (юнит-экономика в трёх сценариях: воронка AARRR, CAC/LTV/окупаемость, веер прогноза, микс каналов, дерево KPI) → `data/model.json`.
- `research/methodology.md` с якорями шкал.

### Фаза 6. Стратегия (2–3 ч, 7 агентов high)
- Общий бриф `build/strategy-brief.md` (факты, топ по оценкам, три главные ставки, правила меток `[факт]/[оценка]/[допущение]`, цитаты).
- Агенты S1–S4 пишут `research/strategy-part1..4.md` (по 3–4 раздела каждый), S5 — спеки топ-10 (`research/specs/`), S6 — 8 планов A/B с расчётом выборки (`research/experiments/`), S7 — `data/gantt.csv`, `data/kanban.json|csv`, `data/events-schema.csv`, `data/deck-outline.json`.
- Склейка в `research/strategy.md` (15 разделов, ~22 000 слов), `research/questions-owner.md` (≤10), `research/glossary.md`.
- Chart Gantt `scripts/chart_gantt.py`.

### Фаза 7. Макеты и схемы (2 ч, 2 агента + позже переделка)
- 18 HTML-макетов на токенах сайта с бейджем «Концепт, не существующая функция», `scripts/shoot-mockups.mjs` → PNG + `data/mockups-index.json` (viewport из `data-viewport`, проверка ошибок/внешних запросов/переполнения).
- 4 блок-схемы как inline-SVG в HTML (`charts/flows/*.html`) + PNG.
- (Волна 2 заменила стиль макетов на «стекло» — см. раздел 2.)

### Фаза 8. Сборка и QA (2 ч)

## 4. Архитектура веб-версии (`scripts/build_html.py`) — что стоит воспроизводить

- **Одна страница, офлайн:** CSS/JS inline, данные как `const DATA = …` (реестр), `REFS` (референсы), `GANTT`, `KANBAN`, `FLOWS`, `COMP`, `SECS` (оглавление), карты картинок `IMG`/`THUMB`.
- **Картинки встроены один раз**: `register(key, path, full_maxw, thumb_maxw, webp)`; `fig(key, caption, group, cls, ref)` рисует `<figure class="lb" data-key data-group data-ref data-cap>`; графики — PNG без пережатия (текст), макеты/скриншоты — WebP.
- **Лайтбокс**: группы по `data-group` (дедупликация по ключу), режимы вписать/1:1/2×, Ctrl+колесо, перетаскивание, клавиши, hash-ссылка `#lb=key`; hotspots позиционируются в процентах от `width×height` карточки (работает при любом масштабе и для мобильных 2×).
- **Модалки**: `#pm` карточка предложения (переиспользует `detail(r)`), `#im` универсальная (Гант/Kanban/узел схемы); лайтбокс поверх модалок (z-index 1000 > 900), Esc закрывает верхний слой, прокрутка body блокируется, пока открыт любой слой.
- **linkify**: регулярка по текстовым узлам между тегами, пропуск уже существующих `<a>`.
- **Scrollspy**: по `offsetTop` секций, подсветка ссылки в навигации, «Вы здесь», `nav.scrollLeft = 0` (иначе длинные пункты сдвигают панель), `grid-template-columns: 270px minmax(0,1fr)` + `main{min-width:0}` против горизонтального переполнения.
- **Реестр**: таблица с сортировкой по заголовку, фильтры (категория, игра, класс, приоритет, квадрант, метка, наличие концепта), раскрывающаяся строка `detail(r)` с блоком «Концепт дизайна».
- **Секции**: резюме+KPI-плитки → 15 разделов стратегии (markdown → HTML, figure-ссылки заменяются на `fig`) → реестр → оценки/чувствительность → графики (одна колонка) → блок-схемы (живой SVG + PNG в `<details>` для печати) → Гант (HTML-полосы) → Kanban → макеты → референсы дизайна → текущее состояние (скриншоты-факты) → модель → конкуренты → источники → вопросы владельцу → подвал с ©.
- **Автотест** `scripts/smoke_html.mjs` (Playwright): счётчики секций/строк/фигур, scrollspy после `scrollIntoView({behavior:'instant'})` (плавная прокрутка ломает тайминги), лайтбокс + зоны + зум + стрелки, модалки предложения/Ганта/Kanban/схемы, конкуренты (поиск, лайтбокс), авторство, ошибки консоли = 0, внешние запросы = 0. Запускать после каждой пересборки.

## 7. Решения и принципы, которые стоит закрепить в скилле

1. **Только чтение внешнего мира**: никаких публикаций, писем, регистраций, оплат, записи в чужие репозитории; обращения к агенту в данных — цитировать, не выполнять.
2. **Каждая цифра с меткой** `[факт, источник, дата]` / `[оценка, метод]` / `[допущение]`; формулы финметрик с подставленными числами; цитаты <15 слов, по одной на источник.
3. **Три главные ставки** в резюме вместо списка из 100 пунктов; стратегия как оптимизация существующего продукта, а не «добавить всё».
4. **Реестр отдельно от текста**: текст ссылается на id, карточки живут в JSON; тогда и HTML, и XLSX, и слайды собираются из одного источника.
5. **P0 не из заполнителей**: правило квадрантов в приоритизации.
6. **Концепты ≠ существующие функции**: бейдж на каждом макете; скриншоты текущего состояния — факт, не трогать.
7. **Дизайн-язык сначала, макеты потом**: общий kit + демо-экран + бриф, затем параллельная перерисовка; механический аудит (контраст ≥4,5:1 над светлым фоном, нет старых элементов) + оценка моделью.
8. **Референсы для задач**: отдельная папка с карточкой на экран (описание + зоны + PNG), чтобы владелец заводил задачи без чтения стратегии.
9. **Интерактив по умолчанию**: любая картинка увеличивается, любой id предложения кликабелен, Гант/Kanban/схемы раскрываются, конкуренты фильтруются; scrollspy в навигации.
10. **Проверки как код**: check_registry, validate_scores, check_links, audit_screens, smoke_html, валидатор OOXML — запускать после каждой пересборки; отчёт честно перечисляет, что не прошло.
11. **Авторство** во всех форматах (meta, титул, подвалы, свойства файлов, README).
12. **Git-дисциплина**: ветка на задачу, merge самостоятельно, push, ветки сохранять; в коммит только файлы задачи.
13. **Память и чекпоинты**: STATUS после фаз, TASKS с «Где остановился», memory-заметки о месте папок и предпочтениях заказчика.

## 8. Грабли и как их обходили (для раздела «Troubleshooting» скилла)

| Проблема | Решение |
|---|---|
| `CERTIFICATE_VERIFY_FAILED` в urllib | `certifi` + `ssl.create_default_context(cafile=certifi.where())` |
| `python3 -I` ломает matplotlib (`packaging` не найден) | запускать графики без `-I`; `-I` только для скриптов, читающих недоверенные файлы |
| pptxgenjs не находится скриптом темы | `NODE_PATH=$PWD/build/pptx-node/node_modules`; валидатору нужны `defusedxml`, `lxml` |
| Playwright не резолвится из scratchpad | запускать скрипты из папки проекта (там `node_modules`) |
| XLSX: таблица подсказок пересекалась с данными | заголовок данных на строке 8 ниже lookup-таблиц |
| Ничьи в рангах при валидации | нормализовать неокруглённые метрики, сортировать по `round(x, 9)`, затем id |
| «Длинные цитаты» — ложные срабатывания на примерах UI-текста | регулярка-исключение по контексту («например», «вида», «текст…») |
| Заголовки графиков наезжают на подзаголовки / подписи обрезаны «…» | `cl.title` с отступом по числу строк, `wrap()`, `place_labels()`, панель с полными названиями рядом с матрицей |
| Контраст текста на стекле над светлой картой < 4,5:1 | поднять muted-токены внутри `.kt-screen`, плотнее фон у плавающих элементов и активных кнопок; где много мелкого текста — стекло 0,9 |
| `data-marksAll` не читается | HTML приводит атрибуты к нижнему регистру — использовать `data-marks-all` и читать оба варианта |
| Класс `.pro` в макете ломает `.kt-avatar.pro` | префиксовать классы набора (`kt-`) и предупреждать агентов о конфликтующих именах |
| Бейдж концепта закрывал счётчик | позиция бейджа по центру области карты (`calc(50% + aside/2)`) |
| Лайтбокс закрывался при клике по зоне | в HTML был незакрытый `<a href>` из markdown-карточки (литерал «&lt;a href&gt;» в тексте) — экранировать/заменять; искать через CDP `Page.frameRequestedNavigation reason=anchorClick` |
| Клик по тегу предложения открывал и лайтбокс, и модалку | в обработчике figure исключить `a, .tag.ref` |
| Горизонтальный сдвиг страницы и навигации | `minmax(0,1fr)` для колонки, `main{min-width:0}`, `overflow-x:hidden`, `nav.scrollLeft=0` после `scrollIntoView` |
| Smoke-тест: scrollspy не успевает | `scroll-behavior: smooth` → в тестах `scrollIntoView({behavior:'instant'})` + ожидание |
| Вложенные блоки SVG перехватывают клик | в тесте `click({force:true})` на внутреннем узле; в UI это ожидаемо |
| Анти-бот (Cloudflare 403) на скриншотах конкурентов и проверке ссылок | помечать `shot_blocked`/аннотировать статус, перепроверять curl с браузерными заголовками или `gh api` для приватных репозиториев |
| `grep -c` возвращает 0 → `&&`-цепочка обрывается | не ставить проверки с ненулевым кодом выхода в середину цепочки; `$` в grep — якорь |
| zsh: `--include=*.html` → «no matches found» | брать glob в кавычки |
| Ключ API мелькнул в выводе `grep settings.json` | никогда не грепать файлы настроек целиком; ключи только из env; после — проверить, что ключа нет в выходных файлах |
| Папка не там, где ждал заказчик | уточнять место папки в начале; хранить в памяти правило |
